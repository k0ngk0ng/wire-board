# 原版采样器验证范围

先建立本清单与验收入口，再编写可复用采样器和独立游戏逻辑。

## 失败场景

- 加载了其他 ROM、其他内核或不匹配的内部 ABI，导致地址观察失真。
- 重构采样器后，输入帧从 1 开始的边界、六键编号或回调顺序发生变化。
- 为原版增加执行钩子改变了 RAM、画面、CPU 时钟或输入轮询时序。
- 把原生字节交换布局直接当成 68000 大端 CPU 地址，导致相邻字节读反。
- 存档缺少模拟器时序字段，却只比较画面并认定状态完全一致。
- 把栈区域一概从比较中排除，掩盖会影响下一步执行的差异。
- 收集到函数中间态或未完成调用，错误地当作规则函数输入／输出。
- 首个动作对照不匹配时替换种子、删掉样本，或用自创参数迁就画面。
- 缓存、临时输出或独立进程写到 worktree 之外。

## 验收

1. 原版冷启动 3,600 帧必须与首轮保存的每帧 RAM 和视频摘要一致。
2. 原始存档路径保留严格差异；诊断路径只能恢复有源码证据的遗漏硬件状态，并对全部 RAM、CPU 可见寄存器和视频逐帧比较，不屏蔽范围。
3. 新工具的钩子关闭／开启分别冷启动，以相同输入验证输出完全一致。启用状态不应靠 RAM 修改、断点跳过或固定结果获得通过。
4. 捕获文件固定 ROM、内核及采样器摘要、输入、帧号、PC、寄存器、内存来源与覆盖区间。
5. 独立 Go 规则的第一批夹具必须先从已验证的原版路径产生，再写实现；逐帧连续样本和函数隔离样本分开记录。

原版与研究工具的完整二进制／内存留在 `.local/md-yuyuhakusho/`，只提交提炼后的状态夹具和核验报告。
