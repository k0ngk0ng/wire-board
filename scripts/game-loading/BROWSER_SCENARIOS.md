# 加载页面浏览器验收（先于实现）

使用生产入口编译的本地服务，真实 HTTP、SQLite、平台计时与浏览器，不注入房间／游戏状态。

1. 清缓存登录，首页静态传输 < 900 KB（未压缩），没有棋盘模块；创建选择显示 25 款封面。
2. 每款游戏用正常 HTTP 创建、加电脑、准备、开始；观察统一进度条，加载期间无行动期限；画面完成后唯一真人确认，电脑不阻塞；记录状态、加载资源和截图。
3. 双真人泡泡堂：第二人的资源请求延迟，第一人到 100% 仍等待；选角期限与模拟时间不前进，直到第二人的实际浏览器完成。观战不阻塞。
4. 320px 加载页封面、进度、玩家状态、重试均可见，无横向溢出。
5. 必需图片与动态脚本失败不发确认；恢复资源后重试能完成，旧回调不能发送确认。
6. 加载途中刷新使原确认失效；对局开始后刷新仅加载本机，不改变服务器期限／开局代次。
7. 赛车首帧、泡泡堂地图／角色和疯狂坦克地图／坦克资源完整；篮球原生运行时实际完成后确认，OSS 资源不进构建。

运行 scripts/game-loading/check-browser.py；保留 JSON、截图，退出时清理本次 profile、测试数据库和临时服务。服务与前端构建整个验收过程固定，不在运行中改写 dist。
