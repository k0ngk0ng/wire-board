# 围棋

独立维护 9／13／19 路围棋，支持两人真人、电脑与平台托管。默认下架，只有管理员上架后才向玩家开放。创建、等待、玩家栏、计时和结果沿用平台框架。

## 规则

规则标签为「面积计分 · 禁自杀 · 全局同形」，参考 [Tromp–Taylor](https://tromp.github.io/go.html) 的连通、面积与位置同形定义，明确采用禁自杀和双方确认终局；不宣称完全符合某版中国竞赛规则。固定来源及实现前失败清单见 [实施规格](../../docs/research/chess-family/weiqi-implementation.md)。

随机分配黑白，黑先，无让子。默认白贴 7.5 目，可选不贴目。棋块沿上下左右相连，邻接空点是气；落子后先提走无气的敌方棋块，己方仍无气则拒绝。落子后的黑白局面不得重复本局任何历史局面，不区分手番；停着和继续对弈不清除历史。

连续两次停着进入计分阶段。任一方可以选中整块棋子切换死子标记，修改提案会清除双方确认。只有双方确认同一版本的提案才移除死子并结束；不自动推测死活。有争议可继续对弈，由第二次停着后的应行动方继续，保留棋盘和重复历史，清除死子提案与确认。

面积为存活棋子数加仅邻接己方的空点数；两色共同邻接或没有邻接棋子的空域中立。白方另加贴目，提子数不重复计分。确认存活的双活棋块按相同面积规则处理，共同气保持中立。分数相同为和局，真人积分变化为 0、不计胜场。含电脑的对局不计分。认输结束时不展示或保存未经双方确认的面积分数。

## 电脑、托管与恢复

两档电脑均通过相同 Apply 接口落子，不改变规则、局面或胜负。入门策略优先提子、救子、增加气、连接和保护眼；标准策略在 350 毫秒预算内对候选行动及对手回应作两层战术搜索。搜索走平台 `BotSearch`，支持取消，保留快速合法回退，不依赖外部模型、引擎服务或额外配置，不承诺 Elo。

电脑在没有合适落点时停着。计分时不会直接判定死活；对方将己方棋子标死时，电脑恢复对弈处理，否则确认当前提案。电脑与真人采用相同的重复禁着和终局流程，没有电脑专用的强制手数上限。

行棋阶段只催当前手番。计分阶段分别记录双方期限，修改标记或确认均不延长时限；已经确认的一方暂不欠操作，提案改变后恢复责任并保留原期限。超时由平台接管，取消托管只恢复本人已过期的操作窗口。存档保留全部重复历史、贴目、提案版本、标记、确认及期限。

## 界面与素材

公共玩家栏显示黑白归属、提子数和计分确认状态。棋盘保持正方形，手机默认完整适屏；棋子过小时点区域只放大，不落子。操作视图棋子至少 24px。支持鼠标左键拖动、无需修饰键的滚轮缩放、触屏拖动／双指、可拖动概览、方向键／回车，选点后另行确认。

落子、提子与确认死子移除使用服务端事件驱动的显示时间轴。被提棋子及提子数在落子动画完成后更新；连续事件依次播放，刷新、重连和事件跳号直接恢复局面，不补播旧动作。支持减少动态效果和平台统一静音。

4 张 WebP 为原创棋盘底纹、黑白棋子与棋罐围空封面，保持与其他游戏一致的插画风格；5 个 WAV 为落子、提子、停着、胜利和和棋。落子使用 Kenney CC0 碰撞素材，其余由平台原创音调离线生成。来源、许可与 SHA-256 见 `assets/sources.json` 和 `assets/licenses/`。

不可变路径为 `ASSETS_BASE_URL/weiqi/v1/`，当前已上传 OSS 并回读校验；本地回退为 `/weiqi/v1/`。修改已发布素材须提高目录版本，不能覆盖当前 v1。

```sh
. scripts/env.sh
# 通用 SVG 渲染依赖；另需本机 cwebp、ffmpeg。
npm install --prefix .local/chess-family/assets-tools --no-save --ignore-scripts @resvg/resvg-js@2.6.2
node --experimental-strip-types scripts/weiqi/prepare-assets.mjs
python3 -B scripts/weiqi/verify-assets.py --dist --decode
```

## 验收

规则 HTTP 用例及动画检查先于实现。规则中局夹具单独标记，不计作自然完整局。HTTP 覆盖多块／同块提子、自杀、劫和更早的历史同形、共享气、中立区、贴目、死子提案、过期确认、并发确认、超时、接管、认输与 SQLite 恢复。

三种路数×两档电脑×两种贴目共 12 局使用生产策略经真实 HTTP 会话完成，均从空盘开始并中途重启；另外三种路数×两档电脑共 6 局使用生产自动调度、真实电脑席位和托管真人，包含取消托管、手动落子、再次托管及重启。原生完整局已通过竞态检查，没有强制指定胜者或提前截断为通过。

浏览器覆盖三种实际路数、PC 鼠标／键盘、390px／320px 完整棋盘和放大、触屏实际平移／双指／落子、静音、死子标记／争议恢复／确认、对比度、刷新，以及 CDN 请求失败后的本地图片与音频播放。九路中局另采集连续两步的实际动画帧，验证提子显示时序。浏览器为 Chrome 原生输入模拟，不称为实体手机硬件验收。
