# 泡泡堂契约

## 房间、版本与地图

- `Module.ID = "bubbleparty"`，名称「泡泡堂」，只接受 2／4／6／8 人。座位 `0..n/2-1` 为红队，其余为蓝队；`Result.Team = true`。
- 新局使用 `rulesVersion=3`。无版本字段的存档视为版本 0；版本 0 和 2 恢复时保留原规则，不因刷新、接管或发布升级。
- 地图包含 `community10`、`waterpark`、`forest`、`desert` 4 张既有地图和 `classic2002-*` 的 112 张经典地图，另提供 `random` 选择；单局时限 180～300 秒。
- 经典地图数据来自同一份 `data/classic-2002.json`，前后端不能分别手写或重排原始矩阵。`Village09` 不冒充国服「小区10」；源编号和既有地图 ID 分开维护。来源与未确认字段见[经典地图研究](../../docs/research/bubble-classic-maps/README.md)。
- 平台棋盘保持 15×13。111 张经典地图为原尺寸；13×11 的 `Village00` 居中偏移 `(1,1)`，外圈封墙。优先采用原始出生点，不足平台人数时只补入有出口的空地，不删除原始障碍；分散选点和红蓝分队属于平台适配。
- 格子类别：0 空、1 不可破坏墙、2 固定可破坏箱、3 水泡、4 可推箱。旧版本不追加新版可推箱规则。原始对象 ID 另外保存为 `nativeObjects`，空格为 `-1`，爆破和推动须同步更新，不能从初始地图补回已移除对象。
- 原始多格障碍从锚点向右、向上展开；方向门、传送带、地面阻挡和矿轨依据已恢复字段处理。未确认的工厂地面字段不当作必死区域。原图 `Village00` 配对端点位于树下，保留硬树，不为展示传送而删除原障碍。详见[平台适配](../../docs/research/bubble-classic-maps/platform-adaptation.md)。
- `community10` 保留官方截图转录的固定布局，不要求 180° 对称，不增加外墙。六棵高树为硬障碍，其余对应果实灌木可穿行；住宅不可破坏，砖和箱子可破坏，中央可推箱独立标记。旧局按已保存碰撞格绘制，不在原本可走的格子下补树墙。
- 小区 10 仍按既有人数安排出生点并保留必要逃生清理；原始布局与位置依据见[地形核查](../../docs/research/bubbleparty/geometry-original-evidence.md)。另外 3 张既有自定义地图继续验证对称、出生区与可破坏后连通性。
- 等待房间修改地图后可「保存并准备」。配置实际变化时清除其他真人准备状态，电脑保持准备；配置相同不清除其他真人准备。

## 开战前角色选择

版本 3 的阶段顺序为 `select → countdown → playing → finished`。

- `select` 最长 20 秒，`selectUntil` 为服务端毫秒截止时间。8 位常规角色可重复选择；默认角色按席位分配。选择卡片更新角色并清除该席位确认，独立确认按钮设置 `selected=true`。
- 全部席位确认后提前进入 3 秒 `countdown`；期限到达时锁定当前或默认角色，再进入倒计时。选角到期不把真人转为托管。
- `select` 的 `Actors` 保留所有席位，使已确认者仍可改选；`Attention` 仅包含尚未确认的席位。电脑和托管席位通过正常角色动作确认，不直接改写状态。倒计时与选角均禁止移动和放泡。
- 角色动作只允许本席位在 `select` 内提交。比赛开始后服务端拒绝换角，前端只提供角色资料。观众不能选择；隐藏 C08／C09 不接受直选。
- 角色初始速度、水泡数、水柱范围及各自上限取自 `Attr/BomberAttr`，按 C00～C09 ID 关联，不能使用原表记录顺序当 ID。C00～C07 对应皮蛋、黑妞、小乖、小强、蓝蓝、葱头、宝宝、胖墩；中文名依据原始头像与现有资料核对，不声称由韩文属性表直接解码。
- `nativeSpeed` 保存原始每 30 ms 的移动像素数，原版一格为 40 像素。无坐骑时实际单格时间使用浮点数 `1200/nativeSpeed`；不能把展示用向上取整值当作运动精度。道具分别提升对应属性，并按所选角色上限封顶。
- 选择与确认写入服务端状态并触发关键检查点。重连不重新选角，不恢复旧 `avatar` 本地偏好覆盖版本 3 的角色，也不延长选角或开战期限。

```json
{"type":"character","epoch":"...","character":2,"confirm":false}
```

`character` 为 0～7；`confirm=false` 选择或改选，`confirm=true` 确认指定角色。该动作不携带移动序号、方向或放泡请求。

## 移动与放泡动作

严格 JSON，最大 8 KiB，拒绝未知字段：

```json
{"type":"input","epoch":"...","seq":12,"move":"up|down|left|right|none","bomb":false}
```

- 只接受当前 `epoch`；`seq` 大于该席位已应用序号，跳跃不超过 2048。拒绝重复、回退序号及错误实例控制。
- `move` 为持续意图；`bomb=true` 为一次性边沿请求。占格、容量或冷却不满足时丢弃该请求，不保留到稍后位置自动放泡。
- 版本 2／3 困泡时清理当前方向和待处理输入。困泡期间输入可确认 `seq`，但不保留移动或放泡意图；救援后须有新的输入。
- 观战者、已淘汰席位、选角／倒计时／结束阶段不能移动或放泡。客户端不提交坐标、生命、水泡实体、胜负或属性结果。
- 输入看门狗在 700 ms 未收到新输入后停止旧方向；真人不会因空闲自动托管，平台不显示回合操作期限。

## 实时移动与推箱

- 平台使用 100 ms 推送帧、20 ms 子步。版本 2／3 的 `OnTimer` 和输入到达都推进完整子步，避免短按被吞掉；`SystemDeadline` 必须为未来或 0。
- 版本 2／3 的 `px=x+offsetX`、`py=y+offsetY` 为连续位置，整数为格中心，`x/y` 保留最近逻辑格。`speedMs` 是实际每格毫秒数，版本 3 可为浮点值；骑乘及矿轨速度由服务端计算。角色碰撞半径为平台参数 0.28 格，转向先回到中心线。
- 房屋、高树、箱子和水泡碰撞由服务端控制。水泡内角色可以离开，但离开后不能折返。客户端最多进行 250 ms 的有界移动显示预测，使用可见障碍并接受服务器校正，不决定推箱、放泡、伤害或结果。
- 版本 3 仅原始标记为可移动的箱子可推。角色须沿格线接触近侧箱面；不允许远程、斜角、推砖、推房屋或连推多箱。飞碟穿箱，不触发推箱。
- 推箱目标须为空，且没有水泡、道具、活动箱体、原始可穿对象或存活角色身体占用。多人同时推动同一箱子不得复制箱体或绕过占用。
- 推动一格持续 300 ms，来自原始 40 像素箱体以每 30 ms 移动 4 像素的节奏。`boxMotions` 保存起点、终点、起止时间及原对象 ID；服务端维护移动占用，前端按相同时间轴插值，不提前穿箱或重复绘制目标箱。箱体爆破后同步删除碰撞、对象及呈现残影。
- 传送带、方向通道和活动推箱附近使用权威位置平滑；普通地形保留本机预测。复杂地形的输入显示可能更依赖快照延迟。矿轨仅提升矿车速度，飞碟屏蔽传送带强制运动。

## 水泡、道具与坐骑

- 水泡容量、引信、连锁、箱体破坏、掉落、拾取、困泡、救援和淘汰均由服务端判定。水泡者离开后占格保留；连锁提前触发，持续水柱会命中后来进入的角色。
- 当前引信为 2.2 秒，水柱存在 420 ms，困泡窗口 5 秒，救援保护 1 秒。这些属于平台调参，尚未由同版本原作运行验证。
- 水柱命中未骑乘角色后先困泡，困泡者仍存活但不能移动、放泡或拾取。活动队友触碰救援并给予短保护，活动敌人触碰击破并获得淘汰记录，困泡超时淘汰。
- 新局掉落速度、水泡容量、水柱范围及 8 种坐骑。当前箱子掉落率 58%，掉落池中三种能力各占 12 个权重、每种坐骑占 1 个权重；这些是平台参数，不是原版服务器概率。原始地图道具权重保留在来源数据中，不将保存原表等同于已恢复原版掉落算法。
- 8 种坐骑为 `turtle`、`turtle-fast`、`owl`、`airship`、`airship-broken`、`octopus`、`octopus-fast`、`railcar`。原包图标、四向本体及角色骑姿分别映射，不能以地面图标替代骑乘模型。
- 骑乘保留基础速度和成长属性，能力升级不会因掉骑丢失。已有坐骑、困泡或淘汰角色不能重复上骑。飞碟及故障飞碟可穿固定箱和可推箱，但不能穿硬墙、水泡，且不能拾取任何道具。矿车只在原始轨道地面提速；不臆造章鱼水域能力。
- 骑乘受击先掉骑，并保留 1500 ms 水柱保护，防止同一水柱立即困住人物。立即显示脱落是对原始 50 tick 过渡的简化；不宣称动画逐帧复原。详细来源见[坐骑研究](../../docs/research/bubbleparty/mounts-original-evidence.md)。
- 盾牌不作为自定义被动升级加入新版掉落池；版本 0 保留历史掉落池，存档已有地面或持有护盾不删除。针、踢泡和投泡未接入。
- 水泡、爆炸、道具、事件、日志和输入队列均有数量上限。

## 公开视图与音效

- `cells` 为数字数组；内部存档仍兼容字节数组。公开服务端时间、阶段、`selectUntil`、位置、属性、坐骑、困泡／保护截止时间、水泡、爆炸、道具、事件和存活／淘汰状态。
- `PlayerView` 提供 `seq`、`character`、`nativeSpeed`、`selected`、`mount` 及实际 `speedMs`。`you`、`canAct`、`spectator` 按席位生成；`canAct` 表示实战操作资格，选角动作资格由阶段和席位控制。
- 既有地图的 `tiles` 继续作为装饰投影，不能决定碰撞。经典地图使用原始地面及当前 `nativeObjects`；`boxMotions` 表示正在移动的箱体。视图不暴露内部 RNG 或未来掉落。
- 全部声音通过平台 `BoardProps.audio` 播放，服从统一静音和原生媒体通道。只有 `item` 事件的 `seat` 等于 `room.you` 且非观战时播放拾取音；`drop` 不播放拾取音。其他公共事件保持各自声音映射。
- 事件去重、静音和页面隐藏门控保持有效；刷新、重连、取消静音不补播旧拾取声音。队友、敌人和观众均不能听到别人的拾取声。

## 素材与交互

- 经典地图、角色和坐骑使用不可变 `bubbleparty/v4/` 资源及同源回退；`v2`、`v3` 旧素材不覆盖。来源范围、SHA-256、生成器和许可状态保留在各清单中。
- 版本 3 提供 8 位常规角色和对应能力；C08／C09 仅保留定义与素材。角色红蓝队色不因造型、移动、困泡、死亡、骑乘或素材失败而改变。任何人物、坐骑或回退均不添加身份数字角标。
- 人物分层沿用 Static 先画、染色 Adjust 后覆盖，原始动画帧顺序保留。显示时基、锚点与红蓝调色算法的项目约定在素材清单中明确，不冒称完全恢复原始绘制算法。
- 选角使用平台 Modal，开局自动显示一次，关闭后可从醒目入口重新打开，不随普通快照强制重开。已确认状态刷新后保留。比赛开始后的角色资料只读，不暂停对局。
- 手机摇杆输出四向 `move`，不新增斜走。死区为有效半径的 17%，原轴在斜向边界使用 18% 转向容差。指针捕获允许移出区域继续转向，松手、取消、失焦、困泡和失去控制权时归中停止；第二指放泡不取消第一指移动。桌面键盘和鼠标使用相同规则接口。

## 电脑、托管与恢复

- 电脑在选角阶段通过正常动作选择并确认常规角色；倒计时不移动。实战寻路、避泡、救援、触碰敌方困泡及推箱都遵守同一规则，只使用该席位可见信息。
- 放泡前须确认可达安全格。全部地图和开放人数均须覆盖电脑完整对局，能以全灭或硬时限结束；真人与电脑混合、托管、手动接管及恢复同样验收。
- `Reclaim` 只清理该席位控制并刷新输入空闲标记，不重置角色、坐骑、地图、箱体、水泡、位置、困泡期限、保护或分数，不改变其他席位期限。
- `Restore` 保留规则版本、epoch、选择状态、能力、坐骑、原始对象、箱体运动、连续位置和已有期限；修复合法范围内缺失的兼容字段及水泡占格，不重新开局。

## 版本 0／2 兼容

- 版本 0 保留原 100 ms 整帧推进、整数格移动及 `NextMoveAt` 门限。输入只入队，不提前推进时钟；首次水柱直接淘汰，护盾吸收一次，不使用困泡救援。旧水柱按生成时命中，不用新规则重复消耗护盾。
- 版本 0 保留 60% 时限后的缩圈和硬时限人数判定；越过收缩安全区直接淘汰。版本 2／3 不缩圈，双方到时仍存活则和局。
- 版本 2 保留原统一移动、容量和水柱参数及困泡救援，不加入版本 3 的角色能力、坐骑、推箱或开战前选角。
- 旧版本保留 `avatar` 0～3 的纯外观动作。存活真人可在倒计时或实战选择，不能改变能力或队伍；观众、错误 epoch、非法外观和托管中的人工操作拒绝。选择独立检查点保存，不推迟系统帧。旧浏览器外观偏好仅对旧规则新倒计时适用。
- 旧局不重置 epoch、位置、`NextMoveAt` 或既有期限，不在原本可走的树格追加硬碰撞。数字视图、放泡边沿和输入停止等通用修复仍适用。

## 结果与持久化

- 一队全员淘汰时另一队获胜；胜方每人 rank 1，负方 rank 2。同帧双方全灭为显式 `Draw`，无人获胜。
- 版本 2／3 到达硬时限时，双方仍有存活者即 `Draw`，不按人数优势判胜。含电脑对局由平台不计分；真人和局所有人积分变化为 0，保留次数和历史。
- 普通输入和物理帧在内存推进，不逐条写动作日志或房间快照。平台每秒保存发生变化的房间；开局、角色选择、结算、托管切换、关闭及 `CheckpointKey` 标记阶段立即事务保存。
- 正常断线重连读取内存最新状态，正常关闭保存剩余变化；存储健康时异常崩溃可能回退约一个保存周期，保存失败时按最后成功检查点恢复。
- 输入确认的 `durable:false` 仅表示已处理，不是落盘凭证。新实例用 `serverInstance` 通知客户端接受恢复版本、拒绝旧实例控制并清理真人旧方向；电脑及托管状态保留。

## 验收边界

验收覆盖全部地图和开放人数、原始碰撞与出生点、选角与超时、角色属性上限、坐骑和特殊地形、推箱占用与同步、困泡接触、非法输入、恢复／竞态、电脑完整对局、红蓝呈现、320 px 原生触控、资源失败回退及多客户端拾取音效隔离。先列出的失败场景见[本轮实现说明](../../docs/research/bubble-classic-maps/IMPLEMENTATION.md)；操作和素材变化须保留可重复执行的浏览器结果，不能用历史旧版记录代替。
