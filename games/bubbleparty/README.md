# 泡泡堂（bubbleparty）

围桌内的实时水泡对战游戏。模块 ID 保持 `bubbleparty`，已有房间、战绩和管理设置不迁移。新局使用规则版本 3，支持 2／4／6／8 人、红蓝两队、电脑玩家和真人托管。

## 开始游戏

等待房间提供 112 张从 2002 年客户端恢复的经典地图，以及小区 10、水乐园、森林公园、沙丘营地 4 张既有地图，并显示地图预览。修改地图后可使用「保存并准备」；电脑保持准备，其他真人需重新准备。

开局先进入 20 秒选角阶段，显示皮蛋、黑妞、小乖、小强、蓝蓝、葱头、宝宝、胖墩 8 位角色的初始速度、水泡数量、水柱范围及各自上限。选择后须确认；确认后仍可在选角阶段改选。全员确认会提前进入 3 秒开战倒计时；选角到期则使用当前或默认角色，不因此托管真人。比赛开始后，角色入口只提供资料查看，不能更换角色或重置能力。

角色能力取自原包 `Attr/BomberAttr`，按资源 ID 绑定。海盗船长和圣诞老人保留原始数据与素材，但不提供直接选择，避免在缺少原版隐藏角色分配规则证据时自行设计机制。红队、蓝队基础色保持不变；人物和回退素材均没有数字身份角标。

## 操作与玩法

- 桌面使用方向键或 WASD 连续移动，空格或 J 放水泡。手机使用可拖动摇杆和独立放泡按钮，仍按原版四向走格。中心死区和转向容差减少误操作；松手、取消、失焦或困泡时停止，可同时用另一根手指放泡。
- 水泡放下后可以离开，离开后不能穿回。水柱沿十字传播，破坏箱子并触发连爆，持续期间仍会命中后来进入的角色。
- 原版标记为可移动的箱子可以推动一格，移动过程为 300 ms；普通固定箱、砖和房屋不能推动。目标格有障碍、水泡、道具或角色时不能推入，也不能连续推一排箱子。小区 10 中央可推箱保留独立外观和碰撞。
- 水柱命中未骑乘角色后先困泡；队友触碰救援，敌人触碰击破，困泡到期仍未获救则淘汰。救援后有短暂保护。
- 拾取道具提升速度、水泡容量或水柱范围，按角色各自的上限封顶。拾取音效只播放给拾取者；队友、敌人和观众不会听到，箱子掉出道具时也不播放拾取音。
- 支持普通／快速乌龟、猫头鹰、飞碟、故障飞碟、普通／快速章鱼和矿车，共 8 种坐骑。骑乘保留角色基础能力，受击先失去坐骑；飞碟可以穿箱，但不能穿硬障碍、水泡或拾取道具。矿车仅在原始轨道地面提速。具体证据和实现边界见[坐骑说明](../../docs/research/bubbleparty/mounts-original-evidence.md)。
- 新局不缩圈。一队全灭时另一队获胜；时限结束双方仍有队员则为平台显式和局，真人和局积分不变，含电脑对局不计竞技积分。
- 支持观战、刷新、断线重连和存档恢复。真人不会因空闲自动托管；手动托管和接管使用平台统一入口。

水泡引信 2.2 秒、困泡 5 秒、救援保护 1 秒和当前掉落概率属于平台参数。原包地图的道具权重已保存为研究数据，当前实现使用平台统一掉落池，不能称为原版服务器的精确概率。原版盾牌是限时消耗品，不作为自定义被动护盾加入新局掉落池；旧存档已有护盾保留原有效果。针、踢泡和投泡尚未接入。

## 地图与素材来源

经典目录覆盖所保留客户端内的全部 112 张地图，不代表泡泡堂历年全部地图。原始格子、对象、出生点及图集按来源恢复；少出生点地图补充平台席位、分队、窄地图居中等处理属于明确的平台适配。`Village09` 不等同于此前官方截图中的「小区10」，两者使用不同 ID 和预览。详见[经典地图来源](../../docs/research/bubble-classic-maps/README.md)和[平台适配](../../docs/research/bubble-classic-maps/platform-adaptation.md)。

小区 10 保留按官方历史截图转录的布局；高树阻挡，果实灌木可穿行。其余 3 张既有地图保留原有自定义布局。经典地图使用对应原始地形和对象图集；方向门、传送带和矿轨按已恢复字段处理，不根据外观臆造危险地形。

新地图、角色和坐骑素材使用独立的 `bubbleparty/v4/` 路径。旧 `v2` 音效和水泡素材、`v3` 外观素材继续保留，不能覆盖已发布文件。角色和坐骑保留原包分层帧及固定红蓝队色，封面为原创手绘 SVG。来源、SHA-256、生成方式与许可状态见[资源说明](assets/README.md)、`assets/manifest-characters-v4.json` 和 `assets/manifest-mounts-v4.json`。

本轮原版规则依据原始资源及 REA 静态分析，没有运行原版 Windows 联网对局；平台浏览器验收不能代替原作动态验证。本项目与官方运营服务无关联。

## 旧存档兼容

无 `rulesVersion` 的旧存档保持版本 0，保留原整数移动、伤害、缩圈和时限人数判定。版本 2 保留原连续移动、困泡救援、统一能力及 4 套纯外观选择，不追加新版选角、推箱和坐骑规则。刷新、接管或恢复不会将进行中的旧局升级到版本 3，也不重置其位置、地图、水泡或期限。

版本 3 的角色选择、成长属性、坐骑、原始对象和推箱运动按服务端状态保存。旧地图内部字节数组继续兼容，公开 `cells` 使用数字数组。具体接口和边界见[契约](CONTRACT.md)。

## 验证

按本次变更范围运行泡泡堂检查，不扩展到其他游戏。以下命令覆盖本游戏规则、前端、角色与拾取音效验收；浏览器检查前须先构建当前前端，并为每次执行指定新的输出目录：

```sh
. scripts/env.sh
go test -count=1 ./games/bubbleparty/...
npm --prefix web test -- bubbleparty
python3 -B scripts/bubbleparty/check-assets.py
python3 -B scripts/bubbleparty/check-mount-assets.py
npm --prefix web run build
python3 -B scripts/bubbleparty/check-map-previews.py --out .local/bubble-classic-maps/previews-acceptance
python3 -B scripts/bubbleparty/check-characters.py --out .local/bubble-characters/acceptance
python3 -B scripts/bubbleparty/check-pickup-audio.py --out .local/bubble-pickup-audio/acceptance
```

浏览器脚本使用真实 HTTP、SQLite、服务端计时和原生鼠标／触屏操作，保存报告与截图，结束后清理本次数据库、浏览器 profile、socket 和临时文件。规则、地图全量对局、竞态及战场操作的验收范围见[本轮实现前场景](../../docs/research/bubble-classic-maps/IMPLEMENTATION.md)和[战场接入说明](../../docs/research/bubble-classic-maps/BATTLEFIELD-INTEGRATION.md)。历史[重构验收记录](../../docs/bubbleparty-refactor-verification.md)仅说明当时执行结果，不替代版本 3 验收。
