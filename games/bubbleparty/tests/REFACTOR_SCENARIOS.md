# 泡泡堂重构：实现前失败场景

本文件先于重构实现与回归测试编写。测试通过模块公开的开始、输入、计时、视图、恢复接口执行；仅在需要准确碰撞时刻的场景中使用存档夹具，避免随机地图导致复现不稳定。

| 场景 | 必须验证的行为 |
| --- | --- |
| 地图被编码为 Base64 | 玩家与观战者 JSON 视图的 `cells` 为 195 个数字组成的数组，包含真实墙与木箱，且两者一致 |
| 放泡后移动清空水泡占位 | 放泡者可离开；返回原格被阻挡；水泡实体和地图占位都保留；其他席位也不能穿过 |
| 离开水泡导致连爆失效 | 已离开的水泡被另一水泡水柱触发，必须提前连爆 |
| 只在爆炸瞬间判断命中 | 水柱存续期间后来进入的角色仍被困泡；水柱消失后不再命中 |
| 正常站立突然托管 | 开局站立 30 秒不产生到期的真人超时席位，不改变角色位置、不代放水泡；取消托管后同样成立 |
| 水柱直接淘汰 | 首次命中进入可救援困泡，仍存活，公开到期时间；困泡期间不能移动或放泡，不能因此提前结算 |
| 队友无法救援 | 队友触碰困泡者解除困泡，公开短暂无敌期限；恢复存档保留困泡期限，救援后继续操作 |
| 敌方触碰无效或误救援 | 敌方触碰困泡者执行淘汰，记录淘汰席位及击杀归属 |
| 困泡永不结束或提前结束 | 到期前存活，到期后淘汰，不依赖下一次玩家输入 |

使用 `trappedUntil` 和 `invulnerableUntil` 的毫秒时间戳作为公开状态约定。测试不规定精确困泡或保护秒数，但要求困泡可操作救援、有界结束，保护确实发生。

可重复执行命令（仓库根目录）：

```sh
. scripts/env.sh
go test ./games/bubbleparty/tests -run '^TestRefactor' -count=1 -v
```

红测和最终验收输出由主任务保留在工作区 `.local` 验收目录；本文件及测试是长期复现入口。

后端实现前补充隔离失败场景：机器人在无退路死角放泡自杀；逃生只检查相邻一格、不能穿过尚未爆炸但未来危险的走廊；队友困泡时仍放泡或走开；可触碰敌人困泡时未补刀；连爆重复水柱消耗护盾后立即复困；取消托管或恢复抹掉困泡期限；旧存档水泡实体存在但占格丢失；旧存档合法行动期限被恢复重置。直接水柱命中测试改为先困泡，保护吸收后仍存活，超时才淘汰。

## 连续运动（第二轮实现前）

- 20～80 ms 短按在同一推送帧内按下并释放，不能被合并掉，必须形成服务端真实位移。
- `px/py` 以整数为格中心，`x/y` 是最近逻辑格；移动中应有小数位置，不能仍逐格瞬移；`speedMs` 随道具更新。
- 角色碰撞半径暂定 0.28 格，墙／木箱／未获通行的水泡边界不能被穿透；放泡者可离开但不能折返穿泡。
- 转弯先回到当前格中心线，不可斜穿拐角墙；松手不得继续移动，断线仍执行已有失联停止期限。
- 恢复旧存档默认 offset 为 0，恢复新存档保留小数位置、困泡、输入序号和其他席位期限。
- 机器人仍以相同公开输入运动，所有地图／人数可完成对局；不能依赖整数瞬移才能逃生或接触救援。

连续运动后的机器人边界：机器人和困泡目标已属于同一逻辑格、实际身体尚未接触时，仍应沿小数坐标接近，而不是将路径判定为完成；身体偏离格中心时放泡，离开原格前仍应允许选择任一方向离开，离开后不能折返。

## 官方小区 10 布局（地图实现前）

布局依据 `docs/research/bubbleparty/reference-evidence/district-10-visual-grid.json` 的人工图像转录，不能据此声称碰撞已经核实。失败场景包括：随机种子改变官方布局；错误地添加外框墙或强行旋转对称；中央三列道路变成草地；住宅、树篱、树、双色砖、木箱混成相同纹理；破坏软块后装饰仍留在画面；出生在房屋／软块上或放泡后没有逃生路线；不同人数出现重复出生点；暂定可穿树篱被当成墙使地图割裂；保存／恢复后布局元数据丢失。

固定出生选择图上已有空地，按队伍交替加入：红队 `(0,0)`、`(1,11)`、`(6,6)`、`(7,1)`；蓝队 `(14,12)`、`(13,1)`、`(8,7)`、`(7,10)`。只为实际参战席位清理必要软块：`(0,3)`、`(14,9)`；四人及以上再清理 `(1,9)`、`(1,8)`、`(13,2)`、`(13,3)`、`(13,4)`。六人／八人的道路出生点无需额外清块。每个出生点验证能在首泡引信到期前走到该泡水柱范围之外。

## 经典对战规则版本（实现前）

新局不得继承自创的缩圈突然死亡；计时归零时双方仍有存活者应显式和局，不按存活人数优势判胜。失败场景：新局在60%时限时开始缩圈或淘汰边缘角色；两对一存活时到时判人数多方获胜；结束视图仍显示缩圈截止；旧存档缺少规则版本时恢复被静默升级、改变既有SuddenAt/MatchEndsAt；旧局缩圈及人数判断消失。新局以 `rulesVersion=2` 标识，缺字段的旧局保留原规则。

原装饰对齐判断已撤销：第 5／9 纵列是重叠的果实灌木，不是奇偶行交替的杉树。重新核对官方截图后，高树仅位于 y=6、x=0/2/4/10/12/14；高树必须阻挡移动、放泡和水柱，灌木可以进入并用前景遮挡表现。新旧对局的兼容与失败场景见实时效率调查中的 MOTION.md。

## 审查确认的控制与旧存档回归（修复前）

- 容量已满或处于冷却时短按一次放泡，失败请求不得排队到数秒后在新位置自动放泡；后续独立新按键仍可正常放泡。新旧规则均覆盖。
- 移动中被困泡必须立即清理当前方向、待处理输入和放泡边沿；困泡期间收到的输入可更新序号但不能在救援后恢复旧方向或放泡。覆盖短于失联停止期限的快速救援，以及先前排队的方向输入。
- 规则 0 水柱仍直接淘汰；护盾只吸收首次水柱，不生成新规则保护或困泡；同一持续水柱不能在同帧重复消耗护盾并淘汰。
- 规则 0 保留整数移动、NextMoveAt 步长门限和原有帧推进时序，恢复不能重置 epoch、原计时或位置。规则 2 才启用连续位置和困泡救援。
