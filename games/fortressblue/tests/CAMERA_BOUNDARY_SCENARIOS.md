# 镜头上边界：实现前失败场景

需求证据来自用户对原作的回忆：炮弹继续飞过地图上方，镜头停在原图上边界。当前未取得可重复的原版运行录像；本次不把该约束声称为已经运行核实的原版参数。

- 高抛炮弹 y < 0 时自动镜头跟到负坐标，显示原图外空白。
- 炮弹回落后镜头仍锁死在顶部，不再正常跟随。
- 手动向上拖拽、鼠标滚轮或双指缩放将镜头重新带到图外。
- 缩小后视区宽或高超过地图，虽然 x/y 已限位，右侧或底部仍露出空白。
- 收紧视区时只改一个维度，拉伸原图比例；边界内滚轮锚点漂移。
- 刷新、窗口缩窄后视区未按新比例限位；小地图拖动重新绕开边界。
- 为修镜头而截断服务端弹道、重写炮弹坐标或打乱命中时间。

验证先写 camera-bounds.test.mjs，覆盖自动跟随、离图后回落、所有边界、PC/320比例、地图小于最小缩放与原位锚点；同步撤销旧测试要求负Y跟随的相反规范。真实浏览器验收只通过合法开局和射击，逐帧记录服务端弹道与实际镜头，执行原生PC拖拽/滚轮和手机拖拽/双指，保留JSON及截图。服务端物理保持原样（现有 y < -240 等弹道边界不在本次修改范围）。
