# 原始动画素材验证（实现前）

失败场景：

- 缺失任意一辆坦克、动作、朝向或可解码原始帧。
- 把地形坡度帧当作连续动画，把待机帧当作死亡帧。
- 裁切、重采样、镜像或重定位改变原始像素及落地锚点。
- 透明像素 RGB 被 WebP 规范化后误判；只比较可见 RGB 与完整 alpha。
- 图集超出 Canvas 常见纹理尺寸、越界或帧重叠。
- 没有证明原始动画时间却把选定播放速度声明为原版参数。
- MinAngle 被省略，ID 13 的配置值与原表不同，或把未知 Round 当回合延迟。
- manifest 缺 SHA、漏掉新文件、修改既有 v2 文件，或资源缺少本地路径。

验证先于实现编写。`python3 -B scripts/fortressblue/verify-animation-assets.py`
逐帧对照 `.i16` 解码像素、尺寸、两个朝向的锚点；核对原表逐列数据、
动作组来源及图集范围；保留 JSON 结果与原始帧接触表。浏览器渲染和时间轴
由游戏 E2E 另行覆盖，素材验证不替代实际对局验证。

## 原生分组与生成链补充验证

原生证据纠正原视觉推断时，先新增 `verify-v3-assets.py`，对错误分组运行失败，再更新动作元数据。另覆盖这些失败场景：

- Fire 被拆成两套弹种动作；Damage、Item 被误当死亡；死亡缺少 Dead 后续帧。
- 真实分组被错误的界面坐标常量替代，或把项目 30 Hz 当作原版更新频率。
- 标准 CI 只检查 v2，遗漏源码或 dist 中的 v3 图集。
- 旧来源验证调用 `build_items()` 意外改写当前道具规则。
- 历史生成器覆盖现有 v2 媒体、坦克、地图或道具数据。
- 来源验证在仓库外创建临时目录，或失败后遗留中间图像。

保留原生分组红灯、30 Hz 参数红灯、旧生成器拒绝覆盖结果，以及隔离来源重建结果。
