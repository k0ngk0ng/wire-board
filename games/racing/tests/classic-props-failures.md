# 可撞毁物件：实现前失败清单

规则范围仅为原数据中已核实的 normal 对象、属性位置一致且 collision type 为 2 的白名单：France 29、Coastal 83、UK 108、Park 45。现有 route 中其他 type 2、billboard、special、type 1、墙和护栏不因猜测分类而移除。

1. 新对局缺少独立 catalog 版本，或以全部 type 2 代替已核实的 265 个物件。catalog 不绑定旧 geometry 与原数值规则文件摘要。
2. 转换错误地修改四份既有 route／geometryHash／server hash-named 规则文件；源 route barrier 到展开 ruleEdges 的对应有遗漏、越界或一边多属。
3. State／View 没有紧凑、完整的当前破坏位图；0-based 物件 0 被 omitempty 吞掉；最后物件或跨字节边界使用错误位序。
4. 物件第一次真实接触仍执行静态墙反弹；同物件的多个边、多次求解、同帧多车接触重复破坏；破坏后后车仍受到阻挡。
5. 车辆静止或远离接触、桥上桥下高度分离却打破物件；固定墙、护栏或未核实对象被破坏。首撞高低动画带与方向不是由权威碰撞前状态计算。
6. 每场破坏状态修改了共享静态 Track／全局网格，导致另一房间同时破坏；电脑或本地预测仍使用已破坏对象构成的空气墙。
7. 客户端可提交破坏位、物件编号或破坏事件；预测写入权威位图或在确认之前改变全局物件显隐。
8. 事件丢失、超过 24 条环、迟到观战或刷新后物件重新出现；仅靠临时动画列表维持世界状态。旧事件被重复播放。
9. 保存／恢复、接管、断线保护、合法复位或比赛结束清空破坏状态，改变车况、比赛 epoch、检查点、名次或期限。
10. 旧 v3 存档缺少新增状态时被拒绝、重置或换用不同几何；已有明确 catalog 版本的存档被静默换成最新目录。旧 physics=0 行为变化。
11. 未知 catalog、几何不匹配、错误 base64／位图长度／未用高位被当作有效状态；计数超界使碰撞过滤越界。
12. 六车运动、同时喇叭和完整 24 条事件环加上新状态后超过 8 KiB，或通过丢弃事件、移除必要车况或限制正常物件破坏来满足预算。

验证以生产 Module 的普通 drive／timer 接触、保存／恢复及真实 View 为主，保留输入与轨迹产物。Go／TypeScript 针对同一 catalog、位图与物理状态做规则一致性比较。原版高低动画速度阈值尚无实机证据；选取的触发值须明确标为重建约定，不修改原有轮胎、车辆传动、圈数、排名或期限规则。
