# 驾驶物理回归场景

本轮先冻结失败场景，再编写测试与实现。完整比赛通过正式 Module 的 Start、BotAction、Apply、OnTimer 和 View 推进；极端碰撞与坡顶使用隔离的几何夹具，避免依赖无法稳定复现的玩家操作。

- 电脑被最慢车型的油门、极速和横向加速度限制；高速车型没有利用自身能力。
- 四条赛道的电脑三圈比赛过慢、撞墙卡死、漏过检查点、依赖复位或超时结束。
- 追尾、对撞、侧撞和高速擦肩穿透；同速擦碰产生不合理冲击；不同高度的车辆互相碰撞。
- 偏心撞击没有偏航，撞击后双方速度不变，已分离车辆重复受到冲击。
- 贴墙保留全部切向速度，持续油门抵消摩擦，墙体另一侧或桥下车辆错误受阻。
- 高速穿过薄墙、硬物体或车辆；可撞倒物件被误当成永久护墙。
- 高速平路无故起飞，低速坡顶起飞，高速坡顶仍吸地，空中转向或刹车改变轨迹。
- 落地穿透地面、弹跳不止、冲击没有减速，复位后仍带着旧的垂直速度。
- 服务端与本地预测的墙体摩擦、腾空、落地和空中惯性含义不一致；恢复后失去腾空状态。
- 小油门堵车不触发恢复，正常低速位移反被误判为堵住，斜卡后只会直线倒车。
- 六车投影超出既定 8 KiB 预算；碰撞事件刷屏或重复播放。

可重复执行：`go test ./games/racing/server ./games/racing/tests`、`npm --prefix web test -- racing`。验收结果位于 `.local/racing-dynamics/evidence/`，包括测试先失败的记录、物理轨迹、三圈比赛时间、竞态结果和浏览器截图。

配速按赛道分别比较原始基线，要求无其他行驶车辆干扰的三圈平均速度至少 29 m/s、峰值提高约 15% 以上（允许 0.05 m/s 的基线比较余量）。不使用所有赛道相同的绝对峰值门槛，因为路线曲率与直道长度不同。混合车型保留首车后 30 秒收车；不再通过限制快车动力保证所有车型同时完成。混合比赛按三圈防套圈场景要求每车至少进入最后一圈、距离终点不足四分之三圈，未完赛车辆只能在收车期限后结算。四条赛道另用正常五圈比赛验证六辆同型快车均自然跑完前三圈，且领先车尚未完成第五圈；三圈完整比赛的收车与排名由混合车型矩阵验证。各车型另以单电脑、另一席位保持手动静止的正常比赛验证独立完赛能力。该区分用于避免把正常收车后的未完赛状态误判成卡死，也保留不同车型的实际性能差异与碰撞损失。

本地预测对照实际压缩快照，位置差小于 4 mm，高度差小于 2 mm，速度差小于 0.035 m/s。墙体与地形边界附近允许快照舍入导致的微小差异，腾空和着地状态必须一致。运动状态保留比显示坐标更高的精度，预测优先使用一致的精细状态，避免地形接缝附近的接触分支漂移。
