# PvZ 后端先行失败场景

这些场景先于规则与模块实现编写。复杂玩法通过公开 Module/engine 动作与时钟推进完整链路验收；产物记录命令、参数、操作及结果。精确单状态战斗夹具明确标注，不能代替自然完整对局。

- 人数与设置：接受 3 人、双人 team/四人 duel、分队不等额、未知字段、无效回合/准备时间，或启动时绕过设置人数。
- 权限：观众、伪造席位/阵营、僵尸种植物、植物出兵、准备期出兵、结束后操作。
- 个人经济：2v2 基础资源翻倍，扣队友钱，金币为负，失败占位/冷却/非法动作仍扣钱，重复序号重复购买。
- 并发与归属：同格重复种植，队友铲除他人植物，过期 epoch 穿过换边，巨幅序号绕过去重。
- 战斗：子弹穿过首个目标、错误跨行命中、护甲未先受损、冰豆不减速、报纸未狂暴、撑杆越过高坚果或无限跳跃、未成熟土豆雷触发、樱桃不按范围爆炸、割草机重复使用。
- 时钟与资源：客户端操作额外推进时间、空闲时不推进、过长离线补算瞬间输局、天降阳光与向日葵给错误钱包、经济小数丢失导致双人总收入减少。
- 双回合：换边未清除钱包/冷却/实体、未重置割草机、比较了错误队伍的进攻时间、双方未突破却伪造胜者、同时间未和局、重复结算。
- 电脑与恢复：2/4 人植物/僵尸电脑不能完成对局，队友反复占位导致策略饥饿，托管取消重置其他玩家资源或期限，存档恢复改变状态/随机数/既有单位。
- 同步：克隆共享 map/slice，原生重复回放摘要不同；操作日志漏动作/无界增长，游标缺口未恢复，观众收到 canAct=true，常规流重复完整实体与静态目录。

拟执行：`go test -json -count=1 ./games/pvz/tests -run '^TestPVZBackend'`。测试内 `.local/pvz/backend/*.json` 保存场景和结果；Go JSONL 由外层命令保存。

## 补充先行场景：边界与真实 HTTP 完局

- 最后一个逻辑 tick 中僵尸越过已消耗割草机的房屋边界，同时到达回合时限：必须先完成该 tick 的碰撞与突破判定；没有突破才判防守成功。
- 自然一胜一负：只让固定一队控制僵尸、另一队全程保持真人空闲；不能因队伍换边而把进攻胜者记到防守队。
- 通过真实 HTTP 主动托管、取消及再次托管，不能自动改钱包、清冷却、改变对手、自动接管空闲真人。
- HTTP 完整 2/4 人电脑局采用 test-only 时钟适配器：只改变模块回调收到的时间与宿主下一次唤醒期限；所有资源、单位、策略、合法动作和结果仍由生产模块产生。必须记录加速倍数、自然生成的回合轨迹和最终结果，不能写入测试钱/位置/胜负。

## 补充先行场景：原版随机计数

- REA 已确认向日葵首次生产 300..1250 个 10ms 更新、后续 2350..2500 更新；固定使用区间上限会改变经典经济节奏。先验证多种固定种子的完整动作/推进/生产轨迹，再替换为显式可存档的确定性 PRNG。
- 豌豆攻击间隔为 136..150 个 10ms 更新，双发额外一发间隔 25 更新。50ms 对战步长须保留累计计数余量，不能每次向上舍入后累积漂移；原生/Wasm 与分段回放必须相同。

## 补充先行场景：原版速度与啃咬

- REA 确认普通啃咬每 4 个 10ms 更新扣 4HP，减速后每 8 更新扣 4HP；用每 500ms 一次 50HP 只能近似平均值，会提前杀死低血植物。验证接触首步和连续一秒的伤害，先失败再改为累计余量。
- REA 确认普通周期均速约 11..17px/s、足球和撑杆持杆约 31px/s、报纸狂暴约 42px/s；验证一秒净位移与确定性回放。此处恢复周期均速，原版 `_ground` 逐帧步态仍由研究报告列为未移植。
