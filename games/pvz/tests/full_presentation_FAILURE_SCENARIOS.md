# 客户端呈现失败场景（实现前）

- 浓雾投影推进会模拟未知碰撞，导致已公开僵尸、植物、弹丸或割草机提前受伤、删除或改变状态。
- 只补回存活对象 HP，无法恢复已预测删除的对象；地形、墓碑、拾取物和金币仍会提前结算。
- 投影自动产钱、收取资源、植物变身或世界计时改变权限，产生服务端尚未确认的行为。
- 整数 50 ms 逻辑帧直接绘制，即使 RAF 为 60 Hz，弹丸像素仍只每秒更新 20 次。
- 使用下一帧插值会提前展示命中、扣血、对象出生／消失；恢复或重复快照重置呈现相位造成停顿。
- 新操作排进已经显示过的历史 tick，快速连续点击覆盖短按；延迟 1 帧插值连本人种植一起延迟。
- 每个 RAF 克隆、导出完整存档和计算摘要；本地预测事件触发重复音效。
- 蹲压、吞咽等晚于出生的非循环阶段未记录起点，进入阶段即显示最后帧。
- 一次本地非法操作丢弃此前有效预测或隐藏具体失败原因；服务端拒绝其中一个序号时误删其他已发送操作。

先行测试：`python3 -B games/pvz/tests/full_presentation_browser.py`。脚本从当前源码构建真实 Go Wasm 和生产 `runtime.ts`，以可重复有效快照驱动浏览器原生点击及 60/144 Hz 时间采样；保留 `.local/pvz/full-presentation/{before,after}.json`、截图、源码／Wasm 摘要。该测试隔离呈现边界，不代替最终正式房间的网络与整局验收。

## 正式页面高密度验收（夹具实现前冻结）

- 简化 Canvas 或桥测试通过，正式 Board 的完整原图层、动画、音效、React HUD、网络和 Go 复制／校验仍超预算。
- 把 RAF 回调计数、原版约 12 fps 的精灵片段帧数当作实际运动更新次数；只统计已绘帧而漏掉长停顿。
- 大量敌军实际位于画布之外，或通过删除碰撞、降低素材精度、暂停规则／音效、固定 HP 伪造密集场景达标。
- 受控初始状态绕开地形、叠层、单位初始化或卡组合法性，生产 View／SyncSnapshot 无法读回。
- 普通与密集负载使用不同网络／渲染协议；将输入 ACK 当作原生事件到首次 Canvas 绘制反馈。
- 测量器每帧读取整幅像素／完整存档导致自身成为主要耗时；必须报告观测开销，按用途分组 Wasm 操作总耗时，不能冒充纯规则计算。
- 320 px 下存在布局溢出、按钮无法点、完整场景挤出视口或密集交互丢输入。

固定预算：每组正式页面采集至少 15 秒，原生事件至首次操作绘制 p95 ≤ 100 ms，可见绘制间隔 p95 ≤ 35 ms；同时报告真实运动更新次数／间隔、原生片段帧率、消息大小与主线程长任务。普通／密集分别覆盖 1440 px 和 320 px，使用独立端口与账户、现有 `web/dist`，不重建或修改生产规则。密集夹具只在 opt-in 测试 Module.Start 中构建约 43 株本体、45 个花盆、43 个南瓜以及 80 个包含僵王的合法屋顶夜间敌军，受控初始化不等于自然完整对局。完整逻辑、音效与真实生产时钟保持运行，记录采样期间实际人口范围。
