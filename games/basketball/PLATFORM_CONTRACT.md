# 平台接入边界

当前为开发中的游戏模块，不加入正式注册表，也不自动上架。最早的接入验收使用四席开发配置；当前平台入口为 1／2 席，支持单人、双人合作、双人对战，详见 [人数与分队](server/PLAYER_MODES.md)。其他场地和原内容仍按复刻计划恢复。

服务端持有唯一权威 `engine.RuntimeState`。客户端只提交逻辑按钮、比赛标识和本席递增序号，不能提交位置、比分、随机数、电脑身份或其他席位输入。相同比赛内允许不同席位并发操作，旧比赛操作拒绝；可靠批次中已确认的旧序号不重复执行，也不刷新输入期限。短按在两次服务端帧之间也须保留；失焦取消只清理本席输入。

输入变化使用有界、带服务器接收时间的队列，按视频 tick 消费。同一 100ms 系统帧内两次连发不能合并为一次；普通松键保留短按，明确取消则丢弃该席尚未消费的变化。

网络批次支持最多 64 个事件和 500ms 相对间隔，排程以服务端接收时间为基准。请求携带认证席位和最近收到的 `serverAt`，拒绝账号换席、未来时间和超过 1 秒的陈旧页面输入。取消可以先于旧请求到达；后续请求须携带尚未确认的取消事件。部分设备取消使用 `cancelMask`，保留其他输入源的按键、边沿和时间线。客户端最多并行发送一个普通请求及一个优先取消请求；服务端快照也可确认序号，不依赖单个 HTTP 响应及时返回。

Start 保留原驱动的控制器 0 归属，对应第一席；不能把其他席位的 Start 偷换为第一席按键。其余席位的输入仍进入各自原控制器槽位。

平台每约 100ms 调用一次系统帧，模块根据真实时间累计 60Hz 视频 tick，再由原驱动决定逻辑更新节奏。恢复／长时间停顿保留世界与规则时钟，限制一次追赶量，不在后台瞬间模拟整场。存档恢复不重置位置、分数、AI、随机状态或比赛标识。

`Context.Automated` 由宿主提供，游戏不能相信客户端声称的电脑身份。切换托管只改变对应席位的原人类／AI 输入选择，释放该席旧按钮与输入组合缓存，保留角色动作、AI 策略、物理、比分和其他席位。原 AI 在原世界输入阶段运行；`BotAction` 不另写一套策略或直接移动角色。无输入超时走平台统一托管，取消通过 `Reclaim` 清理本席输入。第一席处于电脑控制时，宿主可按原控制器 0 确认中场或解除暂停，避免其他真人没有 START 权限而卡住；这只是平台阶段确认，不替代原篮球决策。

声音保留 Go 产生的数字 ID 和递增事件序号。对局结果来自原 `Outcome`，确认后提交最后已生成的结果画面并停止单场推进。平台按人数与分队选项将原两队赢家映射到实际参与的席位；奖励／原菜单去向保留为元数据，不宣称完整战役已实现。

实现前验证失败场景：未上架仍可创建；非法人数／场地／注入选项；观众或其他席位操控角色；并发版本丢输入；短按丢失或取消补发；旧比赛／序号重放；网络丢失持续按住；托管无法运行原 AI或接管重置世界；超时连带改变别人期限；SQLite 恢复重新开局；大批量推进越过结果导致回滚。优先用真实身份、HTTP、系统时钟和 SQLite 验证，另用明确的规则边界验证时钟和单场结算，不冒充自然整场 HTTP 验收。
