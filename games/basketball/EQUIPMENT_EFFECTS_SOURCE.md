# 原版装备特殊效果来源目录

本目录将 **32 件装备的属性等级** 与 **等级之外的特殊效果** 分开记录。属性等级由独立的 Scene 2 `8CEE..8D26` 验证负责；等级表通过不代表特殊效果全部接通。本轮确认了 13 件装备的非等级分支，其余 19 件在本次检索范围内尚未确认额外效果，不能据此宣称它们「没有特殊效果」。

初轮只新增来源报告和本地原版 CPU 探针；后续按授权修复了鞋 23 的完整跳跃入口与鞋 27 的开局计分绑定，测试和来源见对应验证报告。对战模式保留原版 Mode 128 无装备规则；装备用于战役模式。原版悬停球的后续处理策略仍由独立调查负责。

## 身份、模式与证据边界

- ROM SHA-256：`0fa28f60abb8d2ccbbeee90e79e3fa160a5cf32feb90f47ebf1a89168cff569b`。
- 本文地址为 CPU 地址，`bank6` 表示第 6 个 16 KiB PRG bank 映射至 `8000..BFFF`；`fixed` 表示第 7 个 bank 映射至 `C000..FFFF`。
- 除下文 B 的得分分支外，固定函数 `EBFC..EC30` 为下列装备分支提供共同门槛：`Mode & 0x80 == 0`、当前角色所属队伍为 team 0。球对象 6 使用当前球主人的队伍和角色；玩家对象 0..3 使用自身。返回 `Y = 3 * character`，因此装备跟随角色，不跟随平台席位。其他对象返回 `FF`。
- 这些装备分支本身没有 Court ID 条件；投篮和落地触发仍受区域、位置、动作等条件限制。不能把「没有 Court ID 比较」扩大成每张场地、每种几何状态都已验收。
- 正常装备槽位固定为球衣 0..9、短裤 10..20、球鞋 21..31。`9F48` 的 32 字节表供多个函数复用，必须按真实读槽解释；将短裤或鞋的表项直接当成正常球衣投篮效果是错误的。
- 新探针是以保留 RAM 为基础、显式设定初始状态后执行未修改的原 ROM 指令。它验证函数及分支，未声称是自然手柄操作、完整飞行、得分链或完整比赛。

## 精确条件与来源

### S：必杀球型选择

来源：bank6 `9EFC..9F47`，表 `9F48..9F67`；既有 REA `ev_22e089841ea9f9c13f2d325c435946a52e8700cd2ee6a265d6caa7c02c223f6e`。完整出手门槛另见 `CAMPAIGN_SHOT_EQUIPMENT_VERIFICATION.md` 与 `engine/testdata/campaign-shot-*`。

该选择发生在首次释放，不在已进入的动画继续帧重复。地面动作 `1B` 的蓄力周期 3/4、空中动作 `1C` 的周期 2/3 到达必杀候选；缓存区域需 `0x10 <= zone < 0x60` 且低半字节小于 5。地面设置 `SpecialShot=128`，空中为 0。其他周期仍走原来的普通／高目标路径。

装备查询仅读取角色的**球衣槽**。item1/5/6 在 `SpecialShot != 0` 时分别保留映射 13/19/20；标志为 0 时恢复角色表。item7 调用一次 `F9C3`，`value = random & 0x16`；值达到 13 才使用它，因此随机替换集合为 16/18/20/22，其余结果回到角色表。item7 的随机分支不要求 `SpecialShot != 0`，所以空中同样可能改变。没有装备时 team0 四角色的原必杀为 23/21/17/16。

新 `shirt-selector` 探针覆盖 2,112 次合法球衣槽调用、四角色、Mode0/1/128、team0/1、两种标志和四个 RNG 初值。这里没有重复原有 item1 的完整玩家／世界出手验收；后者已有 3,184 次完整玩家调用及 96 次完整世界动作阶段。

### T：目标高度

来源：fixed `E078..E123`，高度表 `E124`，共用 `9F48`。只有表值等于装备 ID 的 2/4/11/15 命中固定高度分支。

`E090` 读取**当前球主人**的动作并去掉 entered 位。若为 `1B/1C`，从查询角色的球衣槽读取；否则改读短裤槽。在短裤路径中，当前对象 `SpecialShot` 为负会先走 `E119` 的 240 高度覆盖并清除标志，跳过装备固定高度。固定高度分别为 272、176、104、160，坐标单位为原版像素。函数选择高度后仍使用原来的弹道求解、碰撞和篮筐规则，不直接得分。

该函数不仅由普通球释放使用，还被原投掷／低跳轨迹共享。不能因为孤立测试将 ID2 放进短裤槽也得到响应，就将该非法组合写入产品规则。本轮 2,112 次 `target-height` 调用使用合法槽位，包括两种球主动作、特殊标志、四角色及模式／队伍反例。现有 `launched-player`、`low-jump-shot` 部分旧夹具含人为装备域，不能自动当作合法库存到完整动作的验收。

### L：短裤 11/15 的落地触发

来源：bank6 `8BBD..8BED`；fixed `EE52..EEF3`。共同落地处理的入口别名为 `06/16/26/36/46`，只有持有 B（`04E0,X & 0x40`）才调用 `EE52`。

`EE52` 要求当前对象为真人控制（`0539,X` 非负）、当前球主人为自身，并排除「同队另一角色的附件值最高位为 1，且去掉最高位后等于当前对象编号」的骑乘情况。随后调用 `EE8B`。此处不是任意有球的电脑动作。

`EE8B` 命中合法短裤11/15时，要求 `cachedZone & 0xF0` 分别为 `0x40/0x50`，且原整数 depth 在 **25..57，含端点**。成功后按 character0..3 选择 `5A/5C/5A/5C`。区域不符时回到普通位置条件；区域符合但 depth 不符直接返回，不再走普通条件。探针选择普通条件无法命中的 X=0，分别验证 24/25/57/58 边界，避免把普通路径误当装备效果。

### A：短裤 14 的攻击配置

来源：bank6 `9FA7..A021`；REA `ev_535248b0e94c2c008702b2638bdcd014b1a5ccfad5b795c1c1af22262b189e6e`。

在共同模式／team0 门槛内，短裤为 14 且动作低半字节为 0 或 4 时：动作 `60` 使用 team0 character1 的攻击配置（variant3、handler5）；动作 `64` 使用 team0 character0 配置（variant4、handler5）。这不是对所有攻击动作施加统一速度倍率，也不修改命中后的得分。角色0..3都可以触发，但原本已使用同一配置的角色不一定显示变化。既有 `attack_player.go` 包含该选择；本轮没有新增完整攻击／碰撞验收。

### G：球鞋 23 的重力

来源：fixed `EC31..EC49`；REA `ev_5a1c9be9254ac3f70100366b4ab6ca44609822276d14a086d39b1f6b244618df`。共同模式／队伍门槛内，鞋槽 ID23 将当前对象重力写成 `0x0080`（半像素／逻辑步平方），并没有直接改写跳跃初速度。

原 bank6 有五个调用点：`8993`（handler8938，动作04/05及0D别名）、`89F0`（handler89A1，34/35）、`8A5B`（handler89FE，44/45）、`8AE6`（handler8A71，14/15）、`8B41`（handler8B12，24/25）。调用时机还服从各动作原来的首次初始化／动画阶段条件。不能将一次 helper 返回当作所有入口已接通。

新 1,152 次 `jump-gravity` 调用覆盖鞋21..31、空槽、四角色、四对象编号、Mode0/1/128和队伍反例。初轮检索仅确认 `auxiliary_player.go` 的24/25接通。后续新增 `world_jump.go`，并以 4,464 次原版完整调用／连续链验证全部11个动作别名；详见 `SHOES23_JUMP_VERIFICATION.md`。旧独立组件 API 的上下文边界仍明确保留。

### J：球鞋 26 的空中再跳

来源：bank6 `82BA..8301`，更外层 A+B 输入／空中判断在 `81E0`；REA `ev_77f361411f66bf6eb0ac2be4ddae512d29e12f12ec526174d0f488f9c65e4301`。

这是**真人输入**的空中后续跳跃许可分支。输入需先满足原 A+B 合键延迟处理，且通过原空中／附着状态门槛。一般 `JumpPhase >= 0` 已允许；只有负值的拒绝路径才查鞋26。该装备例外还要求垂直速度高字节非负、位置高度高字节为0、整数高度小于208。下降时、整数高度208及以上不允许。动作3D..3F对 JumpPhase 的后续写入另有原例外，不应概括成固定次数的通用双跳计数器。

新 1,152 次 `air-follow` 调用验证内层分支及边界，不声称重演了外层完整按键流程。现有 `world_human_input.go` 包含此门槛。

### D：球鞋 30 的随机低跳

来源：fixed `EE70..EE8A`。它与 L 共享 `8BBD` 的落地、按住B、真人、持球、无同队骑乘门槛。先执行 `EE8B` 的短裤／普通选择，再查鞋30。命中后调用一次 `F9C3`，用 `random & 3` 索引 `EEF4 = [5A,5C,5A,5C]` 写入动作，因此最终可覆盖前一步选择。这个鞋分支没有自己的区域／depth 门槛，字符编号也不参与随机动作选择。

新 `landing-selection` 3,072 次调用覆盖短裤11/15、鞋30、空槽、角色、区域、depth边界、模式、电脑与同队骑乘反例；实际检查 RNG 调用次数，避免 seed0 状态不变导致漏计。现有生产层未检索到 `EE52/EE8B` 装备选择的对应接线；已有落地清标志夹具把 held buttons 设为0，不能覆盖这些分支。

### B：球鞋 27 的进球加分（后续补充发现）

来源：bank4 `91BD..91E1`，指针表 `94D8 = [06E4,06E7,06EA,06ED]`。基础进球分值写入 `1B` 后，检查原 `LastShooter`（`06D1`）小于2，再按此对象的角色编号选装备指针，以槽位2读取鞋 ID；等于27时将基础分值加2，随后执行原计分累加。这里使用**对象编号0/1**，没有调用共同 `EBFC`，也没有独立 Mode 或 team 判定。正常对战的空装备仍不产生加分；不能将这个消费者错误改成「任意team0对象均可加分」。

原指令及指针字节保存在 `.local/equipment-effects-catalog/shoes27-source.json`。这是独立静态来源补充，不计入上述9,600次 helper调用。初轮发现 `rim.go` 已有 `ScoringBonus`，但缺少生产初始化。后续已修复 `opening_world.go` 与恢复校验，并通过 6,912 次原版完整篮筐调用、合法密码恢复27→装备→实际开局→JSON恢复；详见 `SHOES27_SCORE_VERIFICATION.md`。此前直接地址检索没有发现本项，正是其不覆盖间接读取的实际例子。

## 本轮产物与复现

工作树内执行：

```sh
PYTHONDONTWRITEBYTECODE=1 .local/board-art-env/bin/python .local/equipment-effects-catalog/probe.py
```

脚本不写入生产代码或 `engine/testdata`。先列出的失败场景位于 `.local/equipment-effects-catalog/FAILURE_SCENARIOS.md`。结果：

- `calls.json.gz`：9,600 次调用，保存每条完整初始 RAM、RAM 差分、入口／出口、执行 PC 路径、RNG 次数和关键输出。
- 夹具 SHA-256：`0bb830546caee07a754907acb2dc1331a399b5e9122955ab130e8f589668522a`。
- `instructions.txt`：原 ROM 指令窗口；SHA-256 `93f34a7329127b0e9cd8e4e84da680992d39f0955e01788b56cf41cde8caf824`。
- `result.json`：ROM、RAM 基础、数量、校验和和 PRG 直接地址检索候选。

PRG 扫描仅查 `LDA/STA absolute/absolute-X/absolute-Y` 对 `06E4..06EF` 的直接引用候选，并结合 `EBFC`、`EC31`、`EE52` 调用点。它不排除间接指针、别名、其他地址形式或非普通库存状态。fixed `E058` 还以 `06E9 + selectedHoop` 读取弧线标志；普通篮筐索引落在篮筐状态区，其他对象索引可能落入装备 RAM 别名。此类索引可达性必须按对象／调用链调查，不能给某件装备凭空增加一个普遍弧线效果。

尚需完成的特殊效果验收：合法库存到各效果的完整动作链；鞋23自然手柄装备跳跃录像；短裤11/15及鞋30的真人落地按键链；每种必杀的飞行／接触／篮筐结果；普通奖励表之外的21/24获取方式；其余19件是否存在本轮边界之外的额外消费。本文不将这些缺口计入已完成。
