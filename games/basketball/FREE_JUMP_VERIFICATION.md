# 普通人物快速起跳与下落验收

实现前失败场景：

- `$0576` 为负时仍播放蹲下，或首次起跳先移动一次；同一世界步骤的第二次人物调用被遗漏。
- 快速起跳在第二次调用重复发射；运行跳跃错误覆盖已有平面速度；普通跳跃未按输入方向赋初速度。
- 特殊跳跃阶段 `0xE0` 应使用 3 像素初速度，却使用人物跳跃等级。
- 普通非快速跳跃时序被修改，既有 633 个原世界步骤不再匹配。
- Falling `0x0F` 进入时遗漏高度速度增加 3.75 像素、重力设 1、固定空中姿态；后续帧重复增加速度或运行普通动画。
- 行走／站立／跑步离开平台后未切 Falling，落地后仍保持下落动作。
- 附着、持球、持物状态被当作普通人物处理，跳过其原独立落地动作；未知上下文必须明确保留限制。

原始证据：bank 6 `$8938` 为普通跳跃，`$9749` 为 Falling。独立 REA 批处理在 `.local/basketball/rea/free-jump/`。自然采样仅选择世界步骤前没有附着、没有球或物体的普通跳跃／下落人物，不写入 RAM；所有入选样本都参与比较。

## 单次动作接口拆分前的失败场景

- 调度器与人物函数都处理重访，导致同一原动作阶段执行两次或四次。
- 单次 API 把两次原 `$E165/$E168` 调用合并，不能保留首次蹲下、快速起跳原姿态或首次无位移的状态。
- 起跳首次清除 processed 标记后没有输出 Revisit；普通后续调用或 Falling 错误要求重访。
- 旧世界阶段包装函数的 633／377 个原样本在接口拆分后发生变化。
- 单次动作失败时返回部分修改，破坏调用方的事务边界。

新增 `capture_free_action.py` 仍使用同一 6000 帧自然输入，记录每次单独的人物调用，并独立保存同一演员同一帧内的重访。先编写单次测试并验证缺少 API 的失败，再拆分实现。
