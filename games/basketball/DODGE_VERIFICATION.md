# 原版闪避动作验证

实现前失败场景：

- 模式 26 已请求动作 `$2E`，人物执行入口仍报不支持，或擅自改回普通跑动。
- 进入动作时遗漏原纵深速度和动画初始化；每帧重复清零横向速度。
- 横向加速丢失进入动作时的 X 速度符号，误用后来的面对方向；半像素累积、最后一帧位移或动画切换丢失。
- 动画结束没有切回原后继动作；人物阶段误写篮球动作或所有权。
- 将原记录中的每帧位置回填给 Go，掩盖连续运动偏差。
- 未支持的承托或特殊地形误套普通地面动作；未知请求不按原合法性处理。

原基准为`capture_dodge.py` 对现有两个场景重采样的全部动作 `$2E` 调用，保存为 `dodge.json`，额外记录原 `$0548` 的速度高字节与 `$0565` 的动作步数，包含长场景及真人传球场景中的两段连续闪避。只初始化每段首条人物状态；其后由 Go 连续推演。静态恢复优先使用 REA，保留查询失败和原指令核对结果。


## 本次结果

两段自然场景共 8 次动作更新全部通过连续对照，完整参考 RAM 不变。固定边界另验证初始速度与面对方向相反时仍保留原速度符号、纵深小数及第二帧相对镜像；电脑模式 26 到实际闪避动作的入口已接通。

REA 最初对宽范围分派的批量请求超时，记录在 `.local/basketball/rea/dodge/run.log`。缩小目标到 `$949F` 与 `$86CF/$8726/$EBE9` 后成功，分别保留在 `action/` 与 `helpers/`。原转换表会拒绝闪避中的旧待机请求，并保持请求待处理；本组件保留该行为，其余中断请求尚未恢复。

先失败与通过记录为 `test-before.log`、`test-after.log`；后续完整篮球包的竞态和 Wasm 验证也通过，见 `world-preparation-summary.json`。尚未据此宣称攻击中断、全部地形或完整对局完成。
