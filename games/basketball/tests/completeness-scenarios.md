# 规则完整性与停滞审查

本轮从线上只读保存的房间状态开始，原始房间快照和服务日志仅保留在 `.local/basketball/live-stall/`；入库夹具只包含不带账号、房间、席位和会话信息的规则状态。

实现前冻结的失败场景：

- 梯子或其他支撑物上的球员进入 0x60～0x68 攻击动作，被世界分发或攻击处理器拒绝，服务器反复重试同一帧。
- 只移除报错而未绑定原版附着运动，导致人物从支撑物掉落、坐标跳变、速度重复积分或支撑物状态丢失。
- 只修复 0x64，遗漏同一分发族的其他动作、进入／继续阶段、真人／电脑、不同角色和支撑物。
- 快照恢复、连续输入、动作结束或后续阶段再次进入未实现路径。
- 既有全部测试通过，但没有覆盖线上实际到达的动作组合。
- 将非法状态保护与合法玩法缺口混为一谈；使用忽略错误、重置人物或跳过规则帧掩盖缺失实现。

审查范围包括 `games/basketball/` 下的规则、服务端、同步协议、Wasm 桥接、前端、资源交付和测试入口；对未恢复路径逐项记录调用条件与现有验证，而不是凭报错字符串数量判断可玩性。

线上事件重放：`go test -count=1 -run TestAttachedAttackIncidentContinues ./games/basketball/engine`。全量回归：`go test -count=1 ./games/basketball/...`。结果保留在 `.local/basketball/audit/`。
