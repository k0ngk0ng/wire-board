# 持球普通待机验证

实现前核验以下失败场景：保留的待机请求被错误丢弃；为绕过动作限制清除球权；所有持球动作都误转运球待机；普通待机持球时丢失纽约通道的持球分支；球跟随错误拒绝原动作 0 的偏移；将平台 HTTP 存档当作原版自然对局证据。

固定前态来自真实 HTTP 房间的故障归档，保留原种子和时钟。原动作语义另用 REA 分析 `$E18B`、`$87AD` 和 `$EC7B`，不能由平台重放成功反推与原版一致。

## 原行为及恢复范围

该 HTTP 前态的 actor 1 仍持球，动作 `$10` 尚未进入，待处理请求为普通待机 `$00`。原 `$E18B` 接受请求后进入 `$87AD`；原处理器不按球权拒绝待机，也不清除持球人。Go 的额外拒绝条件已移除，普通动作保留原动作编号。

范围继续核验到普通动作 `$00..$06`：待机、行走、跑动、急停、跳跃、跑跳、落地。以保留的 RAM 为基底，在原指令执行中明确设置控制器、动作、持球人和动画状态，共 116 次隔离调用。矩阵覆盖真人／电脑、初入／连续更新、快速起跳和跑动尾帧；这属于受控指令测试，不是原版自然对局采样。持球真人跑动按 `$8891..$88D0` 递减原投篮计数，计数归零时转动画游标 3；普通跑动实际读取 `$AB67` 后的相邻字节序列，不能套用持球跑动 `$12` 的动画。

球的跟随偏移完整恢复固定页 `$ECF5` 的 106 个动作选择项、`$ED65` 指针与偏移数据；212 个动作／朝向组合对照原表通过。整数纵深保留原字节回绕，小数继续取球自身坐标。完整偏移表只用于球的位置跟随，不代表尚未恢复的人物动作已经开放。

REA 证据：`ev_faeeb9b491f0f58dc9027340ac979a2b3b5c8f96f497c2b75ee8292e54971cc4`（请求、待机、偏移），`ev_0be536c2b08edf3fa9ac78aa4cae0898009c0678c8c350787809ed8ac4ab0931`（共享跑动、动画、行走、急停、跳跃）。完整输出位于 `.local/basketball/rea/possessed-idle/`。
