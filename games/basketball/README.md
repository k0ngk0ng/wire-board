# 热血篮球重写

状态：已接入游戏平台。实时架构与验证范围见 [main 接入记录](REALTIME_MAIN_INTEGRATION.md)。

目标是以用户提供的 FC《热血篮球》为行为与画面参照，重写为浏览器游戏。Go 内核拥有角色、球、场地、动作、碰撞、得分和电脑策略；同一内核用于原生服务端与浏览器 Wasm。Canvas 只负责呈现。最终运行不依赖 NES CPU／PPU 模拟器，也不逐条解释 ROM 指令。

代码使用有业务含义的类型和可调整参数。原版地址、逆向注释和采样工具留在研究／验收目录，不作为正式规则的公共接口。

## 完成要求

- 原版场地、角色外形、动作帧、球、篮筐及必要音效；逐项核对配色、朝向、遮挡、滚屏、动画时序。占位形状不能作为完成验收画面。
- 行走、跑动、起跳、持球、传球、投篮、扣篮、争抢、攻击／受击等原版可用动作及其衔接；具体条件和数值以原版采样为依据。
- 两人一队的篮球比赛、原版篮筐和得分方式、队伍／人物差异及场地差异。需要建立原版内容清单并逐项验收，不能用第一张场地替代全部内容。
- 可直接修改的 Go 状态机、物理、规则和参数；同输入的原生 Go／Wasm 结果一致。
- 沿用平台创建／等待房间、玩家栏、结算、统一音效，支持 PC 和触屏、电脑和托管、重连／恢复、观战和联机校正。新增游戏默认上架，保留管理员已有的上下架设置。
- 游戏分类为「体育」，产品界面称为游戏和控制器，不出现模拟器入口。平台提供按用户独立保存、按控制器类型区分的可修改输入配置，并为实体手柄预留映射。
- 默认双键控制器：WASD 为上下左右，F 为 Select，空格为 Start，J 为 B、K 为 A，U 为连发 B、I 为连发 A。连发的节奏、松手清理和与普通按键同时使用须单独验收。
- 电脑策略必须从原游戏的决策和执行行为恢复；不自行设计额外策略，也不以简单追球／自动投篮的占位 AI 代替原版。
- 独立游戏验收覆盖实际玩法、完整比赛、画面、操作及平台契约，保留可重复执行的结果。通过某段算术或某张图的检查，不代表完整复刻通过。

## 当前工作顺序

1. 恢复原版场地、角色和动作图集，建立像素与逐帧行为对照。
2. 实现带原版画面和操作的场上动作，同时逐步恢复球、篮筐及碰撞。
3. 完成比赛、电脑、队伍及场地内容，再接入平台和联机。
4. 完成全范围验收，复核素材来源与发布条件。

顺序仅用于组织开发，不缩小最终范围。未完成项目持续记录，不将研究预览当作游戏交付。

原 ROM、存档和原始追踪保存在工作区忽略目录。发布只包含经过校验的公开图片、声音和 Go/Wasm 程序，不包含 ROM、原始内存或调试文件；图片和声音已按不可变内容地址发布到 OSS。现有研究及已验证的横坐标算术见 [研究记录](../../docs/research/nes-basketball.md)。
