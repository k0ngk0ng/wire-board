# 准备阶段的场地与球员选择

选择面板由 `GameModule.Preparation` 接入等待房间；创建弹窗仍只处理人数和合作／对战模式。面板不提供另一套准备或开始按钮。比赛启动使用服务端确认的准备配置，前端不经过原版人数菜单。

图片取自 `games/basketball/selection/catalog.json` 对应的原版像素素材。当前面板仅开放已恢复的球场 0、1、2、3，以及球队 0、1 各自的球员 0、1。纽约以外的场地和球员尚无核验名称，使用数字标识。素材数量不等于玩法可选范围。

服务端仍是权限和交换规则的最终判断者：

- 房主选择场地，并可调整两队阵容。
- 其他玩家只能选择本人角色；占用电脑队友角色时，由服务端交换同队角色。
- 真人队友已经选择的角色不可被另一位非房主玩家占用。
- 观战、请求进行中不可提交更改。图片在只读状态下仍清晰显示。

`prepare` 只发送 `{type:"court",court}` 或 `{type:"character",actor,character}`，不提交其他玩家的数组。角色编号映射为：单人 0，合作 0／1，对战 0／2。输入鉴权仍使用平台席位。

运行组件浏览器验收：

```sh
source scripts/env.sh
python3 scripts/basketball/accept_preparation.py
```

验收使用真实 React 组件、原版 PNG 和原生鼠标／触摸，记录各模式归属、选择命令、只读权限、图片回退、最终计算色对比、320px 实际宽度及点击目标尺寸。产物位于 `.local/basketball/preparation-ui/`：`result.json`、`contrast.json`、PC／手机／观战截图。

这是组件级浏览器验收，不能代替真实房间鉴权、服务端保存／恢复、准备状态失效或比赛启动配置的集成验收。素材仍未获发布验收，未上传 OSS。


实际平台页面另覆盖了图片卡受公共按钮样式影响时的布局：场地图片独立成行，名称和「已选」在图片下方，不能被挤到图片旁边。双人房间未入座的人类角色显示「等待玩家」，不误标为电脑。完整平台证据位于 `.local/basketball/platform-rooms/`；配置开始与图片呈现通过，所有新阵容的完整比赛仍以服务端门禁报告为准。
