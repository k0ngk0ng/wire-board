## 如何理解覆盖状态

| 层级 | 可以证明 | 不能据此证明 |
| --- | --- | --- |
| 原数据／静态分析 | 某原表、分派入口、参数或条件已定位 | 原版自然执行到该分支、完整玩法可运行 |
| 隔离原函数对照 | 所列输入下，Go 与未修改原指令的输出一致 | 菜单可以合法选择该配置、自然整场能触发、完整世界衔接正确 |
| 原自然运行对照 | 指定原输入轨迹的调用或连续阶段一致 | 未出现的队伍、装备、人物、场地和动作已经覆盖 |
| Runtime 接线 | 冷配置和真实世界流水线可以使用该能力 | 所有可达分支无缺口、完整比赛必然结束 |
| 完整比赛门禁 | 指定配置从开局到结果，重复和恢复一致 | 所有内容、原版逐周期完整对局、真人联机整场或画面全部一致 |
| 平台／发布验收 | 实际产品入口、权限、操作、音效、素材和联机经过验收 | 引擎的局部测试可以替代此层 |

所有原来源绑定用户提供的 ROM，SHA-256 为 `0fa28f60abb8d2ccbbeee90e79e3fa160a5cf32feb90f47ebf1a89168cff569b`。本文数字 ID 指原程序的队伍、人物槽或场地编号，不是已核实的中文显示名称。当前仅纽约场地及默认国夫队／纽约队身份有现成记录；其余名称需从原菜单文字与选择记录核定，不能从建筑外观或球队编号猜出城市，也不能假定队伍 ID 与球场 ID 必然对应。

[原全队策略](../../docs/research/nes-basketball-world-schedule.md) 与个人模式是两层。全队先按球权、真人控制标志、比分档和球队表分配模式，然后个人决策提出合法动作；AI 不直接写入命中、比分或胜负。
