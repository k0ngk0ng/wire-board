# 热血篮球代码审查

本轮审查以线上停帧现场为起点，覆盖 `games/basketball/` 的 530 个 Go、TypeScript、JavaScript 和 CSS 代码文件。原始房间快照保存在本地，入库回放夹具仅包含规则状态，不含账号、房间或会话信息。

## 已修复的停帧原因

| 问题 | 触发条件 | 修复 |
| --- | --- | --- |
| 附着攻击被拒绝 | 球员站在梯子等支撑物上，进入 `0x60`～`0x68` 攻击动作 | 世界分发接入已恢复的支撑物运动；攻击结束后的站立、行走、跑动、刹停、落地和下落沿用同一运动绑定 |
| 拒绝过的动作请求再次处理 | 原版动作表保留一个未获准的请求，普通动作处理器随后再次解释请求 | 世界分发标记请求已经由原版表处理；当前动作正常推进，未获准请求继续保留 |

修复保留未知动作、缺失运动上下文和非法请求的校验。规则帧、人物位置、得分及随机数继续由原有规则推进。

## 验证范围

- 全目录 Go 语法扫描通过；`go vet ./games/basketball/...` 通过。
- `go test -count=1 ./games/basketball/...` 全量通过，包含既有完整比赛、平台 HTTP／WebSocket、输入、恢复和原版轨迹检查。
- 前端 53 项测试通过。
- 线上现场从第 2355 视频帧继续推进 600 帧，期间反复序列化和恢复状态。
- 新发布的浏览器 Wasm 与原生规则通过 50 个协议请求对照；现场快照在松键、原始输入、A、B 和 A+B 五种输入下，均推进到第 2955 帧且状态一致。
- 新增 576 种攻击动作、队伍、角色和真人／电脑分发组合检查，以及普通附着动作和已拒绝请求的回归检查。这组检查验证支持范围和持续推进，不单独证明所有组合与原版逐帧一致。
- 覆盖率：整体语句 88.5%，规则内核 90.1%，服务端 84.3%，同步协议 94.9%。开发命令入口未由这轮测试执行。
- 新 Wasm 已构建并按内容地址发布，原对象保留；源码绑定、字节数、摘要、MIME 和 CDN 回读通过。此操作没有部署或重启线上应用。

## 覆盖边界

静态扫描登记了生产代码中 101 处带有未恢复提示的异常分支，其中包含合法性保护和缺失上下文保护。异常文案数量不等于实际缺陷数量。仍需重点扩充的证据包括附着持球瞄准、携带道具的队伍策略、辅助物体的携带／投掷组合，以及不同场地上的交叉动作衔接。

全量测试通过和当前覆盖率不能证明所有合法玩法组合均已覆盖。后续新增正常对局能到达的分支时，应先保留可复现状态或原版轨迹，再实现和验收。

本地结果位于 `.local/basketball/audit/`：`source-inventory.json` 记录文件摘要和异常分支，`guard-inventory.md` 提供逐项索引，`coverage-functions.txt` 记录函数覆盖率，`go-final.txt`、`frontend.txt`、`vet.txt` 和 `lint.json` 保存检查结果。运行命令前按项目约定创建工作区内的缓存和临时目录。
