# 原比赛时钟／暂停／结束验证

实现前失败场景：

- 把一个逻辑更新当作一个视频帧；暂停仍累计时间；把 C5 的 8 位减 60 环绕改成常见正向累加器。
- AFF3 偶数帧轮转显示时漏掉真正的时钟递减；因为当成纯显示而跳过比分十进制缓存更新。
- 0:00 已到但自由球还在空中时提前结束；持球状态错误等待球落地。
- 第一节平分错误进入延长；第二节平分没有延长，或错误重置一个自定义延长倒计时。
- 已进入延长后反复播放哨声；实时得分更新而原显示比分尚未更新时提前判结束。
- 暂停进入必须 Start 恰好独占，恢复只要求 Start 位存在；错把两者条件统一。
- 个别 HUD 或时钟调用内部碰巧发生视频中断时，误把该中断贡献当成本函数行为。
- 原有模式／阶段之外的结束展示未恢复时，不得把 phase 5 标为最终比赛已经完整结束。

静态入口：固定 D35A/D36C/D3EB、显示中断 F25C/F266、页 4 AFF3/B17E/B1CA/B074。自然输入参考先无 hook 运行，再同一输入采样并逐帧 RAM／截图比较。测试保留视频中断在时钟调用前后的实际次数，不能让其变成规则补丁。

## 实现与证据

REA 新批量证据为 `ev_e512234c54456fd3a167b904732643cc324552d487272a08277c6aa6c25f14b0`，完整结果、快照与可重跑 spec 位于 `.local/basketball/rea/match-clock/`。旧 clock-exact 的 `ev_9a4618c74e7d4ebb6b0eb07d0a79bd5c360b490c75a5ad0793c89163d132055b` 与 bank6 的 D36C 结果共同交叉核对。

`MatchState` 明确保留比赛阶段和进入标志、节数、延长标志、十进制时钟及比分缓存。接口按实际调用拆分：

- `AdvanceMatchVideoTick` 对应实际进入 F25C 的视频中断，暂停不增。部分菜单路径根本不经过 F25C，外层视频驱动必须按原入口调用，不能给所有菜单无条件加计数。
- `StepMatchHUD` 对应 AFF3：奇数帧返回；偶数帧在 4 个显示槽轮转，选择时钟或队伍比分。时钟槽实际调用 `StepMatchClock`，比分槽刷新规则读取的十进制得分缓存。不是每次逻辑更新都减时间。
- `StepMatchClock` 按 B1CA：仅非零时钟且累加器小于 60 时环绕减 60，并减一秒。最后 3→2、2→1 秒发声音 17；1→0 不发该声音。原开节先设 3:01，第一次递减到 3:00。
- `CheckMatchPause` 接受按钮边沿恰好 0x10；`CheckMatchResume` 只检查 0x10 位。进入暂停的那次原逻辑仍继续经过结束检查和世界动作。
- `CheckMatchPeriodEnd` 在 0:00 检查节数与**显示比分缓存**。第一节不因平分延长。第二节平分第一次置延长标志并发声音 55，此后保持 0:00 继续；不重设倒计时。满足结束比分条件后，如果球自由且腾空则等球，其他情况请求阶段 5 并发声音 55。当次世界动作仍继续执行。

原期间结束动画、下一节菜单／人物重置、最终结算展示位于阶段 5 及后续场景，当前组件不声称完成那些流程，也不直接生成最终赢家。

## 自然对照结果

两节正常比赛参考为 24,000 视频帧，使用原第 5 槽开始，间歇仅使用 Start 和 A 确认原菜单／战术。第一节在输入帧 10,817 请求阶段 5；第二节在 11,238 开始、22,048 请求阶段 5。之后原版进入最终阶段 6。独立 300 帧暂停参考在帧 62 暂停、92 恢复，30 个视频中断均未增加计时累加器。输入按住 7 帧，避免刚好落入原输入采样间隔的两帧短按。

所有参考先无探针运行，再以相同输入观测；逐帧 RAM 和截图逐字节一致。夹具含 **46,547 个事件**：22,834 次视频计数、1,824 次时钟入口、7,293 次 HUD、7,293 次暂停检查、7,293 次结束检查、10 次暂停恢复入口。367 次秒数递减包含每节初始 3:01→3:00；有两个自然节结束转换和一次暂停／恢复。全部状态与声音编号对照通过。

119 次函数调用中间经过了视频中断。夹具单独记录时钟之前／之后的真实中断增量，并由测试明确组合；这些数值来自探针，不在实现内作为修正数据。自由腾空球延迟结束与平分延长未在这两条自然输入中触发，依据原分支及针对性边界测试验证，不列为自然完整局覆盖。
