# 圣姑家、灵山与树洞奖励验收

本批按[灵山寻药文字攻略](https://gamegene.cn/wiki/364)与当前 Windows 简体原始数据核对。文字缓存为 `sacred-tree-text-guide.md`，不观看视频。

## 实现前失败场景

1. 圣姑家相邻金蚕王共用脚本，被合并成同一领取状态；同点多件药草、蛊或金钱按数量增加点数。按事件分别验证真实库存和各自原生续行。
2. 将原版可无限采摘的鼠儿果事件 2922 改成一次性，或将续档自动重发与玩家新搜索混同。首次及 3 次新搜索逐次核对增加 1，保存恢复本身保持数量；同一事件只计一次。
3. 香蕉树被错误删除，未保留摘取后帧 1，或把已摘过香蕉的后期根档当成未采。使用首次圣姑家外的真实存档，核对两根香蕉、原树帧及重复搜索不再发放。
4. 灵山仙芝与鬼枯藤使用精灵 70，被漏掉或套用不消失的规则。核对当前事件脚本的自身关闭指令，再验证采后、恢复后及重复搜索后不出现。
5. 一人逍遥和阿奴／逍遥的不同剧情队伍被固定为月如队伍；原控制顺序、战斗后的正常伤害和成长丢失。每个案例保留对应真实父档和原角色顺序。
6. 树洞宝库尚未完成原空箱剧情便直接进入，或覆盖主线的空箱／水灵珠对白证据。选择已经完整完成该剧情的真实稳定存档，普通奖励另用独立前缀验证。
7. 相邻宝箱、金钱箱或同箱多物的提示、开启帧和库存不符；战利金混入隐藏金钱。逐点保存钱包，单独记录途中普通战斗奖励，再核对整段账目。
8. 地图出口、山道或原版接触敌人被当作可绕过的碰撞，移动物品或改场景使测试通过。测试仅发送普通行走、搜索、菜单与战斗输入，必要入口走原门口。
9. 新版本汇总覆盖旧 v11、条件奖励清单或冻结归档，或将复验增加计数。先冻结旧进度与证据摘要，新增 v12 前缀只登记本批实际通过事件。
10. 碧血蚕点 2886 的原入口在首轮后续行到炼蛊皿，测试误把第二轮奖励当成重复发放。须继续取炼蛊皿，再实际搜索 3 次不再发放；另一处独立炼蛊皿事件 2887 分开计数与保存。
11. 香蕉原提示中的引号属于原版字体颜色控制，匹配原始控制串而漏掉已显示的奖励，随后重复搜索。匹配实际绘制文字，另以原始指令、库存和树帧交叉验证。
12. 灵山山顶台阶具有原版同场景移动脚本，测试只按静态碰撞寻路而误判药草不可达。以原始四处台阶的触发范围和实际落点规划普通行走，原运行器执行移动，保留台阶演出中的保存恢复。
13. 圣姑家外紫罂粟、醍醐香、鬼枯藤使用原版普通对白提示，测试仅匹配定时黑字导致漏判已取得。须同时读取实际对白，保持原提示类型和消费时序。

## 当前范围

计划核对第 175 场景 8 点、第 177 场景 14 点、第 180 场景 2 点、第 185 场景 16 点、第 189 场景 3 点，共 43 个候选。神木林攀爬区、桃源支线和早期未通过点继续单独处理，不由本批推断完成。

## 已通过范围

43 个不同事件均通过实际搜索、原提示、数量及存档验证，累计已处理 381/734，分母保持。189 次全新运行器保存恢复通过；其中圣姑家 34 次、屋外 59 次、山顶 9 次、树洞 75 次、灵山西侧 12 次。原先 18 条不可正常领取记录保持，本批未新增该分类。

圣姑家两个相邻金蚕王分别保存领取状态。事件 2886 首轮得到碧血蚕 ×7 后，原入口续行到 `28166`，再次搜索取得炼蛊皿 ×1，随后 3 次搜索不再发放；事件 2887 仍独立取得另一只炼蛊皿。同点后续物品不增加事件数。

屋外鼠儿果事件 2922 原入口为 `28191`，发放 1 个后以 `0x0000` 返回，保持可再次采摘。首次及 3 次新搜索共增加 4，逐次核对库存；每次恢复本身不额外发放。同一资源点计 1 点，不改为一次性。香蕉一次取得 2 根，树保留原状态 2，帧由 0 改为 1，入口续行到 `25986`，重复搜索不再发放。

精灵 70 的灵山仙芝和鬼枯藤与精灵 68／69 的药草均按原自身关闭指令消失；屋外 3 处药草的原版普通对白提示保留。原台阶 2950～2953 的触发范围与最后移动指令用于测试寻路，实际仍由正常走路触发；第 2953 处相机移动中的 `PC25950` 通过全新运行器恢复，之后正常到达山顶两株药草。

树洞宝库的 16 个事件在原空箱剧情完成后的真实存档继续，各自开启帧、提示和状态独立保存。两箱各 10000 文分别取得且不重复，共 20000 文；途中 11 场普通物理菜单胜利另得 2416 文，钱包从 55347 文变为 77763 文。其他 4 个分支没有战斗或金钱变化；圣姑家及屋外保留独自逍遥，树洞保留逍遥／阿奴，灵山西侧保留阿奴／逍遥及本人控制。

本批修改仅涉及验收与测试路线，不改原核心、脚本、位置、碰撞、数值或已发布资源，没有上传资源。上批 1072 个不可变产物／主线报告及京城完整支线冻结归档按摘要复核保持。第 185／189 场景绑定补齐炼蛊皿前的实际测试源码，第 175／180 场景绑定补齐普通对白前的源码，第 177 场景绑定最终源码；每版独立冻结，不用最终源码冒充全部执行来源。

## 复现与产物

已准备原资源、规则包及根档后，在仓库根目录执行。区域号分别为 `175`、`177`、`180`、`185`、`189`：

```sh
. scripts/env.sh
PAL_CAMPAIGN_VARIANT=audio PAL_DEVELOPMENT_HEALTH=9999 PAL_TEST_AUTHORITY=1 PAL_HIDDEN_REGION=175 go test -v ./games/pal/tests -run '^TestOriginalRegionalHiddenRewardsAndSavedNoDuplication$' -count=1 -timeout=22m
python3 -B games/pal/tests/sacred-rewards-original-review.py
python3 -B games/pal/tests/hidden-progress.py
npm --prefix web run lint:pal
node games/pal/tests/lint-e2e.mjs
go test -v ./games/pal/tests -run '^TestCandidateCampaignRootRequiresItsOwnCoreCheckpointAndFullReport$' -count=1
python3 -B games/pal/tests/sacred-rewards-evidence-e2e.py
```

区域报告为当前 `audio/development-health/hp-9999/` 目录的 `regional-hidden-v12-<scene>-result-1.json`，保存点与 proof 使用同前缀。实际日志为 `.local/pal/verification/sacred-rewards-<scene>-final-run.txt`，原生只读对照为 `sacred-rewards-original-review.json`，阶段汇总及冻结清单为 `sacred-rewards-stage.json`。源码副本和旧证据基准保存在 `sacred-rewards-source/`。普通一次性点最终至少 3 次搜索不再发放；可再生点验证新搜索的实际增长及恢复不重放，不能把两种断言互换。

本批不代表神木林攀爬区域、桃源可选支线、全部条件奖励、完整性能或发布验收通过。
