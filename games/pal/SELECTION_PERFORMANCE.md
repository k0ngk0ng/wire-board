# 原版菜单与战斗选招响应

后续[到达时钟补验](INPUT_ARRIVAL_TESTING.md)修复了新输入被服务端排队挤过时限的问题。四组主菜单复测均通过。本文保留修复前测量和失败轨迹。

本阶段测量原版主菜单换项和战斗主指令换项。客户端可以提前绘制确定的原版高亮，确认、用物、选敌和规则结果继续走原版输入及权威流程。沿用已有画布尺寸、触控手势和性能预算。

## 实现前失败场景

1. 光标直到服务器确认后才变化，或用背景动画、页面标签、按键高亮冒充光标。比较原版选项区域的实际画布像素，同时记录发送、确认和权威换项。
2. 本地按键顺序与原主菜单的环绕或战斗图标对应错误。按原上下左右输入规则计算；不能预选不可用的战斗指令。
3. 旧权威确认覆盖较新的本地选择。保留有界的未应用方向输入，按权威已应用序号校正，不以收到 ACK 作为已生效。
4. 断开、失焦、后台、暂停、恢复存档或角色／菜单变更后残留旧高亮。按原输入边界清除，并给无确认的预测设置时限。
5. 实际画面没有所需原版绘制指令，或者前后两项显示不完整。保留权威画面，不生成占位图标或改变原始数据。
6. 快速转项或再次点按误执行本地尚未确认的选项。局部显示与原输入路径分开，服务器继续决定确认、菜单切换、扣费和战斗结算。
7. 画面投影修改了权威对象或增加网络载荷。预测只生成局部绘制副本，不修改服务器字段，也不写入存档。
8. 把主菜单和战斗图标的选择成功当作所有菜单、确认、目标和动画的完整性能通过。按实际范围分别报告桌面、触屏与约 200 毫秒连接的结果。

## 实现范围

原版主菜单沿四项循环换项，重用原字形和调色板色号。战斗主指令重用原四个图标，按原方向切换正常亮度和暗色；只有原生画面已经标为可用的图标参与预测。菜单标签或战斗图标的原绘制指令未就绪时，继续展示权威画面。

输入仍发送原序号和按键。未应用的方向输入最多保留 8 个、350 毫秒，仅用于画布显示；按权威已应用序号校正，角色、菜单、操作代次或控制权变更时清除。确认、返回、选敌、法术、道具、奖励及存档均使用原有权威路径。用户仍通过原版画面操作，手机画布保持 320×200。

## 实测结果

战斗主指令的 48 次优化后换项均在权威画面之前出现，随后都与权威状态一致。四组分别使用原生键盘或 320px 原生触控，延迟组的实际 RTT 为 202 毫秒；每组 12 次。主菜单用同一构建观察到本地反馈，但独立复测出现已过期输入，仍不通过本阶段验收。

| 战斗主指令换项 | 基线 P95 | 优化 P95 |
| --- | ---: | ---: |
| 桌面 | 164.8 ms | 15.9 ms |
| 桌面，RTT 202 ms | 368.8 ms | 14.1 ms |
| 320px 手机，RTT 202 ms | 366.5 ms | 18.0 ms |
| 320px 手机 | 150.9 ms | 17.2 ms |

战斗仅移动高亮时保持队伍和金钱；显式确认后打开原版其他指令菜单。实际手机战斗另通过法术菜单和已提交治疗指令的两次个人保存续玩，灵儿体力由 28 回到 103，其余角色照常操作，胜利只发放 3 文。单个剩余敌人由原版自动选择，不能要求选敌页稳定停留，也不算作手动选敌验收。

原主菜单无预测基线在正常和延迟桌面／手机下 P95 为 166.2～399.1 毫秒。启用预测的完整测量尝试中，四组 P95 为 10.9～17.9 毫秒，但一条桌面样本的首次动画帧采样延迟 856.3 毫秒，超过单次上限。独立复测的首个方向输入在 5.6 毫秒得到正确的局部高亮，随后权威帧明确返回 `discardedSeq=1`，选项仍为 1。该输入的 WebSocket ACK 返回 200，故不能仅用 ACK 判为规则已接收。两类失败分别保留原始轨迹，尚未核定输入时间落后原因，不提高 500 毫秒有效期或任何既定预算。

原版规则核心和资源均未变，无上传。阶段汇总为 `selection-performance-stage.json`，旧 7779 个不可变产物与隐藏点进度保持。下一步核对菜单的输入时钟和队列；深层菜单、其他战斗阶段、持续动画及断线／后台恢复都须单独验收。

## 复现

主菜单用正式规则包从真实新游戏到原版客栈，以一次实际原版按键进入主菜单，再开始采样。战斗使用已有的单人三角色原版战斗夹具，不加血；它不代表正式剧情战斗的全部开销。两轮使用同一规则和资源，只改变前端是否绘制预测。浏览器读取实际提供的包并核对 SHA-256，不能用共享 `web/dist` 充当固定基线。

在独立验收副本中，使用阶段归档内的 `board-before.tsx.txt` 和 `baseline-config.mts.txt` 在对应路径重建基线前端，输出到 `.local/pal/selection-baseline-dist`；当前源码构建输出到 `.local/pal/selection-web-dist`。在仓库根目录执行：

```sh
. scripts/env.sh
PAL_BOARD_BROWSER=1 PAL_BOARD_ENTRY=performance PAL_SELECTION_MENU_ENTRY=1 PAL_SELECTION_WEB=baseline go test ./internal/server -run '^TestPALBoardBrowserFixture$' -count=1 -timeout=32m
```

另一终端执行 `python3 -B games/pal/tests/selection-performance-browser.py menu baseline`。用 `PAL_SELECTION_WEB=1` 和 `menu optimized` 重跑优化版。战斗服务改用 `PAL_BOARD_ENTRY=battle PAL_SCREEN_BATTLE_CURRENT=1`，探针参数改用 `battle baseline` 或 `battle optimized`。各轮使用独立前台浏览器，结束后在对应夹具目录写入 `stop`。优化版战斗服务还可运行 `PAL_SELECTION_WEB=1 python3 -B games/pal/tests/screen-battle-browser.py` 验证真实战斗续档，输出不覆盖旧证据。阶段聚合命令为 `python3 -B games/pal/tests/selection-performance-evidence.py`。
