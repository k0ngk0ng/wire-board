# 实时输入的到达时间与执行时间

原版菜单的本地换项已能立即显示，但一次真实复测中，方向键送达后返回了 200，随后又被服务器标记为过期。当前版本以规则执行时刻检查客户端看到的权威时间，服务端等待也计入旧输入判断。需要保留传输和队列的时限，并继续让规则在当前权威时间、当前阶段执行。

## 实现前失败场景

1. 在真实会话中，新输入到达服务器时还未过期，却在有界服务端队列中等待后被误判；验证原版菜单最终选择与权威状态一致。
2. 在到达服务器前已经超过 500 毫秒、来自未来或缺失时间的有效按键仍须丢弃。HTTP 和 WebSocket 都不能由请求正文注入到达时间。
3. 输入在服务器内等待过久，仍须丢弃；服务端时间不能被向前或向后改写，不能在过了期限的原生帧补播输入。
4. 等待中保存、重连、交接或换菜单后，不能用旧操作代次修改恢复后的场景。记录实际执行时间并继续按当前状态检查席位、版本、代次、 nonce 和动作合法性。
5. 普通 HTTP／WebSocket 使用同一平台输入路径，旧中立松开仍保持合法；事务回滚、重复请求、机器人／原生测试直接调用都保持原语义。
6. 不因真实房间环境有抖动而移动现有预算或删除坏样本。验收须保留时间、原生选项和真实网络结果。

## 实测结果

用真实认证 WebSocket、HTTP、SQLite 和原版客栈菜单重现问题。输入到达时距原时间 250 毫秒，平台排队 360 毫秒，旧实现以执行时刻检查，在约 612 毫秒时误丢按键。修复后使用服务器记录的接收时刻判断传输新旧，并对接收后排队另设 500 毫秒上限。WebSocket 在读取完整输入帧后、等待房间锁前记录时刻；HTTP 在已验证请求交给输入队列时记录。两者都将该时刻映射到该房间的逻辑时钟。规则仍在实际执行时刻排入原生输入，不回填历史帧。

真实房间的九项测试通过，包括 WebSocket 排队、HTTP 排队、WebSocket 等待共享锁、到达前过期、队列内过期、未来输入、中立松开、丢弃后新操作及排队请求跨保存续玩代次。验证队员、金钱和页面保持原值。旧控制在恢复后被拒绝，旧时钟不会重播菜单操作。共享平台的事务、去重、慢连接和计时唤醒回归在竞态检测下通过。对原版夹具另做竞态压力诊断时，运行开销使第一项从客户端时间到执行约隔 1.28 秒，触发丢弃；该次诊断保留且不计通过。

主菜单正常桌面、延迟桌面、延迟手机和正常手机各测 12 次，每次从可信键盘或 320px 原生触屏采样，要求原字形颜色正确变化，且随后服务器实际换到同一选项。48 次均先于权威更新且最终一致，没有输入被丢弃。延迟组实测 RTT 为 202 毫秒。

| 场景 | 画面响应 P95 | 单次最大 |
| --- | ---: | ---: |
| 正常桌面 | 13.7 ms | 16.2 ms |
| 延迟桌面 | 16.1 ms | 16.4 ms |
| 延迟手机 | 17.7 ms | 17.9 ms |
| 正常手机 | 16.7 ms | 17.7 ms |

此次修改只涉及服务端。浏览器使用现有本地前端产物的隔离副本，并核验实际加载的包摘要及原版核心。随后全站 TypeScript 检查和 Vite 新构建也已独立通过。资源未改、无上传。旧 7846 个不可变产物与隐藏点进度保持。

本项完成原版主菜单换项与权威收敛。深层菜单、其他战斗阶段、持续动画、断线和后台恢复仍有未验收范围。

## 复现

```sh
. scripts/env.sh
PAL_INPUT_ARRIVAL=1 go test -v ./internal/server -run '^TestPALOriginalMenuInputTimeThroughHTTPAndWebSocket$' -count=1 -timeout=3m
```

浏览器回归沿用[选择性能的原版菜单夹具](SELECTION_PERFORMANCE.md#复现)，以前端产物的独立副本作为 `.local/pal/selection-web-dist`，并使用 `PAL_SELECTION_WEB=1`。另开终端执行 `python3 -B games/pal/tests/selection-performance-browser.py menu optimized --scope input-arrival`。在独立验收副本中执行这些命令，不覆盖旧样本和截图。验收聚合脚本检查实际换项、接受／丢弃序号、固定预算、前端与核心身份和旧产物摘要。
