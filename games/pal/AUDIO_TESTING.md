# 原版主线音频验收

当前已完成原版 PCM 音效、MIDI 音乐及 CD 音轨的转换、OSS/CDN 发布与全量本地回读；原生事件、平台逻辑时钟及原版开场的实际 CDN 播放另有独立验收。完整剧情中的声音、全部场景切换、真机及音画性能仍须继续核对。音频功能不增加剧情完成数。

## 实现前失败场景

1. 原始 MKF、MIDI、CD 文件或音色库被替换，转换仍继续；缓存文件不再核对摘要。
2. MKF 对齐字节被当成 PCM；空音效槽位被重编号；负音效编号无法映射原版绝对值。
3. 压缩改变采样率、声道、位深、采样帧数或 PCM 内容，尤其是 8 位无符号音效和 22222 Hz 的原始采样。
4. 短音效压缩后更大，仍选择体积更大的格式；已压缩 CD 被有损转码。
5. MIDI 合成丢失开头静默、变速、轨道或音符，使用机器上的默认音色库，或丢弃控制器、弯音及力度。
6. 合成器附加的释放尾音延长循环，导致每圈累计漂移；原始 MIDI、音色库、参数和渲染工具身份无法追溯。
7. 合成缺失乐器、丢失音符、产生空音轨或静默文件，却以命令退出成功作为验收通过。
8. 重复生成的音频、清单或压缩文件不一致；清单大小、摘要、MIME 和实际文件不符。
9. 输出路径、已有符号链接或工作目录允许写入原始素材、源码或工作区外；失败后覆盖已验证的清单。
10. 实际播放只保留最后一个音效，重复画面补播旧音效，同曲场景切换重头播放，或保存恢复丢失原版循环与停止状态。
11. 全局静音、隐藏页面、退出及播放失败留下待播队列；取消静音补播旧声音；游戏自行创建播放器绕过平台接口。
12. 音频未计入实际加载大小，未解码就确认就绪，或者音频载荷进入正式服务器包。
13. 只用原生核心的模拟时钟计算音乐位置，导致对白停等时音乐停止计时；续档、加载门槛或服务器重启又把离线时间计入播放位置。
14. 通过客户端声音位置反写剧情时钟、随机状态或原生快照；手动回退后仍接受上一代异步音频加载结果。

## 转换约定

- 音效保留原版编号和所有采样参数。比较原始 WAV 与 FLAC 的实际大小，选择兼容且更小的版本；FLAC 回读到原版整数 PCM 后逐字节相等，STREAMINFO 位深也须保留。
- MIDI 使用原始文件、固定的 TimGM6mb 音色库及 TiMidity++ 2.15.0 离线合成。渲染器从固定源码构建，将初始化随机种子的调用改为固定的 12345，并禁止自动读取系统及用户配置，只接受显式传入的项目配置；构建目录位于 `.local/pal/audio-synth-build/`。关闭按采样对象地址组织的预重采样缓存，使用固定的直接插值路径，避免缓存选择差异改变合成 PCM。保留原始 MIDI 的无损封装和摘要，记录音色库、参数及实际工具摘要。生成音频不能称作原版 PCM；不同硬件原有的 MIDI 音色差异仍存在。
- 合成保留初始静默，以原版各轨最大结束时间为循环边界，向上取整到 44100 Hz 采样帧。固定 16 位双声道输出，保留原版节拍、速度和 MIDI 事件。额外的合成释放尾音不进入循环。
- CD 保留来源 Ogg 文件原字节。gzip 仅作为重复压缩的体积比较，不能作为原生媒体播放文件。
- 所有输出均在工作区内专用的 `.local/pal/audio-media*` 目录。来源素材和只读参考仓库不修改。

原始 MIDI 中有 6 首使用了固定音色库未映射的鼓键。本机原生 GS DLS 的标准鼓组和 Power 鼓组也没有下列键；第 42、43 首还用另一份 GS SF2 交叉检查，结果相同。只读对照记录为 `.local/pal/verification/audio-source-percussion-audit.json`。

| 原始 MIDI | 通道 10 的鼓键及力度非零请求次数 |
| --- | --- |
| `042.mid` | 26：64 次 |
| `043.mid` | 26：96 次 |
| `049.mid` | 95：1 次 |
| `054.mid` | 1：1 次 |
| `064.mid` | 89、92：各 1 次 |
| `066.mid` | 25：128 次 |

保留原始 MIDI 和这些请求，按固定合成器的未映射处理记录，不能擅自移调或替换成另一种鼓音。例外绑定原始文件摘要和完整警告；其他缺失音色或丢失音符仍阻断转换。此项不宣称与原版 Windows 声卡逐采样一致，不能据此判定 Windows 原机音色已通过。

## 原生事件与平台时间线

音频候选核心保留有序的原版音乐、音效与 CD 请求，以及独立序号、原生时钟、循环和淡入淡出参数；每次规则推进均收集新增事件，不能让合并推进覆盖声音或丢失各自发生时刻。只有已审计的 CD 2～9 返回成功，其余按原脚本回退 MIDI。原版 Windows MIDI 后端忽略淡入淡出参数，候选记录参数而不另加原版没有的效果。

当前 `UTIL_Delay` 和 `SDL_Delay` 推进原生模拟时钟，对白阅读停等不会推进它。音乐位置沿平台有效游戏时间累计：阅读时继续，保存退出及加载门槛期间冻结，恢复时重新建立时间基准。客户端仅据此播放，不得修改规则时钟、随机状态或资源；旧核心和旧存档继续绑定原核心。

时间线实现前另登记下列失败场景：原生观察覆盖挂起的 C 栈；环形日志回卷丢失本次推进事件；合并多个规则步后所有音效被错误地放在同一时刻；音乐停止误停仍在播放的 CD；不可用 CD 不回退 MIDI；Windows 原生 MIDI 正在播放时重复同曲导致重头播放；声音绝对编号、重复抑制及重叠声音完成后的复位被改变；音频状态缺失、超前或引用不匹配的资源版本仍能恢复。原生接口隔离验证使用同一真实 Wasm 的公开音频调用，并保留实际请求日志，不能替代真实新游戏或 HTTP／SQLite 验收。

静默媒体准备接口的实现前失败场景：只有元数据就提前就绪；预解码发出声音或绕过统一媒体通道；全局静音使资源加载失败；取消某个房间影响其他房间；取消后触发备用源或旧的完成回调；解码错误、超时及销毁后留下原生元素。此接口在平台内实现，游戏只请求准备资源，不自行创建播放器。

音频发布前另核对：未通过转换回读的目录被上传；源文件、清单摘要、大小、MIME 或路径变化；符号链接越界；覆盖同名不可变对象；缺少任何音源或清单；已压缩音频被再次有损转码；凭据进入日志或发布对象；CDN 返回错误字节、编码、CORS 或 Range；CDN 解码后的 PCM 不符；只验证本地播放或 OSS 上传就写入正式地址；游戏页面仍从本地目录回退。上传使用既有 OSS 发布接口，逐对象禁止覆盖，并在本地完成 CDN 全量回读后才写入发布元数据。

## 音频版本保留的实现前失败场景

1. 更换音源清单后只保留最新采样元数据，导致旧存档被拒绝，或用新时长裁剪旧声音。
2. 音频事件继续时将旧存档的资源标识替换成当前版本；未知版本被静默当作当前版本。
3. 元数据生成覆盖同一不可变版本的旧记录，或删除其他已保留版本。
4. 采样数、采样率或编号出现负数、小数、越界或重复规范化编号，仍生成可用目录。
5. 尚未通过 CDN 回读的音源被设为正式当前版本；生成器写入工作区外或沿符号链接覆盖其他文件。
6. 目录或当前版本缺失时继续生成，Go 代码与保留记录不一致，或重复生成产生变化。

隔离验证仅构造两个不同的时间元数据版本，核对旧时长、旧版本标识和未知版本拒绝；不将测试版本发布到 CDN，也不宣称存在第二份已发布音源。实际客户端兼容须继续使用各自发布记录中的 URL。

时间元数据已按音源版本保存在 `assets/audio-timelines.json`，生成的服务端目录只含编号、采样数与采样率，不含音频正文。生成器追加新版本，拒绝同一版本时间元数据变化；只允许已通过 CDN 回读的发布版本进入正式目录。已存档的声音继续使用其原版本时长与标识，新游戏选择当前版本；未知版本明确拒绝且不修改原快照。隔离测试使用实际原版索引及一份仅用于离线验证的改时长索引，不上传测试变体。

```sh
. scripts/env.sh
python3 -B games/pal/tests/audio-catalog-e2e.py
python3 -B games/pal/build/audio-metadata.py
PAL_AUDIO_E2E=1 go test -race -v ./games/pal/server -run '^(TestRetainedAudioCatalogUsesSavedTimingAndIdentity|TestOriginalNativeAudioRequestsThroughAuthorityTimeline)$' -count=1
PAL_AUDIO_HTTP=1 go test -v ./internal/server -run '^TestPALOriginalAudioLogicalClockSaveLoadHTTP$' -count=1 -timeout=5m
```

生成验收覆盖重复生成、两个版本并存、保留旧记录及 12 项无效元数据／发布状态／路径拒绝，结果为 `.local/pal/verification/audio-catalog-generation.json`。服务端隔离测试通过两个明显不同的原时长核对到期边界、后续事件仍用原版本、新游戏使用当前目录、未知版本拒绝与快照不变；记录为 `.local/pal/verification/audio-catalog-server-run.txt`。同次实际 HTTP／SQLite 存档回归另通过，记录为 `audio-http.json` 和 `audio-http-run.txt`。此处证明时间目录的保留机制，不代替两个真实已发布音源之间的客户端或部署验收。
