# 原版规则核心验收

在编写核心适配前固定失败场景：

- 把原版入口改成自编开场，静默跳过未接入的规则函数或未知指令。
- 读取不同版本资源、混用 DOS 对象布局，或把缺失数据填成零继续运行。
- Wasm 只保存全局变量而丢失脚本局部变量、递归调用、等待输入的位置或只读文件游标。
- 仅保存线性内存而漏掉 C 栈指针，或宿主查询覆盖暂停的局部菜单数组，导致新实例续行后菜单错乱。
- 续档重新执行此前的指令、重复发放物品，或让两个房间共享 C 全局变量和随机数。
- 计时、文件、随机数依赖宿主未持久化状态，不能在新实例恢复。
- 原版数据读取越界、写入原始文件、使用未授权的宿主文件／网络接口。
- 无法终止无限脚本、非法导出参数或不兼容的存档，导致平台挂起。
- 把无画面的脚本验收当作已完成原版画面、声音、战斗或完整游戏。

首次链路使用固定的 98 版 SSS／DATA／文字资源，执行原版场景 1 的入口脚本。断言前 5 条原版消息、队伍位置／形象，以及转入场景 2；在中间对话处保存内存和 C 栈指针，在全新实例中继续，比较后续消息和局面。菜单额外覆盖局部数组、嵌套行囊菜单和独立实例续行。未实现的非绘制接口必须报错，不得返回假的成功结果。

结果保存在 `.local/pal/verification/native-opening.json`；这只能证明开场原版规则执行与续行，不能代替多人、浏览器、战斗和完整流程验收。
