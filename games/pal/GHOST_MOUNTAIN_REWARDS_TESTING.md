# 鬼阴山与鬼阴坛奖励验收

本批范围为场景 70～77 的 26 条普通奖励，按当前 Windows 简体原始数据和[白河寒秋文字攻略](https://gamegene.cn/wiki/360)核对。文字缓存继续使用 `white-river-text-guide.md`，不观看视频。

## 实现前失败场景

1. 为进入主线没有经过的 B／C／D 洞窟直接改场景或坐标。须从实际山道存档经原版洞口进入，保留往返楼梯和队伍。
2. 入口属于其他高度或分离通路，静态直线寻路穿过出口或在墙边反复行走。须核对原始转场落点，按实际门口／山道连接。
3. 戒刀精灵 230 被误当宝箱、持续保留的尸体或药草；遗漏原脚本的物件消失及延后一帧的提示／奖励。按事件 1486 的原始脚本核对取得前可见、取得后消失、原提示、库存及保存恢复。
4. 搜索范围 3 的地面武器消失后，继续搜索误取附近未开宝箱。先处理附近宝箱，再保留原搜索时的站位和朝向，实际搜索至少 3 次，分别核对全部相关库存。
5. 采药后原版药草没有消失，宝箱或珠宝开启帧错误，或同名奖励被合并成一个点。按事件计数，逐点保存领取状态，同脚本／同名物品不合并。
6. 普通战斗消耗待核对物品，或将战利金混入隐藏奖励。仅用原版物理菜单战斗，分别核对金钱、伤害、成长及三人队伍顺序。
7. 误入牢房触发石长老、灵儿离队或剧情结束，仍将收集分支算作原队伍验收。按原版门口保留在收集区域，不将允许剧情战败算作普通胜利。
8. 重构进度报告版本选择时漏掉旧版有效证据、误选审计报告或增加重复事件。新报告出现前须与上一版进度逐字节相同；出现后只允许本批已通过的去重事件增加。
9. 新结果覆盖 v7 归档或完整主线，或保存点清单混入失败尝试。使用 `regional-hidden-v8-<scene>`，只冻结最终通过报告明确列出的保存点，旧产物逐项复核摘要。

## 路线与原版表现

各根档来自同次完整鬼阴山主线的真实存档，绑定完整报告及原生核心摘要。B／C／D 三个可选洞窟分别经山道的事件 1359、1367、1361 进入，坐标为 `1360,1144`、`640,1280`、`1664,1216`。入口洞窟与 E／F 两洞从实际主线经过的对应楼梯存档继续；没有改变角色位置或场景。

四株药草均使用原版精灵 68，取得后消失；普通箱子和珠宝沿原开启脚本从关闭帧 0 变为开启帧 1，取得后、重复搜索及恢复后保持。两个还神丹宝箱按独立事件领取，两个同名物品不合并成一个点。钱包变化均来自逐场核对的战利金，角色正常伤害、成长、三人顺序与本人控制保持。

戒刀事件 1486 的原始脚本为 PC36921～36926：将自身状态设为 0、刷新一帧、显示原提示、发放物品 174、结束。当前原资源的零数量操作数按原版表示 1 把，不能当成不发奖。它使用精灵 230 和搜索模式 3，取得后保持消失，不添加宝箱开启帧；取得前、提示中、取得后及固定站位重复搜索后的全新运行器恢复均已通过。

为覆盖戒刀的宽搜索范围，先领取附近各箱，再从原搜索站位及朝向实际重复搜索至少 3 次，所有相关库存不再增加。各场景均保留原版三人队伍，没有进入坛内牢房推进石长老和离队剧情。

## 进度与历史证据

`hidden-progress.py` 按显式版本清单选择最新报告，保留每版对应的原搜索、动画、钱包、续档和防重复断言。登记本批区域之前，重构输出与原有 256/732 汇总逐字节相同，结果为 `regional-ghost-mountain-selector-equivalence.json`；登记后只增加本批 26 个事件。阶段检查继续逐项比较旧点完整内容、原版保留分类和已有证据摘要，避免仅按数量核对。

上批不可变产物及完整主线共 605 个基准摘要保持。累计进度文件正常更新，其上一版完整副本单独保存。区域报告使用 `regional-hidden-v8-<scene>-result-1.json`；阶段归档只收录最终通过报告明确列出的保存点。
