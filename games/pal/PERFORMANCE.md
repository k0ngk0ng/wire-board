# 仙剑响应与同步性能验收

以下预算在本轮基线测量和实现优化前固定。完整目标仍包括原版剧情、战斗、电脑、存档和发布；本文件不能替代 [ACCEPTANCE.md](ACCEPTANCE.md)。

| 项目 | 预算与范围 |
| --- | --- |
| 本人方向／菜单输入到实际画面首次响应 | P50 ≤ 33 毫秒，P95 ≤ 50 毫秒，单次 ≤ 100 毫秒；桌面键盘和 320px 原生触屏 |
| 单端约 200 毫秒连接 RTT | 本人首次画面响应沿用上述预算；权威确认单独记录，不等待确认才显示本人操作 |
| 浏览器显示采样循环 | P95 间隔 ≤ 35 毫秒；统计全部 rAF，不能只统计已绘制帧 |
| 原版探索持续移动 | 保留原版 10 FPS 逻辑；非碰撞情况下可见移动 ≥ 9 次／秒，P95 间隔 ≤ 150 毫秒 |
| 原版战斗动画 | 保留原版 25 FPS；连续动画可见变化 ≥ 24 次／秒，P95 间隔 ≤ 80 毫秒 |
| 普通探索持续同步 | 每条游戏消息 P95 ≤ 4 KiB；不重复静态地图、素材或完整存档 |
| 密集战斗持续同步 | 每条游戏消息 P95 ≤ 16 KiB；首次接入／恢复检查点另计并单独报告 |
| 单房间规则推进 | 普通单人房间 P95 ≤ 20 毫秒；慢连接不能阻塞其他房间或改变规则时钟 |
| 存档编码／解码 | 当前原版客栈状态各 P95 ≤ 5 毫秒；同时验证摘要、旧格式兼容及失败不污染状态 |

## 测量要求

- 使用真实认证房间、平台 `Board`、原版规则和当前原版资源。原版开场产生的客栈检查点可作为明确标注的性能夹具，不能当作完整剧情验收。
- 原生键盘／触屏事件分别记录时间，读取游戏 Canvas 的像素变化。画面移动通过静态场景的预期相机位移识别，排除虚拟按键高亮、无关 NPC 动画和只收到 ACK 的情况。
- 分别记录 WebSocket Ping/Pong RTT、输入发送及确认、权威帧观测、实际像素响应、rAF 间隔及游戏消息大小。HTTP 请求耗时不作为纯连接 RTT。
- 覆盖两个独立单人房间、其中一端延迟、另一房间保持正常、快速连续输入、重新连接和后台恢复。TCP 延迟代理保持字节顺序和有界队列；不能用逐块限速冒充固定传播延迟。
- 保留原始样本、测试命令、截图和结果。未达到预算的项目保持失败，不能测后放宽阈值。分阶段完成的测量必须明确哪些范围尚未验收。

## 实现前失败场景

1. 本人画面等待服务器往返，延迟连接下操作无即时反馈。
2. 空闲帧不断发送完整绘制列表／缓冲图，静态内容挤占网络或主线程。
3. 慢端积压旧状态，拖住快端、规则时钟或其他房间。
4. 预测穿过原版障碍、污染资源、越过剧情／角色权限，或者恢复后补播旧输入。
5. 编解码或状态复制占满帧预算；优化后存档不兼容、校验失效或失败修改原状态。
6. 以 ACK、按键高亮或无关动画冒充画面响应，或遗漏未更新画面的显示帧。
7. 将原生内存摘要校验与压缩／解压并行后，损坏数据被返回、错误路径遗留后台读取、复用池覆盖尚未使用的缓冲区，或保留核心分派路径漏掉摘要校验。校验必须实际完成，成功后才能返回快照；旧 gzip／JSON 与新二进制格式继续拒绝损坏、超限和多段压缩载荷。
8. 单独测量规则推进时绕过正式规则包、使用旧核心、跳过到期帧或修改原版节奏；捕获内存的优化产生摘要与快照不一致、共享可变内存或实例关闭后的后台访问。隔离采样只用于定位耗时，不能代替真实房间响应验收。

## 当前原版核心的单人测量

当前核心为 `4aeeca84606436fc071b1b9004014ca11767ec048e8c3be5d411c6c0370d6ba3`，使用正式服务端规则包，从真实新游戏推进到客栈，再将测试时钟等量转换到新房间时间原点。两个账号各自建立独立的 1 人房间；手机轻触人物周围控制方向，无虚拟按键，画布保持最大原比例。

第一轮结果位于 `.local/pal/performance/original-solo-current/`，每种场景各 12 次原生输入。像素响应、全部 rAF 间隔和消息大小达到预算，规则回调略超 20 毫秒，因此四项综合结果仍为失败；未放宽阈值。

| --- | ---: | ---: | ---: | ---: |

随后单独尝试的内存复制／摘要并行没有稳定改善规则回调，改动已撤回；该次失败诊断保存在 `.local/pal/performance/original-solo-capture/`，不作为通过结果。当前保留编解码流水优化。

规则回调样本为两房间测量期间的实际 `OnTimer` 完整调用，包含正常早退帧和实际到期推进帧；原始耗时、执行人数及错误标记随报告保留。独立 CPU 诊断位于 `current-field-timer.cpu` 和 `current-field-timer-top.txt`，只用于定位耗时，不代表真实房间预算通过。

当前原版客栈存档编码 P95 为 4.944 毫秒、解码为 3.972 毫秒，压缩后 879626 字节；两项均达到 5 毫秒预算。摘要计算与压缩并行，解压、内存写入与摘要计算流水执行，所有校验完成后才能返回。真实新旧二进制／gzip／JSON、损坏拒绝、并发独立状态和保留核心的竞态回归已通过。报告为 `.local/pal/performance/codec-original-current.json`，回归为 `codec-compatibility-race-run.txt`、`codec-retained-catalog-race-run.txt`。原版手动回退及旧核心 HTTP 续档另通过本轮 `codec-capture-http-run.txt` 中的对应检查。

菜单／战斗的本地响应、持续探索／战斗采样、随机丢包及其他阶段恢复仍须完成。当前客栈结果不能代表完整性能验收。

## 历史双人测量（不计入当前单人验收）

以下为原版客栈检查点中的实际认证双人房间。每轮使用新夹具，按键响应读取 Canvas 静态场景位移；不计虚拟按键高亮。预算保持原值，当前验收未通过。

| 场景 | 优化前响应 P95 | 私有事务优化后 P95 | 当前探索预测 P95 | 当前全部 rAF 间隔 P95 | 当前游戏消息 P95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 正常连接 | 877 ms | 168 ms | 12.0 ms | 17.6 ms | 2,037 B |
| 单端固定约 200 ms RTT | 1,230 ms | 345 ms | 11.5 ms | 17.4 ms | 2,037 B |
| 同时保持另一端正常 | 883 ms | 145 ms | 11.7 ms | 17.4 ms | 2,037 B |
| 320px 原生触屏 | 949 ms | 136 ms | 16.0 ms | 17.4 ms | 2,037 B |

优化包含原生内存二进制压缩、公共锁外的席位投影、一次事务内的私有原生状态、探索移动的本地预测，以及平台时钟与状态副本的调整。实际执行仍创建独立 Wasm 实例，未引入共享可变规则实例或跳过外部存档校验。前四轮记录分别为 `.local/pal/performance/baseline/`、`optimized/`、`detached-stream/` 和 `current/`；首次预测验证为 `prediction-current/`，旧控制包有效期验证为 `freshness-current/`，当前记录为 `clock-copy-current/`。

本轮四个探索场景的响应、rAF 和消息大小通过既定预算。连接 RTT 单独使用每种场景开始后产生的原生 Ping/Pong 样本，按 `sampledAt` 去重；延迟连接实测约 201 毫秒，其输入 ACK P95 约 239 毫秒，画布响应 P95 为 11.5 毫秒。本机正常连接与手机的 RTT 小于 1 毫秒，按整数毫秒记录为 0。短场景的 RTT 样本数较少，不能据此判断公网连接质量。

该历史核心的独立存档编解码 P95 约为编码 7.36 毫秒、解码 5.16 毫秒，压缩后 875,508 字节，原生内存为 8 MiB；当时未达到编码和解码各 5 毫秒的预算。原始记录为 `.local/pal/performance/codec-current.json`。这些数值包含公开快照输入的完整校验；平台私有事务仍在持久化输入边界进行完整校验。

探索预测使用原版碰撞、队伍跟随、走路帧和遮挡顺序，按规则已应用的序号校正；不预测剧情、电脑决策、物品、血量或奖励。预测最多领先 3 步，权威状态超过 300 毫秒未推进时清除旧预测；站立帧不延后新的短按，持续移动保持原版 100 毫秒节奏。关键触发区域停止继续预测，阶段、领队或 epoch 变化会清除旧操作。

旧控制包有效期与客栈网络恢复已另行验证。`.local/pal/network-lifecycle/` 使用真实 TCP 积压／断开、原生标签页和原生输入，检查旧包丢弃、快端操作、WebSocket 自动重连、后台长按释放、重复按键拦截、恢复后的手机触屏，以及同一 Canvas 与权威画面的像素收敛。规则层与竞态检查覆盖 1～3 席和原版战斗指令，见 `input-freshness.json`、`battle-input-freshness.json` 与 `freshness-race.log`。

完整性能验收仍未通过。菜单／战斗本地响应、连续探索／战斗帧率、单房间推进分位数、密集快速输入、随机丢包及其他阶段的连接／后台恢复尚须完成正式测量。本轮客栈和四种探索响应场景不能替代这些要求。
