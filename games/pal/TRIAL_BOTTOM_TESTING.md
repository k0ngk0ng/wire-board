# 试炼窟底层与五灵神像验收

依据[回梦试炼文字攻略](https://gamegene.cn/wiki/365)、当前 Windows 简体原地图及原脚本核对，不观看视频。

## 实现前失败场景

1. 底层入口或地图视觉墙体被当成不可达，直接改坐标、地图或碰撞进入。只沿原传送入口和原地图允许的路线行走。
2. 芦苇漂直接发入库存，原取得提示、消失、重复搜索和存读档遗漏。按事件 3607 的原搜索、物品 294 和原状态保存。
3. 在错误场景或被挡的前方使用芦苇漂仍消费，或把它当作普通固定传送而改位置。通过原物品菜单和 `39856` 放置指令，核对失败保留及成功放置、消费与原自动脚本。
4. 芦苇漂放置后打开原岸口的 3608 状态或船的位置、触发模式、续行没有保存。使用原菜单放到原水边，保存选择中、放置后和原渡运途中，不能直接改障碍状态。
5. 原多段渡运被简化为直线移动，整队位置或方向丢失。解析原骑乘／行走指令，实际移动由原脚本完成。
6. 五件装备共用原开启过程却被合并，精灵 389 原闭帧或开启帧改变，库存恢复后再发放。每个事件独立核对原数量、提示和固定姿态重复搜索。
7. 五灵神像只显示提示却没有实际学会法术，或法术被加给平台席位而不是原角色。使用原魔法菜单、原角色及原学法术指令核对。
8. 火神原条件分支被统一：两人队伍时给阿奴，有灵儿时给灵儿。两条真实正常队伍分支分别验证，不能人为加人或改角色姓名。
9. 已在原升级中学会的法术被误算成新奖励，或重复调查无限添加。先核实各角色原魔法表，再检查学习后及重复后的实际菜单和原事件关闭。
10. 使用当前源码冒充旧根档来源、复跑覆盖冻结前批，或重复两条分支把底层六个物品事件计十二点。原父档摘要绑定真实核心，按事件 ID 去重。
11. 正常战斗掉落、伤害、成长和金钱被重置；或跨图后已领宝箱重闭。保留原正常规则，物品与普通掉落独立记账，末档再核对全部已领状态。
12. 单凭测试画面就宣称完成全部隐藏点、性能或发布。底层只新增六条既有物品候选，五灵神像作为同批原版支线功能验收，不新增候选点数。

## 当前范围

芦苇漂 3607 与五件装备 3641～3645 共六个物品候选已通过；五灵神像 3636～3640 的两人／有灵儿两条原法术分配也已通过。累计已处理 652/735：630 个实际取得或交易／采集事件通过、22 条原版保留记录，剩余 83 个。两条队伍分支不重复增加点数。

## 操作与核对方法

两人分支从已通过传送下层收集的真实末档继续，队伍为逍遥／阿奴 `[0,4]`；三人分支从同一核心的祈雨前真实战场存档继续，队伍为灵儿／逍遥／阿奴 `[1,0,4]`。父档与完整父报告分别按摘要登记，不能改队伍、法术或本次取得的物品。

先搜索取得芦苇漂和魅影神靴。错误使用选择实际可达、前方原地图被挡的站位，核对原菜单选择、失败后保留及原事件未放置。正确使用站在 `288,1440`，朝原西南方向将芦苇漂放到 `272,1448`；原自动脚本关闭岸口 3608、改变芦苇漂状态和触发模式。`256,1456` 不在原地图可走格中，不能作为测试站位。

渡运依次通过 `3607 → 3614 → 3630 → 3631 → 3632 → 3634 → 3635 → 3635`，每段由原输入登船，并在骑乘途中恢复到全新运行器。3635 首次运送改变原障碍和靠岸位置，第二次才能通往神像区；测试按当前船的位置逐段登船，不能把它假设成固定往返边。

每件物品在未领取、原提示、领取后和再次搜索 3 次后分别保存恢复；五件装备保留原精灵 389、开启帧 1 和空箱续行 `36509`。每座神像在调查前、原提示、学习后和重复调查后保存；原生角色魔法表核对唯一新增，原魔法菜单另留可见法术证据。火神按原 `rgwName == 37` 分支分配，有灵儿时给灵儿，否则给阿奴，其他角色不新增火神。

大理战场的静态尸体与附近敌人触碰区会重叠。测试在该场景按当前公开碰撞重新寻路；不能因同格存在触碰区就忽略尸体阻挡。后续洞窟沿用已验证的原传送顺序。战斗正常结算，傀儡虫结束脚本掉落、战利金和隐藏奖励分别记账。

原生只读核对验证 `PALMEM01`、真实核心摘要、完整内存摘要和唯一动态事件表，排除原 SSS 副本。通过角色姓名数组及实际队伍体力定位唯一动态角色表，再核对六名原角色的完整 32 格法术数组。旧已领箱子的最终原位置、开启帧和续行也与源档逐项比较。

两人分支 81 次全新运行器保存恢复，无战斗；三人分支 122 次恢复、17 场正常胜利。合计 203 次保存恢复、16 次骑乘和两条完整五灵神像分支通过。三人路线保留 1673 文战利金及 7 只原战斗傀儡虫掉落，掉落提示和原 PC `42830` 单独核对，不增加隐藏点数。两人源档已有 17 个、三人源档已有 4 个已领箱子的最终原生状态逐项保持。
