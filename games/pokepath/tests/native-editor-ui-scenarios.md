# 原生波次编辑器界面失败场景

测试先于组件实现。编辑器由本项目 React 表单、按钮和布局组成，只提交原生 Go `custom`／`custom_retry`／`custom_exit` 行动，不加载原程序，不使用 iframe 或页面外浮层。

1. 普通流程直接选择已解锁路线、生命与强化参数，并按顺序编辑敌人和间隔分组；不要求用户填写程序 JSON。
2. 生命只允许 1～14，生命／护甲强化为 0～200 且步长为 5；分组为 1～256，展开数量不超过 4096，至少包含一个敌人。非法数值和未知敌人不能提交。
3. 未解锁路线和未发现秘密地图不能借分享码导入；编码损坏、超长、非规范 base64、额外字段和非法分组须明确拒绝，不能静默改写为默认波次。
4. 增减、删除与排序保留分组本身身份；改变其他玩家的宝可梦选择或普通权威快照更新，不能把操作串到其他分组或覆盖本地草稿。
5. 只读、战斗中、暂停、挑战或轮抽期间不能启动实践；观战者不提交世界变更。关闭和复制分享码仍可使用。
6. 分享码使用与 Go 编辑器相同字段，仅包含地图、生命、强化和波次，不夹带返回路线或其他内部元数据。
7. 当前实践可按规则重试或退出；服务端拒绝操作时保留草稿并显示可理解的错误。
8. 桌面与 320 px 手机保持原生 select、数值输入和可点击按钮；弹层留在游戏根节点内，主要操作和错误反馈不被横向裁切。

组件／编码验证：`node --test games/pokepath/tests/native-editor-ui.test.mjs`。真实 DOM 场景：`WIRE_BOARD_EDITOR_BROWSER=1 node --test games/pokepath/tests/native-editor-ui.test.mjs`。结果与桌面／手机截图写入 `.local/pokepath/native-editor-ui/`。
