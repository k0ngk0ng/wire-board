# 浏览器状态推进开销

真实 200 敌人房间先测得 RAF p95 33.4 ms、约 49.6 次运动像素更新／秒，未通过固定预算。调整前核对以下隔离失败场景：

- 推进或操作修改原保留句柄，之后的回滚不能恢复。
- 无效操作、零时间、暂停推进改变原状态或泄漏句柄。
- 少一次外层复制后共享了可被后续规则写入的集合。
- 成功响应的 JSON 编码改变中文、引号、特殊字符或嵌套数据。
- 为缩短开销丢失规则步、事件、碰撞或实际可见帧。

原引擎的 `Apply` 和 `Advance` 都先深复制候选，再于校验成功后替换传入的状态顶层。浏览器适配器可使用独立顶层值，保留引擎内部事务复制，避免再次在适配层深复制同一世界。普通 clone 接口仍维持独立完整深复制。

复验沿用既有完整状态／投影对照、opaque 句柄和 Unicode E2E，再重跑正式 200 敌人页面。预算保持 RAF p95 ≤25 ms、运动像素 ≥55 次／秒、点击像素响应上界 ≤100 ms。

紧凑敌人投影的失败场景：

- 省略零值后没有恢复必要字段，或把原本省略的可选字段添加到公开投影。
- 零与非零、空字符串与中文字符串、真假状态、空列表与活动状态之间切换时沿用旧值。
- 状态计时、伤害收据、被动集合、图集覆盖或路径坐标丢失。
- 分支、导入、释放和后续规则推进修改了已返回的对象。
- 为减少字节缩短公开状态或只验证少量显示字段。
- 浮点负零被默认值合并，导致完整投影的坐标或伤害字段与原值不同。

使用实际 Wasm 中的 200 个不同敌人记录，逐字段比较紧凑还原后的完整投影与原始 Go 投影，同时保留字节数和耗时。零值元数据由同一份 Go 状态定义产生；前端不得自行补写规则事实。

类型驱动复制的失败场景：

- 直接复制结构体后遗漏其中的切片、映射、指针或接口，分支修改污染原状态。
- 把仅含数字和字符串的图集、点或事件按字段重复复制，造成不必要的反射开销。
- nil 与非 nil 空集合的序列化语义改变。
- 同一类型的复制计划被修改、并发初始化不安全，或计划缓存保存了对局数据。

复制计划只包含 Go 类型和需深复制的字段编号。结构体先完整值复制，再递归复制可变字段；纯值切片完整复制。验收使用真实波次、持久场、状态效果、敌人被动集合和快照恢复，遍历修改分支中的已存在数据后检查原快照保持不变。
