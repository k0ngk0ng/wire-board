# 独立 Go 规则的平台验收

本组测试先于新的服务器适配实现建立。最终游戏只调用本仓库独立编写的 Go 规则；不运行、嵌入或解释原版 JavaScript，不使用 iframe 或 Goja。

| 边界 | 预期 |
| --- | --- |
| 1～4 人合作 | 共享生命、地图与波次；每席独立 50 金币和三只御三家伙伴 |
| 配置与动作 | 拒绝未知配置、未知字段、伪造资源、错误人数、观众与过期代次 |
| 原始规则操作 | 部署、升级和波次推进只经独立 Go 引擎校验；输入快照不能原地改变 |
| 并发与回滚 | 两人同时消费各自钱包可以分别成功；争用同一部署点时逐次校验，越权、失败事务和被丢弃候选不改变状态 |
| 保存退出 | 首票冻结完整当前规则状态，取消只解除保存冻结；不解除原有手动暂停 |
| 恢复与重启 | 冻结离线时间，保留 Clock、随机、塔、敌人、弹道与资源，只提升控制代次 |
| 存档身份 | 错误 schema 或 hash 明确拒绝，不改旧 SQLite 原始数据 |
| 本地预测确认 | 服务器按认证席位回显输入 ID；同席重试幂等、跨席相同动作分别执行，收据有界 |
| 网络更新 | 完整同步包含纯 Go State；普通流只发送新操作与必要投影，传输序号独立于引擎子步 |
| 确定性流负载 | 正常游标仅含时钟、操作、确认游标与各席余额；不重复地图、队伍精灵、成长目录、历史事件或存档；同游标空增量也遵守，过期游标才回完整快照 |

执行：`. scripts/env.sh && go test -json -count=1 ./games/pokepath/tests -run '^TestNativePlatform'`。新的结果保存在 `.local/pokepath/native-verification/`，不复用已放弃的嵌入方案验收记录。

双人浏览器续玩验收在第二位玩家的真实加载确认发送前读取恢复快照。此时完整规则状态须与存档相同，只有操作代次增加。放行加载确认后，再验证两人回到同一房间且规则继续推进。图鉴在场计数等会随正常运行变化，不能用门槛解除后的快照替代冻结比对。

多人界面使用 `node games/pokepath/tests/native-trainers-browser.mjs --build`，覆盖真实账号、独立队伍与商店、个人选中状态、队友权限、共享战场和 320 px 的余额可见性。`native-platform-browser.mjs` 的默认入口转入该验收。
