# 原生客户端资源发布验收

先建立本地两版发布链路，再修改 MIME 登记。测试只复制已冻结的 `.local/pokepath/native-web` 到本任务临时目录，不修改浏览器正在使用的构建，不连接真实 OSS。可用 `WIRE_BOARD_POKEPATH_DELIVERY_WEB` 指定另一仓库内构建目录；`WIRE_BOARD_POKEPATH_DELIVERY_REVISION` 和 `WIRE_BOARD_POKEPATH_DELIVERY_FACTS` 可固定最终验收身份。

| 失败场景 | 预期 |
| --- | --- |
| 当前原生资源中的 ICO 或 OTF 未登记 MIME | 完整盘点并保留精确响应格式 |
| 前端构建携带旧 Wasm、旧事实或旧规则版本 | 直接拒绝验收，不在测试中用新文件覆盖旧产物 |
| 发布资源混入参考 JavaScript、原版 CSS 或嵌套游戏页面 | 拒绝验收；只有自编 Wasm、Go 支持脚本和独立前端 |
| 只修改一个图片对象后，未变资源被重新上传 | 图片使用新 URL；其他对象继续复用原 URL，只有依赖的清单随内容变化 |
| 相同构建再次发布或同内容改名 | 新增对象和上传字节为零，改名直接复用已有对象 |
| 循环脚本依赖仅因提交目录变化重新上传 | 用已发布依赖闭包求解，并以真实字节摘要验证；实际变更仍沿依赖传播 |
| 元数据与 Wasm／音频来自不同历史发布目录 | 每个逻辑路径单独经 `/_media` 重定向；不能根据上一响应目录拼接子资源 |
| 游戏启动加载其他路线 | 只读取当前路线、核心事实、Wasm、必要图像和音频；其他路线不预加载 |
| CDN 内容、MIME、CORS 或音频 Range 不符 | 回读失败，不能标记资源验证成功 |
| 服务器剥离后仍有 Wasm、支持脚本、媒体、字体或路线 JSON | 验收失败；只留下应用入口与地址清单 |
| 标准全站构建包含其他游戏已验证的运行时收据 | 保留并绑定其摘要，不把元数据收据当作客户端载荷删除；剥离后仍须验证实际二进制 |

执行：`python3 -B games/pokepath/tests/native-delivery-e2e.py`。结果保存在 `.local/pokepath/verification/native-delivery/result.json`，包括来源摘要、两版复用计划、真实回环 HTTP 请求及剥离后的文件集合。临时目录在测试结束时删除。
