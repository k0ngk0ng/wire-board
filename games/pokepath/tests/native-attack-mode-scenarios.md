# 原生攻击模式事实与失败边界

本组先记录事实与失败场景，再编写端到端规则测试和独立实现。原版 v1.7.3 的 `Tower.js`、`Game.js` 仅用于核对数学、时序和可见行为，不导入、执行或整类翻译为产品程序。测试使用显式已拥有对应宝可梦的战斗前置，以及真实部署、瞄准、开波、推进、命中和完整存档接口；不能把战斗前置冒充自然收集流程。

| 范围 | 可核验事实 | 失败边界 |
| --- | --- | --- |
| 炮击 | `Tower.js:3858–3981`：普通炮弹线性飞行 500 ms，命中后保留 400 ms 效果；圆形区域按面积均匀取样，`rockThrow` 为朝向瞄准点的垂直长条，长 `bombardmentArea×5`、宽 `bombardmentArea`；实际溅射半径为 `bombardmentSplash/2` 加敌人半径 | 无普通目标仍须按周期炮击；不得提前命中、退化为跟踪单体弹、重复命中或超出范围伤敌；重新瞄准清除该塔已有炮弹，但不重置冷却 |
| 瞄准 | `Game.js:157–244,1235–1248`：瞄准点按有效射程投影回圆周；十字形选择最大轴向投影，轴向限制射程、侧向限制区域半径；星星碎片增加两条对角轴；广角镜及胜利之星扩大十字侧向允许距离 | 未部署、非炮击、未知 UID、暂停、无效数值不得写入；多个玩家操作同一稳定 UID；失败完整回滚；不能任意改资源或提交快照 |
| 雷击 | `Tower.js:3874–3936`：雷暴中每轮 3～7 道，起点在落点上方 260 px、150 ms 飞行；6 段折线，中间点水平抖动 ±9 px；离开雷暴不发射 | 天气必须真实门控；数量和取样保留随机数；恢复不能重抽落点或重复落雷 |
| 急速折返 | `Tower.js:4140–4227,5854–5873,6448`：首次立即直伤，250 ms smoothstep 移至目标，停留 300 ms 后选射程内最近未访问敌人；每跳额外增加 `ceil(base×跳数×0.05)`；找不到则 250 ms 归塔，归塔后才重启冷却 | 同一敌人每链仅一次，不能原地逐帧连击或指数增伤；目标消失、换图、收回、波末都不能遗留塔位或闭包状态；完整保存移动与已访问集合 |
| 声波 | `Tower.js:4802–5017`：半径以每原版帧 `range/50` 增长，即每秒 `range×1.2`，环宽 6 px；多环间隔 450 ms；每环每敌人仅一次，达到射程或透明度消耗完后移除 | 未到波前、波后、射程外、隐藏且无反隐的敌人不得命中；多环分别结算；不把全范围敌人同帧一次打完 |
| 剑扫与方向区域 | `Tower.js:6314–6364,7087–7195`：暗影爪以目标为圆心 52 px，强化时 78 px、340 ms；圣剑类是正向射程内、侧宽 50 px 加敌人半径，300 ms 扫剑表现；其他方向区域需按原版各自配置 | 目标周围与塔周围不得混淆；方向背面和侧边界必须实测；视觉持续期不得重复伤害 |
| 精神利刃 | `Tower.js:4721–4768,5826–5849`：弧半径 45 px、半角 `π×0.32`、厚度 12 px；前进每帧 5 px，即 300 px/s；最大前进距离 `range−45`，超级形态每命中延长 60 px | 弧前后和背面不命中；每次波每敌人仅一次；命中延长、飞行进度和去重集合都入存档 |
| 热沙波 | `Tower.js:4772–4796,5791–5818`：沙瀑天气下，沿瞄准方向每帧 2.2 px，即 132 px/s，半带宽 80 px，最大路程为画布对角线；波前走过区域每敌人一次 | 天气真实限制；不能退化为追踪弹或只打一个目标；横向与后方边界正确，恢复不重打 |
| 先制之爪 | `Tower.js:7214,7305`：仅将攻击优先级变为最快，保留原攻击模式和几何 | 不能把波、扫击、炮击等覆盖为不存在的通用 `targetFastest` 弹道 |

本范围不实现核心负责的轨道、回旋弹，以及链接模块负责的暴击再击与诅咒链接。原站没有名为 `feint` 的独立攻击模式，不能凭名称添加玩法。

验收产物保存在 `.local/pokepath/verification/native-attack-modes/`。包含原生规则输入轨迹、完整中途存档、命中与几何断言、Go/Wasm 同输入快照对照。所有可变瞄准、移动、特效、命中集合与随机状态保存在 `State.AttackModes` 或已有显式状态中。

## 已验证范围

23 项原生 E2E 覆盖炮击／雷击的实际发射、飞行与落点，旋转长条取样，双折返链的稳定推进顺序，移动与收回清理，声波多环，剑扫共享暴击及左右交替，暗影爪主目标强化，方向扇形，精神利刃弧形与超级形态每次命中延长，热沙带状波前，以及损坏存档拒绝。与 33 项成长 E2E 一起通过 Go `-race`；子场景包含 173 个通过事件。

Go／Wasm 回放对照 13 种目录形态，每一步完整状态和完整投影使用严格相等断言，共 162 次比较，不放宽浮点误差。早期对照发现原生平台的融合乘加会造成约 `2e-14` 的坐标差；独立模式数学使用显式 `float64` 中间舍入，保持普通双精度计算语义并使回放完全一致。

复现顺序：

1. `. scripts/env.sh && go test -race ./games/pokepath/tests -run '^TestNative(AttackMode|Progression)' -count=1`
2. `. scripts/env.sh && go test games/pokepath/tests/native_attack_modes_e2e_test.go -run '^TestNativeAttackModeProduces' -count=1`
3. `node --test games/pokepath/tests/native-attack-modes-wasm.test.mjs`

战斗前置指定目录形态、等级和已进入的受控敌人位置，不声明这些形态均通过本组自然收集。这里验证规则和 Go／Wasm 一致性，界面像素、实际浏览器帧率和完整路线电脑对局由对应平台验收记录覆盖。
