# 相同规则步的呈现投影复用

200 敌人的真实页面在去除重复事务复制后仍出现间歇性 33 ms 帧。下面先列出呈现缓存的失败场景，再实现：

- 相同物理步只变了显示相位，却重复导出整个世界。
- 缓存误用另一操作分支、导入快照、路线或控制代次的数据。
- 未跨物理步但跨统计分钟时，训练家时间未更新。
- 显示时钟／余数被缓存，画面退化为规则步刷新。
- 消费者修改缓存对象，污染后续呈现或 Go 规则状态。
- 暂停、恢复、操作失败、释放句柄或销毁后缓存仍可错误使用。
- 缓存无限保留历史世界。

仅复用完整只读投影；物理步和操作版本变化必须重新向同一份 Go 引擎投影。完整公开 `project` 接口仍执行原投影，不以缓存替代规则校验。呈现缓存最多保留四个版本，时钟与余数每次从有效句柄更新，训练家分钟值按同一既有规则换算。

执行 `. scripts/env.sh` 后运行 `node --experimental-strip-types --test games/pokepath/tests/prediction-frame-cache-e2e.test.mjs`，在实际 Wasm 中逐项与完整 `project` 比较。最后仍以真实认证页面固定 FPS 和像素延迟预算验收。

操作版本与地图版本分别维护。暂停、恢复等输入不能强迫客户端重新导出地图与完整敌人字段；地图编号、实际镜像方向或自定义路线变化时，必须建立新的地图版本。真实 Wasm 验收对暂停、恢复、进入同编号的自定义路线和退出自定义路线逐次比较完整投影。
