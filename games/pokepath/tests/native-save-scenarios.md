# 原生规则保存与多人续玩失败场景

本验收先于原生保存实现编写。使用真实认证 HTTP、平台加载门槛和 SQLite，不调用旧 JavaScript、虚拟机、iframe 或原版 Main，不更改游戏资源／战斗数值以制造通过。

1. 数据必须是完整可序列化的 Go 状态，不能包含操作录像或旧运行器快照。规则／资源身份固定绑定；错误 schema、错误身份必须拒绝，不能静默重开或改写原档。
2. 1～4 名原真人共享同一世界。首票保存必须立即冻结，后续确认、保存等待与续玩等待不能推进敌人、塔、冷却、弹道、持续状态、随机数、波次或时钟。
3. 保存释放真人席位，观众、陌生账号和未认证请求不能保存、读取规则快照或续玩。未到齐时不能替原成员占位，电脑不能代替真人确认。
4. 正在战斗的完整状态经 SQLite 写入、服务关闭、新 Server 构造与原名册确认后必须一致。只允许恢复所需的操作 epoch 改变；数值比较使用 `json.Number` 保留 64 位随机状态精度。
5. 恢复沿用公共加载门槛，全部真人确认资源前不推进。前端构建身份变化须更新加载版本，不能改写已保存的规则资源身份或游戏状态。
6. 保存首票、最终保存、取消保存和最终恢复的 SQLite 失败必须全部回滚，不能遗留冻结、确认、席位或未提交进度。
7. 保存／恢复重试和原真人并发确认不能创建第二世界、重复扣费、重复初始化、重复结算或重复积分流水。
8. 保存前的页面 epoch、版本和加载令牌不能越过恢复边界；新的真人操作和系统时钟在加载完成后须正常继续。
9. 真人与电脑混合时，只需真人确认，电脑不会自动保存；继续后仍保持编队、资源与电脑控制，不重新发放伙伴或金币。
10. 手动暂停与保存确认暂停分别保留。保存并继续不能擅自解除原来的暂停。

测试命令：`. scripts/env.sh && go test -race ./games/pokepath/tests -run '^TestPokepathNativeSave' -count=1`。结果写入 `.local/pokepath/native-save/`，保留完整状态摘要、原始状态、HTTP 场景与校验记录；临时数据库在导出产物后清理。
