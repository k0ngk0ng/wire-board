# 首波连续对照

在路线 1-1 以 1 倍速打完首波。覆盖不部署伙伴，以及在同一图格分别部署 1 级小火龙、木守宫和呱呱泡蛙。基准场景统一优先攻击最前的敌人，另有一组保留各自默认的选敌方式。

浏览器以虚拟时间推进原版，独立 Go 引擎按真实的 60 Hz 帧推进，每帧按速度缩放并等分为不超过 `1000/60 ms` 的小步。两端记录敌人序号、坐标、生命、发射目标、伤害、奖励和结算。原版 JavaScript 仅由本机隔离的测试 HTTP 服务提供，不进入平台构建。

在仓库根目录运行以下命令：

```sh
. scripts/env.sh
node games/pokepath/tests/first-wave-reference.mjs --settlement
node games/pokepath/tests/first-wave-reference.mjs --starter-defaults --settlement
node games/pokepath/tests/first-wave-reference.mjs
node games/pokepath/tests/first-wave-reference.mjs --ideal-60hz
node games/pokepath/tests/first-wave-reference.mjs --ideal-60hz --warm-enemies
node games/pokepath/tests/first-wave-reference.mjs --starter-defaults --ideal-60hz --warm-enemies
node games/pokepath/tests/first-wave-speeds.mjs
node games/pokepath/tests/first-wave-reference.mjs --item-combinations --ideal-60hz --warm-enemies
node games/pokepath/tests/first-wave-speeds.mjs --items
node games/pokepath/tests/first-wave-reference.mjs --item-combinations --critical-combinations --ideal-60hz --warm-enemies
node games/pokepath/tests/first-wave-speeds.mjs --criticals
```

`--settlement` 比较四组场景的金币、生命、星星、击败数、后续波次、奖励顺序与完波时间。该命令还核对三只伙伴各自的首发中心，以及呱呱泡蛙第一发的 4 次连续命中（6、5、4、3 点伤害）。默认命令额外要求整波命中顺序一致。`--ideal-60hz` 固定每次原版更新为一次 60 Hz 规则步，用于排除原版将略超帧周期的更新拆为两次的影响。

`--warm-enemies` 在原版生成敌人前解码首波图集，使两边的敌人以已知图集尺寸计算中心。原版冷加载时首只敌人的初始中心为 `(358.5, -110)`；先加载图集后为 `(382.5, -90)`，与独立引擎一致。加载等待不计入战斗时钟。

原版采用固定 60 Hz 且预加载敌人图集时，两套选敌设置的四组发射目标、命中顺序、伤害和结算均一致。每发的开火时间误差不超过 1 ms，完波时间误差也不超过 1 ms；个别命中时间仍相差约一帧。原版冷加载时，木守宫的一次攻击仍选中不同目标。带调度微差的原版时钟也仍有命中顺序差异。

`--speed=0.8` 等参数用于其他档位的固定速度对照。`first-wave-speeds.mjs` 顺序执行八档速度和两组默认选敌配置，并验证每次报告的截图摘要，汇总产物见 `.local/pokepath/verification/first-wave-speeds/result.json`。

报告保存在 `.local/pokepath/verification/` 下的对应 `first-wave-reference*` 目录，含规则版本、输入、完整轨迹、源码摘要和浏览器截图。

装备组合扩展保留四个基准场景，并为三只 1 级初始伙伴分别加入蛋白质、碳水化合物、锌、进化辉石和饱腹之香；再加入木守宫持肥料、呱呱泡蛙持作弊骰子、小火龙持瓦斯果冻，共 22 个连续整波场景。装备由固定测试存档预先拥有，两端仍通过各自真实装备规则校验；不把这组场景称作从零购买或自然成长验收。

`first-wave-speeds.mjs --items` 为这 22 组场景分别执行八档速度，并补充 0.8 倍和 1 倍速的原始默认选敌，共 220 个整波对照。每次使用独立运行目录，失败与通过的输入轨迹和截图不会相互覆盖。

扩展前固定失败边界：装备被静默丢弃、非法装备未拒绝、伤害加成取整顺序变化、射程改变导致首发时机或目标变化、攻击冷却的百分比与毫秒换算错误、肥料未改变伏击地形、作弊骰子仍弹射或伤害倍率错误、瓦斯果冻的毒与直伤被混同、饱腹之香读取时钟或整秒边界错误。逐项保留命中类型、金额、顺序和结算，不以最终金币相同代替过程一致。

历史规则版本 `75e9e4a9125e62ac6ef09508ed74b2fa1772b9be704c67da1092f1719cf5175b` 的 220 项已通过，完波误差不超过 0.667 ms。部分弹道命中时刻仍相差数帧，不能将命中顺序一致称为全程逐帧一致。独立的完整电脑百波验证通过；当时竞态套件单独覆盖 542 项。最初将百波验证与竞态套件合并时触发 Go 默认 10 分钟总超时，保留该记录及当时第 94 波纪录的状态，不能算作通过。

暴击扩展在原 22 组基础上，为三只伙伴加入后攻之尾、先制之爪和放大镜，为呱呱泡蛙加入节拍器，再分别执行测试夹具固定 0% 和 100% 暴击率，共 64 个整波场景。固定暴击率只用于两端相同的受控输入，不进入产品，也不能证明暴击随机流完全相同。先制之爪的强制目标不通过原本禁止的改目标动作设置。

扩展前固定失败边界：百分比装备加成在暴击前未取整、减半惩罚与增益混用舍入方向、装备提前改变原始弹道威力导致后续弹射衰减错误、额外目标顺序或强制最快目标被忽略。每次命中的暴击标志也须一致，不能只比较扣除生命后的相同金额。

`--coupled-jitter` 进一步对齐弹射随机输入。夹具从自写引擎本帧实际消耗的随机数中，核对新弹射的出生偏移，再把相同的两个随机值提供给原版两个出生偏移调用点；不传入目标、伤害或命中结果。找不到对应随机数、原版消耗数量不同或弹射已经跨多个子步移动时明确失败，不能反推新的随机值以匹配位置。当前出生观测只支持每帧一个规则子步的速度。

`first-wave-speeds.mjs --criticals` 在 0.4、0.8、1 倍速执行上述 64 组，并补充默认选敌的 0.8、1 倍速，共 320 组；包含原有基准。更高速度的多子步出生观测未纳入这组随机输入对照，不能据此宣称全部随机流或全部时刻一致。

规则版本 `b3cd09b2fbb30c9a128fdf2468245543e69cb9be1bc3a5578fae69093e57fb1b` 的受控 320 项和原装备 220 项均通过。受控场景的发射与命中时间最大误差为 1.667 ms，包含公开整数毫秒事件的取整；完波误差最大为 0.667 ms。未对齐弹射随机输入的 220 项仍有约 50.3 ms 的个别命中偏差。当时独立竞态回归 556 项通过；正式初始 50 金币、1 级伙伴的完整电脑百波验证耗时 452.06 秒，以 2 点生命完成，执行 12109 次合法行动。
