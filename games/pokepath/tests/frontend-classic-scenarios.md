# 原版视觉对照

界面仍由独立 React 与 Canvas 实现。对照固定版本的中文原版画面，复现像素布局、图片、字体、颜色与操作层次，不加载参考程序。

参考文件位于 `.local/pokepath/reference-visual/`：`initial-chinese.png`、`placement-chinese.png`、`deployed-chinese.png`、`details-chinese.png`、`shop-chinese.png`、`box-chinese.png`。几何测量由同目录 JSON 记录。

实现前明确检查：

- 1238×674 逻辑场景；左栏 259 px，中间 720×624，战场起点为 (259, 25)，右栏 259 px。
- 初始 10 张编队卡，前 6 张可用，后 4 张按 40／160／320／540 星解锁；不额外显示人物编号。
- 菜单使用 9 个红底图标；商店、仓库等只覆盖中央战场，左右栏保留。
- 详情使用全场暗幕与 608×578 外框，技能与道具分组，提供 1／5／10 级费用。
- 字体实际加载默认 PressStart2P（稳定原站证据已纠正早先 NGC 研究配置）；头像、生命、菜单、单位图片实际解码后才确认就绪。
- 桌面按场景整体比例显示；320 px 使用同一视觉语言重新排布，图标、按钮和实际塔身可触。
- 部署、升级、目标选择、商店与仓库操作使用稳定拥有者 ID；两席的选择和窗口互不覆盖。
- 未部署与已部署按钮分别使用真实关闭／打开的精灵球图案，并保留完整渐变底色；图案按素材清单校验和加载，不能部署后只剩空白红按钮。

结构检查入口：`node --test games/pokepath/tests/frontend-classic.test.mjs`。最终效果必须另用真实浏览器截图、几何与像素对照验证，结构检查不代表已达到视觉一致。

后续交互失败场景：轮抽中的候选 ID 必须解析为已拥有宝可梦；未选项、过期 token 和观战按钮不能提交有效选择；成长操作只展示服务端投影的资格；道具装备值 0 表示未装备；字体与透明度选项必须符合服务端允许值；隐藏机关以服务端热点命中，不能由客户端直接授予内容。面板图片按需校验后解码，不把未校验的图片字节作为画面素材。

素材解码验收固定使用平台相同的 `img-src 'self' data:` 策略。先验证 blob 图片会被浏览器拒绝，再将已经校验的字节编码为 data URL；不可放宽公共 CSP。

富文本只将已知语义标记映射为 React 文字颜色，不解析 HTML。嵌套、缺失闭合和未知标记不能执行标签或脚本；关闭彩色文字后须保留文字内容。

快速选择层：空编队格只列已拥有的仓库 UID；装备层使用单只只读查询给出的合法道具 ID，不能按名称或下标提交；空列表、观战、已装备和无道具卸下按钮均须可验证。选择层只占所属编队卡，不关闭其他玩家窗口。

语言补验：切换英文及另一语言后，React 菜单、名称、描述和教程必须真实换词；规则标识、表单值、样式、用户自定姓名不可被翻译。词典只读取原版静态多语文案，不执行原 JS，也不修改 DOM 来替代 React 状态。

精灵动画使用独立显示时钟；改变物理速度不改变播放帧率，每个新实体从第 0 帧开始。普通弹道按实际目标方向旋转并使用原 5 px 发光；烈暴风按真实不旋转图集绘制。实体动画相位属于 Stage 展示状态，不写规则快照。

飞行指针输入先登记：仅可控玩家选中的已部署 blimpKeys/unburden 接收地图绝对目的地；空闲鼠标按 50 ms 合并，触屏点按 edge 不丢；地图拖动、滚轮、取消、离开、第二根手指和观战不得误发。延迟回调再次检查 epoch、席位权限与稳定 UID，不能晚到后控制新房间。

训练家页面补验：`ProfileScene.js` 按 `allPokemon.length - 1` 显示拥有、色违与总等级上限；视图仍提供完整图鉴总量，界面按同一公式格式化。初始姓名显示为空输入框的现有姓名占位，左右头像按钮使用原版 `<`／`>` 字形；不能用参考图中未加载的成就图片反向隐藏正确素材。
