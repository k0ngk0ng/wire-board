# 战斗规则时钟验收

- 1 倍速下，60 帧规则恰好用 1 秒。整数毫秒接口在累计收到 17、34 和 50 ms 时各越过一帧，公开的规则时间保留已完成帧的整数部分。
- 同一段时间按单块、网络批次或小块推进，战斗状态逐字节一致。快进时一次真实帧可以处理数个规则小步，每步时长相等。
- 保存正在移动的敌人与不足一帧的时间余量。恢复后切换到另一速度，结果须与同样切换速度的连续对局一致。
- 暂停保留规则快照，恢复不补算离线时间。展示层以真实帧序和余量插值，不能从旧的 20 ms 网格推断帧序。
- 原版浏览器对照分别记录实际发射、命中、结束时间和结算。规则帧对齐不等同于所有能力、碰撞或原站不同刷新率下的行为均已一致。
- 默认 0.8 倍速在真实的第一帧仍推进一次规则；1.2、1.7 和 2.5 倍速分别把每个真实帧等分为 2、2 和 3 步。每步不超过 `1000/60 ms`，不能改成按固定战斗步调整更新次数。

```sh
. scripts/env.sh
go test ./games/pokepath/engine -run '^TestCoreSixtyHertz' -count=1 -json
node games/pokepath/tests/first-wave-reference.mjs --ideal-60hz
node games/pokepath/tests/first-wave-reference.mjs --ideal-60hz --warm-enemies
node games/pokepath/tests/first-wave-speeds.mjs
node --test games/pokepath/tests/prediction-session-e2e.test.mjs
```

独立规则用 `1/180 ms` 的整数单位保存模拟时间。每个真实帧长 `3000` 单位；缩放后按速度向上取整得到小步数，再等分缩放后的时间。真实帧序、模拟时间、小步长度和不足一帧的真实时间分别保存在快照中。预测读取真实帧序与真实余量，移动和冷却使用当前小步的完整分数。平台仍以毫秒记录输入、服务器时钟和加载门槛。

速度矩阵比较八档速度下的 32 组首波，以及默认 0.8 倍速和 1 倍速下保留伙伴默认选敌设置的 8 组首波。共 40 组场景的发射目标、命中顺序、逐击伤害与结算一致。原版参考运行在固定 60 Hz，敌人贴图在生成前加载。报告记录每组的最大开火、命中与完波时间偏差；通过不代表这些时间都完全一致。

技能测试把冷却阈值与实际扫描帧分开。例如，普通光束的单目标冷却为 140 ms，在 1 倍速下首个可命中扫描是第 10 帧：累计收到 166 ms 时无伤害，收到 167 ms 时伤害已经结算。这两项与光束宽度、最大长度、存档和终止断言分别验证。
