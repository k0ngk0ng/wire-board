# 原生截图帧的响应时间

原有测量用截图请求返回时间作为保守上界。上界超过预算时保留原始记录，不把它当作实际可见延迟，也不直接判定通过。新的观测使用 Chrome 原生 `Page.screencastFrame` 图像与帧交换时间，保持 100 ms 的验收预算。

校准页仅验证测量器，不能代表游戏性能。预先覆盖以下失败情形：

- 原生点击后立即改变控件，应识别实际变化帧。
- 控件故意等待 250 ms 后变化，必须超出 100 ms 预算。
- 控件不变化，不得返回通过或用 ACK、内部绘制通知替代截图。
- 焦点框和按下阴影单独变化时，不能当作操作效果。保留控件整体截图，并在内缩 6 CSS px 的内容区域检查结果像素。
- 颜色渐变的首次响应不能被当作渐变完成时间。结果像素须至少有一个 RGB 通道增加，或具有无法由等比例亮度变化解释的色彩残差。逐帧要求所有 RGBA 通道处于基线与目标之间，且至少一半的结果像素提供沿目标方向移动的证据。无此类证据时仍用稳定目标图像，不能直接放行。
- 用即刻与延迟 250 ms 的图标变化分别校准，避免把按下时旧图标的位移算作新图标出现。
- 结果颜色的所有 RGB 通道都下降时，分别验证立即变化、延迟 250 ms 和不变化。独立的等比例按下变暗持续 150 ms，不能作为结果证据；非等比例颜色变化须在渐变开始后 100 ms 内识别，不能等待渐变完成。
- 原生帧消息额外延迟到达时，分别保留帧时间和接收时间，不把接收等待加入可见延迟。
- 缺少点击、时间域错误、缺少帧时间、无效图像或裁剪越界时，明确拒绝测量。
- 被测控件位置与帧尺寸不兼容时不能猜测坐标；比较实际解码像素，保留帧和裁剪图及摘要。
- 不主动驱动渲染帧、不降低游戏刷新率、不改变网络延迟或输入确认条件。
- 截图解码、裁剪和结果 PNG 编码在浏览器外执行，分析阶段不得向游戏页面提交图像或调用页面求值。用 Chrome 自己解码的基线与最终帧核对离线裁剪 RGBA；保留原始 PNG，不改变图像精度。拒绝损坏、截断、无效签名、非 8 位 RGB／RGBA、隔行 PNG、校验错误及越界裁剪。

色彩残差使用当前像素与按 RGB 总和等比例缩放的基线之差。目标残差至少为 4 个通道值，当前残差至少为 2 个通道值并与目标同向，各通道只允许 1 个值的舍入误差。这个门槛用于排除按下时的等比例变暗，不代表对任意界面的通用响应检测；缺少可区分的颜色或图标证据时保留稳定目标回退，并报告保守上界。

帧消息的 ACK 在接收通道立即发出，解码和观察回调晚到均不得阻塞下一张原生帧。延迟回调场景额外等待 250 ms，只改变记录到达时间。
