# 规则修订摘要验收

实现前登记失败场景：

| 场景 | 预期 |
| --- | --- |
| 任何引擎产品 Go 文件新增、删除或行为变化 | 对全部产品文件规范化后更新规则摘要，服务端与 Wasm 使用同一常量 |
| 仅 Go 空白、测试或摘要文件自身变化 | 空白按 `gofmt` 归一；测试和摘要文件自身不进入引擎输入，避免自引用 |
| 生成文件被手改、规则源码或客户端地图变化后未重建 | `--check` 非零退出，不能使用旧规则身份继续构建 |
| 全量目录、核心目录或单图字节变化 | 在完整目录和客户端数据清单中更新独立 SHA-256，不用研究输入摘要冒充程序摘要 |
| 公共清单自引用或重建顺序循环 | 客户端数据摘要只覆盖核心和单图；规则修订清单再由资源索引引用 |
| 重复生成 | 生成字节相同，不改写无变化文件；清单只含路径、大小、摘要和版本 |
| 指定工作区外路径或符号链接逃逸 | 拒绝写入 |

命令：`node games/pokepath/build/rules-revision.mjs`，新鲜度检查为 `node games/pokepath/build/rules-revision.mjs --check`。机制测试：`node --test games/pokepath/tests/rules-revision.test.mjs`。只有最终规则和数据落稳后生成的摘要，才能用于完整对局验收与发布。
