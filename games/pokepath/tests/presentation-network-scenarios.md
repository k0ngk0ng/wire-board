# 正式浏览器呈现与网络验收

场景在网络夹具实现前固定；开发观测仅用于定位问题，不作为最终通过记录。使用真实认证主平台、独立 Go/Wasm 与实际 Canvas，所有浏览器带 `--mute-audio`，平台 `wb_sound=off`。

| 场景 | 失败边界 |
| --- | --- |
| TCP 延迟夹具 | 每方向固定传播延迟，不按数据块累计；字节顺序和半关闭保留；只允许本机地址；断线后丢弃旧缓存；积压使用有界背压 |
| 普通双人 | 运动中的原生 RAF p95 ≤25 ms；实际像素更新 ≥55 次／秒；原生点击到首个变化截图上界 ≤100 ms；静止段单独记录，不用于运动帧率 |
| 快慢双席 | 慢端双向传播各 120 ms，实际 Ping/Pong RTT ≥200 ms；快端继续推进；慢端原生点击像素响应上界 ≤100 ms 且先于 ACK；不能用 HTTP 耗时替代 RTT |
| 单端短暂中断 | 普通双人及快慢端的战斗采样保留实际塔。进入断网场景前通过真实收回操作移除塔，记录操作前后位置与资源，避免正常击杀清空运动对象；暂停慢端收发 1500 ms，快端至少 1000 ms 的可见运动仍达到原预算；恢复后使用有效权威状态，真实席位未自动托管，待确认输入不无限增长 |
| 断线与重连 | 断开慢端 TCP，销毁旧缓存；重连保持房间、资源和控制代次，旧输入不补播 |
| 连续输入 | 原生快速点击按服务器顺序执行；有限窗口可拒绝超额输入，但不得重复扣费或失去后续控制 |
| 协议记录 | 分别保留 RAF、实际像素、规则成本、输入 ACK、协议 RTT、权威帧与消息字节；普通同步不带静态地图、完整历史或每帧存档 |
| 正式密集实践 | 先由测试夹具为独立账户准备已拥有编辑器书籍的有效存档，金币仍为 50、伙伴仍为 1 级；默认账户不得出现编辑器入口。再经真实路线面板、编辑器输入建立 200 敌人的实践房；实际运行与绘图沿用主平台，保持同一 ≥55 次／秒运动像素与 ≤100 ms 点击预算；明确区别于自然通关与纯复制合成负载 |

TCP 夹具验收：`node --test games/pokepath/tests/presentation-proxy.test.mjs`。正式页面测量：`node games/pokepath/tests/presentation-browser.mjs <owned-cdp> <owned-url> <label> 8000 0 '.pokepath-classic-controls .pause'`。延迟由独立 TCP 夹具施加，不依赖浏览器对 WebSocket 的 HTTP 节流设置。

截图测量在原生输入前启动被动原生帧捕获。逐帧保留完整 PNG、控件裁剪、RGBA 摘要、帧交换时间和接收时间。用输入前最后一张截图与输入后截图比较实际像素，按帧交换时间确定首次可见变化的上界；接收等待单独记录。图像解码在 RAF 采样停止后执行。原有请求返回上界保留为历史记录，不以内部绘制通知、ACK 或降低阈值代替截图。

运动帧率按配置的独立采样窗口记录，随后单独记录原生输入和截图。PNG 捕获、消息传输及解码的额外时间不计入帧率窗口；输入响应仍使用捕获中的真实帧。每份结果保留两个窗口的实际长度。解码、裁剪与 PNG 编码必须在浏览器外执行，避免把大图像表达式、微任务和垃圾回收留在游戏渲染主线程中，干扰下一个场景。

已有原生 PNG 可脱离浏览器复核：`node games/pokepath/tests/presentation-audit.mjs <source-report.json>`。工具先校验每张原图的 SHA256，再按原生帧时间与相同规则计算结果，输出原报告路径和摘要。复核不等于重新执行游戏场景。

测量器先通过[原生截图帧校准](pixel-response-scenarios.md)，再在正式房间使用。故意延迟 250 ms 的控件必须仍超过 100 ms 预算，消息晚到不得改变截图帧的采集时间。

正式测量前，至少一名可见存活敌人的剩余路径时间须覆盖测量窗口及准备余量。最后一名敌人即将离场时等待真实波次结束，再通过原生「下一波」操作启动后续波次。没有运动像素的测量无效，不能用稳定 RAF 代替，也不能据此推断慢端阻塞了快端。
