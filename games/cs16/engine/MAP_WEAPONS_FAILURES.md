# 原图武器实体失败场景

本清单和对应 E2E 先于实现。来源为固定 ReGameDLL_CS `weapons.cpp:2516–2622` 的 Armoury Spawn／Restart、`weapons.cpp:2650` 的武器弹药表及 `weapons.cpp:2689` 的 Touch。`fy_iceworld` 的 24 个原始 `armoury_entity` 覆盖 12 类主枪，每实体 count 为 1；其他地图只按各自原实体配置生成。

- 原实体 ID、item、武器 ID、坐标、角度和数量须保留；重复初始化不得累积复制。未知／不一致的武器元数据不能生成可领取物品，源 count 小于等于 0 时按原版归为 1。
- 原 MOVETYPE_TOSS 武器在初始化时从原坐标向下检查实际地板；地图规则元数据保留原始坐标，动态 Drop 保存实际落地点。
- 原武器无需 E，通过 Armoury 盒 `(-16,-16,0)..(16,16,16)` 与玩家实体盒相交拾取。站立、蹲伏、四角、垂直边界及相邻定点整数须分别验证。
- 任意已有主枪时不能消耗另一原主枪实体；CT/T 均可触碰原图枪，不能套用商店队伍购买限制。
- 弹匣须满；备弹按源表给予：多数 60、P90 为 50、AWP 为 20、M3/XM1014 为 24；与已有同弹种的弹药池相加并按上限同步，不能覆盖或复制已有备弹。
- count 大于 1 时每次成功拾取只减 1；多人争抢 count1、同席位重复触碰、JSON 恢复后的剩余数量及下一回合刷新均不能复制物品。
- 每个运行时 Drop 保留 SpawnID 和 Remaining，耗尽的实体从投影移除；每回合从不可变原实体配置恢复初始数量。
- 普通掉枪继续 E 拾取且保留原有弹药；E 不能绕过原 Armoury 自动触碰流程。地图无世界枪时沿用既有行为。
- 普通动态掉枪最多 64 件，淘汰时不能挤掉仍可拾取的原图静态枪。
- 死亡、结束、非法席位不能触碰；电脑只在没有主枪时选择可领取原图枪作为导航目标，目标坐标使用实际落地点上方的玩家中心。

此层使用轻量原规则夹具验证；实际新图实体解析、地形可达、正式十人完整对局与浏览器模型另由集成验收覆盖。记录统一保存 `.local/cs16/verification/map-weapons-*.jsonl`。
