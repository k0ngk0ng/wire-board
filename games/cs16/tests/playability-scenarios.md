# 试玩反馈修复验收

实现前登记以下失败场景，保留真实 HTTP、浏览器原生操作、像素和截图产物。

- 默认十席房间只有 2、3、6 人时开始按钮禁用，或前端放开后服务端仍按十份队伍配置拒绝开局。
- 开局裁剪空席时丢失实际玩家的阵营、角色、友伤或地图设置；单方无人或某队超过五人仍能开始。
- 少人数对局返回等待后无法修改地图，或新增玩家后不能再次开始；扩展空席须保留原参与者的选择，并为新席位补齐合法阵营与角色。
- 空席显示成五名队员，阻止真人换队；队伍卡片不含 T／CT、真实人数、玩家状态或明确的加入入口。
- 平台名称残留「1.6」，创建、等待、玩法速查与服务端登记不一致。
- 浏览器暂时拒绝鼠标锁定后弹出泛化错误，下一次可信点击无法正常重试；触屏错误触发鼠标锁。
- 原始线性光照被标为 sRGB，血战回廊暗部再次衰减；修正后丢失纹理或把其他地图高光全部截白。
- 枪口使用没有 alpha 贴图的整块矩形；只扣弹而没有火光、短暂弹道、墙面弹着点或权威人物命中反馈。
- 火光和弹道从固定屏幕点出现，未跟随原模型 attachment、骨骼动画和持枪镜像；滚动后的截图裁剪到页面顶部，不能作为战场视觉证据。
- 每次射击分配永久对象或逐帧新纹理，手机开火时持续增加绘图与内存负担；短暂特效必须有界复用并按时隐藏。
- 首次显示隐藏的火光、弹道或弹着点时才编译 GPU 程序，首次开火出现长任务。正式验收须包含首枪，不能通过提前射击或丢弃首个样本规避；所需程序与纹理应在提交加载就绪前准备。
- 手机换枪仍在右侧或底部中央；右拇指被密集按钮挤占；次要操作收起后无法访问。
- 可选瞄准区开火模式误把左侧移动、换枪、菜单或跳跃点击当作射击；右侧按住拖动可瞄准开火，松手必须立即释放，并保留默认独立按钮模式。
- 左侧换枪与移动互相遮挡，右侧开火、瞄准、跳跃、蹲下抢触点；横竖屏和全屏下越过安全区或低于 44／64 px 命中尺寸。
- 真实原生事件只改变内部坐标而未改变像素；已测键鼠、触屏、帧率和慢连接门槛被放宽。
- 慢连接发送窗口占满时，固定等待 60 ms 后读取最后一条已发消息，把正常排队误判为触点未释放。松手须分别验证下一显示帧的本地触控状态，以及有界等待后的实际网络操作；不得用网络发送时间代替本地操作延迟，也不得删除任何已测像素样本。
- 浏览器把触摸移动合并到显示帧后才分发 PointerEvent，排队时间接近 46 ms，使触屏到像素超过 51 ms。支持原始指针更新时优先接收该事件，不重复消费普通移动；不支持时继续原 PointerEvent 路径。原始事件的创建时间、排队和像素响应须纳入同一验收。

默认十席开局覆盖真实 HTTP 的 2、3、6、10 人，以及实际真人换队、房主管理电脑、满队拒绝和双方至少一人。浏览器覆盖桌面与 320 px 触屏的队伍布局、左侧换枪、双指移动开火、展开次要操作、线性光照和连续射击可见效果。实体手机仍须单独记录，不将 Chromium 模拟称为实体硬件验证。
