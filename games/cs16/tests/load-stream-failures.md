# 多房间负载客户端读取边界

网络负载测试须持续读取 WebSocket。同步采集其他房间的 HTTP 状态时，不得停止消费本人权威帧，否则下一条操作会携带过期参考帧，错误触发服务端 500 ms 传输年龄保护。

验收失败场景：

- 发送线程在第八次操作确认后暂停 650 ms，期间仍须消费权威帧；恢复后的操作必须使用新帧并取得全部 40 次确认。
- 首次输入前消费 WebSocket 权威快照，首次四房间 HTTP 采样期间同样保持读取，不能只在后续输入循环中持续读取。
- HTTP 房间采样与输入流并存，不得导致读取循环停止或丢失射击事件、消息大小和确认计时记录。
- 连接关闭、上下文超时或消息解码错误必须结束读取并传播失败，不能丢弃错误或无限等待。
- 慢观战者仍保持不读取，其他四个房间继续推进；不改变普通性能用例原有确认和时钟延迟预算。
- 序号、生命代次、对局身份与服务器过期校验保持有效，不通过放宽阈值或重试过期操作取得通过。
- 四十真人的非性能正确性用例允许服务器明确拒绝排队超过 200 ms 的输入，但只接受 `ack`、状态 `400`、精确原因“操作排队已过期”、`durable: false` 和有效 nonce 同时成立的响应。记录拒绝数量及确认耗时，并发送下一序号的新操作验证恢复；不重试旧操作。
- 普通性能用例对上述拒绝仍须失败，未知原因、错误状态、缺失持久化标记、非确认消息及不完整响应均须失败。
