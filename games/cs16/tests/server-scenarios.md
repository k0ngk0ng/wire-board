# CS 1.6 服务端失败场景

本清单先于服务端实现及测试编写。生产模块与真实 HTTP／WebSocket／SQLite 路径是主要验收边界。

## 设置与席位

- 少于 2 或超过 10 人；非整数人数；队伍超过 5 人或缺少对手。
- 未知地图、非整秒回合、非法局数、队伍与人数不一致、造型与队伍不符。
- 重复 JSON 字段、未知字段、null、尾随 JSON、超大请求。
- 非房主改地图或赛制；修改其他真人的队伍或造型；借助电脑席位参数越权。
- 选队时保留原造型导致跨队造型；队满后仍然切换；准备失败部分修改设置。
- 队友误伤仅为房间布尔规则，默认关闭；null、数字、字符串、重复键不得当作有效 bool。非房主不能改，开局后不能修改冻结规则，不增加个人设置或其它未授权 cvar。

## 输入与权威

- 旁观者、失效 epoch、旧生命、重复或跨过上限序号、未来参考帧。
- 超范围移动或视角、伪造位置／生命／命中／资金、未知输入字段。
- 服务端排队过期、短按被持续输入覆盖、收到即错误当作规则已应用。
- 可靠连接传输中阻塞后，旧 fire press／release 在同一生命重新执行。服务器签发帧参考的传输年龄上限 500 ms，与收到后执行排队 200 ms 分开检查，覆盖 500／501 和 200／201 ms；只清理的 cancel 仍验证代次、序号和执行排队，不因旧画面而无法释放。
- 手雷拉栓后失焦取消却投掷、取消耗雷、旧 pending 在取消后重播；普通松开误取消投掷。cancel=true 必须全释放，仍验证 epoch／life／seq／排队年龄，托管时只允许此清输入动作。
- 真人死亡仍然攻击；断线或接管后旧输入继续开火；过期输入在新回合重播。
- 购买跨越队伍、时间、区域、资金或容量边界；重复请求重复扣钱。

## 投影与恢复

- 高频投影泄漏完整地图、输入队列、随机状态、历史命中盒、其他人的库存和资金。
- 事件游标跳过未读事件、重复发送旧事件、超出历史窗口后静默丢失。
- 恢复改变 epoch／开局时刻／回合分数，重播旧音效；重启自动托管真人。
- 恢复重复传输已经由 CDN 校验加载的静态碰撞／surface／导航地图；恢复应只含动态投影、mapId、rulesSHA256。规则摘要必须与后端实际规则相同，篡改／过期摘要不得继续运行。
- 全局爆破公告用事件 XYZ 绕过位置裁剪；旁观者通过 buy 事件得到私有资金和背包；T 通过 Bomb.Defuser／DefuseAt 看见隐藏拆弹进度。
- 旁观者恢复取得本人预测私有状态；错误地图或结构版本继续运行。
- 阵亡玩家仅用尸体视线导致队友摄像机缺少敌人；误用敌队视线；本队全灭后仍泄漏活敌人位置。阵亡观战权限为本队存活队友视线并集，独立旁观者可看全场。

## 比赛与性能

- 四图、10 席电脑仅耗尽时钟而未实际战斗；爆破／营救无法结束。
- 回合结算重复、胜队映射错席位、平分错误记录双方获胜、含电脑仍然计分。
- 一个慢 WebSocket 阻塞正常端与权威帧；高频输入拖慢其他房间。
- 每帧完整地图或无限事件历史造成负载持续增长。

测试执行后保存 `.local/cs16/verification/server/` 的 JSON 结果、初始与结束身份、席位数、输入／事件数量及网络投影字节数。通过项不代表未执行的浏览器或原版轨迹验收通过。

新增同服务验收预算在测量前冻结：4 个十席正式 HTTP 房间并行，一个旁观 WebSocket 接收缓冲限制为 1024 字节且不消费消息；正常连接的输入 ACK P95 不高于 100 ms，采样权威规则时钟落后 P95 不高于 100 ms，各房间持续前进，旁观慢连接不触发真人自动托管。此 ACK 预算不替代原生输入到画面的浏览器预算。

十真人连续输入容量在同一既有房间／连接上补一秒每席 100 次 yaw 更新。每连接最多 8 个在途，独立读取 ACK 与权威 frame，不在每包前通过 HTTP 取状态。必须发出并确认 1000 条、合计完成速率至少 800 条／秒、ACK P95 不高于 100 ms，持续输入期间规则时钟不能停止，结束后所有 appliedSeq 追上。窗口等待、真实发送数、完成时间与时钟样本均保存；不足则保留真实失败并分析，不能放宽窗口或提高采样频率掩盖。

## 自动席位回调优化的预先失败清单

- 批处理直接写位置、命中、资金或得分，绕过普通 `QueueInput`／`Buy` 规则。
- 批处理和逐席位 `BotAction`＋`Apply` 的队列、购买、序号、事件顺序或推进结果不同。
- 对真人席位也生成自动操作；取消托管后仍残留下一次自动输入。
- 因为减少回调而减少 100 Hz 规则、碰撞、命中历史或网络负载采样。
- 更改外层采样周期与 BotInput 的席位相位冲突，使部分电脑永久复用旧输入。
- 长时间停顿时机器人在旧世界提交主动操作，阻塞权威时钟追赶。

优化须先通过与原普通操作路径逐帧字节等价的生产模块 E2E，再以相同负载和阈值复测；CPU profile 与前后源摘要一起保存。

## 历史懒解码与未变投影快路径的预先失败清单

- 控制输入、普通投影跳过历史展开后，重新保存遗漏／重排／修改历史命中盒或门状态。
- OnTimer 没有在规则推进前完整还原历史，影响回溯命中；回合切换把上一回合 raw 历史重新拼回。
- 既有 JSON 存档格式无法读取，或输出改变类型；无效历史被当作空历史继续推进。
- header-only 判断忽略 epoch、viewer、brush、权限、catchup、规则摘要或数据格式而错误跳过。
- 优化结果与正常逐动作路径的世界状态、队列顺序或新帧结果不同。

仅 OnTimer／战斗需要展开历史；持久化仍保存完整原格式，不删除历史、不降低规则步或碰撞。用完整旧格式读取／重写、逐字段历史保真和相同后续推进结果验证。

历史 brush 副本仅在全 engine 无读取、回溯目标只取 Players 且门／穿透按当前 Brushes 的证据下省略。测试必须覆盖当前门开／关与相反历史门状态的射击结果一致；32 帧 Players／Frame 完整保留，当前门状态不能删除。旧格式 brush 字段继续可读，新写入只清无读取用途的副本。

## 网络投影复用的预先失败清单

- 首包、恢复或新 epoch 没有完整 brush 状态，导致客户端错误使用旧地图／门／可破坏物状态。
- brush 未变化却重复发送整表；brush 变化或回合重置时错误省略；空表无法清空客户端缓存。
- 游标属于另一局、未来帧、未来事件或格式损坏时静默跳过。
- 相同帧与事件下权限／追赶状态变化被 Unchanged 吞掉。
- 普通已接收但尚未应用的输入触发重复全状态；为了减少重复投影而延迟 ACK。
- 输入或接管每次重新延后规则 deadline，让高频鼠标输入推迟服务器规则步。
- 客户端断线后仍复用另一 epoch 的 brush；手机缓存与 WASM碰撞使用不同状态。

先验证每连接游标与初始／恢复语义，再测十席活跃消息数量、每秒正文大小与独立 ACK。原延迟阈值保持不变。

## 仅排队输入通知的预先失败清单

- 普通已接受输入只改变待执行队列却唤醒全房间十个连接，最终每端都返回 Unchanged。
- 声明延后通知后连 ACK 也延后，客户端等待才采样；或短按被合并／丢失。
- buy／cancel 或关键阶段、结果、checkpoint／公共权限变化被错误延后。
- 未声明能力的旧模块行为被改变；没有 realtime／OnTimer／StreamView 的模块错误启用。

CS16 只对已经成功 Apply 的普通 type=input 且 cancel=false 声明仅排队。原有有序 QueueInput 和 100 Hz 规则完整保留，传输 ACK 立即，下一原有规则帧发布实际应用序号与投影；buy／cancel 仍立即发布。
