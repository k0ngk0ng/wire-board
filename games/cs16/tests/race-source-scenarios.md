# race 四房真人夹具的预先失败清单

- 40 个独立模拟真人共用一个回环源地址，真实注册入口被单 IP 限流正确拒绝，却误判为游戏并发故障。
- 为使夹具通过而关闭限流、绕过注册／登录写用户、信任生产转发头、改队列 200 ms 期限或降低普通性能预算。
- 同一模拟客户端 HTTP 与 WebSocket（包括自定义慢接收 Transport）被识别为不同源，或多个客户端仍共用源。
- 客户端伪造的 Forwarded／X-Forwarded-For 改写测试端口固定来源；源地址模拟泄漏到生产 Handler／配置。
- race 正确性房间仍包含电脑，或把四房 40 真人仅少量真人发送输入声称成 40 人高频容量认证。
- 修改 race 夹具同时改变普通四房每房 1 真人加 9 电脑或原 count=4／10 的 HTTP 夹具。

独立来源只由专用 httptest 入口包装设置：41 个测试端口共享同一真实平台 Handler，各端口固定不同的文档示例 IPv4 地址；40 个账号加 1 观战者继续经过真实注册／登录、HTTP 和 WebSocket。先通过真实 HTTP／WebSocket 往返验证端口源身份一致且不信任客户端转发头，再跑 race 四房 40 真人正确性与普通四房 4 真人加 36 电脑性能。分别保留参与组成、源身份方式和测试结果，不把 race 数据用作耗时认证。
