# 首版真实浏览器验收

本清单和验收脚本先于浏览器验证建立。入口为 `python3 -B games/cs16/tests/accept_browser.py`，使用生产 `web/dist`、真实 HTTP、SQLite 和 WebSocket；两个真人浏览器加八名电脑组成十席，另开一个观战浏览器。不将桌面触屏模拟称为实体手机实测。

## 失败场景

- 生产构建、资源清单或任一地图、模型、贴图、WASM 缺失；资源错误却提前就绪。
- 六张经典地图、24 种枪械、8 个角色未完整登记；所有选择只有文字而无实际模型。
- 十席无法创建、队伍超过五人、机器人未进入同一权威比赛。
- 队友误伤默认开启、创建／等待未显示规则、非房主可以修改，或开局后规则与等待选择不一致；只对炼狱小镇开启一次并自然完成一回合，不扩展伤害矩阵或注入伤害。
- 大厅或等待房间在 320 px 横向溢出；公共玩家栏关键信息不可见。
- 普通、原生全屏和网页全屏切换重建画布或对局；游戏文字、触屏操作和长按产生原生选区或菜单。
- 真实键盘、鼠标相对位移、触屏没有立即改变画面；仅 ACK 或内部坐标变化被误记为像素响应。
- 移动、转头、攻击的短按被覆盖；两指输入互相松开；失焦、断线或隐藏后仍保持攻击。
- 后台释放计时误用冒泡到窗口的元素失焦事件；仅以真实窗口失焦或页面隐藏的可信原生事件时间戳计算中立输入发送延迟。
- 原生触屏事件排队、像素读回和主线程长任务混为单一延迟；保留每个样本的原生创建、派发、实际 GPU 读回完成时间及长任务，不修改既定总延迟门槛。
- 像素观察器每帧三次同步 GPU 读回增加测量开销；优化后若减少原三块 16 × 16 像素、去掉重叠区域的重复计数、改变逐像素顺序／哈希、分配每帧大缓冲或修改 GL 状态，也必须失败。仅 canvas 尺寸改变时重建采样计划与读回缓冲。
- 原生输入结束后的首次手机截图由另一 CDP 会话恢复浏览器 surface 默认宽度，导致 320 px 视区变成 500 px；须在完成测量后，由截图所在会话显式固定手机尺寸并等待实际绘制，保留原布局和时延门槛。
- 全屏截图沿用浏览器 surface 尺寸而裁切模拟手机画面；截图显式使用当前视区裁剪，记录同一 CDP 会话的布局。
- 全屏模式属性已更新但第一绘制帧尚未完成时，立即断言 HUD 重叠；或改为持续等到重叠消失而掩盖稳定布局错误。固定等待 3 个动画帧且确认实际完成至少 3 次绘制，保留第 0、1、3 帧的矩形与 CSS 避让值，再执行原无重叠断言。
- 手机左指移动、右指按住主开火按钮拖动时，不能同时转向与射击；主开火目标小于 64 px，关键操作小于 44 px；松开任一手指错误取消另一手指。
- 手机蹲下切换短按后不能保持或再次短按不能站起；失焦、断线后保留过期攻击和移动。
- 手机购枪长列表无法通过原生触摸滑到装备／弹药底部，滚动被战场手势拦截，或滑动误购商品。
- PC 原版 Q 切回上一武器、滚轮换枪和数字槽位失效，或为了手机操作改动键鼠含义。
- 本地预测无权威应用确认、普通确认反复重建时间轴、重连重播旧输入或音效。
- 一端高延迟、受限带宽或断线时，正常端时钟、帧率或输入被拖慢。
- 主动托管／手动接管重置生命、回合或比赛；断线擅自自动托管。
- 阵营购买限制、资金不足、当前阶段或位置不合法时仍能购枪；枪械选择后画面和权威武器不一致。
- 爆破图与人质图的规则阶段、胜负提示和结算不一致。
- 十人自然对局不能结束，或含电脑对局仍计竞技积分。

## 六图扩展失败场景

- `fy_iceworld` 或 `cs_bloodstrike` 只出现在地图按钮中，资源清单、实际加载、视区或权威地图 ID 仍只有原四图。
- 无筛选正式运行只完成原四图却报告通过；未核对实际 case 数、唯一地图 ID 和每张新地图的必要子场景。
- 根据地图文件名前缀猜测目标模式；未依据原 BSP 实体与引擎登记确认爆破、人质或纯歼灭目标。
- 将 Dust2 的 800 资金、购买 Deagle、阵营禁购、AWP 不足款或备用弹药假设直接用于新图；原图地面武器与禁购区没有通过正式拾取和购买规则验证。
- 验收通过写入位置、武器、弹药、资金、生命或胜负准备新图；测试必须使用正式出生装备、原图拾取、合法购买和原生输入。
- 新地图只验证一种控制方式；每图必须有十席的真实 PC 键鼠与 Chromium 模拟触屏，保留原预算、真实像素变化、两指移动转向开火和权威应用确认。
- 新地图中近距离战斗导致手动样本期间死亡或换回合，却将不同行动者或生命的响应、弹药和应用序号混为一次成功操作；必要准备必须确认同一 epoch、life 与可操作阶段。
- 中断触屏尝试后 CDP 仍保留旧手指，导致下一生命出现悬空按压、旧指 ID 冲突或无法释放；每次驱动退出均发出真实全指释放。
- 新图因缺少备弹不能换弹，或 CDP 观察器缺少旧字段时误认已有备弹；按确认后的地图规则准备，仍用真实原始 WebSocket 确认效果。
- 每张新图缺少 250 ms 慢端与同时正常端的输入、权威时钟、真实原始 WebSocket 包量证据。
- 每张新图没有十席自然终局或密集交火；两名真人须显式开启托管后由正式规则和八名电脑完成，不能通过结束牌桌操作伪造自然结算。
- 原四图的购枪目录、原生输入、友伤回合、全屏、后台、恢复、慢端和 Assault 自然结束覆盖被新地图分支跳过或放宽。
- 六图扩展后的八组新增原生操作、合法死亡等待和两场自然比赛仍共用旧 25 分钟夹具，导致各场景尚在原有允许期限内时被容器总生命周期强停；Go 外层超时还须晚于夹具期限，保留正常退出窗口。

两张新地图的模式、原版出生装备、地面武器、购买区域与时间窗口以资源／引擎确认结果登记；事实未确认时不得设置会绕过失败的默认前置条件。定向目录预检可以在不启动浏览器／服务的情况下对旧四图产物产生 RED；该预检不构成正式验收。

原 BSP 已确认两图均为无自动复活的回合歼灭。冰雪世界双方各 12 个出生点、24 份地上枪与唯一中央买区，出生不可购买；血战回廊双方各 10 个出生点、没有地上枪或显式买区，使用默认出生买区。原图枪、出生手枪和合法购买分别验证，不能把冰雪世界误记为整图禁购。

新图手动操作场使用正式 30 回合设置，另开正式两回合实战验证自然终局。手动组仅在原始 WebSocket 明确观察到死亡或同 epoch 的完整实体 life 替换，并且失败属于被打断的操作时，最多等待下一生命重试两次；每次原失败 JSON／CSV、全部已测响应与帧样本均保留并计入预算。任一尝试或合并样本超出原性能门槛立即失败，不重试性能、布局、协议泄露或驱动故障。三个尝试均被打断时仍失败，需拆分更短功能组，不能注入无敌或冻结规则。

## 预算与产物

正式 `six-map-integrated-final` 在提交 `c7eaca4a84a6068800e6fcf7543a08f5ece9d2d2` 的 Dust2 原生全屏检查产生 RED，失败原文和截图保留在 `.local/cs16/browser/reports/six-map-integrated-final/`。独立探针 `.local/cs16/browser/reports/fullscreen-layout-probe/layout-probe.json` 的三次进入均观察到第 0 帧避让值为 `0px`、弹药 HUD 与聊天按钮重叠；第 1 帧避让值更新为 `64px`，第 1、3、10 帧均保留 8 px 间隔。验收驱动只修正采样时点，不修改产品、无重叠断言或性能门槛；即使第 3 帧仍有重叠，也必须停止并保留失败。

正式 `release-sixmaps-ed89891e` 的 Aztec 触屏响应 P95 为 50.100000381 ms，严格超过 50 ms，原失败与 24 条响应保留在对应报告目录。P95 样本的原生排队为 45.6 ms、派发至读回开始为 2.6 ms、读回与哈希为 1.9 ms。观察器改用一次包围矩形读回后，仍按原三块像素及原顺序计算同一哈希；读回结束和哈希完成后才记录响应时点，不扣除开销、不减少样本、不修改场景。须先通过重叠、边界、横竖屏的字节／哈希等价验证，再在同一个非全零真实 GPU 绘制帧对照并确认 GL 状态不变，最后执行一次原门槛的 Aztec 触屏定向。

正常网络目标为 RTT 不高于 80 ms；键鼠事件到首次像素变化 P95 不高于 33 ms，触屏不高于 51 ms（50 ms 目标加用户允许的 1 ms 浮动）；显示目标 60 FPS，帧间隔 P95 不高于 20 ms、P99 不高于 33 ms。单端高延迟场景使用 250 ms RTT；另记录实际 WebSocket RTT、输入 ACK、规则应用、权威帧到达及协议字节，不能用 HTTP 耗时充当纯连接 RTT。

六图测试容器生命周期为 60 分钟，Go 外层为 61 分钟。原四图正式运行约 299 秒；新增冰雪世界与血战回廊规则自然两局分别约 163.38 秒与 44.28 秒。新增八组原生操作各允许至多三个有权威死亡证据的尝试，仅冰雪世界四组在原 120 秒下一生命等待内发生合法中断就可能使总运行超过旧 25 分钟。此处只延长整套测试的容器生命周期；原生驱动单次 60 秒、下一生命等待 120 秒、密集交火最多 45 秒、自然终局等待 240 秒及全部输入／帧／ACK／性能门槛保持原值。

脚本保留源码 SHA-256、浏览器版本、网络配置、原生事件、逐帧记录、JSON／CSV、截图、失败 DOM 和必要 trace。所有服务器数据、profile、socket、缓存、报告与临时文件统一位于 `.local/cs16/`。数据和浏览器进程由本测试创建并清理，不触碰其他游戏和用户会话。

最终来源绑定覆盖游戏与处理脚本、公共服务端与 game API、控制器、实时传输、音频、主界面和构建入口；开始与结束任一 SHA 变化即不通过。产物另绑定实际 `game-load-manifest.json`、入口及 CS16 所用 JS／CSS、资源清单、WASM 和支持脚本，并核对运行时源码清单。包量为 WebSocket 应用正文，不包含 TLS／帧头；普通、密集、慢端和恢复分别保存实际当前协议的频率、大小分位数、峰值、事件和禁止字段检查。

密集观察使用十席自然电脑接管后的真实交火，至少记录两名射手的十次射击，最多等待 45 秒，不修改命中、位置、资金或终局。恢复观察在断线前建立独立 CDP 网络监听并握手就绪，跨越掉线与真实页面刷新，核对同一 epoch 与持续权威时钟。

浏览器检查分为六图加载和操作、十席完整比赛、移动与触屏、恢复与慢端隔离。24 枪械的所有原始参数和完整射击语义另由规则 E2E 验证；浏览器验证完整购枪目录、合法购买、选择与实际视图模型。若受原版经济或回合限制无法在同一局中逐一购买全部枪械，报告必须明确其覆盖范围。

`CS16_BROWSER_DIAGNOSTIC=1` 只用于功能联调：仍按原预算计算并记录失败，任何功能或性能失败均使 `passed` 保持 false，并继续可执行的后续场景以收集证据。`CS16_BROWSER_MAP_FILTER` 和 `CS16_BROWSER_SKIP_FINISH=1` 会将报告标为 partial。正式验收不使用这些选项，首次失败即停止。

2026-11-22 用户明确「50上下1就允许吧」，将本游戏触屏 P95 验收上限设为 51 ms。保留原始测量值直接判断，51 ms 通过，大于 51 ms 失败；不扣除浏览器排队、GPU 读回或哈希开销。原生键鼠 33 ms、帧间隔与帧率门槛沿用原值。历史报告保留当时的 50 ms 门槛及失败，不改写旧结果。

## 触屏样本途中阵亡的预先失败清单

- 玩家在 24 次手势途中被击杀，后续事件已无触屏目标，驱动却把阵亡前的最后一条出站操作当作松手状态；必须在原始权威投影确认中断时立即结束该组。
- 活着的玩家实际释放失败被当作阵亡跳过；只接受同 epoch、同席位、完整原始投影中的 alive=false 或明确的新 life，未知／部分投影和其他玩家阵亡不成立。
- 生命中断掩盖性能失败或丢弃慢样本；沿用已有最多三次尝试，先校验并保留每次全部已测响应和帧，再等下一生命。

`release-sixmaps-2149c934/fy_iceworld-touch-input-native.json` 为原始 RED：生命 1 样本中途 HP 变成 0，服务器输入已归零，最后出站移动仍属于阵亡前。新判断只将有此类完整原始证据的中断归入既有生命重试，不放宽释放、像素、布局或性能断言。

## 结算元数据晚到的预先失败清单

- game.finished 先到、room.result.id 后到，结果浮层的 key 从 finished 变成战绩 ID，主动收起后又被重新挂载打开。
- 玩家离桌带来的普通房间更新补齐战绩信息，遮罩重新挡住离开入口；同一 matchId 的收起状态必须保留。
- 为稳定浮层而仅使用房间号，导致同房间下一局结束不重新显示；新 matchId 必须形成新身份。

正式 `release-sixmaps-61f70b14` 已完成五图，清理 FY 自然终局时产生 RED，main-failure-dom.txt 显示结果浮层重新遮挡离开入口。开局已有的 room.matchId 应优先于晚到的 result.id，旧房间缺少 matchId 时保留原回退方式。

- 权威 HTTP 已结束但浏览器尚未挂载结果浮层，立即用存在性判断会漏掉稍后出现的遮罩。清理自然终局时先等待结果浮层或已收起入口出现，再主动收起，并等待遮罩退出后执行原离桌确认。
