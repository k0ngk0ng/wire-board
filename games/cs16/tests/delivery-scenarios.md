# 运行时与资源发布失败场景

先建立以下检查，再实现构建器。测试入口为 `node --test games/cs16/tests/delivery.test.mjs`，夹具与报告位于 `.local/cs16/verification/delivery-tests/`。

- 资源路径为空、绝对路径、反斜线、NUL、空路径段、`.` 或 `..`，拒绝读取。
- 资源或其父目录是符号链接，即使指向工作区内也拒绝。
- 字节数、SHA-256、MIME 或资源正文不匹配，拒绝发布。
- 同一逻辑路径出现不同内容描述，拒绝发布；完全相同描述去重。
- 清单缺少任一首版地图、8 个玩家模型或 24 种枪械模型，拒绝发布。
- 编译器、Go 支持脚本、生产源码或构建器变化后，不复用旧运行时。
- 编译失败、源码在编译过程中变化、WASM 无效时，不替换上一个有效目录。
- 相同输入重复执行，资源和运行时身份保持一致。
- 任何创建目录的入口先幂等创建其父目录；临时、缓存、报告均限制在 `.local/cs16/`。
- 运行时支持脚本剥离代码注释，单独保留上游版权和许可证文本。

最终验证须另外编译生产运动核心，以 Node 的真实 WebAssembly 执行与原生 Go 同一轨迹，不能以静态清单通过代替预测一致。
