# 两张经典小图服务端的预先失败清单

- 只添加大厅目录，配置、开局、实际地图规则或 rulesSHA256 未支持 fy_iceworld／cs_bloodstrike。
- 两图被当作爆破或人质模式，生成 C4／人质事件，或到 60 秒直接判 CT 获胜而没有自然歼灭。
- iceworld 未生成原图的 24 个地面武器；bloodstrike 错误生成原图没有的地枪／目标，或遗漏由转换回退产生的出生买区。
- 小图电脑只耗尽计时，无法拾枪、购买、实际开火、造成击杀并完成十席完整对局。
- 将 iceworld 的拾枪模式强套经典爆破图购买次数；删除旧四图原有完整对局要求以迁就新图。
- 任一新图旧 schema1 存档恢复丢失历史／代次／分数；初始、恢复或差分缺少对应规则身份，或恢复再次传输静态几何。
- 友伤开关两种模式下私有输入扫描／改写与完整原路径不同，后续真实规则推进产生差异。
- 把六种地图直接塞入原四房预算夹具，越界或改变已冻结命令／房间数量；小图独立四房批次没有真实创建和推进。
- 交战负载没有实际 shot 事件，或把 module JSON 大小说成包含完整平台／WebSocket 包裹的 wire。
- 六图密集 WS 夹具只有 ACK、没有 appliedSeq 或本人真实 shot；将 full／恢复／换回合包混入普通 fire delta 的分位数。

原四房性能／race 入口保持原地图与原预算。新增独立小图四房入口各包含 iceworld 与 bloodstrike 两房，同样保留慢观战隔离和预算。配置、六图十席自然完整对局、交战逐包／逐秒正文、旧 schema1 恢复和两种友伤输入等价均产生可重复执行的结果；自然对局只加速墙钟，不修改规则、位置、伤害或获胜状态。

六图密集 WS 独立复用现有十真人账号夹具；所有人真实向下交替扣动扳机，保留 8 个在途上限，确认 400 个输入均被确认并应用、每席至少两个本人 shot。只测量协议负载，不把它替代自然对局的交战和歼灭证据。逐连接分别保存 state full、game full、恢复、换回合、普通 delta 与含新增 shot 的 fire delta 应用正文；密集样本仅报告，不替代普通 2 KiB、ACK 或权威时钟预算。
