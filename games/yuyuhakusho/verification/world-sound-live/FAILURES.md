# 世界声音共享队列：先行失败场景

范围是实际 World → manager / collision / fighter / child / effect / overlay → enqueue 调用链，以及 World 与现有 audio/session 的事务。尚不提供 CPU 工作量定价、VDP IRQ 接受时刻或完整比赛音频。

在修改生产实现前冻结以下测试：

1. 观察器关闭与开启但不修改时，世界状态、事件和原生整轮对象结果必须一致；11 个角色和专属子对象调用路径不得漏接。
2. 负队列槽的 TST 与 CMP 之间修改实际 owner，CMP 必须重新读取，不能读取组件入口副本。
3. 入队之后模拟消费者清队列并修改 AudioPause，后续组件合并不得恢复旧队列或旧暂停值；所有操作必须借用同一份 World owner。
4. 同帧多个请求、队列全满、已有相同请求、零请求路径必须沿用既有 enqueue 语义。pending 的清除不由 enqueue 是否接受决定。
5. 未调用、重复调用、调用后返回错误、保留 apply 后延迟调用，不能提交不完整世界。错误后不得继续触发外部观察器。
6. 成功入队后，后续对象或帧末 palette 失败，必须撤销整个 World 与音频分支；原始 map/slice/声音状态不得改变，不得返回局部事件。
7. 真实 audio/session.Interrupt 在入队点消费请求，世界必须看到消费结果；后续失败必须连同音轨、PCM、芯片、调度器一起撤销。
8. 未就绪、比赛已结束、非法按键必须沿用原接口语义，不提前调用观察器。
9. 存档 JSON 恢复后继续执行，仍须使用新的临时端口，不序列化 hook、queue 副本、原 PC 或事件历史。

原生 fixture 和旧测试保持不变。新增介入测试是事务与因果测试，传入的合成 IRQ 时刻不是原版世界时序证明。
