# 四客户端联机验收

最终记录为 [four-human-overlap-final/result.json](four-human-overlap-final/result.json)。四个独立 Chromium 浏览器使用四个已认证账号，占用四个真人席位；没有电脑或托管。运行在同一台 Mac，使用实际 HTTP、SQLite、WebSocket、Go/Wasm 与原生键盘输入。慢端在真实 TCP 写入处每次增加 120 ms 延迟；不代表四台实体设备或任意公网环境。

| 场景 | 可见更新／秒（席位 0／1／2／3） | 最差帧间隔 p95 |
| --- | --- | --- |
| 普通移动 | 60.15／60.08／60.10／60.01 | 26.2 ms |
| 席位 3 慢连接 | 60.17／59.88／59.87／54.88 | 30.6 ms |
| 四端连续攻击、跳跃 | 58.83／59.03／59.64／59.92 | 23.4 ms |
| 连续操作且席位 3 慢连接 | 59.98／60.13／60.17／59.19 | 25.0 ms |

普通移动的原生输入到首次本人位置／像素变化为 20.9～48.6 ms；慢端在两个慢连接阶段为 47.1／29.7 ms，均早于自己的网络确认。四端各阶段恢复调用均为 0。常规 game 消息不携带完整 checkpoint／World；只含压缩按键窗口和必要的权威元数据及公开玩家投影。原始输入、确认、权威消息、逐帧绘图、截图和首次 checkpoint 保留在结果目录。

沿用既有 50 fps、p95 40 ms 预算；新增普通移动输入 75 ms 上限在修正前固定。没有测后放宽阈值。历史失败均保留：初始 12 帧先行范围用尽时慢端出现 151.9 ms 移动等待；扩大为有上限的 20 帧后，进一步省略已显示历史中间帧的重复像素构造。完整规则仍逐步计算，最后与提前终局保持真实回调绘图。[原失败及计划](REPLAY_FAILURES.md)、[真实资源和终局像素检查](prediction-advance-native.jsonl)。

高频操作还复现了 `replay gap`：界面上次消费帧 874，同批收到帧 881 与 883 后，React 只呈现最后一份；原六帧重叠从 876 开始，因而缺 875。发送游标仍按成功发送推进，按键重叠扩大到与先行范围一致的 20 帧；完整恢复环仍为 120 帧，不逐次重发完整环。新增四席模块覆盖测试先复现原六帧行为，再实现；2048 字节 View 预算保持。[真实行为红灯](stream-overlap-real-red.jsonl)、[竞态与既有游标／元数据检查](stream-overlap-race.jsonl)。首次测试的诊断格式错误另见 [修正记录](stream-red-lineage.json)，不把编译失败当成行为证据。

Wasm 与真实终局验证见 [scene-advance-final.log](scene-advance-final.log)：20 帧上限、错误摘要恢复、跳过中间绘图、终局不继续推进及真实终局 RGBA 均通过。原有声音请求 E2E 同时通过；历史回放不重播声音，新本地步骤保留声音。

重复测试先在仓库内构建本地完整应用，再运行 `python3 -B -u scripts/yuyuhakusho/check_four_human_network.py --dist <本地 dist 路径> --label <未使用的标签>`。脚本创建独立测试数据库与浏览器，结束后关闭自身服务；不用实际试玩玩家的房间。对关键代码和执行脚本的绑定保存在各结果与最终验收清单中。
