# 平台前端边界复核

复核在既有前端实现冻结后进行。补充失败范围和浏览器证据，先报告 Root，再安排生产代码修复。真实认证、WebSocket 和快慢连接并存由 Root 收口；本文不把模块测试宿主计入真实平台网络验收。

## 先行失败范围

- 暂停期间输入仍按网络 tick 接收，但客户端提前停用预测，使 Start 恢复必须等待服务器确认。
- 输入 ACK 持续到达但权威帧停止到达，客户端误判连接正常；本地帧停在预测上限后不主动恢复。
- epoch、用户、席位、版本或时钟切换时，旧 checkpoint 请求覆盖新对局；旧按键在恢复后重放。
- 有界重放窗口缺帧／校验不同，恢复请求并发或无限高频；失败后不能手动重试。
- 资源下载中断或 SHA 不同，提前报告 ready；共享缓存保留已失败请求，重试仍失败。
- 长时间积压时输入历史、帧预测、恢复请求或发送数量无界；失焦、隐藏、卸载仍保持输入。
- 完成局重复发送 game loaded，恢复时误将终局帧加一或重播结算。
- 公共 `room.loading` 尚未消失时发送游戏 `loaded`、空释放或输入，被宿主拒绝并阻断公共 ready；静止的游戏 loading frame 被误作断线，产生同步和释放请求风暴。

现有实现的静态上限：本地预测 12 帧，待确认／待应用输入各 64 项，普通并发输入最多 8 个，取消释放有独立通道，checkpoint 恢复单请求在途并有退避。checkpoint 在 JS 端始终保留原始字符串；资源采用压缩与解压两层摘要校验。

`platform_pause_acceptance.py` 用实际 Go/Wasm 检查暂停后 500 ms 输入延迟时的本地恢复；结果记录在同目录指定 label。原生触屏测试使用 CDP 触屏事件，虚拟手柄测试明确标记 Gamepad API 虚拟设备，均不声明硬件型号兼容。
