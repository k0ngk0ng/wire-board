# 实际联机性能失败范围

正式平台 `network01` 已验证认证、WebSocket 与同 epoch 恢复，但本地正常双人画面仅约 9 fps，不能作为完成结果。可见画面间隔中位数约 108.8 ms、最大约 121 ms；原始证据由 Root 保留在 `verification/platform-app-browser/network01`。以下性能复核先于优化实现。

- 正常双人、20 Hz 权威更新、完整场景和规则下，可见画面不能接近 60 fps。最初失败阈值为持续显示至少 50 fps、间隔中位数不超过 25 ms、95 分位不超过 45 ms；Root 正式双人预算进一步收紧为 95 分位不超过 40 ms，本目录最终复核采用该更严预算。不通过放宽阈值、减席位、删角色／场地、少跑规则或少校验确认帧来通过。
- 把 JavaScript 主线程阻塞造成的 fetch 回调等待记为纯连接 RTT；不区分 Resource Timing、浏览器回调、输入 ACK 和本地可见响应。
- 权威追赶的每个中间帧都做完整像素绘制，即使消费者没有请求像素；随后再次绘制相同预测帧。
- 每次 fork／Preview／重放都经过完整 JSON 保存、解码和验证；typed fork 共享了可变容器导致预测污染权威。
- 每个只需像素的预测 step 都做未被消费者使用的完整摘要，或优化后漏掉确认帧的规则与呈现摘要校验。
- 跳过不可见帧的像素构造后，规则或 renderstate 与原逐帧路径不同；带像素的最后一帧改为按最终对象猜图。
- 增加多份长期缓存或重复状态掩盖开销，破坏 renderstate／存档的单一所有者；错误路径不再原子或资源上限被取消。

记录实际 RPC 调用次数、耗时、CDP CPU profile、Resource Timing 与可见 Canvas paint 时间。优化只在已确定的瓶颈处进行，并复跑既有正确性及完整人物／场地路径验收。
