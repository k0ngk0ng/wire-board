# PCM 命令状态边界复核

本清单与下面的独立回归先于相应修复，冻结的 12 组原版 E2E 保持不动。

- 已知 single 播放阶段没有 `Single` 资源上下文，仍被 `Restore` 接受，可在下一次推进解引用 nil。
- 动态 inactive 双槽阶段的 part 上限采用宽泛常数，允许原子时长表之外的位置。
- rate 延迟／复制等循环的剩余量为 0，或当前 nibble 阶段没有已消费的字节，仍被接受。
- 活跃双槽工作阶段与 mode／资源上下文不一致，或 held 窗口的 grant 与唯一执行 frontier 不一致。
- single 初始化已锁存 header 而尚未读完 bank 字段时，另一描述发布会把不同来源的原元数据组合。当前逻辑资源 API 不支持这种组合，必须原子拒绝。
- 同槽转交已读入 bank 字段但尚未读完 size 时覆盖该槽，也须明确原子拒绝。另一槽的独立发布仍允许。

这些拒绝限定 opaque-resource profile，不能声称恢复了任意恶意 window 对原 ROM 地址的混合读取。正常原版连续命令矩阵不触及这两类输入。
