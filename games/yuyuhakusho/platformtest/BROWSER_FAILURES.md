# 正式平台浏览器验收场景

本清单先于本轮正式页面验收及由其发现的修复。使用正常 Vite 应用、实际 games.Modules、server.New、认证、SQLite 和 WebSocket。测试专用第二监听器只延迟 TCP 写入或关闭真实连接，不重写游戏消息。

- 游戏在大厅／创建列表缺失；创建、选场地／角色、公共准备按钮和开始流程不通。
- 只下载脚本便提前确认加载，或一个真人未完成初始化时规则已推进；观战与重连再次暂停全员。
- 正式应用没有本地预测，原生按键等到 ACK 才改变真实画布；读取 DOM 坐标却未验证像素变化。
- 输入窗口、预测步数或重放积压无界；慢端阻塞快端、权威时钟或其他席位。
- TCP 延迟后松开无效，真实连接关闭后残留按键、自动转 AI；恢复后局面重置或不再推进。
- 默认 MD 六键与公共设置不一致，修改游戏键位无效；设置弹窗／编辑框穿透游戏输入。
- 虚拟 Gamepad 输入断开时误释放其他来源；关闭设置后未确认中立便重触发。
- 320px 横向溢出、画面与控制器重叠、公共体力不可见；全屏包含平台头部或 ESC 失效。
- 将测试壳、人工延迟消息、ACK 或稳定 FPS 当作真实平台、网络或首次可见响应的证据。

结果须分别记录连接 RTT、输入 ACK、权威帧到达、显示帧间隔和原生事件至画布首次变化。测试使用虚拟手柄时明确标注，不声称实体品牌兼容。

正式页面首次实测约 9 次可见更新／秒。性能回归随后冻结：正常双人房间每端 2.5 秒可见采样，至少 50 次更新／秒，帧间隔 p95 不超过 40 ms，页面必须实际可见。原始 `performance-red01` 复现 8.80 次／秒及 119.1 ms p95；测试预算不因优化结果而放宽。HTTP 的主线程回调耗时与 Resource Timing、平台 WebSocket RTT 分开记录，避免把同步 Wasm 阻塞误写为纯网络延迟。
