# 碰撞管理器：实现前验证范围

目标为 `0x1edac..0x1ee1c` 的完整调用，组合顺序必须是投技、相消、攻击／受击、身体分离，再清除五个计数、提交声音和更新慢动作。原版管理器先于人物更新；本阶段只消费已提交形状，不代替完整世界调度。

可能失败的场景：消费者顺序改变导致目标掩码、动作、队伍或坐标不一致；适配器漏传字段或用前一阶段旧人物；误清缓冲内容而非计数；漏清投技计数；暂停仍改写任一字段；慢动作先判断后减一、bit1 或零值分支错误；声音队列槽位的有符号判断、同值覆盖和满队列行为错误；下游错误后已部分修改输入 map／slice；把角色编号、对象 ID、目标位号和平台席位混为一谈；遗漏旧特效参数；将独立声音消费者的异步改写归因于碰撞函数；用各组件分别通过代替完整管理器的原 CPU 比较。

先保存完整管理器自然调用和声明私有输入的隔离原 CPU 调用，再写组合测试并保留缺实现失败，最后实现。测试比较全部人物对象、四个形状缓冲、投技区、五个计数、特效池与参数、游标、声音和慢动作状态；单初态连续管理器序列只变化外部输入，不回灌期望中间态。完整人物运动、特效寿命、电脑和完整对局仍须另外验证。

## 已验证结果

2,068 次自然完整调用、264 个原 CPU 隔离边界，以及 5 条单初态连续流共 50 步，与独立 Go 组合规则完整一致。自然观察的 3,600 帧 RAM／画面基线不变，没有未完成调用或独立声音队列消费插入。本阶段原生竞态与 Node/Wasm 集成回归通过。

自然记录包含全部 16 个连续人物对象及缓冲引用的额外 owner，逐个比较完整 256 bytes；同时比较四类形状 1,024 bytes、投技区 512 bytes、特效池 2,048 bytes、五个计数、分配游标、待处理声音、四槽队列、暂停、慢动作、连击标志与场地边界。512-byte 投技区是取证窗口，不作为原生产者容量的证明。

隔离矩阵覆盖四个消费者的 16 种存在组合，分别加入防御、KO、同队、跨线和暂停；尾段另覆盖慢动作 0／1／2／3／4／160／65535、旧标志和队列各槽状态。连续流只初始化一次，之后不恢复存档、不读取期望中间态，也不重新提交已清除的形状：首次调用后形状已清空，后续步骤主要验证声音／慢动作尾段，不能作为持续碰撞、完整人物或对局序列。自然片段的实际形状 owner 只有 `8400/9000`；其他对象类型和四人物组合调度尚待扩展。

暂停直接保留全部输入状态。缺失 owner／无效计数的早期失败，以及攻击之后身体消费者失败的晚期路径，均验证调用者 map／slice 不变和整体原子失败。真实红阶段因缺少 `CollisionManagerState`、`CollisionActor` 与 `ResolveCollisionManager` 编译失败，记录先于实现。
