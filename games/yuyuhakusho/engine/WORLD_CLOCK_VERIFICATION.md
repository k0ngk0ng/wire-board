# 世界时钟与暂停：实现前验证范围

目标为帧业务入口内已确认的计数、暂停和震动更新：逐个恢复实际函数完整返回，再按已知顺序用于世界步。对象调度、输入采样、场景分派及完整视频帧不由这些小函数替代。

可能失败的场景：把视频帧、未暂停逻辑计数与慢动作步当成同一时钟；错误冻结暂停切换或在错误通道接受 Start；暂停 bits6/7 顺序和优先级错误；byte／word 溢出或有符号条件错误；震动请求、持续时间、衰减和方向来自错误字段；忽略零除数及原 CPU 的 DIVU 边界；把后阶段使用的慢动作标志提前冻结；把清理呈现游标误作清除上一帧碰撞形状；用每帧注入原计数替代真实连续更新。

静态分析只从已知帧入口到达函数。实现前须先采集原 CPU 完整自然调用与明确私有输入的边界，再写测试并保留缺实现失败。完整比较所有相关世界字节，连续流只修改声明的输入／外部请求；生产模型保持具名状态和必要事件，不携带完整 RAM 或执行原指令。

## 已验证结果

已恢复五个完整 helper：`3a76` 视频侧计数、`3a86` 未暂停逻辑计数、`3a9c` Start 通道暂停切换、`3ad6` 暂停位与音频标志同步，以及 `39ac` 震动／反馈。16,436 次自然调用、4,536 个原 CPU 边界、4 条单初态流共 640 次 helper 调用完整一致，原生竞态和 Node/Wasm 集成回归通过。固定输入全部 3,600 帧 RAM／视频基线未改变。

完整比较 `F550..F58F` 的 64 bytes、8 个通道输入字节和 `F807`。边界覆盖 word 回绕、零计数、暂停位全部 byte 值、无通道时仍检查通道 0 的原 do／while、同时 Start 只切换一次、无暂停权限时跳过无效通道数，以及反馈请求、除法、无符号衰减、奇偶输出和零幅度保留旧偏移。生产边界只接受最多 8 个逻辑通道，不模拟损坏计数读取相邻 RAM。

测试文件先于实现建立。首次包级预实现构建被另一并发组件的缺类型错误阻断，原始日志保留；它不是一个成功到达这些测试的聚焦缺符号运行。随后全包回归实际运行并通过三项 `TestWorldClock`，记录见[世界基础阶段验收](../verification/world-foundations.json)。

这些函数不包括 `3a2e` 整帧分派、`3afe` 软复位、场景分派、对象遍历或完整声音驱动。慢动作的调用门槛由世界层按原顺序决定，不能把同一旧 `SlowFlag` 固定应用到整轮对象。复跑原版使用 `capture_world_clock.py --out .local/md-yuyuhakusho/world-clock-replay`，独立测试使用 `go test -race -count=1 -run '^TestWorldClock' ./games/yuyuhakusho/engine`；缓存／Wasm 路径沿用研究工具说明。
