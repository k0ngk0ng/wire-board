# 酎弹体规则阶段：实现前验证范围

目标为父人物 `+0x100` 子槽使用的 `0x1313e` 回调规则，覆盖初始化、持续运动、接触响应、动画／形状提交、投影与删除。规则阶段止于 `0x1580` 前的绘制请求，或 `0x3556` 清槽完成；精灵提交由独立呈现阶段处理，不称为完整世界对象／像素更新。

可能失败的场景：只恢复创建而忽略阶段表；把内部返回误当完整回调返回；跳过暂停、慢动作或删除分支；角色／父对象／目标位号混用；遗漏对父对象、形状、声音、随机数或全局状态的写入；碰撞接触标志在错误时间清除；把 word／byte 写入改为整个定点字段覆盖；动画更新与判定提交顺序颠倒；丢弃旧槽未写字段；缺少语义数据时部分修改调用者状态；用隔离输入冒充自然游玩；中途回灌期望状态后声称连续轨迹；原版观察改变 RAM／画面或时基；把精灵缓冲一致当成独立完整渲染。

先记录已确认的控制流和可能失败场景，保存完整自然／隔离原 CPU 输入输出，再写 Go 测试并保留缺实现失败，最后编写独立规则。所有采样、临时工具和缓存仅写入当前 worktree。正式引擎不执行 ROM 或模拟器。

## 已恢复语义

阶段 0 设置专用图形／图块／动画／形状资源、清图形缓存，并设定初始动画计时；其他非零阶段进入持续路径。每次调用先写生命字段 255，暂停 bit7 或非零慢动作标志时只请求绘制，保留运动／动画／投影。

活动路径依次执行动画时钟、满足条件的地面尾迹、固定横纵速度积分。落地先于水平边界判断；边界删除先于接触标志判断。接触 bit3／4 或落地按蓄力档 0～2／3～5／6～7 分配三种影响特效，然后删除；仅越界时直接删除。继续飞行时提交动画／形状、声音并投影，最后请求绘制。没有额外重力积分，也不消耗 RNG。

尾迹读取递增前坐标，影响特效读取积分后坐标。前者复制完整定点坐标，后者只写高 word，保留复用特效槽的小数。高档影响的 Y 高 word 另减 16。分配失败仍保留游标推进；尾迹先于影响，可能在同次调用中分配两次。

`0x3556` 默认在 size 为 0 时清 64 bytes，否则清 `(size>>4)*16` bytes。独立规则验证最多 256-byte 逻辑槽内的清除范围，明确拒绝损坏大小导致的大范围地址别名；不发明容量裁切。队伍和目标位号保持到它们所在前缀被清除；对象 ID 是逻辑存储身份，不作为原内存字段清零。

静态证据见 [主路径](../../../docs/research/md-yuyuhakusho/static/chu-projectile-core.txt)、[删除及尾迹](../../../docs/research/md-yuyuhakusho/static/chu-projectile-helpers.txt) 和[影响特效](../../../docs/research/md-yuyuhakusho/static/chu-projectile-effects.txt)。当前 REA 不支持 raw 68000；这些静态结果来自直接 Ghidra，实际语义由原 CPU 对照验证。

## 验证结果

- 自然片段仅一条实际弹体：第 2,180／2,181 帧请求绘制，第 2,182 帧接触 bit3 后删除；对象 `9100`、蓄力档 7。三次规则阶段完整一致，不能把它称为三个弹体或完整对局。
- 4,678 个原 CPU 隔离调用完整一致，其中 1,208 次删除。覆盖初始化／持续、暂停／慢动作、七种不同姿态的两帧、尾迹、三档影响、落地与越界／接触的优先级、池满、坐标／尺寸回绕，以及 16～256 bytes 的全部清除前缀、默认／向下取整大小。
- 18 条单初态规则轨迹共 948 步全部到达实际删除。只在指定接触轨迹的第 8 步设置外部接触标志；其余步骤不恢复存档或注入期望中间态。每步包含原规则自己的动画时钟和动画／形状提交；没有运行呈现、碰撞管理器、特效生命周期或完整世界调度。
- 每调用比较完整弹体 256 bytes、父对象 256 bytes、特效池 2,048 bytes、形状区 1,024 bytes、全部计数、游标、声音和环境。父对象未被修改；自然／隔离均没有独立声音消费者插入，队列没有例外屏蔽。全部 3,600 帧原版 RAM／画面与同输入的未挂钩原内核基线一致。

接口为 `StepChuProjectile(state, environment, library)`，输出 `Draw` 或 `Deleted/ClearedBytes`。动画／世界位置由 `AnimationActorState` 单独持有，屏幕坐标独立；资源 ID 只用于只读数据查找。专用 [14 帧语义库](../data/chu-projectile-animation.json) 可供后续世界加载，不依赖测试夹具或原 ROM。

测试先于实现，并保留缺类型／函数的真实红阶段；增加队伍／目标位语义字段时另保留字段不存在的红阶段。缺帧、无效影响档或损坏删除范围均验证原子失败，暂停初始化不要求未使用的帧库。最终原生竞态和 Node/Wasm 的三项弹体测试均通过，来源、夹具与日志摘要见[验证记录](testdata/chu-projectile-validation.json)。本阶段采用显式源文件聚焦编译，避免其他并行组件仍处于缺实现红阶段的影响；父阶段仍需执行整包集成回归。

## 复跑与边界

```sh
mkdir -p .local/md-yuyuhakusho/tmp
PYTHONDONTWRITEBYTECODE=1 python3 scripts/yuyuhakusho/capture_chu_projectile.py \
  --out .local/md-yuyuhakusho/chu-projectile-replay
GOCACHE="$PWD/.local/go-cache" GOMODCACHE="$PWD/.local/go-mod" \
GOTMPDIR="$PWD/.local/md-yuyuhakusho/tmp" \
go test -race -count=1 -run '^TestChuProjectile' ./games/yuyuhakusho/engine
```

采样复用已保留的 `chu-special-motion-inputs.json`，先在未挂钩原内核生成同输入基线，再运行观察内核。Wasm 使用[研究工具说明](../../../scripts/yuyuhakusho/README.md)中的执行器与 worktree 内缓存目录。精灵组合、硬件缓冲、完整房间对战、服务器时间轴与所有角色弹体均不在本阶段验收范围。
