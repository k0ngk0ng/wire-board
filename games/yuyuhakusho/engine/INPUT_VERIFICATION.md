# 首批输入规则：失败场景与原版依据

本文件及 `input_test.go` 先于独立规则实现建立。游戏尚未注册，也未实现完整战斗。

失败场景包括：方向／A/B/C／X/Y/Z／Mode 位顺序错误；高低字节交换；将持续按住误作重复按下；松开边沿丢失；同帧多键互相覆盖；交换 A/C 后未重新计算边沿；六键扩展污染基础键；三键模式继承六键旧状态；非法按钮位或未知型号悄悄混入状态；采集函数尚未返回就认定输出；Go 计算依赖 CPU／ROM 执行器。

原版依据是 `0x2d5e..0x2d94`（三键）和 `0x2dce..0x2e32`（六键）。CPU 地址顺序 `FFF780` 起每隔 8 字节依次是基础键当前、上帧、变化、按下、松开；`FFF7A8` 起为扩展键的相同五个字段；`FFF7D0` 为设备标志。`0x2dac` 根据对应通道的 A/C 交换设置处理 bit5 与 bit6。

验收以真实冷启动、原版函数进入／退出采样为首批夹具。研究钩子不得改变 3,600 帧原有 RAM／画面摘要。自然覆盖不到的型号转换等边界另列待验，不把自行计算的期望值冒充原版证据。

本轮实际采集 6,575 个完整调用，观察器未改变任何基线帧。第 382 帧暴露了额外失败场景：六键函数的 `MOVE.B` 保留入口寄存器高字节，D0／D1 的部分旧位传播到扩展状态高四位。夹具增加入口寄存器后按原运算恢复，没有删帧、清高位或改写期望值。规则采样状态保留完整 16 位；平台输入边界只接受有物理语义的低 12 位。Go 原生竞态检查与 Node 执行的 Wasm 对照均通过。
