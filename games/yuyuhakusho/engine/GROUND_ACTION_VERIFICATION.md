# 基础地面动作构造器：实现前验证范围

本清单先于采样、测试和实现。恢复范围为通用动作重置 `0x19c1c`，站立／蹲起过渡／蹲下／防御／站立转身／蹲下转身／行走构造器，以及起跳准备 `0x1854a`。实际起跳和落地的特效、速度参数及世界对象池是后续连接范围。

失败场景：构造器尾跳通用重置却遗漏其写入；把动画完成标记当作每次自动清理的布尔值；错误清除当前动画标志／物理速度／未写字段；转身用布尔取反替代 byte 的 `1-oldFacing` 回绕；未清四组命令历史和请求；防御没有根据下方向选择姿态；起跳准备覆盖整个纵速度字段，而原版只写高 byte 保存方向；场上队伍未恢复为基础队伍；嵌套／尾跳调用配对错误；未知对象写入被忽略；只比较几个字段就声称完整构造器一致。

先被动记录完整原函数入口到最终 RTS 的对象状态，并验证 3,600 帧基线不变。再执行明确标注的原 CPU 隔离输入，覆盖字段残留、朝向和 byte 回绕、方向及保护字段。夹具和测试必须先于 Go 实现，原生和 Wasm 都读取同一原版结果。不会把这些片段通过称为连续战斗或完整角色完成。

## 已验证结果

自然记录为站立 51、通用重置 148、起跳准备 3、行走 23、蹲下 10、蹲起 7、防御 2、站立转身 2，共 246 个完整调用；包含父子调用重叠。另有 9 类入口各 20 个原 CPU 隔离用例，共 180 个，覆盖方向和朝向的 byte 边界、旧字段残留与命令历史。蹲下转身没有自然样本，不冒称自然覆盖。

观察后的 3,600 帧 RAM／视频与基线一致，所有写入均在声明的完整人物字段内。夹具及测试先于 `ground_actions.go`，首次缺实现编译失败后才加入规则；原生竞态和 Node/Wasm 均通过。起跳准备保留原纵速度低 24 位，只替换高 byte 的方向请求，实际起跳再装入完整速度参数。

复跑：`python3 -B scripts/yuyuhakusho/capture_ground_actions.py --out .local/md-yuyuhakusho/ground-actions`。
