# 酎攻击选择：实现前验证范围

目标为地面 `0x17e12`、空中 `0x17f54`、地面特殊 `0x17fca` 和空中特殊 `0x18092` 的完整返回调用，包含实际到达的招式构造、能量门槛、重置及特效。先保存原 CPU 的完整输入／输出，再编写测试并保留缺实现失败，最后编写独立 Go 规则。

可能失败的场景：把当前按下、变化和持续输入混用；忽略命令请求优先级；方向相对表范围或基准错误；反向、非法方向组合和多个攻击键的优先级变化；把 byte／word 写入速度字段当作整个 long 赋值；能量比较、扣除或阈值的有符号语义错误；构造失败却清除请求或改变人物；未知动作回退为自创招式；漏掉相邻子对象占用门槛、角色参数或原版特效池；把共享重置误作所有字段归零；丢弃旧特效槽残留；漏比人物或全局写入；将指令可达性当成正常游玩触发；每调用回灌原版结果后声称连续对局；观察器改变完整帧。

验证比较完整人物对象、涉及的相邻对象、特效池、游标和实际写入的其他全局状态。自然采样与固定 3,600 帧 RAM／画面基线逐帧一致；隔离原 CPU 矩阵明确声明替换输入，覆盖全部分派路径、成功／失败门槛与副作用。本阶段恢复招式选择和初始化，不提前声称完整招式运动、投射物、特效寿命或完整对局。

## 已验证结果

四个选择器共 4,348 次自然完整返回，其中地面普通 1,965、空中普通 156、地面特殊 2,071、空中特殊 156；这不是招式成功次数。另有 4,596 个原 CPU 隔离调用，覆盖 21 个实际到达的构造／提交入口，以及 4 条单初态流共 32 步。独立规则的原生竞态和 Node/Wasm 集成回归均通过。

完整比较人物 256 bytes、相邻对象 256 bytes、特效池 2,048 bytes、投技区 512 bytes、计数及游标。方向 0～15、按下 B／A 的优先级、请求 0～8、朝向 0／1／3、能量各成本临界值、生命 111／112 和子槽占用均保留原 CPU 证据。速度／重力中的 byte 或 word 写入保留其余低位；能量不足时不重置动作。投技调用完整的 `SubmitChuThrow`，不另写一份提交规则。

连续流仅初始化一次；第一个成功特殊构造会清请求，后续步骤主要验证请求消耗后的保持行为，并非完整招式或世界步。自然片段只触发有限构造，其他入口由明确隔离输入验证。完整来源与日志见[本阶段验收](../verification/actor-pipeline.json)。
