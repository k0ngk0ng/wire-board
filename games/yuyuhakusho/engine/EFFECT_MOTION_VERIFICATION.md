# 通用特效生命周期：实现前验证范围

目标为行为 `0x149ac` 的完整规则阶段，包含类型表 `0x14a00..0x14a48` 的 37 项（`0x00..0x24`）初始化、延迟、序列计时、运动／跟随、投影与删除；阶段止于 `0x1580` 绘制请求、直接返回或 `0x3556` 清槽完成。硬件精灵提交另由呈现阶段处理，不将规则边界冒充完整像素或世界更新。

可能失败的场景：只覆盖早期尘土／命中类型而遗漏投射物尾迹；把类型数、共享初始化数和序列数混为一谈；将相对类型表基准错误或延伸到后面的代码；暂停前遗漏初始设置；延迟期间仍绘制或移动；byte 倒计时、255 初始帧、结束 duration0 或图形索引单位错误；擅自循环／回收或发明 TTL；错误清除复用槽旧字段；跟随 owner 时复制完整坐标而非高 word，或未验证 owner 缺失时的原子失败；坐标积分／投影回绕错误；早于／迟于原版删除；损坏 size 引发的越界别名被伪造为固定容量规则；内部 RTS 被误当完整阶段；观察器改变原版帧；每步回灌期望中间态后声称连续生命周期；把实际创建次数或独立阶段数当作完整对局。

先保存已确认的原指令和原 CPU 完整自然／隔离输入输出，再编写测试并观察真实缺实现失败，最后编写独立规则。测试比较完整槽、owner 输入、相关计数与全局状态，保存单初态直到真实删除的轨迹；正式引擎不读取 ROM 或执行模拟器。所有写入、项目与缓存均留在当前 worktree 内。

## 已确认流程与数据

37 个类型映射到 21 个初始化入口及 21 条独立有限序列。类型 0～15 设置普通图形／图块资源、清横纵速度，并使用全局 `A031` 图块游标；其余类型使用预装图形资源，设置跳过图块上传标志，部分类型直接提交声音 `a5/79`。没有把后面的代码当成更多类型。语义数据见 [effect-sequences.json](../data/effect-sequences.json)，原指令见 [effect-motion-core.txt](../../../docs/research/md-yuyuhakusho/static/effect-motion-core.txt)。

阶段 0 先设置阶段 2、调色板属性、图形缓存、帧索引 255、计数 1 和标志 0，再执行类型初始化，**直接返回且不绘制**；它不继续进入暂停／慢动作和运动阶段。旧延迟、跟随 owner、未明确设置的图块基址／上传标志均保留。

非零阶段先检查暂停 bit7 和任意非零慢动作标志，冻结计时并请求绘制。正常时，延迟非零只减一并直接返回，不绘制。之后 byte 计数先减一，只有结果为 0 时才递增 byte 帧索引并读二字节序列项；图形参数为图形 byte 乘二，duration 为新计数。读到 duration0 立即删除，不能擅自循环或附加 TTL。进入时计数已经是 0 会先回绕为 255，不会立即删除。

没有 owner 时按完整 16.16 速度积分。有 owner 时只复制 owner X／Y 的高 word，保留特效自己的小数；自跟随按同一槽别名处理。运动后使用已恢复的投影，再请求绘制。`A031` 使用先 byte 加法回绕、再无符号阈值判断的原顺序，属性上的图块增量也先在 byte 中回绕，不能改为一次扩大加法。

结束使用 `0x3556` 的 16-byte 块清除，size0 默认 64 bytes。规则验证逻辑槽内 16～128 bytes 的全部前缀及非整块向下取整，明确拒绝损坏大小导致的多对象／RAM 地址别名。它只恢复 `149ac`，不把 `14930` 连击数字、`14ec6` 附着状态或其他行为默认为同一种生命周期。

## 原 CPU 与独立规则验证

- 1,130 次自然规则调用完整一致：1,014 次绘制请求、58 次初始化直接返回、58 次实际删除。自然类型仅 2、16、25，覆盖全部 16 个池槽；类型范围不能扩大为所有类型均在自然输入出现。
- 5,752 个原 CPU 隔离调用完整一致。37 个类型分别验证初始化，21 条序列分别验证 byte 计时、暂停／慢动作、延迟、owner 与结束边界；另外覆盖坐标回绕、图块游标回绕、声音队列槽位及清除前缀。
- 111 条单初态完整生命周期共 2,700 步，全部到达原版删除。每类型分别验证自由运动、跟随外部 owner 和自跟随；移动 owner 只使用记录中声明的外部 X／Y 输入，不恢复存档或回灌期望特效状态。轨迹不执行硬件精灵提交或完整世界调度。
- 每次比较完整 128-byte 特效槽、2,048-byte 池及实际读取的 owner 原始字节，确认其他槽和 owner 未被修改。全部相关全局状态完整一致，没有独立声音消费者插入，不屏蔽队列字段。观察内核的 3,600 帧 RAM／视频与同输入未挂钩原内核逐帧一致。

接口为 `StepEffectMotion(state, world, owners, library)`，返回状态、全局游标／队列及 `Draw/Deleted/ClearedBytes`。初始化和延迟的普通返回以全部 outcome 标志为 false 表示；这不能被调用方当成删除。只读 owner map 和语义库保持不变，缺类型、缺序列、缺 owner 或超出逻辑槽的删除均整体原子失败。

测试和真实缺类型／函数红阶段先于实现。最终原生竞态和 Node/Wasm 的三项聚焦测试通过，见[验证记录](testdata/effect-motion-validation.json)。本阶段显式编译 `effects.go`、`motion.go`、`effect_motion.go` 和本测试，以避开其他并行组件的缺实现红阶段；父阶段仍需运行整包集成门禁。
