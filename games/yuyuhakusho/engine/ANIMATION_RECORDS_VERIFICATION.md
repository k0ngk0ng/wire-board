# 动画记录与四类形状提交：实现前验证范围

目标为 `0x1eb40` 到其真正返回，包括尾跳 `0x21960` 的四槽声音请求操作。先建立本清单，再采集原版夹具、编写测试并观察缺实现失败，最后恢复独立 Go 语义。

失败场景：把姿态表的相对偏移当成绝对地址；动画帧为 8 bytes、形状目录为 4 bytes 的步长错误；只在计时零时触发声音／94字段重置的条件丢失；未保留原有 A030 请求；把面对方向当作只能0/1从而改变原byte/word语义；X朝向翻转与形状X/Y翻转混用；高word世界位置、word回绕和图形属性高byte更新错误；第一类四个前缀数据和最后字节两nibble拆分错误；前三组记录终止位误读、第四组错误循环或清bit7；满缓冲时覆盖末槽却被改成丢弃／扩容；未改字节被清空；四类counter和actor标识错位；声音队列的负值占用／同值覆盖／四槽全忙拒绝遗漏；把中间声音出口当作其他调用的返回；观察器改变基线；未解释的对象或全局写入被屏蔽；将本阶段通过宣称完整动画／碰撞／音频播放完成。

自然观察须核对完整对象字段和全部四个 256-byte 缓冲，并与同输入的 3,600 帧 RAM／视频基线一致。原 CPU 隔离用例用于翻转、计时、队列、容量和回绕边界，明确不属于额外自然对局。生产规则只接收已解析动画／形状记录，不执行 ROM 或 CPU 指令；形状类别的业务语义未确认前保留编号，不擅自命名攻击／受击／投技框。

## 当前验收结果

| 范围 | 结果 |
| --- | --- |
| 自然对象、完整形状缓冲、计数及 A030 | 4,134 个完整调用一致；当前只提取到 1 组集合的 101 个不可变帧 |
| 自然完整队列状态 | 4,126 个调用一致 |
| 外部队列消费 | 8 个原始快照差异，保留并逐项核对独立 PC `0x37c56`、D→A 四个地址、byte 宽度、清零值、SR 优先级提高和栈变深；它们不是动画函数的预测结果 |
| 原 CPU 隔离边界 | 69 个用例的完整状态一致，含四类缓冲、翻转、计时、末槽覆盖、四个队列写出口及全忙拒绝 |
| 观察器基线 | 带只读执行／队列写观察的 3,600 帧 RAM、画面及尺寸与未观察原内核完全一致 |
| 采样缺失／异常 | 未完成调用 0，采样异常 0；自然记录还保留 628 个调用期间其他外部 RAM 区域的变化，未将其归因于本函数 |

夹具和测试先于 `animation_records.go`，首次编译因 `AnimationActorState / AnimationSubmissionState` 等不存在而失败。初始严格全状态比较发现第 2,003 帧的真实队列差异，随后追加独立写入追踪定位消费者；没有通过改写输入或放宽所有队列比较消除失败。

最终测试对每个调用全量核对对象和缓冲；任何队列差异必须精确对应那 8 组独立消费者事件，且不得有 `21960` 新提交。Go `SubmitAnimationRecord` 保持只做自己的提交。消费者及其世界时基尚未建模，不能把目标测试通过描述成全部自然原始状态都由一个原子函数解释。

原生目标 `TestAnimationRecords*` 已通过；竞态与 Wasm 由父任务统一运行，本组件不宣称已执行。生产接口按 Actor 的集合 ID、姿态和帧索引查只读库，缺数据或损坏记录原子失败；当前不是完整 11 角色动画库，也不是碰撞判定或音频播放验收。

复跑命令：

```sh
python3 -B scripts/yuyuhakusho/capture_animation_records.py --out .local/md-yuyuhakusho/animation-records
mkdir -p .local/md-yuyuhakusho/tmp
GOCACHE="$PWD/.local/go-cache" GOMODCACHE="$PWD/.local/go-mod" \
GOTMPDIR="$PWD/.local/md-yuyuhakusho/tmp" \
go test ./games/yuyuhakusho/engine -run '^TestAnimationRecords' -count=1 -json
```
