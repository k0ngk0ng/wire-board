# 切线构造器：实现前失败场景

范围为原 `0x186be` 到尾调用动作重置的最终 `0x19c44`。此阶段决定切线初态并分配尘土，不包含切线后的完整轨迹或攻击判定。

失败场景：遗漏先于角色修改执行的双侧尘土分配；只用是否有其他玩家代替对应轨道占用位；用完整小数而非地面高 word 判断出发轨道；错误统一上下两方向的起始纵速；层级 byte 加减 0x40 未回绕；两个方向均覆盖深度而原版只有一方向设置 200；忘记清全局轨道占用标志；未包含公共动作重置；池满、单槽或第二次分配失败时静默忽略游标／对象变化；传入非法池时部分修改状态；尾跳／函数返回配对错误。

先固定原版自然调用及明确声明的原 CPU 隔离输入，再写测试与 Go 实现。完整对象池、游标、角色字段及占用 byte 都参与对照；没有屏蔽未知对象写入。自然样本的观察必须与 3,600 帧基线一致；隔离用例不得冒充自然四人对局。

## 已验证结果

首轮原输入时间线没有触发此构造器，保留这一负面覆盖事实。随后使用 `scripts/yuyuhakusho/lane-inputs.json` 从正常冷启动选人并通过 Y 按键切线，记录 26 个自然调用；带观察器的 3,600 帧与相同输入的未观察原内核运行完全一致。没有改写自然对局 RAM 或冻结电脑。

另有 120 个原 CPU 隔离用例，覆盖地面高 word 304／320、占用 0／1／2／3／255、空／满／单空槽池、游标 0／0x780、层级 0／240。总共 146 个完整调用在 Go 原生竞态和 Node/Wasm 中核对角色、完整池、游标、两侧分配索引和占用 byte。夹具和测试在 `lane_switch.go` 之前建立。

复跑：`python3 -B scripts/yuyuhakusho/capture_lane_switch.py --inputs scripts/yuyuhakusho/lane-inputs.json --out .local/md-yuyuhakusho/lane-switch-active`。后续切线轨迹未包括在本批结果中。
