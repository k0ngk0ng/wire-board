# 地面输入决策：实现前边界

目标是完整 `0x15cb0` 地面移动／防御／切线／起跳准备决策，包含它实际调用的构造器及对象池副作用，不包含共享尾段中的攻击解析和动画表提交。

失败场景：把阶段中间的通用 reset 返回当作整个决策返回；忽略构造器对后续条件的影响；转身与行走优先级颠倒；把 XOR 的上方向变化误当新按下，漏掉 C 配合松开方向的切线；起跳准备或落地姿态提前阻断本应优先的切线；蹲下／防御姿态转换漏掉重置；方向为斜向或对向同时按住时自创归一化；未保留命令历史清理；池满和单侧特效失败改变主体动作；未涵盖完整角色／池／占用字段；修改失败后留下部分状态。

原版自然记录必须确认返回时栈位置与入口一致，排除中间 JSR 的返回，保持整帧基线不变。原 CPU 隔离矩阵明确列出输入姿态、朝向、方向、C 状态、方向变化及扩展 Y；它们不代表额外完整对局。先夹具、测试，再实现独立规则。

## 已验证结果

基于正常切线输入场景得到 2,099 个自然完整调用，观察不改变同输入的 3,600 帧 RAM／视频。每个调用只在栈位置回到其入口位置时结束，避免把中途蹲起构造器的 RTS 错当最终输出。

隔离原 CPU 矩阵有 1,414 个用例：11 种姿态、2 种朝向、16 种方向组合、C 按住与上方向变化的独立组合，加起跳／落地等姿态的扩展 Y 优先级检查。原对象池随用例切换为空、全满或单空槽，包含两条轨道和占用位。全部人物字段、完整池、游标、占用和分配索引在原生竞态／Node-Wasm 中一致。

测试先于 `ground_control.go` 并实际观察到缺少 `StepGroundControl` 的编译失败。实现通过已恢复的动作／切线构造器组合，不用简化移动来替代转身、守势或特效副作用。攻击解析和完整共享动作尾段仍未包含。

复跑：`python3 -B scripts/yuyuhakusho/capture_ground_control.py --inputs scripts/yuyuhakusho/lane-inputs.json --out .local/md-yuyuhakusho/ground-control`。
