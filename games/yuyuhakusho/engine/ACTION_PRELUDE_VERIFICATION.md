# 动作前置阶段：实现前失败场景

范围从原 `0x15a20` 至正常分派前的 `0x15a58`，或命中停顿分支到 `0x15b40`；角色专属命令准备位于此前，动画／判定提交位于此后。

失败场景：停顿分支仍推进运动和动画；用递减前的停顿奇偶决定抖动；抖动强度 0／1 被减成负数；屏幕偏置未按 word 回绕；普通分支遗漏清抖动；负生命仍占用轨道；用地面完整定点值判断轨道；两个 byte 计时器错误下溢；状态计时器刚变零时就提前拷贝默认状态；衰减位移与动画时钟顺序颠倒；对副作用范围外字段发生修改；未明确标注角色命令准备尚未包含。

先被动采集完整分支、对照 3,600 帧基线，再用原 CPU 明确的边界输入覆盖计数、生命、轨道和位宽。夹具与测试先于实现，返回值明确表示是否进入普通动作分派，不把停顿分支当作一帧没有任何效果。

## 已验证结果

4,134 个自然阶段中普通分派为 3,974 次、命中停顿为 160 次，观察不改变整帧 RAM／画面基线。另有 144 个原 CPU 隔离用例，覆盖停顿／抖动、两个计时器、生命和地面高 word、位宽回绕、衰减和动画边界。

先生成原版夹具、写测试并验证缺少 `ActionPreludeState / PrepareActionStep` 后，才编写独立实现。所有完整人物 bytes 和占用状态在原生竞态与 Node/Wasm 对照通过。停顿时只更新该分支的剩余时间与屏幕抖动，普通分支按原顺序调用已恢复的衰减及动画时钟。

复跑：`python3 -B scripts/yuyuhakusho/capture_action_prelude.py --out .local/md-yuyuhakusho/action-prelude`。
