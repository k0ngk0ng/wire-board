# 切线运动：实现前失败场景

范围是动作 10／11 对应 `0x19e08`／`0x19ecc` 至 `0x15afc` 共享尾段之前，包含实际落地构造及尘土分配。它与普通空中积分不同。

失败场景：两条轨道共用错误的地面漂移或加速度；显示层级 byte 和深度 word 未回绕；深度按无符号而非有符号比较夹到 256；先积分后更新轨道地面导致落地早一帧；落地比较包含原版不比较的小数；落地时没有规范化地面／层级／深度；忽略尘土分配必须使用规范化后的坐标和层级；把普通跳跃的额外跳跃标志清零套到切线；占用标志没有按方向累加；整段已完成却又执行共享尾段；对象池或人物未知写入被漏掉；连续对照每步重置原初态。

先做自然和明确声明的原 CPU 隔离采样，保存完整角色／池／游标／占用字段，观察不改变同输入整帧基线。另在私有原 CPU 状态中从一次切线初始化连续推进到落地，Go 只能从同一初态开始，不能逐步注入原中间状态；该序列仍不是包含其他角色／碰撞／动画尾段的完整游戏。测试和夹具先于实现。

## 已验证结果

1,029 个自然阶段覆盖两种切线动作和 26 次落地，带观察器的 3,600 帧与同输入未观察原内核完全一致。162 个原 CPU 隔离用例覆盖姿态、池容量、有符号深度、word／byte 回绕和上升／落地边界。

12 条隔离序列从一次切线初始化开始连续推进，长度分别为 52／52／52、23／23／23、58／58／58、26／26／26，共 477 步。Go 只初始化一次角色、池和占用状态，之后用自身上一步输出推进；所有完整人物 bytes、池 bytes、游标、占用和分配结果与原 CPU 一致。序列不包含完整世界的其他阶段，不能当作自然完整对局。

夹具和测试先于 `lane_motion.go`，首次出现缺少 `StepLaneAction` 的编译失败，之后才加入实现。原生竞态与 Node/Wasm 全部通过。切线落地保留额外跳跃标志，不套用普通空中动作的清零规则。

复跑：`python3 -B scripts/yuyuhakusho/capture_lane_motion.py --out .local/md-yuyuhakusho/lane-motion`。
