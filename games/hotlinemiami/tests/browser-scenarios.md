# 正式页面浏览器验收场景

先记录失败场景，再编写浏览器验收与游戏实现。验收不替换游戏时钟、规则、命中、得分或输入接口。HTTP 仅用于建立真实账号和房间；游玩使用 Chromium 原生键鼠／触屏事件。

## 必须失败的情况

- 游戏未默认上架、房间无法创建，或 2 至 4 人无法经统一准备流程开始。
- 内容扩充后没有完整提供 6 张地图、8 个角色造型和 12 类武器，或重复 ID 冒充新增内容。
- 地图、人物或武器只有名称，参考图没有加载，或者修改了其他真人的选择。
- 新增地图只能看参考图，无法真实创建、移动、攻击或完成全屏游玩。
- 新增造型或武器只能在列表选择，实际对局渲染仍使用错误素材或旧装备。
- 客户端在真实素材和画面初始化完成前确认加载；慢玩家重连使全员重新等待。
- 原生输入已经到达而本人移动、瞄准或开火仍在等待网络 ACK。
- 键鼠输入到实际响应帧 P95 超过 33 ms，触屏超过 50 ms。
- 实际可见帧数不足；只报告稳定帧间隔却跳过了应当显示的更新。
- 一端添加 250 ms 往返延迟后，另一端的响应、规则推进或显示被阻塞。
- 快速短按丢失，长按中断后继续移动或开火，后台恢复补播过期操作。
- 合法投掷后已变为徒手，左键／J 无法立即呈现拳弧或没有进入相同的权威击倒规则。
- 重连更换了对局身份，重播旧事件，或者自动把真人交给电脑。
- 电脑或主动托管无法交战、无法完整结束比赛，取消托管重置其他玩家。
- 320 px 手机横向溢出、触屏控件互相遮挡、全屏丢失操作或重新挂载画布。
- 枪击、死亡与计分没有按服务端事件保持顺序，或者结算不能关闭与重新查看。

## 证据与复跑

入口为 `python3 -B games/hotlinemiami/tests/accept_browser.py`。需要先构建正式前端和资源。测试在 `.local/hotlinemiami/browser/` 建立独立 SQLite 服务、浏览器 profile、Go 缓存和 transport 控制文件；所有路径均在仓库内。

输出包含 `report.json`、原生事件与响应记录、帧时间、协议观察、网络条件、实际截图和 JSON／CSV 指标。原生输入响应计时同时要求本地渲染状态变化和画布像素变化；ACK 延迟单独保留。手机触屏由 Chromium CDP 原生触屏仿真发出，不宣称实体手机硬件实测。

内容矩阵按正式素材清单逐张运行全部 6 图，轮换 2／3／4 人与 1440／390／320 px 视口。每张图均通过原生移动与攻击，核对 8 个造型和 12 类武器的参考图与服务端选择结果；最后一张执行完整自然结算和正常／慢连接并存验证。原 3／5／7 内容的 `reports/final2` 仅作为历史基线，不能替代扩容后的结果。

正常网络以不超过 80 ms RTT 和 20 ms 抖动为预算；验收使用实际 TCP 传播延迟，并在报告中记录 HTTP 探针、WebSocket 观察和输入响应。快速端和慢速端使用独立代理入口，慢端不改变快速端的网络。

## 生产最小验收

只有部署完成并核对目标版本后才启用生产模式。`HOTLINE_BROWSER_PRODUCTION_CONFIG` 指向 `.local/hotlinemiami/release/` 中权限为 `0600` 的配置文件，字段为 `origin`、`invite`、`expectedVersion`；执行同时要求 `HOTLINE_BROWSER_ALLOW_PRODUCTION=confirmed-deployed`。邀请码、账号密码和房间密码仅经进程标准输入传递，不进入命令参数或公开报告。

生产模式使用两个专用临时账号，分别验证带密码的真人双人房和真人／电脑双人房，检查默认上架、参考图、真实加载、PC 键鼠、320 px 触屏、原生音频管线、全屏与稳定操作。网络不注入延迟，也不修改普通用户的管理设置。完成后先关闭并离开本次房间、注销测试会话；精确账号与房间 ID 存在私密 `browser-identities.private.json`，由发布流程按 ID 清理测试记录，不按名称前缀批量扩大删除范围。

本地调试可使用 `HOTLINE_BROWSER_SKIP_FINISH=1`，此模式不证明完整比赛结算。`HOTLINE_BROWSER_DIAGNOSTIC=1` 只允许在已经保留失败指标后继续独立检查，报告仍标记失败；不能用于放宽性能阈值或替代正式验收。
