# 浏览器输入与呈现场景

先建立这些失败场景和验证，再实现客户端。正式平台多浏览器验收由独立测试入口覆盖。

- WebSocket 未就绪、观战、托管和结算时不发送或积压输入。
- 前一条请求未确认时，后续移动和射击仍能采样；投掷、拾取、处决的短按不被移动合并丢失。
- 已收到序号与已应用序号分开处理；迟到快照不能降低本地序号。
- 换席位、重生和重连后不重发旧生命输入；旧请求失败不能影响新身份。
- 主动托管使输入停用时立即切换传输代次，丢弃旧队列；取消托管后旧请求失败或完成不能显示错误、释放新代次的发送信用或重用旧序号。
- 中断必须释放移动和攻击，不能在后台恢复时补播旧攻击。
- 预测不依赖 ACK，150 ms 后冻结本人预测，普通确认不能重置显示时钟。
- 复活后的中性保活与静止瞄准不占未来移动步；权威连续前推超过尚未应用的方向后，下一显示仍须重放一帧移动，不能等待该方向的 ACK。
- 固定鼠标在相机边缘移动时，新增输入的即时预测步之后再按最终人物／相机姿态计算瞄准；同一输入包与下一绘制角度一致，不能残留前一姿态的角度。
- 回滚只重放未确认输入，死亡立即使用权威状态。
- 同一事件只播放一次，恢复时不补播历史声音。
- FLAC 效果音元数据时长仍未知时，应从头实际播放；不请求基于时长的 seek，不因复用选项在开始阶段销毁声音。
- 同一效果事件的 playbackID 不重播，新事件沿既有 8 条有限 lane 替换；不能用背景音乐的播放成功代替效果音验收。
- 本地枪口反馈使用共享规则武器元数据，受权威冷却、倒地与处决约束；空弹药和未确认最后一发不能产生额外开火。
- 合法投掷后徒手攻击在下一绘制显示拳弧，不扣弹药；徒手冷却取共享规则独立元数据，不加入 12 类可选武器数量。
- 投掷、拾取、处决和互动在下一显示帧有本地姿态或目标高亮；不改变权威武器归属、伤害或门状态，按序号和生命去重，150 ms 内结束，失焦／死亡清除。
- 选项按钮不提交创建表单；本人只能选自己的造型，房主可以选电脑造型。
- 地图、人物、武器均显示参考图；资源失败不能提前确认就绪。
- 扩容后创建与等待房间提供 6 张不同地图、8 个造型和 12 类武器；新增近战仍显示「近战」，不误报 0 发。
- 玩法速查按地图、武器、造型、操作与对局分组，覆盖每个开放 ID 的实际特点；明确造型同属性／同碰撞、枪械不能装填、投掷击倒、处决风险、复活保护、和局与托管。
- 地图 6 图仍为紧凑图卡，角色和武器沿用单一图示选择器；320 px 玩法速查折叠展开无横向溢出。
- 平台 CSP 禁止图像与脚本的 blob URL，已验证资源须经无 URL 的位图解码及同源脚本初始化，不能为素材加载放宽公共 CSP。
- 手机 320 px 多指操作互不覆盖，所有控制和全屏结算可见。

针对性验证覆盖纯输入排队、事件去重与共享规则预测时钟；正式房间验收覆盖实际 Canvas 像素和原生键鼠／触屏响应。
