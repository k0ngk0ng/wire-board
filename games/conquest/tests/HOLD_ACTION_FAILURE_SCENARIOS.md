# 图标长按：先行失败场景

本清单与 `hold-action.test.mjs` 先于实现。纯控制器测试隔离输入时序，真实按钮、原生触摸／鼠标与游戏动作仍由地图 E2E 验证。

- 轻触／短按被计时器重复触发；650ms 前误执行长按；持续按住反复执行。
- 长按完成后浏览器又发 click，导致额外执行短按、再次扣金币。
- 长按不可行或回调失败时退化为短按；Promise 拒绝无人处理。
- 移动超过触摸容差、拖出按钮、pointercancel、丢失捕获后还执行动作；返回按钮又把同一次手势当新短按。
- 禁用、身份／回合／选区变化、失焦、页面隐藏、卸载后仍使用旧状态执行；网络很快结束并重新启用后，旧 pointerup/click 又下单。
- 第二指加入（包括另一按钮上）、多输入交叠或重复 pointerdown 后两个动作都执行。
- Shift+Enter 与长按不等价；按住键产生重复 keydown；普通 Enter／Space 丢失或被旧指针抑制标记吞掉。
- 在 Space 按下与抬起之间切换选区，释放时误操作新领地。
- React 更新后调用旧闭包；取消定时器之后已经排队的回调仍执行。
- hook 卸载／StrictMode 重新挂载后残留监听器或永久禁用。

长按不可行的具体原因由游戏回调说明。控制器只决定一次输入对应短按还是长按，永不决定资源、规则或战斗结果。短按和长按都必须进入同一个平台动作接口。
