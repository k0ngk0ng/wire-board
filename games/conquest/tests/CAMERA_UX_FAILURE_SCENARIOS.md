# 镜头与触控先行失败场景

本清单与浏览器验收夹具先于镜头改动编写。使用实际 React hook 和世界地图的 206 个地区，配合 Chromium 原生 CDP 鼠标／触摸事件核验。夹具只用于隔离呈现瓶颈，不代替整款游戏的端到端验收；最终真实游戏由地图交互验收覆盖。

- 单指在一个 SVG 地区起触，第二指落在另一个地区时丢失第一指，无法放大。
- 一指先按住，第二指稍后加入；两指同时落下；手指跨越 SVG 子元素、标签或地图边界时丢失触点。
- 双指中点移动导致缩放锚点漂移；第二指先松开后单指拖动跳跃；三指加入或取消时产生无穷缩放。
- 一次输入触发多个 React 更新，拖动过程中重复渲染全部地区；同一帧多个输入没有合并。
- 地图图层、屏幕标签和小地图窗口的变换不同步；手势结束后 React 提交把地图倒退到旧位置。
- 小地图位于地图视口内时，原生 touch 事件与 React pointer 事件走不同传播路径，主地图误将小地图拖动当成平移并覆盖定位结果。
- 手指抬起、取消、失焦、页面隐藏或卸载后继续输入；滚轮停顿没有提交最终状态。
- 单次轻触失去正常地区点击；拖动或双指结束后误触进攻；新的轻触被上一轮抑制标记永久拦截。
- 只限制8倍全图缩放导致320px下小地区仍无法准确观察；极端滚轮输入越界或露出地图外空白。
- 滚轮在地图外仍被拦截；地图内滚轮不能按鼠标位置缩放；鼠标松手丢失导致继续拖动。
- PC 从地区路径或兵力文字起手时左键拖动失效；拖出地图到页面后松手未释放；之后无按键移动仍拖图或正常点击一直被拦截。必须记录真实命中元素与原生可信 pointerdown。
- 初始全图 fit 时 clamp 强制居中，鼠标／触摸虽然收到事件但始终零位移；验证不得先放大再拖动掩盖此问题。平移余量须有界，复位仍精确居中，小地图视窗须显示实际可见交集。
- 页面尺寸变化后地图位置、命中坐标或比例失效；只有宽度变化时忽略动态浏览器工具栏的高度变化。

证据写入 `.local/conquest-camera/`，保存输入事件计数、React 提交数、变换采样、帧间隔、截图和执行结果。Chrome CDP 移动视口不是手机真机，也不能冒充 WebKit 验证。
