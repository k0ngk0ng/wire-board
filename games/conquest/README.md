# 征服时代

2～8 席同时规划的区域征服游戏，默认世界地图。世界地图 206 个地区，欧洲及地中海周边 75 个地区，美国 50 州及华盛顿特区共 51 个地区，中国按 34 个省级玩法区域组织；四图共用规则与电脑策略。玩家经营领地、征募军队、安排陆路与海路行军，并在所有存活势力提交后统一执行指令。消灭其他势力、成为最后一个存活势力即获胜，不要求继续占领剩余中立地区。

## 参考与实现边界

用户识别的参照为早期 iOS《Age of Conquest: World》《Age of Conquest: Europe》。本实现使用官方仍公开提供的旧版桌面 Age of Conquest III 3.0.5318 的手册、教程、执行代码与原类探针作为交叉参考；没有取得同版本 iOS 程序，不能宣称与 iOS 原版逐项一致。证据和手册／程序差异见[旧版规则研究](../../docs/research/conquest/legacy-rules.md)。不使用第四代规则。

运行时为 Go 服务端与 React／TypeScript 前端，不依赖 Java。Java 仅用于开发阶段调用旧版原程序核对规则；原 JAR 和反编译中间文件不进入应用构建或镜像。

本版选择自由争霸和无外交模式，平台容量限定为 2～8 席。税率可调整，经济与军费支出率固定为 80%。默认公开兵力，可开启战争迷雾；公开模式不提供无实际作用的瞭望塔建设。地图以 Natural Earth 公有领域数据独立制作，部分大国按地理方位细分，地区不是精确行政区，也不冒充原版商业地图。电脑使用正常资源和公开操作接口，不复制原包部分难度的额外金币。封面与音效为项目原创。

## 开局与操作

统一创建房间第二步选择世界／欧洲／美国／中国、电脑难度、60／120／180 秒规划时限和战争迷雾。新房间默认世界，已有房间保留保存的地图。美国的阿拉斯加与夏威夷使用插图布局，中国的港澳提供放大示意，地区逻辑连接仍按真实地理关系定义。等待房间沿用平台添加电脑、准备和开始入口；已开始对局不可更换地图或规则。

每个势力从一个带城镇的地区开始，拥有 500 兵、5,000 金币和 3.2 行动点。各方先规划招募、建设、税率、解散及行军；计划仅本人可见，可撤销单条指令，依赖它的无效后续指令也会移除。提交后可在结算开始前撤回，不重新获得完整规划时间。全部提交后先执行经济与建设，再执行解散和按优先顺序排列的行军，最后进行回合经济更新。

点击己方领地后，在地图中的图标栏选择征兵、进攻或筑堡。征兵默认选择当前合法上限的一半，派兵默认选择剩余可移动兵力的一半，奇数向上取整。滑块支持鼠标、触屏与方向键，也可直接输入精确人数；「一半」按钮恢复动态半数。征兵选择后确认，进攻选择后点相邻领地。手动人数在普通快照中保留，换领地、换操作或新一轮后恢复默认；上限减少时按剩余可用人数收紧。

未手动调整时，连续进攻依次派出剩余的一半，例如 1,000 兵依次派出 500、250、125。手动数量随每次点击入队，后续调整不会修改已排队的指令。每次派兵使用原规则行动点，相连海路另付每兵 2 金币；海费不足时不下单，不静默改成少量兵力。连续快速点击会依次等待服务端确认计划。

选中己方领地后显示预计剩余人口与当前可征人数。可征人数受金币、单次不超过剩余人口一半、驻军容量及行动点约束；不足时显示具体原因，仍可打开人数面板查看。征兵与派兵各消耗 1 行动点，筑堡消耗 0.5 点。计划按钮下显示已用／总行动点，随规划、撤销和新一轮更新，不将免费税率计划算成一步。

长按筑堡可直接建城镇，不要求先修工事；资金或行动点不足时提示原因，不回退成短按扣费。键盘 `Shift+Enter` 等价长按。地图和君主按钮使用同一款带金色底座、冠齿与宝石的皇冠。

君主随军、瞭望塔与解散也通过选区图标操作；计划按钮用于查看和撤销，金币入口保留次要的财政与税率设置。无需使用常驻数量输入框或目标下拉。君主进攻失败时仍留在出发地；工事、城镇和君主提供防御加成。君主失守时按剩余领地数进行割地继承，小国会淘汰；完整公式和边界见研究记录及[接口契约](CONTRACT.md)。

PC 支持左键拖动、滚轮以鼠标位置缩放、键盘选择与确认；手机首次进入时镜头靠近己方君主，支持连续双指放大／缩小、双指改单指和取消手势，最多放大到全图尺度的 32 倍。全图按钮保留总览，小地图可连续拖动定位。手机选中己方领地时，应用确保行动图标处于可视区；连续点击进攻目标不自动移动镜头。

地图保留第一版的平面分区、领土配色和轻纹理，不引入立体地形。地图不再给每块中立地区放置常驻数字框；军队旁使用轻量兵力文字，点选中立领地查看守军。镜头在手势期间按帧更新变换，结束后再提交 React 状态，避免每次移动重绘全部领地。行军与占领仍由服务端时间线驱动，刷新不会重播旧事件。

## 电脑、恢复与暂停

所有开放人数、地图和可见性模式支持平台电脑玩家与真人托管。策略只使用该席位可见的数据，不读取敌方计划或隐藏军力，不直接修改资源和结果。取消托管保留局面与其他玩家期限。淘汰者可通过平台离桌，原席位与最终战绩仍保留。

所有存活真人同意后暂停，电脑视为同意；暂停停止电脑与时钟，并保存计划和各席剩余操作时间。恢复也需要存活真人同意，电脑不会主动恢复。明确暂停的房间保留 30 天，普通房间仍遵守连续 24 小时无人操作自动关闭规则。到期关闭不计胜负或积分。含电脑对局沿用平台不计竞技积分规则。

存档绑定规则 schema、地图 ID、版本和 SHA-256。升级后不能静默以新地图替换旧局；地图身份不匹配时明确拒绝。地图与游戏模块按需加载，统一加载屏障等待全部真人实际就绪；观众和电脑不阻塞，重连不重新暂停其他玩家。

## 验收复跑

从仓库根目录运行，全部缓存与证据留在仓库 `.local/`：

```sh
. scripts/env.sh
node --test games/conquest/tests/*.test.mjs
go test -count=1 -timeout=15m ./games/conquest/server ./games/conquest/maps
go test -count=1 -parallel=4 -timeout=45m ./games/conquest/tests
go test -race -count=1 -timeout=5m ./games/conquest/tests -run 'Concurrent|Pause|Loading'
WIRE_BOARD_CONQUEST_SCHEDULED=1 go test -count=1 -timeout=26m ./games/conquest/tests -run '^TestConquestAutoPlayMixedCompleteHTTP$'
python3 -B games/conquest/tests/accept_map_ux.py
python3 -B games/conquest/tests/accept_camera.py
python3 -B scripts/check_game_boundaries.py
```

完整 HTTP 对局使用真实账户驱动生产电脑策略以减少宿主电脑行动间隔，所有操作仍经过 HTTP、鉴权、版本校验和 SQLite 事务。另一个显式入口使用真实平台电脑席位与真人托管，按正常调度节奏完成对局。两类记录分别标注，不互相冒充。

`.local/conquest/http/` 保存初始状态、每步动作／时钟／快照摘要和最终结果；验收从初始状态逐条重放并检查摘要一致。模块电脑矩阵位于 `.local/conquest/rules/bots/`。新版浏览器截图、原生输入、实际可见性与连续镜头采样位于 `.local/conquest-map-ux/browser/`；旧版实测基线在同目录的 `baseline/`。独立镜头证据位于 `.local/conquest-camera/`。原 `accept_ui.py` 转发到新入口，不继续依赖已移除的表单。

浏览器验收独占本地构建目录及测试服务，勿与另一轮构建或验收同时执行。`accept_map_ux.py --baseline` 仅在已有旧版 `baseline-dist` 时使用，会临时替换生成的 `web/dist` 并在结束后恢复，不改动源码。公共暂停的独立 HTTP／竞态证据位于 `.local/module-pause/`。仅前端改动运行本游戏前端、地图／素材和实际操作验收；服务端规则未变时不重复完整规则矩阵。最终结论以修复完成后的结果为准。
