# 原始素材提升分辨率评估

可以先把小图拼成图集，每张图集独立调用一次 GPT-Image-2.5 编辑，再按记录的坐标切回单帧。排布测算中，宽高均变为 2 倍时，不留白可达到 30 次；宽高均变为 4 倍时，可排成 120 次，面积下限为 118 次。动画帧之间保留每侧 4 个原始像素的透明留白后，分别需要 36 次和 145 次。以上均不包含试样、重试和返工，也不代表模型已经通过动画一致性验收。初始测算不调用模型，后续实际执行情况见末节。

## 素材口径

统计覆盖当前竞技场全部候选、骑乘与武器造型，以及实际引用的战斗背景和菜单。逐帧 PNG 按路径去重，共 9,477 张、27,407,895 字节（26.14 MiB），不是每场对局的下载量。

| 类别 | 图片数 |
| --- | ---: |
| 宠物与骑宠本体动画 | 4,699 |
| 人物骑乘动画 | 1,096 |
| 人物与武器造型动画 | 3,616 |
| 装备图标 | 57 |
| 战斗菜单图标 | 8 |
| 战斗背景 | 1 |
| 合计 | 9,477 |

按文件 SHA-256 再去重，有 3 个重复文件，可共用增强结果，实际需处理 9,474 张不同图片。不同图片原始像素总和为 60,785,828，最大单图为 640×480。统计依据是 `web/art.json` 与源目录中的 PNG 头部，没有复制原始图片。

## 模型边界与请求定义

OpenAI Docs 当前提供 `gpt-image-2.5-sunburst` 和 `gpt-image-2.5-flare`。下表按两者共同的输出尺寸边界计算：宽高均为 16 的倍数、长宽比在 1:3 至 3:1、单边最多 3,840 像素、总像素最多 8,294,400。2880×2880 和 3840×2160 都恰好达到这个像素上限。超过 2560×1440 的输出属于实验分辨率，需要试样验证。[来源：图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)

本报告把「一张独立图集、一个编辑任务、一个输出」计为一次请求，即 `n=1`。编辑接口允许最多 16 张输入参考图，`n` 最多为 10；这些参数不能直接解释为「16 张输入各自增强」或「一次请求完成 10 个不同图集任务」。官方没有承诺多个输入与多个输出一一对应，因此不能把 30 次直接除以 10，声称只需 3 次。[来源：Images edit API](https://developers.openai.com/api/reference/resources/images/methods/edit)

## 排布测算

| 方案 | 宽高 2 倍 | 宽高 4 倍 | 含义 |
| --- | ---: | ---: | --- |
| 纯像素面积下限 | 30 次 | 118 次 | 忽略留白与形状，`ceil(原始总像素 × 倍率² / 8,294,400)` |
| 全局紧密合图，无留白 | 30 次 | 120 次 | 已验证坐标无重叠；2 倍达到面积下限，4 倍未证明最优 |
| 全局合图，每侧留白 4px | 36 次 | 145 次 | 便于切图并减少相邻帧干扰；2 倍达到这个留白假设下的面积下限 |
| 每个精灵造型独立合图，每侧留白 4px | 167 次 | 239 次 | 尽量让同一人物或宠物的帧集中处理，包含独立图标组和背景 |

「2 倍」「4 倍」指宽、高分别乘以倍率，像素面积分别变为 4 倍、16 倍。留白 4px 使用原始坐标，输出分别变为每侧 8px、16px。紧密合图追求较少请求，相邻帧可能互相干扰，不作为已验证质量的生产方案。

排布使用确定性的高度降序货架算法，不旋转图片。遍历方形、横向和纵向三种最大图集，保留请求数较少的结果，并逐项校验全部不同图片恰好出现一次、没有越界、没有重叠。面积下限之外的结果是可执行排布，不能据此声称已求得数学上的最少次数。图集坐标与重复文件映射保存在 `.local/stoneage/upscale/atlas-plan.json`。

如果把输出限制在 2560×1440 范围内，2 倍、每侧留白 4px 的全局排布需要 82 次。4 倍后的背景为 2560×1920，需更大输出或分块，因此不能直接套用同一范围。完整候选尺寸和限制见 [upscale-estimate.json](upscale-estimate.json)。

## 建议与验收

建议先以 2 倍作为目标，按每侧留白 4px、36 个独立编辑任务估算请求预算。先从这些图集中选一个样本，包含人物、骑乘、宠物、方向 3／7 和攻击、待机、受击、死亡动作，验证后再处理其余图集；合格的试样可以计入这 36 次，失败重试另计。

GPT-Image 属于生成式编辑。它能增加细节，但没有承诺逐像素保留每帧姿态、透明轮廓、脚底位置和图集坐标；仅提高输出分辨率也不能证明原始细节被准确恢复。大图集中数百帧可能漏帧、串格或风格漂移，逐帧看似合格时，连续播放仍可能闪烁。

正式替换前需要验证固定画布、透明背景、每帧裁切边界、原始动作与方向、脚底锚点，以及完整循环播放。下载后再次核对输出实际尺寸，坐标不符合预期的结果不得直接写入素材索引。渲染须保留原来的逻辑尺寸与帧偏移，避免高分辨率图片导致人物体积或落脚位置改变。普通确定性放大应作为对照基线，用来判断生成细节是否值得引入这些变化。

排布脚本仅测算，不生成、覆盖或上传图片。以后若采用增强素材，应使用独立、可回退的版本地址，保留现有 CDN 资源。

## 复现

从当前仓库执行，源 StoneAge 目录保持只读：

```sh
python3 -B games/stoneage/tools/audit_assets.py
python3 -B games/stoneage/tools/estimate_upscale.py \
  --source /path/to/stoneage \
  --manifest .local/stoneage/upscale/atlas-plan.json
```

脚本只读取 PNG 头部、计算坐标和输出 JSON，不生成图集，不请求模型。统计结果绑定 `web/art.json` 的 SHA-256，索引更新后应重新运行。

官方型号说明：[Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst)、[Flare](https://developers.openai.com/api/docs/models/gpt-image-2.5-flare)。

## 当前 CLI 的执行核查

首张合图已用 `gpt-image-2.5` 通过 imagegen 技能自带 CLI 实际编辑。输入为 2880×2880，`size=auto`，提示词要求保留该尺寸；实际返回 1254×1254，低于 1440×1440 的原始合图。透明边缘还存在彩色杂边，未提升为可替换帧。本次观察不能据此认定所有 GPT-Image-2.5 接口都具有相同输出限制。

现有 CLI 仅在模型名恰好为 `gpt-image-2` 时启用自定义尺寸校验；两款 2.5 只能传 `1024x1024`、`1536x1024`、`1024x1536` 或 `auto`。这与官方模型本身支持自定义 4K 尺寸是两个不同层面的能力。用户已选择继续沿用现有 CLI，以小合图增加请求数量，不另写 API 调用程序。

最终采用 768×512 原始坐标、每侧留白 4px 的小图集，目标 1536×1024；动画和图标共 191 个图集，背景另处理一次，已导出完整的 9,477 张 2 倍 PNG，共 413.73 MiB。两次大图尺寸试验均返回 1254×1254，未计入可用高清图片；实际共执行 194 次编辑任务。正式小图集采用 `gpt-image-2.5-sunburst`。

导出使用原始透明轮廓和灰色投影，逐帧局部对齐后裁切，保持原有逻辑尺寸、偏移、方向与 tick。全部图片通过摘要、物理尺寸和原始 Alpha 独立回读，按钮另核对蓝色正常／红色按下状态。原图与高清帧提供同步播放页；自动检查不代表模型已经逐像素恢复原始内部细节。

客户端的 `web/hd.json` 保存新版本的地址与真实摘要，原来的 `art.json` 继续提供逻辑帧信息。图片发布到同一石器 CDN 根的独立版本，原始对象不覆盖；实际加载与容量、2 倍 Canvas、手机和全屏通过浏览器验收。

官方标准定价中，`gpt-image-2`、`gpt-image-2.5-sunburst`、`gpt-image-2.5-flare` 的图像输入均为 $8／百万 token，图像输出均为 $30／百万 token；换成 2 不代表单价更低。同单价也不保证同一次任务消耗相同 token，实际兼容服务的费用须以其计费为准。Sunburst 侧重编辑精度，Flare 侧重速度；当前逐帧恢复优先验证 Sunburst，以减少错位和返工。[官方价格](https://developers.openai.com/api/docs/pricing)
