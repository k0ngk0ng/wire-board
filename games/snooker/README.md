# 斯诺克

纯 2D 俯视、标准十五红球，支持 2 人单打和 4 人双打；可选单局决胜、三局两胜和五局三胜。游戏独立维护物理、裁判、界面及素材，沿用平台大厅、等待房间、玩家栏和音效通道。默认下架，由管理员上架后才能创建。支持电脑玩家及真人托管；需要操作时有 120 秒倒计时，超时自动托管，不因超时本身罚分。球运动时不计操作时间，取消托管后可继续手动操作。

## 玩法

红球 1 分，黄、绿、棕、蓝、粉、黑分别为 2～7 分。红彩交替，最后一颗红球后仍可打一颗自选彩球，再按黄至黑清彩；合法进球继续击打。普通犯规给对方加 4～7 分，同杆多个犯规取最高适用罚分。白球在手时从 D 区摆放。

实现自由球、有效遮挡球判断、彩球占点复位、贴球、Miss 原位重打、具备规定直线路径时的连续未中警告、黑球平分决胜及双方同意重新摆球。原位重打保留罚分，并固定恢复后的白球位置。仅剩黑球且当前一方领先超过 7 分，可宣告本局胜利；普通超分不会自动结束比赛。

认输本局须符合有人需要罚分才能取胜的条件，双打须由搭档共同确认，对方仍可选择继续打。另有「弃赛本场」，明确退出并判负整场比赛。独立确认支持同一决策窗口内的并发请求，不要求搭档因另一人先确认而再次点击。

双打可在等待房间选择分组。每队共用比分和胜局数，按照整次上手机会轮换，例如 A1 → B1 → A2 → B2。连续进球不换人；犯规后要求重打仍由原犯规者执行。两队交替开局，每局开始前可调整队内顺序。

规则依据为 [WPBSA 官网提供的 2024–25 版规则书](https://www.wpbsa.com/rules/)。来源与条款核对见 [调研文档](../../docs/research/snooker.md)。

## 自动裁判与物理边界

球台内沿为 3.569 × 1.778 米，球直径 52.5 毫米。服务端以连续碰撞检测处理球、有限库边、袋口和圆角接触，模拟滑动／滚动摩擦、高低杆和侧旋。每杆只提交方向、力度、击点及必要的提名；客户端不提交球位、进球或得分。

现实裁判对「尽力击中」和行为意图的判断，按公开的自动判据执行：直接路径采用角度区间检测；无直接路径时搜索最多四次库边反弹的候选，并以实际击球模拟确认。结合是否需要罚分的例外决定 Miss；没有证实可执行路线时，保守地只计普通犯规，不声称数学上证明了所有路线都不可行。D 区自由球判断使用可见区域边界与合法摆球位置，避免只取几个采样点漏掉狭窄可打位置。

球杆只有一次瞬时击球，不提供跳球或抬杆操作；界面为二维，球台物理参数固定，不宣称复刻某一张职业比赛球台的材质。搭档交流规则写入玩法说明，平台保留普通牌桌聊天，不推断玩家在外部的交流或行为意图。

球运动按服务端轨迹播放，球停稳后统一结算并复位彩球。轨迹只保存变化球位，坐标和时间不作有损压缩；持久化包含轨迹完整性校验。刷新不重算旧杆，旧声音与旧复位提示不重播。

## 操作与视觉反馈

- 按住球桌并移动鼠标／手指调整方向，力度条往返变化，松开击球；短点按只调整方向。移出球桌或按 Esc 取消蓄力。键盘方向键调整方向，按住空格蓄力、松开击球。
- 切换「移动视图」后，鼠标或触屏拖动平移；滚轮按光标位置缩放，触屏支持双指缩放。缩放、失焦、切换回合及取消手势会取消蓄力，不提交击球。
- 手机采用纵向球桌和局部瞄准放大镜；显示和碰撞使用同一球径比例。
- 有出杆、滚动、碰撞、落袋和彩球复位提示；减少动态效果时取消装饰性出杆和闪烁，保留理解结果所需的球运动。
- 音效通过平台 `BoardProps.audio`，统一静音、媒体音量及离桌清理。恢复隐藏页面或取消静音不会补播已经发生的碰撞。

## 素材与可重复制作

10 个原创二维图像：独立封面、台呢、八种球色。22 个 MP3：击球、落袋、犯规、胜局，以及球碰球／碰库各三档力度、三个变体。外部原件来自 [Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds)，CC0；提示音为项目合成。没有使用 3D 模型、商业游戏录音或赛事录音。

- `assets/source/`：SVG、采用的音频原件与许可。
- `assets/source-manifest.json`：外部来源、原件和许可校验和。
- `assets/manifest.json`：生成方式、成品路径和 SHA-256。
- `assets/public/snooker/v1/`：明确允许公开并随前端打包的文件。

从仓库根目录执行；需要已有的 Node.js、FFmpeg 和 `cwebp`：

```sh
. scripts/env.sh
npm --prefix web ci
npm install --prefix .local/snooker/rasterizer --no-save @resvg/resvg-js@2.6.2
node scripts/snooker/render-assets.cjs
python3 -B scripts/snooker/prepare-audio.py
```

正式 OSS 前缀为 `bga/v20261002-1/snooker/v1/`。发布后不得覆盖已有对象；修改素材须使用新版本目录。本地公共文件和 Canvas／SVG 继续提供回退。

## 电脑策略与验收

电脑使用公开球位生成进球、合法接触、自由球与隔库候选，通过本地物理模拟选择击球，再提交普通操作。单打和双打均支持单局、三局两胜、五局三胜；双打按整次上手轮换。策略能处理开球、D 区摆球、犯规后接打、黑球决胜、局间准备及对方认输。它是基础电脑策略，不保证职业级走位或在所有复杂遮挡局面找到最佳解法。

`go test -v -count=1 ./games/snooker/tests -run 'TestSnookerBots|TestSnookerComputerSeatsHTTP'` 验证生产策略、六种人数／赛制组合、特殊阶段和真实托管接管。完整 HTTP 对局使用 `WIRE_BOARD_SNOOKER_HTTP_FULL=1`，沿用真实系统时钟。结果写入 `.local/snooker/verification/` 和 `.local/poker/snooker/http/`。直接击球操作通过 `python3 -B scripts/snooker/check-gesture.py` 验证，截图与报告保存在 `.local/snooker/gesture/`。

本次补充验收：六种人数／赛制组合共完成 18 局自然电脑对局；真实 HTTP 单打和双打各完成 1 局，包含手动接管与 SQLite 恢复。331 项前端测试通过；桌面及 320px／390px 的直接击球、原有界面和进球反馈共保留 31 个浏览器检查点。证据总表位于 `.local/snooker/computers-controls-verification.json`。

超时计时按待操作席位独立保存，摆球与非阻塞投票不延长击球时间。局间已准备的玩家不再计时；取消超时托管只恢复本人的操作时间。旧版无时钟的活跃对局在加载时一次性补上倒计时，后续重启保留原期限。`TestSnookerTimeoutAutoplayHTTP` 使用真实 120 秒时钟验证自动接管，`TestSnookerLegacyClockMigrationHTTP` 验证存档迁移；证据仍保存在 `.local/poker/snooker/http/`。
