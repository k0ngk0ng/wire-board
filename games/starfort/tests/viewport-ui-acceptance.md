# 星垒地图视区与清晰度验收

以下失败场景先于实现列出，使用真实 HTTP 房间、生产前端和 Chromium 原生输入验证。

- 普通 PC 地图仍被旧高度换算的宽度上限压成小框；1366×768、1920×1080、2560×1080 分别记录地图实际尺寸、宽高比和房间内容宽度占比。
- 原生全屏或页面回退全屏保留普通模式的尺寸上限，地图周围出现大块空白；地图须填满扣除资源、波次、操作与导航后的主要空间。
- 320×740 手机或 740×320 横屏中，关键资源、倒计时文字或主要按钮被裁切、遮挡、低对比度或挤到视口外。
- 全屏入口错误出现在等待房间，或进入后包含公共房间菜单、标题、玩家栏；退出未恢复滚动、焦点或 inert 状态。
- 全屏切换重新挂载 Canvas，清空选中的塔或重置房间、波次、对局数据；弹窗 portal 脱离全屏目标。
- 原生鼠标滚轮未缩放、滚动了页面，左键拖动或小地图连续拖动不生效；鼠标位置缩放锚点漂移。
- 真实浏览器触屏拖动、双指缩放、点击塔身建造／升级失败，或拖动误开弹窗。
- 地形与道路、水面混为一色，塔和敌人轮廓不清楚；文字最终计算对比度不足 4.5:1，关键非文本边界不足 3:1。
- 选择或建塔弹窗切换全屏后丢失、无法关闭／重开，ESC 或退出按钮不能恢复普通视图。

运行前先构建与待验收源码匹配的前端。修改实现前运行 `--baseline`，保存旧构建的测量结果；完成实现并重新构建后，运行正常验收：

```sh
npm --prefix web run build
python3 -B games/starfort/tests/accept_viewport_ui.py --baseline
python3 -B games/starfort/tests/accept_viewport_ui.py
```

脚本默认只运行星垒浏览器夹具，不重建前端、不运行其他游戏。`--baseline` 保存旧实现同一几何检查的失败清单和截图；正常运行必须通过全部检查。可通过 `STARFORT_VIEWPORT_OUT` 指定仓库内产物目录，通过 `STARFORT_VIEWPORT_CACHE_ROOT` 复用已有 Go 缓存。嵌套工作树路径过长时，通过 `STARFORT_VIEWPORT_SOCKET_DIR` 指定任务目录内较短的浏览器套接字路径。产物含来源摘要、构建摘要、命令记录、每个尺寸的几何／对比度、原生输入记录和截图。

夹具说明：`stage4` 跳过前序波次，提供多路线战场；`natural`、`growth-vote`、`battle` 提供准备、特殊选择和有塔场景。`--visual-only` 保留战场近景和实际选择河流路线后的截图，用于对照地形、道路、塔和敌人的轮廓。此验收证明布局、视觉和交互，不宣称自然完整通关。手机指 Chromium 的 320px 视口及 CDP 原生 touch 输入，不代表物理手机或 Safari。
