# 星垒战斗节奏、射程与全屏聊天验收

## 实现前失败场景

- 200ms 规则步长把不同攻击间隔向上取整；升级后面板间隔变短，实际发射仍同频。
- 多个 shot 在一个网络快照到达时同帧播放，丢失服务端 `atMS` 间距；连续命中使 HP 一次跳到快照末值。
- 生命或护盾在弹丸抵达前变化；同目标多次命中顺序错乱；刷新、重连重复播放历史 shot。
- PC 悬停或键盘聚焦塔身不能查看射程；点击塔只能弹出遮暗模态，遮住战场；320px 手机操作面板挡住射程或主操作。
- 射程选择与升级、出售耦合；升级／出售无效、出售后射程或命中区残留；拖动塔身误开菜单。
- 全屏后聊天入口或面板留在全屏目标外；普通／全屏切换丢失草稿、消息或未读状态。
- 聊天输入空格、Enter、Escape 误触游戏；全屏消息不能发送或另一真人不能收到。
- 手机右下聊天、重置／缩放、支线及塔操作互相覆盖；只检查 DOM 存在而未检查实际命中与矩形。
- 左上生命／波次／金币和状态分成两个大卡，重复信息遮挡战场；桌面无法保持一行紧凑信息，手机超过两行，倒计时字样实际裁切或被遮挡。
- 退出全屏重挂载 Canvas，丢失选塔；ESC／退出按钮残留 `inert` 或滚动锁；建造／更多详情弹窗跑到全屏目标外。

## 可重复验证

`python3 -B games/starfort/tests/accept_combat_controls_ui.py --skip-build`

先运行同一前端构建，再启动真实 HTTP fixture。浏览器操作走原生鼠标／触摸；只读测量 Canvas 绘制、矩形及 WebSocket 事件。fixture 的 stage4／cadence 场景只设置可重复的中途状态，不代表自然完整通关。生产规则完整对局、竞态测试由规则测试另行记录。

产物包含 `result.json`、源文件及构建 SHA-256、命令记录、服务端事件／实际绘制时间、PC 与 320px 截图。`--baseline` 仅记录原版问题，不将已知失败计为通过。

可用 `--ui-only` 或 `--combat-only` 进行针对性复测。正式验收运行默认范围；源码在验收期间发生变化时，结果不能标记为通过。

`--baseline-combat` 将已发布前端连接到当前测试服务端，只用于隔离前端批量播放问题，不代表旧服务端的攻击间隔。它与 `--baseline` 分别写入独立目录。
