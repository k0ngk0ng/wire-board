# 后期性能与数量上限

## 上限

- 普通出兵从第 18 波起固定为每波最多 44 个。
- 同屏最多 64 个敌人，包含首领护卫和分裂子体。生成逻辑共享剩余名额，不因无尽波数提高上限。
- 合作地图最大 40 个建造点。每座塔攻击间隔最低为 200 毫秒，40 座塔最多每秒攻击 200 次。
- 后期通过生命、护甲、伤害和编队变化增加难度，不无限增加实体数量。

上述数量是规则上限。实际帧率仍取决于设备、浏览器和网络，不能仅凭有上限就声称满负载流畅。

## 本轮修复

旧实现虽然只发送近期事件，但密集攻击仍在每次出手、每次命中中重复完整敌人状态；范围攻击还重复携带各受击者的位置，并逐个绘制一整组爆炸粒子。极端炮塔重叠场景的事件存档可超过 2 MiB，随后无法解码。

本轮改为：

- 同次范围攻击按相同的实际伤害值分组，保留所有目标；保存完整目标 ID，网络投影使用目标基数与偏移，避免后期 ID 增长扩大重复负载。
- 同一短窗口只在需要时发送完整目标，后续命中使用绝对生命、护盾及减速状态。生命变化仍在弹道命中后显示；旧存档的逐目标事件继续可读。
- 网络保留最近一个完整的一秒仿真批次和空闲游标。丢批、刷新和重连按当前快照恢复，不补播过期动作。规则存档与网络投影分开。
- 一次范围攻击绘制一次爆炸，不为每个受击者复制整组粒子。装饰性爆发同时最多绘制 48 组，保留弹道、真实命中时间、血量和死亡。
- 跳过视区外的塔和敌人绘制，保留其运动与弹道目标数据；裁剪边界包含缩放后的实际图形。每帧复用出手记录与塔查询结果。

## 验收与边界

场景包括 45 波中央地图、合作扩展地图、从一份 43 波结束存档提取的 18 塔配置，以及人工构造的 40 炮塔重叠上界。均以耐久敌人保持持续负载；后者用于压力上界，不代表自然对局能按该布局建塔。测试包含 64 个同屏敌人、40 座高等级塔、每秒 200 次攻击、后期实体 ID、存档恢复和超过 1000 波仍不增加数量的规则检查。

真实存档只提取塔种类、位置、等级等配置到 `tests/testdata/late-wave-build.json`，不包含房间或玩家身份。测试机未重现用户报告的两秒页面延迟，因此没有将本地压力结果表述为完全复现现场；已量化并修复网络与绘制冗余。

浏览器检查使用真实 HTTP／WebSocket、生产 Canvas、PC 原生鼠标、320px 触屏仿真，并保持 CDP CPU 节流会话直到采样结束。计数器不复制每帧精灵或网络包，以避免记录器自身制造卡顿。保留实际绘制帧率、rAF 间隔、长任务、绘制调用数、消息字节数、平台连接状态、独立 HTTP 请求耗时和按钮响应。CPU 节流不是某款实体设备的性能保证。

验收预算：完整房间消息不超过 192 KiB、平均每帧不超过 2000 次绘制调用、采样帧间隔 P95 不超过 34 毫秒、按钮响应不超过 200 毫秒。规则检查同时确保全部 200 次攻击保留，分组伤害与每个目标的实际损血一致，不能用漏算攻击来满足预算。

```sh
. scripts/env.sh
go test -count=1 -run 'TestLateWaveDensityProfile|TestMaximumDensity|TestGroupedDamage|TestEndlessEnemyCounts' ./games/starfort/server
npm --prefix web run build
python3 -B games/starfort/tests/accept_density_ui.py --enforce
```

浏览器脚本会先生成合法压力夹具。产物位于 `.local/starfort-density/`；长路径工作区可用 `STARFORT_FOLLOWUP_SOCKET_DIR` 指定仓库内较短的 socket 目录。完整规则、HTTP、命中动画、技能及竞态回归分别保留，压力采样不替代完整对局验收。
