# 即时游戏开发规范

适用范围：即时操作、本地预测、服务器校正、慢连接隔离和响应延迟验收。开发流程同时遵循 [通用规范](common.md)。

## 真人控制与连接恢复

- 即时游戏不做自动接管。空闲、超时、断线或切到后台均不得自动把真人席位交给电脑；只允许玩家通过平台统一入口主动开启或取消托管。显式添加的电脑玩家照常运行，游戏内超时按各自规则处理。

## 实时同步与操作响应

- **即时游戏必须先在本地响应按键，再用服务器结果校正。** 采样逻辑按键后，客户端立即使用本地规则进行预测并呈现本人操作，同时向服务器发送有序输入；不得等服务器 ACK、下一次快照或往返请求完成后才显示按键反馈。
- 本地预测只改善操作响应，服务器校正仍以权威状态为准。收到服务器确认后，核对已确认帧与输入序号，按需回滚、重放未确认输入并平滑修正画面；胜负、积分、生命和资源等最终结果由服务器决定。校正不得重复结算、重播旧音效或重置对局。
- **即时游戏只传输必要的网络数据。** 两端能确定性重演规则时，常规同步优先只传按键／操作输入，以及帧号、序号、确认和校验摘要等必要元数据；首次接入、重连或失步恢复时，才按需传权威快照。只预测部分运动的游戏可以发送必要的权威投影，但不能因此逐帧发送完整存档、静态素材或历史事件。
- 存档状态与网络更新必须分离，不得把持久化历史事件、内部调度计数器或重复地图作为每帧负载。静态地图与地形绘制按内容变化缓存；刷新、重连及丢帧后使用当前快照恢复，并用事件游标防止重播。修改须记录普通和密集对局的消息大小、可见帧间隔与操作响应；连接往返延迟和本地帧率分别验证。
- 慢连接只影响该客户端的接收、预测和恢复，不能阻塞服务器时钟、其他客户端的输入处理或画面推进。各连接独立维护有界发送队列和游标，积压时由落后客户端追赶或恢复；不得等待最慢玩家的网络确认，也不得因此自动接管真人席位。
- 初始开局保留统一的真人加载就绪门槛。开局后换关、重连、后台恢复或单个玩家加载较慢时，只限制尚未就绪玩家的输入与本地显示，不得重新让全员等待。
- 预测时长、待确认输入和显示缓冲必须有明确上限。断线、失焦、页面隐藏和取消输入时释放对应按键；恢复后从有效权威状态继续，不能补播过期操作，也不能靠持续增加显示缓冲掩盖网络积压。
- 操作延迟验收必须测量原生键鼠或触屏事件到首次可见响应的时间，并分别记录连接 RTT、输入 ACK、权威帧到达、显示排队和本地帧间隔；不得用 ACK 耗时或稳定帧率代替操作响应。覆盖正常网络、单端高延迟／丢包、重连、快速连续输入及双人快慢连接并存，保留可重复执行的测试和测量产物。

## 同步模型与性能

- 设计或排查同步时，先对照已接入游戏的实际代码和验收记录。确定性输入重演可参考热血篮球与魂斗罗，低频权威数据加本地运动预测可参考泡泡堂；按规则是否可重演、碰撞和随机数的归属选择模型，不机械复制另一款游戏的全部字段或网络频率。
- 规则推进、网络发送和显示刷新使用各自的时钟。降低网络发送频率不得降低本地渲染帧率；预测时使用与权威时间对应的接收时间锚点，不能把旧规则时间与每次轮询的新接收时间拼接。普通权威确认追上本地预测时保持显示时钟相位；只在身份变化、显式恢复或真正长时间停顿后重建时钟。相同帧或重复消息不应反复重建预测状态。
- 输入按语义处理：连续方向可以合并为最新值，跳跃、射击、放置炸弹等短按边沿必须有序保留；按下后立即松开也不能被在途请求覆盖。校正与下一次显示刷新之间收到的新输入，必须排在已显示的本地目标帧之后，不能回填进历史预测帧。分别维护“服务器收到”和“规则已应用”的确认，使用有界在途窗口，不能每次等待一个 ACK 才继续采样或显示。
- 可靠连接优先按各自的帧／修订游标发送新增输入或事件，游标在成功发送后推进，可附少量有界冗余；不能给所有连接不断重发整个历史环。游标缺口、epoch 变化或超过重放窗口时明确恢复，不猜测遗漏的随机数、AI 决策或权威结果。慢端游标独立，不拖住快端。
- 网络负载小不代表客户端开销小。须分别测量主线程、规则推进、状态复制、校验和绘图；高频分叉和重放避免完整存档的 JSON 往返，只导出实际需要的紧凑结果。摘要校验保留在权威确认边界，未消费的本地预测摘要不重复计算。
- 重放的每个规则步和必要呈现状态仍须完整推进，但不绘制不会显示的中间像素帧。只有状态发生可见变化时重建静态图层；不得用减少碰撞、丢弃输入边沿、猜测最终对象画面或降低素材精度换取帧率。
- 公共加载确认必须在实际画面初始化完成后提交。游戏另有就绪动作时，须与公共门槛明确排序；等待加载、暂停或结算期间的静止帧不自动视为断线，不产生恢复请求或空输入释放的循环。
- 性能预算先于优化冻结，并在正式认证房间验证正常双人及快慢端并存。分别报告可见帧率、帧间隔分位数、原生事件到像素响应和协议负载；浏览器主线程等待的 HTTP 耗时不能冒充纯连接 RTT。测试夹具须使用正式时钟契约，并覆盖显示刷新率与逻辑帧率不整除的相位差；不能只用逻辑 tick 驱动测试，或只统计已绘制帧的间隔而遗漏可见更新数量。不能用夹具达标代替正式页面，也不能测后放宽阈值。

## 界面与阶段提示

- 实时游戏将战场、关键资源、波次和倒计时放在主要视区；自动开始须显著标明，选择期限与开战期限分开显示，暂停时停止倒数。扩展地图／强化选择使用可关闭、可重开的统一弹窗，次要情报与支线折叠，不随快照更新强制重开。
