# 加载与资源发布规范

适用范围：按需加载、就绪门槛、OSS/CDN 资源和构建剥离。开发流程同时遵循 [通用规范](common.md)。

## 发布资产与镜像边界

- **所有游戏的客户端运行时与素材都不得进入正式服务器构建或容器镜像。** 浏览器端 Wasm、JS 运行时及图片、音频、视频、字体、地图素材等发布资产统一使用 OSS/CDN 不可变内容地址；不得通过复制文件、`go:embed`、压缩包或生成代码等方式把这些载荷带入镜像，也不得由应用服务器的本地目录提供这些资产的线上回退。
- 源码可以保留在 Git；研究素材和本地验收缓存只保留在工作区的忽略目录或 OSS，不进入 Git 历史，也不能被正式打包流程收集。应用入口和资源清单仍由应用服务器提供；清单只保留版本、地址、大小、摘要等元数据，不夹带资源正文。
- 此处的运行时与素材指客户端加载和呈现使用的发布资产。服务端独立规则代码及计算必需的规则数据按服务端模块维护，不能借此携带客户端素材副本。
- 通用资源发布必须覆盖构建目录内所有客户端载荷，包括非 `assets/` 目录中的图片、音频、地图 JSON、字体和运行时。按精确上传清单生成只含地址、大小、摘要及 MIME 的 `cdn-assets-manifest.json`，再移除载荷；候选包发布前须通过本地 CDN 回读，不能仅剥离某一款游戏或编译后的 JS／CSS。
- 正式环境的相对资源地址按已验证清单跳转到不可变 CDN URL，不从应用服务器提供文件正文，也不代理素材下载。没有发布清单的本地开发构建仍可直接加载本地资源；正式产物必须通过实际二进制摘要与编译嵌入输入清单检查。
- 本地资源工作线程的同源引导属于应用入口，只生成指向已验证 CDN 工作线程模块的 `importScripts`，不携带缓存实现或资源正文。实际工作线程仍按客户端程序发布、校验和剥离；引导不得指向未登记的来源或通过素材别名绕过入口约束。
- 发布验收须检查最终服务器包、二进制嵌入内容及镜像文件，确认没有上述客户端载荷；不能仅凭源码目录、Dockerfile 中没有直接复制素材，或 CDN 上传成功就判定已剥离。
- 音乐、音效及其原始数据按[音频资源压缩规范](audio.md#音频资源压缩)生成无损压缩产物后再上传 OSS；资源清单的大小和 SHA-256 对应实际上传对象，回读校验同时覆盖压缩产物与无损还原结果。

## 资源地址稳定与上传去重

- 全平台的图片、音频、视频、字体、地图、模型及游戏资源按文件内容复用。内容和响应格式未变时，必须继续使用已发布的原地址，不得因为应用提交、构建时间、资源集合版本、文件改名或发布批次变化而复制上传同一份资源。
- 不可变表示已发布地址不覆盖内容，不表示每次更新都创建一套地址。新版本清单可以同时引用不同历史批次的资源；只为实际变化且尚未发布的文件创建对象。某一首音乐变更不能导致其他未变音乐重新上传或换地址。
- 发布前按 SHA-256、大小、MIME 和 Content-Encoding 查询已验证的发布记录。优先保留同一逻辑资源的原地址；其他路径已有完全相同且响应格式兼容的对象时，直接复用。文件名相同不能证明内容相同，文件名不同也不能成为重复上传的理由。
- 上传计划必须区分复用对象和新增对象，记录各自数量、字节数及逻辑路径到实际 URL 的映射。相同资源集合重复发布时，新增对象数和上传字节数必须为 0；同一批次内重复内容也只上传一次。
- 已有对象先验证再复用，写入必须禁止覆盖。CI 按[流量与费用规范](deploy.md#ci-流量与费用)使用可信历史记录或 HEAD 元数据核对，不得为复用而完整下载对象；本地 CDN 回读继续负责实际正文、CORS 和音频 Range 验收。发现原地址内容或响应属性不符时停止发布，不能覆盖修补、跳过校验或静默改用本地资源。已经被页面、存档或回滚版本引用的旧地址继续保留。
- 清单版本与资源对象地址分别管理。允许清单随引用关系变化生成新版本，但未变资源的 URL 必须保持稳定；程序提交目录不能作为重新复制静态资源的理由。验收至少覆盖原样重复发布、只修改一个文件、重命名后复用、批次内重复内容及旧存档引用保留。

## 资源目录、源码仓库与业务配置

- 游戏资源的 OSS Key 必须以 `bga/<game-id>/` 开头；公共资源使用 `bga/_common/`。目录和发布文件名不含日期、发布版本或应用提交号。使用内容 SHA-256 区分变更；不同 HTTP 编码须使用不同对象名。构建来源通过清单的 `sourceSHA` 绑定，不进入资源地址。
- 图片（含 SVG）、音效、音乐、视频、字体、客户端二进制、压缩包和生成的公开地图／图集数据，不得进入 Git 当前树及任何分支、标签历史，也不得把载荷改成 Base64 或代码中的字节表来规避。图形绘制源码、服务端规则数据及只含路径、摘要、大小、类型的清单可以保留。测试中的小型图案在运行时生成。
- 当前源码资源通过 `assets/resources.json` 恢复，历史资源通过 `assets/resource-history.json` 登记，运行中使用的外部资源由 `assets/external-resources.json` 定位。清单不含资源正文。恢复时校验 SHA-256、大小和 MIME，拒绝路径逃逸和符号链接。
- 本地业务配置从 Git 忽略的 `.local/business.json` 读取；执行 `. scripts/env.sh` 时生成并加载 `.local/business.env`。GitHub 测试和发布只读取仓库变量 `PUBLIC_ORIGIN`、`CDN_ORIGIN`、`OSS_BUCKET`、`OSS_ENDPOINT` 和 `ASSETS_BASE_URL`，不得回退到写在代码中的线上站点域名。
- 本地执行 `python3 -B scripts/resource_store.py hydrate` 从配置的 CDN 恢复源码资源。普通 GitHub 作业只通过统一的 GitHub 缓存入口按用途恢复，禁止执行 `hydrate` 直接回源。私有 OSS 的限额读取只用于独立的手动缓存准备；具体预算、失败行为和报告遵循[CI 流量与费用](deploy.md#ci-流量与费用)。游戏任务包含必要的生产 Go 嵌入输入，不恢复其他游戏的测试夹具与媒体。恢复仍须校验摘要、大小和 MIME，不以 CDN 回读替代源码恢复，也不在 CI 中执行 CDN 回读验收。
- 旧逻辑路径仅用于恢复工作区和兼容跳转，不作为新的 OSS Key。应用的 `/bga/<逻辑路径>` 按清单跳转到游戏或公共资源的内容地址，不返回资源正文。缺失的旧素材不能因为同属 CDN 域名而被强制改写到另一份发布清单。
- 重写 Git 历史前保全工作区并校验备份；改写后扫描全部分支、标签及对象，验证无资源载荷和业务站点域名，再从远端空目录执行普通克隆测量下载量。Git 清理不联动删除已经发布的 OSS 对象。

## 游戏加载

- **所有游戏统一遵守：本局首次加载成功后，游戏过程中只通过网络传输操作、状态及必要业务数据；图片、音频等已准备资源只读取本地正文，不再下载。** 预加载须保存可复用的完整资源正文，只有「下载过／校验过」的标记或依赖浏览器普通 HTTP 缓存，不能视为完成。
- 开局前完整准备本局可能使用的必要程序、贴图、动画、字体、音乐和音效，完成本地保存、必要解码与场景初始化后才确认就绪。保留当前地图和角色所需的完整资源范围，通过有界并发、去重和缓存加速；不得将首次使用的必要贴图或声音推迟到游玩时下载。
- 就绪后，连点、重建播放器、重新绘制、状态校正、断线恢复、同资源重开、Range 请求或缓存参数变化均复用已保存的正文。读取、播放、解码、校验或缓存发生问题时，**不得自动回源、重试下载、换备用 CDN 或改走应用服务器下载**；按需显示当前失败或跳过失败声音，不影响其他玩家及正常游戏操作。
- 该约束由平台公共资源层统一执行，覆盖普通 `fetch`、原生图片、CSS 图片与字体、原生音频和媒体 Range 请求；不能只给某一款游戏或某一个播放器打补丁。工作线程被系统停止后重新启动，也不得遗忘对局的本地读取约束。
- 资源服务更新不得让尚未接入驻留加载的旧页面突然丢失图片或声音。旧窗口进入新版本加载流程后再建立本地只读约束；兼容旧窗口不能放行已接入游戏的工作线程回源。
- 同一局内可能用到的关卡、场景、角色变化及相应音效，计入本局首次加载的必要资源范围，不能在流程中遇到时再补下载。只有进入确需新资源的新对局、修改开局配置或显式加载新版本时，才准备新增资源并重新通过就绪门槛；原本已成功加载且内容未变的资源继续本地复用，不能借重开、恢复或进入加载页重新下载。
- 验收保留冷加载、缓存复用、连续操作、原生图片与音频、Range、加载失败、缓存正文丢失、工作线程重启和连续重开的浏览器记录。以真实请求计数证明：加载成功后的游玩阶段，图片和音频资源的网络下载数为 0；只检查 HTTP 缓存标记、调用次数或 DOM 内容不能替代该证明。

- 正式构建的前端 JS／CSS 和游戏代码模块发布到 OSS/CDN 的游戏命名空间。main 完成所需检查后，Actions 上传资源并生成已剥离载荷的候选包；CDN 回读必须在本地执行，验证 SHA-256、大小、MIME、CORS 和音频 Range 后才允许正式发布，不得在 GitHub Actions 中回读。入口和资源清单仍由应用服务器提供。tag 不重新构建或重复上传，旧代码对象不得删除或覆盖。公共结算页随应用界面就绪，不得在游戏结束时首次加载旧版游戏大模块。
- 首页仅加载轻量游戏目录与封面，游戏实现、地图数据和运行时按需加载。游戏元数据在 `catalog.tsx` 维护，运行模块引用同一份元数据。
- 全部游戏开局使用统一的淡化封面加载页与真实进度。代码、必要素材和画面初始化完成后才能确认；全部真人确认后才推进规则与计时。电脑自动就绪，观战者不阻塞，已开局重连不得重新暂停全员。
- 所有游戏的加载页须同时显示百分比和「已加载大小／总大小」，使用 KB／MB 等可读单位，不能只显示百分比。大小按资源清单与实际读取字节统计，覆盖游戏程序、Wasm 和当前对局必需素材；不得按百分比反推大小，也不得为统计总量而预加载其他地图。尚未取得总量时显示读取清单状态，取得总量后立即显示大小。
- 并行下载按资源去重汇总，缓存复用按已验证的资源容量计入并说明缓存状态；校验、解压和画面初始化阶段保留已完成的大小。验收覆盖冷加载、缓存复用、失败重试、桌面与 320px 手机，保存可重复执行的测试、大小记录和截图。
- 预取优化保留完整资源范围和开局就绪门槛，通过有界并发、缓存及解码开销优化加速；不能把当前对局必要贴图推迟到游玩时首次下载。公共加载器不长期持有整款游戏的已解码图片对象；隐藏初始化区域的懒加载图片须主动加载、解码完成后再确认就绪。小文件回归入口为 `node games/cs16/tests/prefetch-browser.mjs`，结果位于 `.local/cs16/prefetch/`。
- 大型 Canvas、WebGL 或原生运行时必须报告实际初始化完成或失败；不得只在脚本下载完成、组件挂载或固定延时后提前确认。失败保留重试，资源只覆盖当前地图和必要角色，不预加载全部历史素材。
