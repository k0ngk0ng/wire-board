# 密室逃脱开发规范

先阅读[通用规范](common.md)、[即时游戏规范](realtime.md)、[界面规范](ui.md)、[控制器规范](controller.md)、[加载规范](loading.md)和[音效规范](audio.md)。

- 平台名称为「密室逃脱」，游戏 ID 为 `escape`。封锁站、沉没档案馆是可选密室；新增密室继续使用同一游戏入口和公共房间框架。
- 支持 2／3／4 个角色、三档难度、真人与电脑混合、主动托管及手动接管。电脑只读取席位可见的投影，使用普通行动完成调查、校准、运输、配电、联锁、救援和撤离。
- 同一生成版本和地图编号必须复现地图、机关目标和事故序列。布局生成连通图，资源与线索不受自身前置条件封锁，全部人数至少存在可完成路线；不能把随机答案本身当作全部重玩内容。
- 机关、有限补给、共享电源容量、搬运负担、两种撤离路线和有预警的事故共同影响策略。改变谜题约束时，先验证可解性，再增加生成范围。
- 未调查的房间不泄露类型、物件与答案；发现的线索按队伍共享。观众使用队伍已发现的信息。初次进入、普通实时投影和恢复接口保持相同限制。
- 远端联锁要求两处装置同时存在健康队员，不能由单个角色在不同房间先后点击代替。全员抵达、交付携带物并确认才共同获胜；不能结算部分队伍胜利。
- 连续移动先本地显示，权威状态校正。方向、点击移动、操作队列、短按边沿、失焦和触摸取消分别处理；常规消息不重复发送静态房间、完整存档或历史事件。
- 图像使用本游戏统一美术规格与原创资产；精确提示词、来源模型、尺寸和摘要保存在 `games/escape/assets/`。背景、人物和设备必须保持相同投影、光向与比例；移动、生命、机关和音效以当前规则时间呈现。
- 手机人物至少可辨认，地图、笔记、机关、配电、补给、呼叫和救援均可触屏操作。通过公共全屏，所有操作和弹窗留在游戏区域内。
- 验收保留完整电脑对局、普通动作的合作机关、资源边界、事故和救援、真实 HTTP／SQLite 恢复、桌面／320px 触屏与快慢连接并存的可重复测试和产物。冻结的场景与指标见 `games/escape/ACCEPTANCE.md`。
