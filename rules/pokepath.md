# 宝可梦：巡径守卫

原版对照目标为 PokéPath TD v1.7.3，网页为 <https://pokepathtd.org/>。开发同时遵循[通用规范](common.md)、[复刻规范](recreation.md)、[即时规范](realtime.md)、[地图规范](maps.md)、[塔防规范](tower-defense.md)、[加载规范](loading.md)和[存档规范](saved-games.md)。

## 当前交付优先级

2026-11-18 用户明确调整为尽快游玩，允许停止非必要精修。本次先交付独立重写、1～4 人共享合作、核心战斗与成长、电脑、桌面／触屏和存档恢复；逐像素菜单、全技能组合和连续画面逐帧一致性作为后续改进，不再作为本次发布门槛。多人正确性、基本可玩性和通用发布检查仍须通过。

## 独立实现

- 用户明确要求自行复刻重写。产品使用独立 Go 规则和原生 React／Canvas 界面；不得嵌入原网页、加载原版程序、打包原版 JavaScript 运行器，或把原版程序封装成另一个语言后称为独立实现。
- 原站用于规则、视觉和行为对照，允许参考局部代码厘清机制。可归一地图、波次、属性、名称、素材尺寸等事实数据；不得整套照抄、自动翻译或封装上游程序。参考原始程序保存在研究目录，不进入游戏产品目录或正式载荷；产品规则与界面须独立可控，并保持原版显示和玩法。
- 对照范围为 40 条百波路线和 7 个特殊地图，共 4007 个波次；517 个形态、257 个收集编号、347 个敌人、254 个能力、85 个敌人被动、197 个道具定义，以及挑战、轮抽、图鉴、编队、编辑器、秘密交互和成长系统。逐项记录已实现与待验收内容，不能以数据完整或少量通用塔代替规则完整。
- 初始伙伴为小火龙、木守宫和呱呱泡蛙，由房间设置选择。平台准备后直接进入战场，不再创建原版账号或进入另一套大厅。

## 多人合作

- 支持 1～4 人守同一张地图，共享队伍、金币、生命、仓库、波次与成长。每名玩家独立打开本地管理面板，选择使用稳定宝可梦标识，不用可能变化的队伍下标鉴别目标。
- 所有行动通过平台席位鉴权与服务端独立规则校验。客户端不能提交任意资源、快照或胜负；并发部署、购买、升级不得重复支出。失败保留原状态。
- 观众只能查看。操作代次、输入收据与平台幂等共同防止重试或旧页面重复执行；恢复后拒绝旧代次。
- 电脑与真人使用同一合法接口，不直接发资源、改敌人死亡或跳过战斗。覆盖正式初始条件的完整路线、混合席位、多人共享资源、托管与手动接管。

## 规则与存档

- Go 状态显式保存全部规则数据、随机数、敌人、塔、弹道、冷却、状态效果、延迟事件与选择。禁止在闭包、浏览器 DOM 或进程全局中隐藏可变规则状态。
- 原版通过金币升级，没有独立经验值机制；默认速度为 0.8。地图、敌人和能力的数值须有可核验来源，不能凭印象补写。
- 伤害按原版阶段分别取整。半血增伤在受击时读取当前生命，不能提前合并到发射威力或暴击倍率；超级大嘴娃的额外半威力攻击先结算暴击，再乘 0.5 向上取整，之后才结算半血增伤。领域加成先于技术高手的 1000 伤害门槛，验收同时比较实际扣血和完整伤害统计。
- 浏览器预测编译同一份自写 Go 引擎为 Wasm，服务器直接执行 Go。显示、规则与网络各用自己的时钟；本地先响应操作，再按确认序号校正，不能以逻辑 60 Hz 冒充实际画面流畅度。
- 保存在状态中的规则数学结果须在宿主机与 Wasm 上一致。距离统一经过固定舍入的 `vectorLength`；产品引擎禁止直接引用 `math.Hypot`，包括导入别名和函数值转存，由 Go AST lint 检查。原版对照测试可以独立使用参考计算，不能通过放宽完整状态比较隐藏末位差异。
- 保存与恢复沿用平台完整快照、原真人名册、冻结时钟和事务机制，不另建存档系统。恢复不补跑离线时长，不重发初始资源，不能用仅含关卡编号的原版成长档替代完整战斗现场。
- 规则、数据和客户端运行时有明确版本与摘要。未知版本保留原档并拒绝误恢复；不能静默重开。

## 界面与素材

- 中文名为「宝可梦：巡径守卫」。沿用平台大厅、准备、公共玩家栏、全屏、观战、托管与保存入口；封面使用独立 SVG 插画。
- 自行实现地图、编队与管理面板，以布局分组表达信息。关键金币与生命在公共玩家栏清晰可见，零值不隐藏。
- 320 px 手机保留可辨识宝可梦与真实塔身触摸；地图支持鼠标滚轮锚点缩放、左键拖动、触屏平移与双指缩放。拖动和取消不能误触部署或升级。
- 音频统一使用平台接口与静音控制。若原版分组音量关联隐藏机关或伤害，独立规则保存对应配置，实际播放增益也须一致。
- 参考素材按当前地图、队伍、敌人和必要界面按需加载，校验实际字节与摘要；不得预加载全部地图图像。正式客户端载荷使用统一 OSS/CDN 去重与剥离流程。
