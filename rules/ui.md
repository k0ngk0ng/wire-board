# 界面与交互开发规范

适用范围：公共界面、视觉、动画、全屏和游戏目录。开发流程同时遵循 [通用规范](common.md)。

## 界面与视觉规范

- 禁止默认给人物、角色、载具或玩家棋子叠加席位号、序号角标、编号圆点，尤其是右下角数字标记；封面、正常素材和素材失败后的回退都遵守此规则。身份通过造型、颜色、轮廓及公共玩家栏或邻近姓名辨认，不能把数字编号当作通用装饰。游戏规则本身必要的牌面数字、资源数值、等级或排名按其明确语义显示，不混作人物身份角标。
- 所有游戏沿用统一的界面框架：创建弹窗分两步，第一步只用统一封面卡片选择游戏，点击后进入第二步，显示所选游戏简介、房间名称、并排的座位／密码字段及该游戏的规则选项；提供返回选择游戏的入口。返回同一游戏保留规则草稿，切换游戏保留房间名称和密码并重置专属规则，关闭弹窗后清空草稿。等待房间使用封面说明、座位卡片、规则选项与统一的准备／开始按钮；普通对局页面保留公共玩家栏、回合提示和响应式布局，全屏模式遵守下方「游戏区全屏」规范。游戏可定制棋盘和必要的操作面板，不得另起一套大厅／房间布局，也不得用游戏 CSS 隐藏或重排公共界面来随意发挥。
- 现金、生命值等关键公开资源须在公共玩家栏直接、清晰地显示，区分当前玩家。手机端不得因横向裁切而隐藏其他席位的关键资源；验收须检查真实可见性、零值和操作后的更新，不能只断言 DOM 文本存在。
- 新游戏封面沿用现有封面的手绘式矢量插画风格、横向画幅和低饱和配色。优先在游戏目录提供 SVG 绘制组件，不能直接用盒装照片、扫描封面或大段标题字替代封面插画。大厅、创建选项和等待房间使用同一封面。不同游戏须有与名称或核心玩法对应的独立主体和构图，不能仅换色或替换小配饰而复用同一画面；缩略图下也须能区分。
- 游戏卡片集中放在创建房间弹窗，使用统一封面选择模板；选中后显示该游戏的中文简介、人数与规则。大厅以房间列表为主，首屏必须能看到房间及加入／观战入口，顶部提供明显的「创建房间」按钮；不得用欢迎大图或游戏卡片墙把房间推到下方。统一不显示英文标语、英文副标题及「基础版」等版本角标；不得让新旧游戏各用一套布局。游戏模块只提供封面和元数据，今后新增字段或更改语言策略须对所有游戏一致应用。验收覆盖全部已接入游戏及 320px 手机宽度。
- 文字颜色必须与实际背景成对定义，不得只改背景而保留另一主题的文字色。普通正文／小字对比度至少 4.5:1，大字与重要非文本控件至少 3:1；弱提示、禁用按钮仍须可读，不能通过整体低透明度让文案消失。验收必须检查最终计算样式、桌面和手机截图，不能只检查某个 CSS 文件中的颜色。
- 掷骰、棋子移动、抽牌等关键反馈应有可辨识的动画；以服务端结果驱动，不在前端决定游戏结果。刷新、重连不得重播旧动作；快速连续事件、跨起点、反向移动和进入监狱须保持正确顺序，并支持减少动态效果设置。
- 公共回合提示在「请行动」「等待其他玩家」「对局进行中」等状态间切换时保持高度稳定。动画期间隐藏倒计时须保留布局占位，且不显示或播报无效时间；桌面和窄屏验收须逐帧检查棋盘位置，不能只检查文案。动画结束的唤醒须容忍计时器提前触发，不能依赖下一次网络轮询才解除操作锁。
- 对局结算统一使用可关闭、可重新查看的浮层，不在棋盘上方插入结算横条。关闭后普通快照更新不得自动重开，新一局结束须正常显示；顶部操作按钮切换也不得挤动最终棋盘，保留查看最终局面的空间。
- 子弹飞行、命中特效、护盾／生命变化和死亡显示须保持同一时间轴，以服务端结果驱动；不得在视觉命中前显示扣血或移除目标。连续攻击、范围伤害、刷新／重连及减少动态效果须验证。
- 棋子要能在手机棋盘上辨认，常规显示直径至少 24px，使用清晰轮廓和玩家颜色，不按实体棋盘比例缩到难以识别；同格多棋子须保留可辨识的席位提示。

## 游戏区全屏

- 所有现有及后续新增游戏统一复用平台的 `GameFullscreen`（`web/src/ui/room-fullscreen.tsx`），不得另做一套全屏入口。全屏按钮只在开局后显示，与「开启托管」放在同一组房间操作中；等待房间不显示，游戏尚未加载就绪时不可用。不得将入口单独悬在房间标题中间、游戏区上方或另起一行。
- 全屏目标必须是游戏区元素，不得对 `document.documentElement`、`document.body` 或整个房间页面申请全屏。全屏排除顶部平台菜单、房间标题、邀请等房间操作及上方公共玩家栏；普通页面仍按公共界面规范显示这些内容。
- 全屏必须保留完整可玩性：棋盘／战场、游戏内必要状态和资源、倒计时、道具、主要操作、特殊阶段选择、行动错误提示及结算都须在游戏区内可见、可操作。不得只放大 Canvas 而丢掉操作面板，也不得要求退出全屏才能出牌、确认、交易、建造或使用技能／道具。不能由现有键鼠操作替代的游戏按钮须保留；手机必须保留触屏操作。
- 只有全屏激活时，才在游戏区右上角显示退出按钮；同时支持 ESC 退出。进入后键盘焦点交给游戏，空格等按键不得误触全屏按钮。退出、离开房间或异步请求晚到时，须恢复页面滚动、焦点和交互状态，不能残留遮罩或 `inert`；ESC 仍须传递给游戏以取消蓄力等操作。
- 游戏弹窗、动画、特效和结算图层必须留在全屏目标内。使用 portal 的游戏复用 `web/src/ui/game-overlay-root.ts`，不得固定挂到全屏目标外的 `document.body`。切换全屏、调整尺寸和退出不得重新挂载棋盘、重置对局、清空操作选择、重播旧动画或改变服务端计时。
- PC 全屏应利用可用空间放大游戏区，适合宽屏的游戏可扩展视野；保持合理宽高比例，不拉伸画面，也不把必要操作挤出可视区域。手机单独适配；不支持或拒绝原生全屏时，回退为游戏区铺满网页可视区域，上方菜单和玩家栏仍不带入。
- 新增游戏及相关修改的验收须覆盖 PC 和 320px 手机：等待房间无入口、开局后入口分组正确、全屏范围正确、真实键鼠／触摸操作、游戏弹窗与图层、ESC／按钮退出，以及退出后状态恢复。倒计时须检查文字本身的边界、计算样式对比度和遮挡，不能只检查外框或 DOM 存在；保留可重复执行的测试、测量和截图。按本次影响范围选择游戏，不因此固定运行无关游戏的规则或完整对局矩阵。

## 游戏目录与筛选

- 游戏数量会持续增长。按游戏筛选使用带标签的下拉选择，不按游戏数量平铺一行 tab；手机宽度下不能挤窄文字或造成横向溢出。
- 游戏分类通过模块元数据维护。大厅、创建房间和管理后台统一提供分类下拉，并与名称搜索组合；分类不能绕过上下架设置，不为新增游戏另建一排分类 tab。
- 大厅房间列表提供房间名／房间号／游戏名称搜索，以及游戏分类、游戏和状态筛选；筛选无结果时提供清除入口。创建房间集中展示全部已上架游戏的统一封面卡片，提供分类、搜索、稳定卡片宽度和限定高度的滚动区域。切换游戏后须显示当前选择并按对应规则创建。
- 管理后台游戏列表提供搜索；个人战绩按游戏分批展示，避免把好友和对局历史推到长列表底部。新增按游戏列出的页面须验证大量游戏、长名称、无匹配结果及 320px 手机宽度，保留截图和可重复执行的验收记录。
