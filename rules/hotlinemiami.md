# 迈阿密热线

游戏 ID 为 `hotlinemiami`。开发同时遵循[通用规范](common.md)、[即时游戏规范](realtime.md)、[复刻规范](recreation.md)、[界面规范](ui.md)、[控制器规范](controller.md)、[加载规范](loading.md)和[音效规范](audio.md)。设计依据见[多人混战方案](../docs/hotlinemiami-multiplayer-plan.md)。

## 规则与房间

- 采用第一代原版作为美术、地图和动作对照，以独立规则实现 2 至 4 人自由混战；不提供组队、合作闯关或原版剧情菜单。
- 地图、时限和出生装备在平台房间设置中控制。地图提供实际可玩区域的参考图，每席提供角色头像、俯视造型和武器参考图；服务端鉴权限制真人只能修改本人席位，房主可管理规则和电脑席位。
- 默认 3 分钟。击杀加 1 分，自杀减 1 分，最高分并列按平台显式和局处理。伤害、弹药、拾取、击杀和复活由服务器确认，同一生命不能重复结算。
- 角色造型不改变速度、碰撞体、生命或武器规则，不直接带入原版面具能力和 Boss 抗性；允许重复造型，通过配色、轮廓和姓名辨认，不添加席位数字角标。
- 枪械与近战保留致命攻击，投掷、击倒和处决遵循明确的帧内顺序；拾起掉落枪械保留实际剩余弹药。复活清理旧生命的输入与攻击关系，出生保护期间不能挡弹或堵门，主动攻击前解除保护。
- 电脑、托管与真人进入相同输入和战斗接口。电脑不能直接改写命中或得分，断线和后台不自动托管；含电脑的对局不计竞技积分。

## 原版证据与素材

- 证据、下载样本、解析中间数据和处理产物保存在 `.local/hotlinemiami/`，来源摘要与转换参数可复核。REA 静态证据、普通工具解析、运行观测和设计改编分别记录，不把资源名当作行为证据。
- 地图图像、墙体、家具与碰撞须来自同一关卡数据；新增出生点、武器点或连接记录为多人改编，不称为原版布局。多楼层过关触发器不能直接成为多人传送入口。
- 多人地图的背景和预览不得固化原版敌人、NPC、Boss 或尸体，避免形成不能受击的假目标；实际人物和死亡表现由多人状态渲染。人物即使位于 `Enviroment` 目录或继承家具父类，也必须按对象审计排除，并同步核对其静态碰撞；保留真实家具、海报与装饰。新增地图须保留原图对照、精确对象清单及碰撞正反例。
- 每个角色核验移动、持枪、近战、投掷、击倒、死亡等动作覆盖。新增或适配的帧单独登记，不把补绘称为原版提取。
- 图片、图集、公开地图数据、音频、WASM 和客户端构建资产不进入 Git 资源历史或服务器镜像。源码只保留绘制代码、必要服务端规则数据及不含载荷的资源清单。
- 素材使用 `bga/hotlinemiami/` 内容地址；当前地图和必要角色按需加载，选图使用独立小预览。加载百分比、实际字节和画面初始化完成后再确认就绪，失败保留重试。

## 输入与同步

- 规则固定步长推进，显示与网络各自使用时钟；使用 `RealtimeDeadlineFrames` 接入细帧截止检查，不能以普通 50 ms 检查代替规则帧。
- 本人移动、瞄准和攻击表现立即本地预测，权威确认后重放未确认输入。连续移动和瞄准可合并，射击、拾取、投掷、处决边沿不得丢失；分别维护收到与已应用序号。
- 预测、输入窗口、事件历史、发送队列与远端插值均有硬上限。慢端独立追赶或恢复，不能阻塞服务器和其他玩家；普通确认不重建显示时钟、不重播枪声。
- 输入携带对局代次、序号和生命代次，服务端检查旧输入、乱序和非法字段。失焦、隐藏、断线或手柄中断释放瞬时输入，恢复不补播攻击。
- 服务器进行高速弹丸连续碰撞。涉及历史命中补偿时同时考虑目标、墙、门和生命代次，并限制回溯；客户端时间和计算结果不能直接决定命中。
- Go 业务坐标、角度、速度、时间、随机数和边界计算使用整数或明确倍率的定点整数。TypeScript 输入和预测先将控制器连续值量化为整数，浮点绘制值不得回流规则比较。
- 上述整数全链及本游戏 lint 中更严格的浮点限制属于运动／战斗与同源预测的跨端确定性约束，不是通用规范对所有语言、公共代码或纯显示计算的全面浮点禁令。
- PC、手机和实体手柄进入相同逻辑动作。手机双摇杆必须支持多指、滑出与取消，失焦恢复先确认中立。全屏和音频使用平台接口。

## 检查范围与产物

- 新增地图 ID 会扩展平台房间恢复所需的地图集合；旧镜像的 `MapByID` 不认识新 ID 时会拒绝恢复。发布前按部署规范提高存档兼容代次并保留一致备份，不能仅凭状态 `schema` 未变就认为旧镜像仍可回滚。

- 先编写失败场景和可复跑 E2E，再编写复杂功能。需要隔离的物理、协议或提取检查先列失败场景，再编写测试与实现。
- `node games/hotlinemiami/build/lint.mjs` 递归检查 `games/hotlinemiami/` 和 `scripts/hotlinemiami/` 中全部受支持自编源文件，包括检查器与测试；范围不代表全仓库。Go、TypeScript／JavaScript、Python、CSS、JSON 分别执行语法、命名、目录和禁用写法规则。`assets/public/` 外部载荷不按自编代码解析，但每个文件必须在 `assets/resources.json` 登记并通过大小和 SHA-256 验证，缺失、损坏、未登记或符号链接均失败；该子树以外的自编资产元数据继续检查。
- `node --test games/hotlinemiami/tests/lint.test.mjs` 运行正负例和定向 CI 选择。结果位于 `.local/hotlinemiami/verification/lint/`，临时目录和 Go 工具缓存限 `.local/hotlinemiami/`，入口先幂等创建目录。
- CI 自动发现游戏目录、前端测试和 Go 测试。单独前端／素材变更不扩大到其他游戏或本作后端完整比赛；后端变更执行本作规则与相关竞态验收。资源恢复遵循待发布提交的统一平台入口：直接按 `--game hotlinemiami` 恢复，或使用 `restore-resources` action 的 `scope: game` 与 `game: hotlinemiami` 校验缓存；对应版本的真实恢复机制必须通过测试，不依赖其他任务尚未提交的 CI 代码。采用缓存策略的普通 CI 下载预算为 0，缺失对象须通过平台明确的手动预热入口处理。
- 正常网络预算在实现前冻结：RTT 不高于 80 ms、抖动不高于 20 ms、无注入丢包；键鼠原生事件到首次画面响应 P95 不高于 33 ms，触屏 P95 不高于 50 ms。显示目标 60 FPS，帧间隔 P95 不高于 20 ms、P99 不高于 33 ms；指标不得测后放宽。
- 验收覆盖 2 人与满员、密集交火、快慢端共存、多房间、重连、托管接管、320 px 手机与全屏。分别记录 RTT、输入 ACK、规则应用、权威帧到达、显示排队和输入到画面响应，不用单项替代另一项。
- 保留版本、设备、随机种子、网络配置、输入和事件记录、JSON／CSV 指标、截图／录屏与复跑命令。未执行的原版运行对照、实体手柄或性能场景不得写为已通过。
