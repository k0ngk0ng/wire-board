# 控制器开发规范

适用范围：键鼠、触屏、控制器映射、连发和输入释放。开发流程同时遵循 [通用规范](common.md)。本文件是控制器规范的统一入口，`AGENTS.md` 和游戏规范引用本文件。

## 控制器与输入

- 平台只提供一个「控制器设置」入口，不在每款游戏中另设重复的设置按钮。进入后优先显示当前游戏的方案，并可在同一界面切换游戏。配置按用户、游戏独立保存，并按实体手柄型号维护；用户可以修改和恢复自己的默认键位，切换用户或型号不能串用、覆盖另一份配置。
- 默认双键控制器使用 W 向上、S 向下、A 向左、D 向右、F 作为 Select、空格作为 Start、J 作为 B、K 作为 A、U 作为连发 B、I 作为连发 A。游戏解释逻辑按钮在当前玩法中的意义，公共层只负责输入映射、按下／松开与连发。
- FC 经典双键的游戏内手柄和「控制器设置」复用同一视觉组件与红白机红金配色 SVG 底图。左侧为十字方向键，中间为 Select／Start，右侧上排 Turbo B／Turbo A，下排 B／A，两列上下对齐；连发键放在手柄内，手柄标注使用 Turbo B／Turbo A，不写「连发」。比赛画面与手柄分区显示；PC 与手机均将手柄置于比赛画面下方的独立区域，居中排列，不在比赛画面内叠加手柄。游玩模式只显示逻辑按键名，键盘映射仅在配置模式显示；底图与按钮不重复印字。不同型号分别适配布局。十字键支持连续触摸滑动和斜向，多指输入互不覆盖；取消、失焦、页面隐藏、禁用、换配置和卸载时释放对应输入，命中区不得互相重叠。验收保留 PC、320px 手机、设置模式和真实游戏模式截图及原生鼠标／触摸结果。
- 键盘映射与实体手柄的按钮／轴映射分开保存，统一输出逻辑按钮。须处理按键冲突、多种输入同时使用、失焦、页面隐藏、设备断开和连发停止；输入框及配置弹窗不触发游戏操作。

## 实体手柄

- 通过浏览器 Gamepad API 读取 USB／蓝牙手柄，统一输出逻辑按钮，不伪造键盘事件，也不让游戏直接读取另一套物理键号。现有游戏输入循环调用 `PhysicalController`，与键盘、触屏合并后继续使用原有预测与服务端操作接口，不增加等待服务器响应的采样环节。
- 以浏览器报告的 `standard` 映射使用位置预设，不能仅凭厂商名称猜测按键编号。FC 布局默认将下方／右侧面键映射为 B／A，左侧／上方面键映射为 Turbo B／Turbo A；SFC 布局的左侧／上方面键为 X／Y，L2／R2 为 Turbo B／Turbo A。十字键和左摇杆均可控制方向。非标准映射设备须支持自定义按钮及轴方向，未配置时不得擅自发送游戏操作。
- 实体映射按用户、游戏和浏览器报告的手柄型号分别保存，与键盘映射隔离。连接序号只用于识别本次连接，不能当作持久化型号或用户身份。自动选择应保持当前可用设备，不因插入另一台设备而抢走操作；一次只采样所选的一台手柄，断开后重新选择也须重新确认中立状态。
- 提供按钮／轴方向录入、冲突提示、解除绑定、默认映射恢复、摇杆死区和实时按键反馈。录入忽略开始前已经按住的输入；恢复或清空某台手柄映射不得覆盖键盘及其他手柄配置。服务端校验逻辑按钮、物理索引、轴方向、重复绑定、配置大小与修订号；旧版键盘客户端省略实体映射时，不得清空已有手柄设置。
- 连接、重连、换配置、失焦恢复及关闭设置后，须先松开按钮并让摇杆回到死区内，才能重新触发输入。设备断开只释放对应物理来源，不得取消仍按住的键盘／触屏输入；页面隐藏、禁用、卸载或进入编辑控件／配置弹窗时及时释放输入。摇杆使用死区和滞回抑制抖动；相反方向同时输入时归零，普通 A／B 不得被另一来源的连发间隙松开。
- 不支持、拒绝或暂未暴露 Gamepad API 时，设置页显示明确状态，键盘和触屏继续可用。兼容性以浏览器实际报告为准，不承诺所有品牌、型号、驱动或连接方式都可识别。
- 验收覆盖标准与非标准映射、稀疏连接序号、多设备选择、配置持久化与用户／型号隔离、死区、连发、混合输入、设置拦截、断开及恢复，保留桌面和 320px 截图。必须在受影响游戏的真实房间中检查可见响应、服务端接受及松开结果，不能仅以设置页检测到设备或 ACK 成功作为可玩性证明。虚拟 Gamepad API 输入须明确标注；未使用实体硬件验证时，不得把某个具体手柄型号写成已实测兼容。

## 普通游戏与操作方案

- 每款游戏独立保存用户的操作方案，并提供默认预设。FC／MD 等复刻布局可以作为预设类型，普通游戏按「移动、开火、挥拍、选择、确认」等实际动作展示，不强行套用 FC／MD 的按钮名称。
- 游戏声明动作、输入类型、默认键位和标准手柄预设，解释动作对玩法的意义；公共层负责映射、采样、冲突和输入生命周期，不直接决定出牌、落子、建造或物理结果。
- 棋牌／地图类支持方向导航、选择和确认。方向操作只切换当前焦点／目标，不自动移动牌、棋子或部队；手牌按相邻牌及行切换，地图按相邻格子／地块切换。选牌与出牌、选地与执行操作分开，仍使用游戏原有的合法性校验和确认流程。
- 导航须有清晰可见的焦点，不用人物编号或序号角标代替。普通快照不得抢走当前焦点或清空已选内容；焦点目标消失时选择合理的相邻目标。不能把配置界面的按键录入当成游戏操作。

- 只有已接入实际游戏操作的方案才能出现在设置列表；不得为未接入游戏展示可保存但不生效的通用方案。旧协议游戏也按同一元数据和配置接口接入，不能因未使用独立模块而漏掉方案。
- 改键后原默认键不再绕过映射触发旧处理器；保留默认键须作为用户可见的替代绑定。游戏内弹窗独占导航和确认，平台弹窗及文本编辑暂停游戏输入；关闭后重新确认手柄中立状态。
- 手牌上下换行按牌所在行定位，不把选中牌的上提偏移误认为另一行。确认键长按只选择一次，方向键长按可按稳定节奏重复。导航到可视区外时同步滚动或调整地图视区，不能只改变不可见焦点。

- 独立 Ctrl／Shift 等修饰键可以作为动作绑定；修饰键组合仍须尊重浏览器快捷键。按住移动与单次动作分开处理：旋转、硬降、暂存或确认不得因新方块／新状态出现而再次触发，重复速度由游戏既有规则决定，不统一套用连发器。

- 蓄力动作须区分主动松开与输入中断：主动松开才执行发射；设备断开、读取失败、失焦、隐藏、编辑／设置界面、换配置及回合切换均取消蓄力。设备断开事件尚未到达时，也要从采样结果识别中断；未连接手柄不能导致键盘蓄力被误取消。另一输入来源仍按住同一动作时，应保留该来源，不能因移除一个来源而误发射。

- 游戏内复选框、单选框和下拉选择属于可导航控件；下拉字段用上下方向选择选项，确认后离开字段，再由原有提交按钮执行操作。文本编辑和游戏区外的配置控件仍拦截游戏输入。取消优先关闭当前游戏弹窗，不能同时清空弹窗下的选牌或选子。
- 目标被移除或禁用后，按最近可见位置在同组内恢复邻近焦点；旋转、缩放和手机转置均依据实际显示位置导航。无方向或确认输入时，不逐帧遍历整张棋盘的控件几何。

- 模拟输入由游戏动作声明 `continuous`，公共层同时提供逻辑按键和 0～1 连续值。摇杆越过死区后按剩余行程归一化，扳机保留原生压力；普通数字按钮继续遵循原来的按下语义。键盘与触屏可以提供满幅输入，合并来源时不能因拔掉手柄而松开仍按住的键盘操作。游戏继续通过自身的输入、预测及服务端接口解释这些值。

- 游戏内数字／范围字段可用手柄按原生 `min`、`max`、`step` 调整；短按为一步，持续按住后可加速，切换字段时重置加速。确认只离开编辑字段，业务操作仍通过原有提交按钮执行。键盘在此类字段内保留正常编辑，不把输入数字或光标键当成棋盘操作。多组表单应按可见业务分组导航，避免跨字段只能反复绕回棋盘。
- 手牌抬起仅改变呈现，不能改变方向导航的行归属；没有独立行容器的卡片组按未变换的布局位置判断相邻行。

- SVG `viewBox` 或 Canvas 镜头不能仅依赖 `scrollIntoView`。公共导航发出可取消的 `controller-reveal` 事件，由游戏将目标移入视区；镜头调整只影响显示，不改变选中内容或提交行动。鼠标拖动后的防误触状态不得拦截后续键盘／手柄确认。

- 导航类游戏可在公共方向、确认、返回和分组动作之外声明独立快捷动作；默认导航绑定仍须保留。快捷动作通过 `controller-action` 交给游戏原有处理器，受同一配置、输入生命周期和弹窗范围约束。不得用长按普通确认键隐式触发另一项业务操作。

- 具有二维选择等特殊含义的游戏控件，可取消 `controller-direction` 事件并自行解释已映射的方向；公共导航仍负责重复节奏和范围。未接管的控件沿用普通空间导航，不伪造键盘事件。
- 新增或修改动作预设后，须通过真实 HTTP 接口读取并保存全部已注册方案，验证默认键位、替代键和实体映射都满足服务端约束；不能只证明设置页能够显示。ESC 等平台保留按键不作为可保存的默认映射。
