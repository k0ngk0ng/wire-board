# 控制器开发规范

适用范围：键鼠、触屏、控制器映射、连发和输入释放。开发流程同时遵循 [通用规范](common.md)。

## 控制器与输入

- 平台入口统一称「控制器设置」。配置按用户独立保存，并按控制器类型／型号维护；用户可以修改和恢复自己的默认键位，切换用户或型号不能串用、覆盖另一份配置。
- 默认双键控制器使用 W 向上、S 向下、A 向左、D 向右、F 作为 Select、空格作为 Start、J 作为 B、K 作为 A、U 作为连发 B、I 作为连发 A。游戏解释逻辑按钮在当前玩法中的意义，公共层只负责输入映射、按下／松开与连发。
- FC 经典双键的游戏内手柄和「控制器设置」复用同一视觉组件与红白机红金配色 SVG 底图。左侧为十字方向键，中间为 Select／Start，右侧上排 Turbo B／Turbo A，下排 B／A，两列上下对齐；连发键放在手柄内，手柄标注使用 Turbo B／Turbo A，不写「连发」。比赛画面与手柄分区显示；PC 与手机均将手柄置于比赛画面下方的独立区域，居中排列，不在比赛画面内叠加手柄。游玩模式只显示逻辑按键名，键盘映射仅在配置模式显示；底图与按钮不重复印字。不同型号分别适配布局。十字键支持连续触摸滑动和斜向，多指输入互不覆盖；取消、失焦、页面隐藏、禁用、换配置和卸载时释放对应输入，命中区不得互相重叠。验收保留 PC、320px 手机、设置模式和真实游戏模式截图及原生鼠标／触摸结果。
- 键盘映射与实体手柄的按钮／轴映射分开保存，统一输出逻辑按钮。须处理按键冲突、多种输入同时使用、失焦、页面隐藏、设备断开和连发停止；输入框及配置弹窗不触发游戏操作。


## 实体手柄

- 通过浏览器 Gamepad API 读取 USB／蓝牙手柄，统一输出逻辑按钮，不伪造键盘事件，也不让游戏直接读取另一套物理键号。现有游戏输入循环调用 `PhysicalController`，与键盘、触屏合并后继续使用原有预测与服务端操作接口，不增加等待服务器响应的采样环节。
- 以浏览器报告的 `standard` 映射使用位置预设，不能仅凭厂商名称猜测按键编号。FC 布局默认将下方／右侧面键映射为 B／A，左侧／上方面键映射为 Turbo B／Turbo A；SFC 布局的左侧／上方面键为 X／Y，L2／R2 为 Turbo B／Turbo A。十字键和左摇杆均可控制方向。非标准映射设备须支持自定义按钮及轴方向，未配置时不得擅自发送游戏操作。
- 实体映射按用户、逻辑布局和浏览器报告的手柄型号分别保存，与键盘映射隔离。连接序号只用于识别本次连接，不能当作持久化型号或用户身份。自动选择应保持当前可用设备，不因插入另一台设备而抢走操作；一次只采样所选的一台手柄，断开后重新选择也须重新确认中立状态。
- 提供按钮／轴方向录入、冲突提示、解除绑定、默认映射恢复、摇杆死区和实时按键反馈。录入忽略开始前已经按住的输入；恢复或清空某台手柄映射不得覆盖键盘及其他手柄配置。服务端校验逻辑按钮、物理索引、轴方向、重复绑定、配置大小与修订号；旧版键盘客户端省略实体映射时，不得清空已有手柄设置。
- 连接、重连、换配置、失焦恢复及关闭设置后，须先松开按钮并让摇杆回到死区内，才能重新触发输入。设备断开只释放对应物理来源，不得取消仍按住的键盘／触屏输入；页面隐藏、禁用、卸载或进入编辑控件／配置弹窗时及时释放输入。摇杆使用死区和滞回抑制抖动；相反方向同时输入时归零，普通 A／B 不得被另一来源的连发间隙松开。
- 不支持、拒绝或暂未暴露 Gamepad API 时，设置页显示明确状态，键盘和触屏继续可用。兼容性以浏览器实际报告为准，不承诺所有品牌、型号、驱动或连接方式都可识别。
- 验收覆盖标准与非标准映射、稀疏连接序号、多设备选择、配置持久化与用户／型号隔离、死区、连发、混合输入、设置拦截、断开及恢复，保留桌面和 320px 截图。必须在受影响游戏的真实房间中检查可见响应、服务端接受及松开结果，不能仅以设置页检测到设备或 ACK 成功作为可玩性证明。虚拟 Gamepad API 输入须明确标注；未使用实体硬件验证时，不得把某个具体手柄型号写成已实测兼容。
