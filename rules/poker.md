# 扑克牌游戏开发规范

适用范围：选牌、牌面、手牌布局、牌桌稳定性和手机交互。开发流程同时遵循 [通用规范](common.md)。

## 扑克牌游戏

- 选牌不绑定行动窗口编号。普通快照、他人出牌／过牌、回合轮转和当前出牌不合法时，不得清空玩家已经选中的牌；只移除已经离开手牌的实体 ID。新发牌、换房间或换观察席位时重建选择。进贡／还贡、升级收底和斗地主收底的新牌加入现有选中集合并保持抬起，不能覆盖原有选择；首次进入或刷新看到的整手牌不算新收牌，不自动全选。
- 提示优先保留完整牌组；三带二在主体相同、拆牌代价相同时，带的对子按点数从小到大选，不按实体 ID／花色排序。有完整自然炸弹时，不能默认拆成较小炸弹留下孤张；合法的一手出完优先，手动拆牌仍由玩家决定。规则各自维护。
- 手机倒计时验收必须检查时间文字本身的边界，不能只检查外框。主要操作不得放在可滚动的按钮容器中；进贡、还贡、亮主、扣底和结算说明不得挤出确认按钮。Safari 相关问题须保留 WebKit 的可见性／命中检查，并保留 Chrome 真实房间回归结果。
- 手机扑克牌桌以浏览器实际可视区域为边界，倒计时放在桌面紧凑位置，不使用独占整行的大横幅。本人手牌、公开出牌和主要操作优先显示在同一视窗内；平台、房间、玩家详情等次要入口由平台统一折叠，仍可随时打开。适配浏览器工具栏伸缩及窄屏高度变化，不以挤出底部操作按钮换取大块留白；PC 保持既有布局。
- 公开出牌不得强制单行并使用横向滚动条。按可用空间叠放、换行，完整保留牌组，较长牌组可点击放大；出牌、过牌和牌数变化不能挤动手牌或按钮。验收须检查可视窗口中的实际位置、完整牌组、触屏选牌和折叠后的公共操作。
- 牌桌、各席位出牌区、操作区和手牌区使用稳定占位；有牌／无牌、出牌／不出、轮次切换、牌型预览和手牌减少不得改变区域位置及页面高度。手牌按玩法最大容量预留，多行手牌上下叠放，不要求完整显示每张牌的插画，但须保留点数、花色和可点击角标；选中上提不得遮住上一行角标。长牌组和展开内容在所属区域内查看，不撑开牌桌。桌面及 320px 手机验收须逐帧比较几何位置，并验证溢出内容可用鼠标、键盘和触屏查看。
- 牌面左上角的数字、J／Q／K／A 与 Joker 字母统一字体、字号和字重，10 不单独缩小。牌面不叠加「主」「级」「配」等中文角标；主牌与级牌信息放在桌面规则区域，读屏标签可保留。三套皮肤和图片失败后的回退均遵循此规范。
- 本人的手牌始终显示在下方，只旋转显示位置，不修改服务端席位编号或阵营关系。
- 双副牌使用独立实体 ID。换肤不改变牌值、手牌顺序或选牌。320px 下须验证 27／33 张手牌的可读性、暴露角标的实际命中、鼠标及触屏拖动多选，不只断言 DOM 数量。
- 共享代码只处理牌面、牌背、偏好、手势、座位与反馈，不建立跨游戏牌型引擎。规则和地区选项分别维护。
- 素材保留原始来源、许可证明、生成方式与 SHA-256；图片和音效使用 OSS 不可变版本目录并提供客户端回退。回退遵循[通用镜像边界](loading.md#发布资产与镜像边界)，不得把素材副本重新打入服务器构建或镜像。外站许可页面原始 HTML 只作为源码证据保存，不作为同源可执行页面公开。
