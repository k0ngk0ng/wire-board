# 房间图标补全与键盘焦点验收

在实现前登记以下失败场景。图标检查覆盖完整前端的等待、游玩、结算、观战及离开状态；存档图标使用实际组件的轻量渲染检查。焦点浏览器夹具仅隔离 FC、MD 及通用输入适配器和公共游戏边界，不替代游戏规则与物理验收。

| 范围 | 失败场景 |
| --- | --- |
| 房间工具 | 任一状态仍出现文字按钮；新按钮缺少图标、名称或快速提示；保存相关动作遗漏；禁用状态或保存投票状态丢失；对局日志、复制邀请、结束与离开入口失效 |
| 托管能力 | 组件转换后，魂斗罗仍必须隐藏开启／取消托管并保留单人及双人选项；旧测试不能依赖原生按钮标签而失去实际能力判断的覆盖 |
| 背景点击 | 点击游戏外普通文字、空白或可聚焦容器后按键失效；恢复焦点造成页面滚动；无游戏焦点入口或尚未就绪时错误抢焦点 |
| 编辑与导航 | 点击聊天、输入框、选择框、可编辑内容、链接、按钮、摘要或设置弹窗时抢焦点；文字选择或修饰键点击受影响 |
| 输入生命周期 | 切换窗口／标签页后卡键；回到页面自动恢复旧输入；禁用或卸载后仍抢焦点；切换游戏残留监听器；触屏取消和按键释放失效 |
| 启用就绪 | 同步请求启用后，React 尚未提交状态或恢复公共监听器就提前发送按键；验收须等待实际 DOM 启用状态、就绪状态和全屏入口状态一致，再点击背景并发送新的按键，不重用旧输入 |
| 全屏 | 普通页面、原生全屏和网页全屏回退的焦点规则不一致；点全屏工具栏触发游戏；全屏退出后焦点与滚动异常 |

浏览器结果和截图保存在 `.local/room-tools-followup/verification/`。完整平台结果继续使用 `.local/room-flow/verification/`。全部入口须可重复执行，临时 profile、编译及服务文件限制在工作区内。

焦点报告保留可信点击与按键、活动元素、窗口焦点、页面可见性、请求启用状态、实际 DOM 启用与就绪状态及渲染帧数。失败时先区分输入未到达、页面失焦、尚未启用和生产焦点恢复失败；不得用固定等待或持续强制焦点掩盖问题。
