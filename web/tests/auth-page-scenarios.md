# 登录页验收场景

实现前冻结以下失败场景：主视觉地址未登记或未使用公共 OSS 命名空间；图片缺失导致布局坍塌；登录字段或请求改变；邀请码注册缺失；确认密码不一致仍提交；邀请房间提示丢失；忙碌状态可重复提交；错误不可访问；更新日志入口消失；320 px 下横向溢出、输入框或按钮小于 44 px；桌面图文区域与参考失配；页面依赖外部字体服务。

先运行 `node --test web/tests/auth-page.test.mjs` 验证组件和资源登记。再以实际登录组件执行桌面与 320 px 浏览器操作，保留登录、注册、校验、忙碌、错误、邀请状态的结果及截图。运行时图片须完成本地 CDN 回读，原稿保存在 `.local/_common/login/source/`。

## 登录页桌面与手机新版布局

实现前冻结以下失败场景：品牌插画仍是独立方图，未铺满品牌区；390 px 下品牌区与参考的 360 px 高度失配；手机隐藏介绍或游戏分类；桌面未保留左右分栏；320 px 下分类、表单或页脚溢出；手机输入字体小于 16 px 导致系统放大；短屏或横屏裁掉注册提交按钮；图片缺失使品牌区坍塌；新背景通过应用地址跳转或源码写死 CDN 域名。保留邀请码、确认密码、请求字段、邀请提示、忙碌与错误语义。

浏览器验收使用实际 Auth 与公共 CSS，覆盖 1440 × 900、1024 × 768、768 × 1024、390 × 900、320 × 740 和 844 × 390。检查品牌区和背景图的实际几何、分类可见性、两种表单、44 px 点击目标、16 px 输入字体、滚动可达性和直接 CDN 请求；不创建生产账号。结果与截图写入 `.local/_common/login/responsive/verification/`。命令：`AUTH_PAGE_BROWSER=1 node --test web/tests/auth-page-browser.test.mjs`。
