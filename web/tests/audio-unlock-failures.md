# 输入期间音频解锁失败范围

本清单先于修复与针对性测试。桌面 WebKit 的原生媒体探针确认：2 个采样的 WAV 触发 `MEDIA_ERR_DECODE`，`play()` 的 Promise 仍未结束；真实幽游白书页面每次单点 C 都重设这段源并再次播放，30 次点按记录了 30 次中断。热血篮球共用同一平台入口。

- 静音 WAV 必须包含可解码的有限 PCM，RIFF、数据长度、采样率、位深和全部静音采样一致；不能继续使用原来的 2 采样片段。
- 解锁尚未完成时，快速触控与键盘输入共用一次原生播放，不重设源、重复 `play` 或产生等待队列。
- 正常开始后不再重播解锁片段，游戏音乐、效果声、其他 owner 和媒体音量不受影响。
- `NotAllowedError` 或其他播放拒绝返回失败，允许后续真实手势重试；不能永久缓存失败，也不能自动反复播放。
- 原生解码错误可能不结束 `play()`；错误事件和明确超时均须结束本次尝试，移除自己的监听与计时器。
- 静音、停止、卸载和新播放接管取消旧尝试；旧 Promise 迟到不能标记新一代已解锁，也不能暂停或清空新的游戏声音。
- 验证真实页面的不按键、单键连点和长按，记录静音解锁请求、原生媒体错误及服务端实际应用输入。WebKit 与 Chromium、桌面与 iPhone 分开记录，不能以桌面通过宣称真机修复完成。

## 原生浏览器重放

安装固定版本的 Playwright 和 WebKit 到工作区临时目录后，执行 `PLAYWRIGHT_BROWSERS_PATH=<工作区浏览器目录> node web/tests/audio-unlock-browser.mjs <工作区内的 playwright/index.mjs>`。用 `REFERENCE_SHA=8203d8b6aa10f2f199a2611d6f7ad4da8d6bc086` 重放修复前源码；这次负向回归预期失败，错误码、播放次数和未结束请求保存在 `webkit-reference.json`。当前源码应通过并生成 `webkit-current.json`。

同一脚本支持 `BROWSER_ENGINE=chromium`，另传入已安装 Chromium 可执行文件路径。旧片段在 Chromium 可正常解码，其对照报告的 `errors` 为空、`results` 全部成功且 `plays` 为 1；旧源码仍会因片段字节数与新版验收要求不同而以负向结果结束，不能把这个结果解释成 Chromium 解码失败。

这些记录验证真实媒体解码和连续输入调用，不把静态平台夹具当成真实对局帧率或 iPhone 真机验收。幽游白书、热血篮球的真实认证房间操作记录另按各游戏保存。
