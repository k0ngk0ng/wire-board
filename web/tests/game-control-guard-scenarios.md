# 游戏区原生选择与菜单保护

先保留失败场景和浏览器失败证据，再编写实现。

- 公共游戏边界遗漏标题、比分、Canvas、图片、链接、摇杆标签或底部说明，长按后仍出现原生文字选区或复制、搜索菜单。
- 只有标准 `user-select`，没有 WebKit 选择与长按菜单保护；正常与全屏模式行为不同。
- 拦截浏览器菜单时停止事件传播，使游戏自己的右键菜单无法打开。
- 全局取消指针或触摸默认行为，导致双摇杆、多指点击、滑出、松手或取消失效。
- 输入框、文本域、下拉选择、可编辑内容或游戏区外聊天和说明无法选择文字、复制粘贴或打开正常原生菜单。
- 浏览器的原生输入选区与 DOM 选区锚点不同，活动编辑器被误清理；并行测试或异步选区更新时，未确认页面焦点与实际选区就读取旧值。
- 已产生的游戏内选区无法在继续操作时清除；清理选区误伤编辑器或区外内容。
- 组件卸载或游戏切换后仍残留文档监听器。
- 枪械显示零发却没有可执行提示，误导玩家寻找不存在的装填操作。
- lint 必须拒绝游戏边界标记或清理钩子被移除、WebKit 声明缺失、全局触摸拦截、错误目录／命名、代码注释和动态执行。

运行 `node --test web/tests/game-control-browser.test.mjs`。测试使用实际公共 `GameFullscreen`、实际迈阿密热线双摇杆及其 CSS，以 Chromium 原生鼠标和模拟多指触屏验证长按、选择、菜单、松手和全屏；输入和区外复制作为反例。输出位于 `.local/hotlinemiami/mobile-selection/verification/`，包括源码摘要、原生事件、逐项检查和截图。模拟触屏不等同于 iOS 实机验收，WebKit 专属 CSS 另由策略检查约束。
