# 斯诺克实施与验收

目标：纯 2D 俯视，WPBSA 标准十五红球，1v1 与 2v2（整次上手轮换），统一房间／玩家栏／音效，原创二维素材及 OSS 不可变发布，新游戏默认下架。调研来源见 `research/snooker.md`。此文记录未完成的完整目标，不能以物理演示替代交付。

## 实现前的失败场景

- 物理：高速穿透、初始重叠、贴球粘住、碰撞顺序不确定、近同时碰球漏判、碰库增加能量、角袋／中袋几何错误、袋口一碰就吞球、球未停止就允许下一杆；高低杆不影响走位、侧旋仅装饰；NaN／Infinity／越界力度／击点被接受。
- 规则：红彩交替错误、最后红球后漏打一颗彩球、多红同进漏分、犯规还计入该杆进球分、多个犯规叠加错误、罚分归错队、红球无故复位、彩球错位或重叠、白球在 D 区外摆放。
- 特殊判罚：自由球仅用球心射线判断；自由球同进计分错误；贴球离开仍判未碰球；Miss 无法恢复原位；需罚分或不可能解到时仍机械判 Miss；警告前直接三次判负；改位置重打未清连续计数；超分自动结束；黑球平分未重置／先打权或队内选人错误；僵局重开丢失开球方。
- 双打：每杆换人、队友代操作、重打换搭档、换局开球不交替、局中改顺序、重连丢当前击球者、战绩把搭档当对手、认输被单人误操作提交。
- 平台：未上架可开房、3 人开局、重复 nonce 重复击球、旧窗口操作、非当前玩家／观众操作、滚动中第二次击球、倒计时与标准无出杆时限冲突、持久化恢复重算不同球位、动画提前计分或重播。
- 界面：320px 球桌失真／关键分数被裁切、鼠标拖动或缩放触发击球、触屏手指遮住瞄准、旋转控制误触、缺少取消、高亮改变实际碰撞尺寸、颜色／文字对比度不够。
- 素材音效：使用编号美式台球、3D 资源混入、来源或许可不明、OSS 覆盖旧文件、无本地回退、未击中先响、离桌／隐藏／静音仍有声音。

## 验证和交付顺序

1. 先写物理边界测试，验证确定性、碰撞、口袋、旋转和参数拒绝；保存失败及通过日志与轨迹 JSON。
2. 先写裁判与完整模块／HTTP 对局场景，覆盖普通规则、特殊判罚、双打顺序、持久化和幂等；明确区分人工设置球位的边界夹具和自然开局完整对局。
3. 接入统一大厅和等待房间；实现可操作的纯 2D 球桌、瞄准、力度、击点、摆球和判罚操作。
4. 制作二维封面／球桌／球杆与音效，保存来源及生成方式，上传 OSS 并回读。
5. 真实浏览器覆盖 PC／320px／390px、1v1／2v2、完整击球时间轴、回放／重连、缩放拖动、平台静音和上下架；保留截图、结果与重跑脚本。
6. 按 main 验证、tag 发布已验证产物的既有流程发布更新，检查健康状态与上下架设置。

当前状态：本地功能及验收已完成，素材已上传 OSS 并回读。等待 main 对同一提交的验证构建，再按版本 tag 发布和更新服务器。验收的范围、产物及重跑命令见 [验证记录](snooker-verification.md)。

## 完成项与边界

- 纯 2D 球桌、统一封面／房间／玩家栏、体育分类、2／4 人配置、队伍分组和局间顺序。
- 服务端物理、碰撞关键帧、稀疏轨迹、受校验的存档及断线恢复；比分在运动结束后结算。
- 红彩交替、自由球与有效遮挡、整个 D 区判定、隔库路线核验、原位重打、警告、彩球复位、黑球决胜、认输本局与弃赛本场、并发同意和准备。
- 自然开局完整单打／双打／多局赛、真实 HTTP 完整比赛、全部席位和真实浏览器交互；有明确球位的夹具单独标注。
- 原创二维图像与具有许可证明的音效，共 32 个 OSS 对象。Native media 播放成功、时序、统一静音、隐藏页面不补播、减少动态效果和文字对比度均有核验。

自动裁判采用公开的几何／物理判据，不声称能读取现实玩家的行为意图。没有证实隔库可执行路线时不追加 Miss；具体算法范围写入模块说明和玩法速查。没有引入 3D 画面、六红球预设、电脑玩家或强制出杆倒计时。
