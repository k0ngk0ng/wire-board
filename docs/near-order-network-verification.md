# 近身接球、游戏排序与网络状态验收

## 乒乓球

原来的静止挡球需要等落台后 100ms，但底线附近长球的示例窗口只有 46ms，短球则有 324ms。拍子还会随来球前后自动改变距离，使屏幕大小和接触时机不易判断。

修正后，球拍使用固定屏幕尺寸绘制，PC 拍面半径为 42px、手机为 24px。指针与球的可见重合也参与触发；固定尺寸的触区投影为有界的世界坐标范围，由服务端校验。去掉固定 100ms 等待，触屏已经迎住球时可以立即轻挡。合法接球区域扩展至底线后 0.88m，并调整视野，仍不能在落地或二次落台后击球。

同一测试的长球窗口由 46ms 增至 168ms。原生触屏检查在本方深度约 1.82m 迎球，服务端确认在约 2.07m 处轻挡成功；旧边界为 1.7m。上抽测试从可见拍面触区之外开始划动，避免把已经重合的静止挡球误当作上抽。检查记录实际投影中心、拍面半径、输入、确认事件与出球轨迹。

快速上抽按相邻指针事件之间的连续路径检查接触，最多回看 80 ms，并提交实际交点与时间。只检查画面帧会漏掉两帧之间穿过球的动作；补充检查同时覆盖发球与回球，并拒绝过期动作和窗口外接触。

320px 原生触摸模拟在增加 250 ms 延迟后，连续验收记录了四次上抽回球成功；服务端确认出球落到对方台面，击球高度约为 0.84～0.92 m。另验证断线恢复与刷新后继续操作，不自动托管。

客户端针对性检查覆盖短窗口、可见触区、固定尺寸、两端视角和相机投影；服务端覆盖长短球及电脑准备范围。规则、自然完整对局和竞态检查仅运行乒乓球，不扩展到其他游戏的规则矩阵。

## 后台排序

`scripts/check-order-network.py` 启动真实生产应用和本地数据库，使用 PC 原生拖拽、320px 原生触摸测试排序、保存、刷新和玩家创建列表。分类筛选排序保留其他游戏的位置，隐藏游戏不会重新上架。HTTP 验收覆盖非管理员拒绝、无效列表、过期编辑冲突、审计失败回滚、重启保留顺序和新游戏追加。

## 网络信号与静默恢复

信号格按 WebSocket Ping/Pong 的真实往返延迟分级：不超过 80ms 为四格，180ms 为三格，350ms 为两格，更高为一格；未测得或断线时不显示假满格。顶部显示当前设备连接的测量值；玩家栏显示该玩家有效连接中的较高延迟，多端连接会在提示中注明。电脑席位不显示假延迟。

延迟测量异步运行，不阻塞游戏快照或输入确认。独立网络元数据包不改变游戏时钟，不泄露其他房间的玩家数据。过期 HTTP 快照不能覆盖较新的延迟记录，旧连接结束也不会清空新连接的测量。

真实 TCP 代理给其中一端增加 250ms 延迟，手机页面实测显示约 252ms，另一端约 2ms。断开并恢复真实连接后，乒乓球没有需要关闭的同步提示，坦克大战可直接继续输入，不必点击重新同步。传输失败仍作为拒绝处理，以清理旧输入；权限和规则错误继续正常反馈。断线不自动托管真人。
