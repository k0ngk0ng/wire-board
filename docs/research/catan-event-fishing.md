# F03：事件牌与渔夫

2026-10-08，本地实现，未发布。接通独立渔夫及渔夫＋城市骑士三至六人；四岛／穿越沙漠／布匹三四人，迷雾／奇迹／新世界三至六人的既有捕鱼海图也可选择事件牌，允许叠加友善强盗、港口霸主或两者同开。

## 规则与实现

- 2025《商人与蛮族》第 5–6 页：先执行事件文字，再按点数生产；瘟疫使城市只生产一张资源，城市骑士不领取商品；强盗逃跑无沙漠时移到场外，不偷牌。第 9–10 页规定鱼筹码的生产、满额替换与消费。
- [官方渔夫＋城市骑士组合](../board-expansion-rule-sources.json)中的 `catan-fishing-knights-2025`：鱼不是资源或商品；只获得鱼仍有引水渠资格。沿用已固定的海图组合配方，见 [渔夫来源](catan-fishing-sources.json)。本阶段重新读取本地固定规则与[官方 T&B FAQ](https://www.catan.com/faq/traders-barbarians)，未找到改变鱼筹码定义的瘟疫例外。
- 因此，湖泊和渔场使用事件牌的生产点数，瘟疫不减少鱼筹码，鱼也不进入事件赠送、偷取或七点弃牌。没有增加新的补充规则；原有本站事件牌组、友善退路、布匹退路和骑士组合版本保持。
- 实际顺序为事件文字、城市骑士回应、资源／商品生产、满额换鱼、金矿资源选择、引水渠。炼金术使用所选骰子生产，不抽事件牌；五六人配对第二人不重复生产。

移除事件会话对捕鱼的整体拒绝，增加生产计数和回应阶段一致性校验。满额换鱼与事件回应、骑士回应、金矿回应不能相互覆盖；存档恢复后仍只有一次产鱼。正常建房、等待开关、实际开始、重开、战绩和规则说明均接入组合。未启用事件的捕鱼及未启用扩展的基础版继续走原流程。

尚未完成的前提组合仍归固定工作包：遗忘部落事件归 F04；四图五六人捕鱼归 F06，新海岸归 F07，Helpers 归 F08，捕鱼海图骑士归 F09，双人归 F10。没有以 F03 完成为由宣称这些嵌套组合已完成。

## 验证

- 独立、独立骑士及六种海图的可用人数共 26 种配置，分别不开变体／同开友善与港口，每种执行 12 类真实抽牌事件：**624 条路径**，含真实起始建设、回应、保存恢复、鱼库存及配对第二人不重复生产检查。该矩阵在初始普通批次及本阶段 race 批次均通过；后者批次总耗时 74.950 秒，但后续金矿测试夹具将新年牌当普通牌索引而失败，不能称整批通过。
- 瘟疫城市的一张资源／无商品／两枚鱼；满手替换后引水渠、炼金术不抽牌；三人和六人先换鱼再选金矿资源；损坏计数、错误回应阶段原子拒绝。初始两个夹具的牌面选择与鱼库存错误已修正，定向 race 2.015 秒通过；金矿夹具排除新年牌后，金矿与损坏存档 race 1.693 秒通过。这些是明确的中局夹具，不是自然完整局。
- **24 场正常建房的自然完整 HTTP 对局**，108.393 秒通过：独立三至六人各两场；六种海图各三人及其当前最高人数一场、同开友善和港口；独立捕鱼＋城市骑士三至六人各一场、同开两变体。检查超时、托管、恢复、资源与鱼实体守恒、观战隐私、实际规则战绩及唯一结算。
- 组合开关、访客拒绝、准备重置、重启、重开、转新世界、回基础 race 4.704 秒；所有基础游戏隔离 race 3.661 秒。相邻捕鱼生产、七点、城市骑士消费、事件及炼金术回归 race 2.448 秒；旧事件启用／显示／拒绝及公开配置回归 game 2.056 秒、server 2.577 秒。
- 前端 181 项、生产前端、Go 构建和 game/server `go vet` 通过。第一次前端构建发现新说明属性被错误加到剧本选择器造成重复属性，已改到事件选择器并通过重新构建。保留既有大包提示；这些结果不是最终全仓 CI。

## 页面与交付
