# 声音驱动工作字节与特殊球比较

可以把原声音驱动恢复为独立的 Go 音序／效果状态机，计算玩法意外读取的 `$00FF`，无需产品内 CPU 或 APU 模拟器，也无需改变实际 MP3／WAV 播放。不过，恢复范围必须包括音序、包络、音高插值及原整数计算的顺序；只按音乐 ID、音效 ID 或经过帧数取固定值不成立。

调查阶段完成原写入闭包和开发用源程序探测。随后已按这些证据建立独立 `games/basketball/audiostate` 包，完成 silent control 原状态对照；尚未接 world／runtime。以下调查和建议保留来源边界，当前实现及验收见该包 `README.md`。

## 已确认的玩法依赖

`held_ball_offset` 的 612,544 次受控原函数调用已证明：特殊球动作 14 被设备改为 4 后，`$BDD2` 越过原偏移表，偶数篮圈选择会读取 `$00FF..0100`。上传完成时 `$0100=255`，右侧目标位置成为 `207 + $00FF`。合法 Court 2 的 X=280／380 会因声音状态不同而得到不同的下一动作。

原证据位于 `.local/basketball/rea/special-turn-alias/`。`court2-counterexamples.json` 使用实际 music 61、先更新 90 次、再请求 sound 30 的声音驱动结果。它是原组件可达值与原比较函数的组合验证，不是完整自然对局中已出现该错误的证明。

新增探测把三个关键结果追到最后写入：

| sound 30 后的声音更新次数 | `$00FF` | 最后来源 |
| --- | --- | --- |
| 1 | 132（`$84`） | 音乐通道 2 解析命令，`$8364` 写入处理入口的高字节。 |
| 2 | 54（`$36`） | 音乐通道 0 包络计算在 `$8746` 写 55，乘法辅助过程 `$8968` 将其减为 54。 |
| 25 | 179（`$B3`） | 音乐通道 2 的音符时长／门限比例在 `$8275` 写 180，`$8968` 将其减为 179。 |

同一音效并不能决定这些结果；音乐的节拍累加器、各通道游标及最后执行的支路共同决定该字节。

## `$00FF` 的完整驱动写入点

对 bank 0 `$8000..897A` 的指令检查排除了 `$836E..83AD` 的命令跳转表。该驱动共有 10 个直接写入点，本轮 8 首音乐加 sound 30 的受控执行实际覆盖了全部 10 个点。

| 写入地址 | 来源和后续用途 |
| --- | --- |
| `$80B0` | 通道加载的增益参数。外部正声音请求传入 `$80`；打击乐子请求可传入其他值。即使稍后优先级拒绝，写入也已发生。 |
| `$8275` | 当前音乐通道的门限比例 `$079E+channel`，随后与音符时长相乘。 |
| `$832A` | 打击乐分发表指针的高字节 `$07C0`；后续子声音加载通常再次改写。 |
| `$8364` | 当前序列命令的原处理入口高字节，来自 `$838E+commandIndex`。 |
| `$846D` | `CD` 命令读取的音色／包络参数表指针高字节。 |
| `$8746` | 包络值与通道音量相乘前的乘数：根据标志选择附加量，再加基础音量和 1。 |
| `$880D` | 应用通道增益 `$0781+channel`，仅在其高位未置位时进入乘法。 |
| `$888E` | 相邻音高周期表低字节的差，作为细分音高插值乘数。 |
| `$88F2` | 颤音幅度 `$07BC+channel` 右移一位的中点。 |
| `$8968` | 乘法辅助过程对该工作字节减 1；如果另一乘数 `$FE` 为 0，则提前返回，不执行减 1。 |

因此该字节既可能是地址高位，也可能是整数计算的中间值。命名为 `WorkByte` 比命名为音量、音高或当前命令更准确。必须保存最后一次写入，而不是每次更新都清零。

本轮的完整写入清单只针对声音驱动范围，不把字节模式搜索误认为全 ROM 的写入可达性证明。

## 原状态与更新顺序

原请求入口为 `$C000 → $FBCC → bank0:$8000/$8006`，原更新入口为 `$FBE3 → bank0:$8003/$8183`。

`$8006` 开始处理请求时清除 `$07E5` 的 bit 7，完成时重新置位。声音更新先检查该位；未就绪则直接返回。未来事件调度应保留请求与声音更新的顺序，不按同帧 ID 集合去重或重排。

一次完整 `$8183` 更新依次执行：

1. 检查就绪位；按 bit 5／bit 6 和 `$0702` 处理周期重触发请求。
2. 按 **8、7、6、5、4** 顺序推进效果／DPCM 通道音序，随后各自应用待更新参数。
3. 检查暂停位 bit 6；暂停时此处返回。效果部分已执行，不能把暂停理解为整个控制机冻结。
4. 按 **2、1、0** 顺序执行音乐通道颤音、应用待更新参数、包络。该段每次声音更新都会运行，不以音乐节拍进位为条件。
5. 将 `$0705` 加到 8 位累加器 `$0706`。没有进位则返回。
6. 进位时先推进音乐通道 **3**，再按 **2、1、0** 推进音乐音符和门限计数。

同一声音更新中，效果部分可能多次写 `$00FF`，随后被音乐包络覆盖；节拍进位时，又可能被后面的音乐命令或时长比例覆盖。只维护「最后活动的效果」不足以恢复该行为。

各通道音序处理包含活动标志、剩余时长、门限倒数、指令重复、两个计数循环、单层返回位置、音符参数及控制命令。原命令表 `$C0..DF` 包括音高／音量设置及相对调整、门限比例、节拍、音色表、循环、跳转、子序列调用／返回、结束、暂停、移调、声音请求、重复、颤音和 DPCM 参数。实现前应从实际曲目／效果流提取命令图并核对覆盖，未知命令不能猜测处理。

## 可维护状态机的必要字段

建议使用明确的字段和小型通道结构，而不是把 `$0700..07E6` 原样作为通用 RAM 快照塞入存档。地址用于与证据对照，不应成为产品的读写接口。

| 状态组 | 原字段依据 | 必要性 |
| --- | --- | --- |
| 当前／保存音乐、重触发声音及倒数 | `$0700..0703` | 请求、暂停恢复和周期重触发改变通道内容。 |
| 就绪、暂停、重触发和音乐活动标志 | `$07E5` | 决定更新支路及哪些通道继续推进。 |
| 节拍步长和相位 | `$0705..0706` | 决定音乐音序是否在本次更新的最后阶段推进。 |
| 9 个通道的活动标志、待应用标志、音序位置、剩余时长 | `$0715+ch`、`$070C+ch`、`$071E/$0727+ch`、`$0730+ch` | 决定下一条实际执行的命令与先后顺序。 |
| 效果优先级和通道增益 | `$0703+ch`（效果通道）、`$0781+ch` | 影响请求能否覆盖，以及音量乘法是否执行。 |
| 音高、细分音高、音量和音符长度／门限 | `$0739/$0742/$074B+ch`、`$078A/$0792/$0796/$079A/$079E` | 即使不输出声音，也会写工作字节并改变后续计数。 |
| 移调、包络指针、包络阶段／值／倒数 | `$07A2`、`$07A8/$07AA`、`$07AC/$07A6/$07AE` | 决定 `$8746` 及其乘法支路。 |
| 颤音等待、当前偏移、方向步长及幅度 | `$07B6/$07B9/$07B0/$07B3/$07BC` | 决定 `$88F2` 和音高插值支路。 |
| 两个循环计数、子序列返回位置、重复计数 | `$0754/$075D/$0766/$076F/$0778+ch` | 保留音乐和效果的原控制流。 |
| 打击乐表、DPCM 控制和必要的输出寄存器影子 | `$07BF..07E0` 及对应参数 | 保守保留相关语义；确认不反馈到工作值的写硬件动作可以省去。 |
| 工作字节 | `$00FF` | 无写入的请求／更新保留旧值；可被玩法兼容层读取。 |

原数组存在仅对部分通道有效的范围和地址重叠，不能机械声明 9 份所有字段。建议先以命名字段覆盖原控制闭包，再按已证实无反馈的字段缩减。

序列数据、音高表和包络表可以离线导出为有来源摘要的结构化常量。对于 `$8364` 这类意外依赖原地址高字节的行为，应把原处理地址高字节作为命令来源元数据保留；不能改用 Go 函数地址，也不能把它误当成可任意重新编号的操作码。CPU 寄存器、指令解码、APU 振荡器和 PCM 生成均不属于这个产品状态机。

本轮原驱动执行没有读取任何硬件设备状态；声音输出使用写 APU 寄存器及影子状态。原 FCEUX 的 sound 30、music 61 两组各 597 个初始化后 `$0700..07E6` 状态，与不实现 APU 的受控原指令执行逐字节相同。后续 Go 包也已逐步匹配这些 oracle 状态；产品的 IRQ／世界调度仍未接线。

首次音乐更新另有一个无效包络指针的读操作：停止零值包络时读取 `$0001`。其运算为 `min(所读字节, 0)`，结果恒为 0，后续曲目命令再装载实际包络。Go 实现只在「空指针、停止阶段、当前值为 0」条件下消去这个无关读取；其他缺失包络返回错误，不引入任意 RAM 输入。

## 控制命令的工作字节语义

- `0` 清除声音状态区 `$0700..07E6`，**不清除 `$00FF`**。探测先置工作字节为 `$5A`，执行原 reset 及空更新后仍为 `$5A`。
- 正声音 ID 在通道加载入口先写 `$80`，再执行来源和优先级判断。音乐请求还清除暂停位；效果请求不走同一音乐分支。
- `253` 置暂停位并关闭 APU，本身不写工作字节。后续效果通道仍可将该字节改为 131／132 等值，音乐包络和节拍部分停止。
- `255` 清除暂停位；若需要重载保存的音乐，可能重新加载通道并写工作字节。本轮同曲恢复路径不写工作字节，随后更新恢复音乐计算。不能把所有 `255` 都简化为固定输出。

这是供玩法别名使用的原控制语义。实际平台播放器的暂停、媒体进度和静音策略属于另一层，本研究没有修改它们。

## 时间顺序不能简单等同于 NMI

原 ROM 的 NMI 向量 `$FFF1` 跳到 `$F089`。固定 bank 中唯一的 `JSR $FBE3` 位于 **IRQ 分派尾段 `$F368`**，经 `$F365` 关闭 IRQ 后执行声音更新，再恢复主线程。不能将其描述成 NMI 处理程序直接调用声音驱动。

新增只读运行探测复用 slot 5 的纽约场地 music 66，以及已有 `runtime-pause-audio` 的 300 帧输入。保存的逐帧 RAM 与旧记录完全一致，SHA-256 为 `b044c052c22ab5a7902f2803f6aeb51fa34faf493b2c782ab21805296e105605`。观察到：

- 300 次 NMI、300 次完整声音 IRQ 更新、9 对主线程声音请求。
- 15 次 NMI 插入到声音 IRQ 更新尚未返回的位置。一个实例是 IRQ 前 `$00FF=254`，NMI 入口时为 47，IRQ 返回时为 54。NMI 时刻可能看到声音计算中间值。
- 88 个 `$D345` 进入观察点的工作字节都等于最近一次已完成声音 IRQ 的结果；其中 82 次来自前一视频帧，6 次来自同一视频帧。不能仅凭帧号推导执行顺序。
- 此次没有触发 `$BDD2`，也不是 Court 2 特殊球自然链路验收。它只能确认原声音、NMI、世界入口和请求的相对观察顺序。

主线程在 IRQ 返回后才继续执行，所以对玩法最有用的接口是按原事件顺序执行 `RequestSound(id)` 和 `AdvanceSoundIRQ()`，保留最后的 `WorkByte`；世界比较使用它实际执行时已完成的状态。进一步接入前，仍须在 Court 2 的目标链路中确认相关 IRQ 与主线程请求的位置。不得为了消除未知调度直接把当前帧的音频更新统一挪到世界比较之前。

`$FBDE` 是共用的 bank 返回代码，不能把每次命中都计为声音请求结束。探测只把它与前面的 `$FBCC` 配对。原始 trace 保留全部该地址命中，便于复核过滤过程。

## 后续实现与验收边界

先定义失败场景和原数据夹具，再实现状态机：八场音乐、全部当前效果、同帧顺序请求、优先级拒绝、打击乐嵌套请求、节拍进位／不进位、包络停顿、乘数为 0、循环／返回、结束、暂停仍推进效果、同曲／异曲恢复、reset 保留工作字节、存档与接管延续。

第一阶段只做离线状态机对照，每步核对 `WorkByte` 及命名状态，不接世界逻辑。第二阶段恢复原事件调度，并在 Court 2 的自然或明确受控特殊球链路中核对 `$BDD2` 比较前值和结果。两阶段通过后再移除该路径的保护；不能以 1,440 个当前样本吻合代替所有支持曲目、效果和调度边界的验证。
