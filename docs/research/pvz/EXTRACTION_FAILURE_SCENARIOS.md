# 原版资源提取失败场景

先记录失败场景，再编写提取器。提取器只读指定的原版样本，只向指定的新目录输出；不执行原版程序。

- 输入不是 XOR 0xf7 的 PopCap PAK，或版本不是 0：拒绝。
- 文件表、文件名、长度或时间戳被截断：拒绝，不输出部分文件。
- 文件表缺少结束标记、成员内容被截断或有未解释尾部：拒绝。
- 成员包含绝对路径、盘符、空段、`.`、`..`、NUL：拒绝。
- 同名或大小写冲突的成员：拒绝，避免跨平台覆盖。
- 输出目录已经存在：拒绝，避免覆盖用户文件。
- 正常包：输出字节与成员一致，清单记录 SHA-256 和源位置。

测试：`python3 -B -m unittest discover -s games/pvz/build -p 'test_extract_classic.py'`。

重动画解码另覆盖：zlib 标记／解压长度错误、定义／轨道／变换结构尺寸错误、字符串截断、非有限数、尾部未解释内容；正常轨道保留原始帧与变换字段，并按 `-10000` 哨兵继承前一帧。不从指针值推断资源地址。

## 头部附属动画缺失身体

- 原版豌豆、双发、寒冰射手的 `anim_shooting` 仅包含头部动画，身体在独立的 `anim_idle` 中循环。单独烘焙头部区间会留下悬空头部。
- 每个攻击帧都必须同时包含原版身体的前后叶、上下茎、头和嘴；不能用总 alpha 非空、整张图可解码或 idle 截图代替。
- 身体时钟和头部时钟分别取各自动作区间，保持脚底锚点和原始图层顺序。
- 接入原版附属矩阵后，攻击姿态保留头部运动；不能通过复制一张 idle 图掩盖问题。
- 所有 shoot 状态和受损／特殊状态分别核对图层清单；手机和桌面应使用同一完整原画。

## classic-v2 完整资源目录

- 原样本植物表有 53 项、僵尸表有 33 项，常规种子为前 49 项；错误数量或 ID 缺口必须失败。
- 所有单位都要有可独立加载的完整预览；三线、裂荚、机枪的闲置和攻击均包含身体及全部附属头。
- 所有场景保留原始格子坐标。泳池／浓雾必须叠加水面，不能把原背景的空白池底当作完整场景；屋顶列坡度由二进制公式确定。
- 单位及动画使用自己的脚底锚点；宽幅跳跃、车辆、僵王不按普通单位边界裁切。
- 护甲、报纸、旗帜和植物僵尸头部必须按对应单位绑定；不把全套可选图层一起绘制。
- 受损坚果／高坚果／大蒜／南瓜保留原始替换图层；只改颜色或血条不算恢复原画。
- 清单按场景和单位列出资源，各单位预览独立；不得把全目录图集作为开局必载项。
- 任意缺失原图、未解码轨道、无图像片段或缺失附属资源都应报告；不能静默省略单位或以通用图标替代。

## 发布文件契约

- 原资源名中的空格等字符不能直接进入发布路径；规范化后仍须避免名称碰撞，且所有矩阵数据／清单同步引用新名。
- 压缩重动画是独立 gzip 载荷，使用 `.pvzr`、`compression: "gzip"` 和明确格式；不伪装成通用 CDN 的 `.gz` 旁车。
- 公共 CDN 原有严格路径和压缩旁车校验保持生效；完整目录必须通过实际 `scripts/cdn_delivery.py.inventory`。
- 旧的不安全名称和未引用的本轮中间载荷必须从未发布 v2 目录清除，不能仅修改清单掩盖残留文件。

## 经典场景音乐

- 源 MO3 摘要、解码器架构／版本／摘要不匹配时停止，不执行原版 Windows 程序。
- 任意 order/row 越界、未找到循环、循环长度为 0 或扫描超过上限时拒绝出货；不能凭试听估算曲尾。
- 使用 BASS MIXTIME 回调中的 DECODE 字节位置定位 PCM 采样帧；改变 GetData 缓冲大小必须得到完全相同的前奏／循环边界和 PCM。
- 前奏只播放一次，循环段保留准确起始采样帧；不能把前奏反复拼进循环或截掉主题首音。
- 保留实际 PC 二进制的 30 通道静音配置；不能按存在差异的历史源码把末通道漏掉或错误划分泳池打击层。
- 导出的 FLAC 必须逐段解码回 PCM16LE，与渲染 PCM 的采样率、声道、采样帧数和 SHA-256 一致；主轨必须非空／非静音。原版夜晚 order 92 是有意的静音待机段，只有这一已验证段允许全零，并明确标记；同曲有声高潮从 order 76／77 开始，不能用别曲替代。
- 菜单、草地、夜晚、泳池、浓雾、屋顶、夜屋顶 Boss 各有明确曲目与 order 来源；只按当前场景懒加载。
- 浏览器只使用平台原生 `audio.track`；静音、离桌或后台清理声音，恢复按有效权威时间定位，不补播过期播放。
- 恢复原主题、分轨和循环位置不代表与原版随敌人数变化的动态混音逐帧等价。
