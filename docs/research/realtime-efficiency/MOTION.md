# 本地运动显示的失败场景与验收

实现前列出失败场景：

- 按下方向后仍等待服务器快照；松手继续按客户端旧方向推进。
- 丢包或后台停顿后无限外推；新实例／房间／回合／席位／控制归属未清理预测与按键。
- 穿墙、穿箱子、穿基地或边界；斜切拐角；泡泡所在格不能正常走出，或走出后又穿入。
- 权威新墙体／冻结／被困／死亡／重生到来后仍保持旧运动；大幅校正穿越战场。
- 纠正显示坐标时穿越障碍；累积漂移，持续网络帧却反复跳回。
- 预测修改输入快照、生成泡泡／子弹、提前显示伤害／死亡，或改变其他玩家资源。
- 断线重连、失焦与手动接管后恢复旧按住方向／开火，或重播历史音效。

先用独立运动显示函数验证碰撞、时间上限、校正及不修改快照；浏览器使用原生键盘与 300 ms 真实网络延迟，读取实际绘制点并留存截图／网络轨迹，验证移动先于服务器位置变化。正常网络、PC 与 320px 也需检查。测试属性仅报告真正传给 Canvas 的显示坐标，不注入游戏状态。

逐帧截图发现补充失败场景：出生点附近的显示坐标、脚下圈已移动，但角色精灵被边界坐标钳制，图片仍停在原处。证据为 `browser-motion-pc-touch-320/bubbleparty-prediction-desktop-{0,1}.png`。修复须让精灵与脚部同向同距离移动，并用绘制边距保留顶部角色的可见性。
角色绘制边距同时覆盖护盾、困泡与回退头像，避免它们与脚部错位；本机朝向和行走帧可跟随方向意图，但死亡、困泡、保护状态及对应开始时间仍只由服务器事件决定。

用户追加核查：禁止角色数字角标并写入 AGENTS；验证高树为静态障碍、可穿灌木与高树外观不同，原版类型证据与具体地图坐标证据分别记录。新局碰撞、爆炸阻挡、视图装饰必须一致；旧存档不能在玩家脚下新增墙或重置对局，缺少树碰撞位时改用可穿灌木外观。测试失败场景包括高树可走/可放泡/被炸穿、灌木被错误封死、所有人数出生区隔离、旧局玩家被补墙困住及角色锚点被误判后再偏移半格。

## 人物选择（实现前）

用户新增要求：提供多套人物可选，红队/蓝队基础色固定。失败场景包括：换人物同时换队/属性/坐标/输入序号/期限；观众或托管席位能代选；非法人物ID或旧epoch被接受；选择后刷新/重启/托管丢失；开局倒数内无法选、选择弹窗使旧方向继续发送；静态帧为队色而困泡/死亡变回黑色；未着色层污染脸部或透明像素；新局/旧存档缺省人物无法显示。优先恢复原包多个角色的Static/Adjust层，以队色只着色可调层；所有状态与素材失败回退保持相同红蓝阵营。

人物选择E2E补充：关闭人物弹窗后焦点仍在“选择人物”按钮，空格重新打开弹窗而非放泡，导致选完人物无法立即继续键盘战斗。失败截图与运行记录为 tree00c394；修复后应返回战场焦点，保持标准弹窗的Esc/Tab行为。

真实断开已连接的 TCP WebSocket 后，街霸方块在新完整快照到达 300 ms 之后仍连续发送旧的按住方向，且旧错误回调反复将输入序号回退。失败网络轨迹：`browser-reconnect-red/spf2t-reconnect.json`。修复须同时清理重连后的键盘重复队列、忽略旧传输错误，并保证晚到的权威序号可以推进队列下界；新按键仍能操作。

选择人物弹窗跨越困泡到淘汰／结束时，必须自动关闭，不能以已禁用的人物卡片盖住死亡或公共结算。对局普通快照及其他玩家选择不能重开该弹窗。

双人结束边界：人物弹窗关闭不能把焦点从新出现的公共结算浮层夺走。原生浏览器在困泡时打开选择，再等真实淘汰结算，检查浮层唯一性和实际 activeElement。
