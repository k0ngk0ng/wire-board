# 实时状态的内存推进与检查点

用户明确补充：实时游戏不需要每走一步写数据库。本要求覆盖正常移动、输入批次和物理帧，替换此前的每操作事务及过渡性的短窗口批量落盘方案。

## 目标语义

- 真人输入与电脑／物理帧在内存中按房间顺序处理；移动、放泡泡、持续射击和方块操作不逐条写动作表，不逐帧保存房间快照。
- 每秒为发生变化的实时房间保存一次完整检查点。健康存储下，异常崩溃可回退约一个保存周期；保存失败时须记录失败与最后成功检查点，不能声称新状态已经持久化。
- 开局、结束／积分、托管切换、关闭、席位变动及游戏声明的关键阶段切换立即事务保存。正常服务关闭也保存脏状态。
- 实时输入 ACK 表示服务器已接收并处理；`durable` 明确区分内存接受与关键节点持久化。普通回合制命令的既有事务语义不变。
- 内存中保留有界的幂等收据；游戏自身的 epoch／seq 继续阻止重复行动。恢复以后客户端必须接受服务器的新实例标识和检查点版本，不能用旧的较高版本挡住恢复状态，也不能重播旧控制。
- 正常断线重连读取内存最新状态，不发生回退。进程重启从检查点恢复，停止真人旧方向／按住开火状态，保留比赛、炸弹、重力、选角及结算的权威期限；电脑和手动托管继续由平台调度。

## 验收失败场景

- 连续多个输入或系统帧仍产生逐条 UPDATE／INSERT；没有变化仍周期写库。
- ACK 把尚未持久化的移动称为 durable；重复 nonce 在内存中重复行动。
- 检查点保存失败却更新 saved version；丢失脏标记，后续重试不保存最新状态。
- 游戏结束或积分先发布、后写库；失败／重试导致重复胜负或积分。
- 正常关闭丢失已接收输入；异常进程退出不能恢复最近检查点，或客户端拒绝接受恢复后的较低版本。
- 新实例收到旧实例的控制仍执行；重连／恢复复活旧按键，或把旧事件重新播一遍。
- 检查点、关键事务、房间关闭与输入并发造成覆盖、重复写入或其他房间阻塞。
