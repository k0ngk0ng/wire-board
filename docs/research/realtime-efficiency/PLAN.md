# 实时游戏效率优化与验收计划

目标：为泡泡堂、赛车、坦克大战、俄罗斯方块、街霸方块提供适合实时操作的输入和状态通道，减少重复网络请求、全量组装与高频处理开销。保留服务器权威、权限、可靠动作、断线恢复、手动托管和电脑玩家。普通回合制及疯狂坦克的精确事件时钟继续使用已有语义。

用户补充：实时游戏不再显示操作倒计时或因不操作而自动托管。比赛时间、开局倒数和游戏明确规定的选择阶段期限独立保留；断线／失焦后旧方向必须停止，不能让角色持续移动。

## 交付顺序

1. 使用真实 HTTP／WebSocket／SQLite 建立网络、调度和事务基线，先编写失败场景与 E2E。
2. 增加平台统一的双向 WebSocket：可靠输入确认、精简游戏状态推送、生命周期与大厅数据分离、慢连接合并、重连补全。保持原 HTTP 接口可用。
3. 取消五款实时游戏的空闲倒计时托管，迁移旧超时托管状态；手动托管继续有效。逻辑推进不依赖输入到达，电脑不会被真人连续输入饿死。
4. 将逻辑步长、状态推送和渲染分离；完善持续输入、一次性按钮、确认和重连处理，为连续运动游戏加入有界预测／插值与权威校正。
5. 降低全局锁和频繁完整快照保存的开销。按用户补充，普通输入确认仅代表内存处理；每秒保存检查点，关键节点立即持久化，结算保持幂等。详见 `PERSISTENCE.md`。
6. 运行公共平台检查、五款受影响游戏的对应检查和真实浏览器／弱网验收，保留前后指标及截图；清理本次临时运行。

## 先验失败场景

- 未登录／跨源连接、观众或他人席位输入被接受；下架、关闭、离开、托管或取消托管后旧连接仍可控制。
- 状态跨房间泄露、隐藏视图被复用给另一玩家；过期房间／新局／旧版本覆盖新快照；退出后重新进入旧房间。
- 重复 nonce、重连补发或多标签页造成重复放泡泡／硬降；移动合并吞掉短按和松手；输入队列无界积压或错误重播。
- 每条游戏推送仍引发 `/api/state`；大厅／配置／聊天被高频重复发送；慢连接拖住其他玩家。
- 真人持续输入改变逻辑时钟期限、电脑策略饥饿；服务器过载时无限追帧；普通游戏被加速。
- 实时玩家不操作被自动托管，或旧存档恢复后继续倒计时；取消托管改变比赛期限／选择阶段／对局进度。
- 预测穿墙、位置纠正抖动、伤害被客户端决定；爆炸／死亡时间错位；隐藏页面、断线、托管和重连遗留输入。
- 数据库失败仍声称关键节点已持久化；重启丢失已成功保存的检查点／种子／时间、旧实例按键继续执行或重复积分；检查点跨版本覆盖或日志无界增长。
- 多房间争用全局锁导致延迟；状态编码和磁盘阻塞发生在全局锁内；取消／关闭与正在提交的帧发生竞态。

## 证据要求

源码和构建 SHA、命令、样本规模、原始记录与结果须可核验。比较客户端 GET 数、输入确认延迟、状态字节、帧到期延迟、数据库事务／快照次数，并覆盖不同房间数、8 人局、观众和 50／150／300 ms RTT。指标是实测结果，不预设承载人数或性能提升倍数。
