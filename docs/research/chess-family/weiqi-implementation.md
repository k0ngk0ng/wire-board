# 围棋实施规格与验收清单

本规格在实现前冻结，现已完成本地接入与规则、电脑、界面及素材验收，尚未部署。独立模块为 `games/weiqi`，不把规则放入公共平台。支持两人、9／13／19 路、入门／标准电脑、真人托管和手动接管。默认下架。

## 规则与来源

标签为「面积计分 · 禁自杀 · 全局同形」，不宣称完整符合某版中国竞赛规则。参考已保存的 [Tromp–Taylor 规则](https://tromp.github.io/go.html)，证据为相邻 `evidence/go-tromp-taylor.html`，SHA-256 为 `40acb3abdc98d30087a9200c07b413e319f965e4a9286df7238f5418dc8c00fb`。采用其相邻连通、提子、面积和局面同形定义，明确改用禁自杀；双停着后增加双方协商终局流程。

- 黑白随机分配，黑先，无让子。默认白贴 7.5 目，可选不贴目；两者均须完整验收，不开放未实现的让子或其他计分法。
- 棋盘只沿上下左右连通。落子后先提尽所有无气的相邻敌方棋块，己方棋块仍无气则拒绝；同一敌方棋块不能重复提取。
- 落子后整个黑白局面不得与本局任何历史局面相同（位置同形禁着，不考虑手番）。停着不受此限制，连续停着也不能清除历史。历史从空盘开始，保存于存档，恢复对弈仍保留。
- 停着后对手落子将连续停着数清零；连续两次停着进入计分确认，不直接产生胜负。
- 计分阶段任一方可点选整块棋子切换死子标记，修改提案会清除双方确认；所有动作携带轮次、手数和提案版本，旧确认不能接受新提案。观众不能标记或确认。
- 双方确认同一份提案后移除标记死子并计分：己方存活棋子数＋仅邻接己方的空点数。邻接两色或两色都不邻接的区域中立；白方另加贴目。提子数量只作展示，不额外计分。相等即和局，真人 0 分、不计胜场。
- 双活不使用自动死活裁定。双方确认存活后，混合边界的公共气为中立，只有单色边界的空域计入该色。对死活有争议可恢复对弈，由第二次停着后的应行动方继续；取消全部标记和确认，不删棋子、不清除重复历史。
- 任何阶段可以认输。棋局没有为电脑增设的强制手数上限、提前判负或私有胜负规则。

## 时限和电脑

行棋阶段只催当前手番。计分阶段双方分别承担确认责任，记录各自截止时间；标记与确认不得延长时限，已确认方暂不欠操作，修改标记后重新欠确认但保留原时限。重新开战才分配新的行棋时限。取消托管只恢复本人已过期且尚欠操作的期限。

电脑走相同 Apply 接口，只读取本局公开视图，不直接赋值胜负。基本策略关注提子、救子、气与眼，不依赖外部模型或服务；标准策略在平台预算内搜索。计分时不把策略死活预测直接作为真值；对己方被标记的棋块可以恢复对弈处理，不能无条件同意对手标死全部活棋。必须覆盖双方电脑自然完成和混合真人／电脑阶段接管。

## 界面与素材

统一创建、房间与玩家栏，显示执黑／执白、提子数、手番和白贴目。棋盘保持正方形；手机默认全图，放大后精确操作。鼠标拖动、无需 Ctrl 的滚轮、触屏双指、概览、键盘方向键和回车均沿用平台地图约定；拖动不得落子。落子前有可取消的选点确认，落子与提子按服务端事件呈现，刷新不重播，统一静音。

原创封面采用棋罐与围空构图，不能只改五子棋封面的颜色。棋子、棋盘底纹、封面及落子／提子／停着／胜利／和棋音效进入不可变 OSS 路径，提供本地回退，保存来源、许可、生成方式和 SHA-256。

## 实现前失败场景

1. 人数、路数、贴目或难度接受无效值；新游戏默认上架；过期／重复请求多次落子；旁观者、非当前手番操作成功。
2. 边角误连、对角误连、气重复计数、同块重复提取、多块提子遗漏；先判自杀导致合法提子被拒绝；真自杀获准。
3. 直接劫、隔多手的历史同形获准；合法劫材后回提被误拒绝；停着或重启清除重复历史。
4. 单次停着提前结束；落子未清零连续停着；双停着跳过确认；旧提案确认误用；并发确认互相失效或重复结算。
5. 死子标记只标一枚、不清确认、计分重复算提子；双活／中立区域归属错误；贴目或和局积分错误；争议恢复丢棋或手番不对。
6. 标记、确认、观战或刷新延长时限；已确认方仍被自动托管；取消托管延长他人时限；持久化恢复丢失提案或确认。
7. 电脑提案非法、输入被修改、预算不可取消、填真眼直至自毁、无限无意义争议；无法完成三种路数或计分阶段。
8. 手机棋盘裁切、触屏误落子、提子先于落子动画、重连补播、音效绕过静音、CDN 故障无回退。

以真实 HTTP／SQLite 和浏览器 E2E 为主。规则中局夹具独立标记，不冒充自然完整局；保存三种路数×两档电脑完整轨迹、生产调度、恢复、混合席位和界面截图。仅验证围棋及必需公共平台，不重跑未改棋类的完整局。
