# 军棋实施规格与验收清单

本文件是待实现的明确规格，不表示军棋已经接入。用户要求两人陆战棋与四国军棋均支持真人、电脑和托管。两种棋盘、全部规则和策略均放在 `games/junqi`，只复用平台会话、房间、玩家栏、音效与地图操作工具。

参考资料为已固定提交并保留来源的 `BitByBitG/siguo-junqi` 的 `RULES.md`（MIT），见相邻 `sources.json` 和 `evidence/`。参考其通常规则与四角弯道说明，不照搬其 BOT 专属 16 步和棋、Rating、外部 API、三人或斗地主模式。本项目采用下述明确的暗棋规则，不宣称覆盖所有地方变体。GitHub 树接口暂时 TLS 超时，不依赖下载整份程序才能实施。

## 人数、布阵和胜负

- 仅开放 2、4 人。两人互为对手；四人按原始席位 `seat % 2` 分队，对家搭档。显示旋转不改变原始席位、先后手或队伍。
- 每方 25 枚：司令 1、军长 1、师长 2、旅长 2、团长 2、营长 2、连长 3、排长 3、工兵 3、炸弹 2、地雷 3、军旗 1。
- 每阵地六排五列。前排为第 0 排、后排为第 5 排。行营为 `(1,1)、(1,3)、(2,2)、(3,1)、(3,3)`，开局为空；大本营为 `(5,1)、(5,3)`。
- 军旗只能置于一个大本营；地雷在最后两排；炸弹不得放在前排。开局先生成合法私有阵型，真人可交换己方两子或重新随机布阵，确认后等待全部就绪。电脑也要通过同一确认行动完成布阵。
- 默认随机布阵宜把另一大本营留给地雷，避免电脑把重要可移动棋子锁在总部；这是合法策略，不是额外规则。
- 普通军阶为 9～1，大吃小，同级同归。工兵排雷并存活，其他普通棋子碰地雷阵亡。任一方为炸弹则双方阵亡；炸弹撞旗也双方移除并使旗主出局。
- 夺旗、认输或轮到时没有合法移动，均使该方出局并清除其棋子；司令阵亡公开军旗位置。四国出局队友可以继续观战，剩余队友继续行动；仅剩一队时全队获胜，包含已出局的队友。
- 200 着连续无战损或同一实际局面与手番出现四次时和棋，双方人数及真人／电脑一致适用；吃子、同归及出局清子重置无战损计数。夺旗与正常胜负优先。另支持存活者一致同意和棋，提议和回应不改变时限。
- 真人和局统一 0 积分、不计胜场；含电脑对局仍不计分。新游戏默认下架。

## 两种独立道路图

道路均为相邻的横直连接；行营另与相邻斜点相连。行营内敌子不能攻击；可进入空行营。进入任何大本营后不能移动；军旗和地雷始终不移动。

两人图只包含南北两阵地，前排的左、中、右三列跨中界连接，不引入未使用的东西阵地或四国中央九宫。每方前排、倒数第二排以及两侧边线的前五排为铁路；最后一排无铁路。

四国图为四阵地加中央九个铁路点，九点按三行三列连接。各阵地前排第 0、2、4 列与中央相接；第 1、3 列没有向中央的连线。四角另有相邻阵地边线连接的弧形铁路。

建议几何坐标：中央九点为 `x,y ∈ {-2,0,2}`；南阵地为 `(c-2,3+r)`，另外三方绕中心旋转 90°。两人图改为南 `(c-2,1+r)`、北 `-(c-2,1+r)`，省去中央点，直接连接三条跨界线。

普通棋子沿同一连续直线铁路走任意多个空点，不能越子；四角弧线视为连续边线。实现时给铁路边标记可延续的线路 ID：水平／垂直线路，以及每条四角弧线及其两端边线组成的曲线线路；普通移动整条路径必须保留同一个线路 ID，不能在交叉点偷换线路。工兵可沿铁路转弯，实际必须转弯的路线会公开工兵身份。优先选择不转弯路线，不能因服务端随意选了一条绕路而泄露工兵。

敌子只可作为终点，己方或盟友棋子不能进入、穿过或攻击。行营保护、总部禁出和不可移动棋子应在道路与铁路逻辑之前统一检查。前端只显示服务端的合法终点和路径，不重新决定铁路合法性。

## 隐藏信息与电脑

- 私有状态保存全部军阶，但玩家视图只显示己方、已公开的工兵及已公开军旗；队友与观众也不能看到其他暗子。结束后可以公开棋子供复盘，仍不得在进行中泄露。
- 棋子 ID 使用独立随机标识，不能按军阶固定顺序编号。输出列表按公开位置排序，避免列表次序或数字编号直接泄露军阶。
- 日志、事件、合法行动、错误、玩家摘要、结果详情和存档恢复均须检查泄漏。公开战报只说攻守存活／同归、司令阵亡、旗位和出局，不公布未授权的交战军阶。
- 基本电脑必须先投影为该席位的视图，再选择行动；不得用完整私有状态试算交战。可根据公开布阵限制推测前排不会有雷／炸弹，或根据已公开旗位规划路线。
- 策略优先合法出动、接近敌方大本营、使用工兵处理后排风险、避免无意义往返，并服从相同布阵、交战与胜负接口。两人、四国、混合真人与电脑、真人托管全部验收。

## 多人阶段与时间

- 布阵采用每席独立截止时间和修改序号。不同玩家同时布阵，不能因别人调整或确认而丢失自己的合法提交；可用模块 `AcceptStale` 配合当前对局、阶段和本人修改序号处理。
- 重复请求仍由平台 nonce 去重。自己的旧序号、已锁定布阵、上一局或过期阶段一律拒绝。全部确认后才切换为轮流行动。
- 超时进入平台托管，取消托管只恢复自己的过期期限，不能延长其他布阵席位的时间。行棋阶段仅当前手番欠行动。
- 和棋表决带独立提议标识，不能把旧提议的同意应用到新提议；任意走子或拒绝取消当前提议。

## 视觉与素材

沿用公共房间与玩家栏。玩家摘要公开存活／出局、剩余棋子数量与已公开状态，不暴露军阶。两人保留纵向棋盘比例，四国保留方形；手机用平台拖动、滚轮／双指缩放和连续概览定位，棋子可见宽度至少 24px，触摸区域与图形区分。

军棋使用矩形中文棋子，四方颜色和席位提示；暗面为旗星图案。计划为 48 个字面、4 个背面、2 个棋盘底纹和 1 个独立四向军旗封面，共 55 张 WebP。字体使用有许可来源的 Noto 字体，保留摘要和生成方法；道路图由服务端节点与边绘制，避免图片和实际连线错位。

走子、交战、同归、爆炸、亮旗、胜利、和棋等音效使用有许可来源或原创合成，通过平台 `BoardProps.audio` 播放。素材发布到不可变 OSS 目录并提供本地回退。

走子动画沿服务端实际路径移动；被吃、同归、出局清场和结果须在到达后一起呈现，不能提前揭示结果。连续快照顺序、刷新／重连与减少动态效果分别验证。

## 先于实现的失败场景清单

1. 2／4 人模式配置错误，默认上架，3 人误入，四国席位旋转改变阵营。
2. 布阵数量、行营、旗位、地雷、炸弹约束被绕过；同 nonce 重排两次；并发他人布阵导致合法请求失效。
3. 普通道路、行营斜线、铁路跨界、中央及弯道漏连／多连；普通子转直角；工兵不能转弯；跨越棋子、攻击盟友、攻击行营或从总部出发。
4. 大小、同级、炸弹、地雷、工兵、军旗任一组合交战错误；司令阵亡未亮旗或过早泄露军阶。
5. 私有数据通过 ID、列表次序、错误、事件、日志、观众、队友、恢复或电脑输入泄露；更换不可见敌子军阶改变同席位电脑提案。
6. 夺旗／无着／认输清场与轮转错误；四国单人出局误判整队输；和棋覆盖正常获胜；旧投票被接受。
7. 托管、接管、部署并行截止时间、重启和重复提交改变他人时限或局面；电脑不能自然结束完整局。
8. 手机无法辨认棋子或误触，拖动意外走子，路径与显示不一致，战损早于视觉到达，重连补播旧动画或静音失效。

验收必须保存真实 HTTP、完整电脑轨迹、竞态、PC／手机浏览器截图、素材摘要与 CDN 回读。只选择军棋和必要的公共平台，不重复未修改棋类的完整对局。
