# 中国象棋裁定实施记录

中国象棋已接入并完成当前规则范围的本地验收，默认下架，尚未部署。本文保留规则来源、实现范围与验证记录，不宣称对全部竞赛裁判案例进行认证。

## 固定来源

官方落地页链接的 [2018 世界象棋规则（中文 PDF）](https://www.wxf-xiangqi.org/images/wxf-rules/2018_World_Xiangqi_Rules_Chinese_2018.pdf) 已下载到 `.local/xiangqi/rules/wxf-2018.pdf`。文件为 6,278,474 字节，SHA-256 为 `f61f5c82ddaf2abb45eb25c24d58f2b278d2c150439f391d413c32c4ce275b3e`。

PDF 元数据为 92 页；正文主要是扫描图，`pdftotext` 只读到页眉和页码，不能用提取文本声称已读规则。已渲染并检查 PDF 第 10～13、27～34 页，图片保留在 `.local/xiangqi/rules/`。目录中的页码与页面实际页码并不一致，引用以 PDF 页序为准。

## 已确认并转成验收的差异

- 中国象棋困毙判负，不能复用国际象棋的逼和逻辑。无合法走法时先判断胜负，不以自然限着覆盖将杀或困毙。
- 第 3 条自然限着为连续 50 回合、双方共 100 着未吃子；不能把动兵也作为清零条件。与平台休闲计时结合时，服务器代替现场裁判确认条件；不宣称提供竞赛总时钟。
- 第 19～20 条要求按循环行为区分长将、长捉及许可重复。长将的责任高于长捉；双方均为同类违规或均无违规时可和棋，不能把所有重复统一判负或判和。
- 长捉判断需保留实体棋子 ID 和连续目标。两步追逐不同目标不等于始终追逐同一子；将帅、兵卒及未过河被追兵卒有专门例外。
- 真根必须在假设吃子后仍能合法回吃；不能只检查几何攻击。马、炮追逐有根车有不同规则；同类棋子能否互吃还受牵制和马腿影响。
- 交替出现捉与兼兑时不能简单丢掉有交换可能的那一步。已构造马腿阻塞与互吃交替的 HTTP 场景，先复现误判和棋，再保留交换标记并对完整循环判断。

平台的循环提示暂定为：第三次出现同一局面时提示有责方变着；第四次出现时按两轮循环责任裁定。该流程是线上提示与判定时点的明确产品约定，仍须对照更多官方棋例核验，不能把提示过程藏在电脑策略中。

## 当前代码与剩余审计

`games/xiangqi/tests/http_test.go` 先于规则实现，`bot_test.go` 先于有预算的策略实现。当前基础 HTTP 用例已通过，包括马腿、象眼、炮架、九宫、过河兵、照面、自将、困毙、循环警告及恢复、有根／无根长捉、和棋提议和交替兼兑。

电脑已提供快速合法回退与有预算的 Alpha-Beta。策略选择不能代替模块裁定；将军与困毙都是有效获胜方式。测试曾错误要求一个可直接困毙的局面必须用将杀结束，已改为检查合法即时获胜。

## 当前验收证据

- `TestXiangqiHTTPOfficialMutualChecks` 按官方 PDF 第 32 页图 4 走出双方连续解将反将，验证和棋；长将、有根／无根长捉、假根和马腿兼兑另有实际 HTTP 行动轨迹。
- `TestXiangqiHTTPChaseExceptions` 覆盖马炮追有根车、不同目标、将帅与兵卒例外。`TestXiangqiHTTPAlternatingAttackers` 复现并修复两车交替捉同一目标、对方用象轮流挡住的问题，且相同结构中的未过河卒仍判和。
- 长捉历史还记录对方是否实际躲避或直接消解前一手攻击。`TestXiangqiHTTPIgnoredAttackIsNotPursuit` 防止把对方未回应的持续攻击误判为长捉。
