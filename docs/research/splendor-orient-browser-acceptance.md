## 本阶段通过的路径

通过页面依次完成：购买三级东方卡 → 免费取得二级复制连锁卡 → 复制双宝石奖励 → 免费取得一级复制卡 → 复制刚配对的卡 → 贸易站领取宝石 → 放置第三座要塞 → 征服并弃置两张复制卡购牌 → 再领宝石 → 移除对手单座要塞。

- 在 390px 手机、320px 城市同开组合、1440px 桌面完成十次阶段切换；所有页面文字为现有中文说明，无水平溢出或 JavaScript 异常。
- 两次免费拿牌均产生对应玩家的可见 `free` 动画，最终事件序列为 `buy / free / free / buy`。
- 连锁过程中牌堆张数不变，被拿走的市场位置保持空位；效果全部完成才补牌并交给下一玩家。
- 复制阶段刷新后仍可继续选择，已经发生的获取动画不重播。
- 完成后的永久奖励为 `[2,2,1,0,0]`、分数为 5、筹码为 `[0,0,1,0,1,0]`，与原 HTTP 连锁用例一致。
- 窄屏要塞列表需要滚动内部容器，桌面同时展示基础和东方市场；脚本按实际可见控件操作，不点击隐藏切换按钮或滚动区外的卡牌。

初次操作耗时超过回合期限时，系统按规则进入托管；后续正式验收在新夹具中连续执行，保留正常的 120 秒计时。一次自动点击尝试被聊天按钮命中，经检查是目标卡尚在浮层内部滚动区之外；滚动至可见后点击正常，因此未修改聊天或浮层样式。

## 复跑

先构建网页，并在一个终端启动受控的本地验收服务。素材基地址从私有环境配置传入：

```sh
source scripts/env.sh
npm --prefix web run build
WIRE_BOARD_ORIENT_BROWSER=1 \
ASSETS_BASE_URL="${ASSETS_BASE_URL:?请配置实际素材基地址}" \
go test ./internal/server -run '^TestSplendorOrientBrowserFixture$' -count=1 -timeout=12m -v
```

需要城市同开时，为上面的测试命令另设 `WIRE_BOARD_ORIENT_CITIES=1`。在第二个终端执行：

```sh
source scripts/env.sh
python3 scripts/accept_splendor_orient.py --width 320
```

每个视口使用一个新夹具；宽度可改为 390 或 1440。脚本使用静音、独立的浏览器会话，保存阶段 JSON 和截图。结束时向测试服务提交通过／失败结果，关闭浏览器并清理浏览器配置；Go 测试随后退出并清理临时数据库及测试登录信息。默认 Go 测试会跳过这个需要浏览器配合的夹具。

本轮产物：`.local/orient-chain-390/`、`.local/orient-chain-320-cities/`、`.local/orient-chain-1440-760e56f4/`，以及 `.local/orient-chain-ui.log`、`.local/orient-chain-320.log`、`.local/orient-chain-1440.log`。
