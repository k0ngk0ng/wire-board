# 卡坦事件牌：规则、牌表来源与内部实施边界

核对日期：2026-10-05。本阶段实现独立的内部牌堆组件，没有接入正式游戏构造器、掷骰动作、房间或界面。不能将其视作事件牌扩展已经可玩；不开放或发布。

## 官方依据

- 2025《Traders & Barbarians》印刷第4–6页，固定来源及PDF哈希见 `../board-expansion-rule-sources.json` 的 `catan-traders-2025`。
- [官方 T&B FAQ](https://www.catan.com/faq/traders-barbarians)，问题12–24；原始HTML哈希见 `catan-event-card-sources.json`。FAQ包含旧Mayfair版本的说明，不能不区分版本套用。

### 已确定的牌堆规则

36张普通事件牌，加1张New Year（新年）。打乱36张普通牌，底部放5张盖牌，其上放新年，剩余31张放在新年上面。每回合翻开一张，先执行事件文字，再按点数生产或处理7。

翻出新年时将全部36张普通牌重新洗牌，按同样顺序重建牌堆，并在**当前回合立即再翻一张普通牌执行**。因此每轮实际抽到31张普通牌，底部5张不公开；不能等抽完全部36张才洗牌，也不能让新年占据一个没有生产的回合。

城市与骑士组合按2025规则另掷红骰及事件骰，在事件文字与生产之间处理。FAQ14记载旧Mayfair牌面有红骰数，不能用旧版印刷红骰替代2025版要求的掷骰。FAQ15/16：炼金术士替代此次事件牌抽取；只执行事件但仍抽牌是FAQ另列的可选家规，本项目不默认采用。

### 2025事件效果与接入注意事项

| 事件 | 规则与待接入点 |
| --- | --- |
| A Beautiful Day | 无事件，正常生产。 |
| Calm Seas | 港口建筑数量最多者各选1普通资源。按建筑数，不套用港口霸主的城市2点；零建筑平局仍待进一步核对。 |
| Conflict | 有最大骑士奖时依该奖处理随机偷资源，否则独自拥有最多骑士牌者可偷；需澄清原文“you”及Knight cards与亮出牌的关系。城市骑士按激活骑士总强度，最高并列无效，可偷商品。 |
| Earthquake | 每人尽可能损坏1条自己的路；全部修复前不能新建路，每条修复费1砖1木，损坏路仍计最长路线。 |
| Epidemic | 本次城市只产1普通资源；城市骑士不产商品。 |
| Good Neighbors | 每人如有资源，选1张给左邻；城市骑士可给商品。接入时需明确定义同时选择/转交，避免刚收到牌被再次转出。 |
| Helpful Neighbor | 最多VP者如有资源，各给**一位**更低VP玩家1张自选资源；城市骑士可给商品。旧资料“给每位低分玩家”的文字不可照搬。公开/隐藏VP比较仍待核实。 |
| Plentiful Year | 每人选1普通资源。仍需接入库存不足与多人选择。 |
| Robber Attacks | 正常处理7：弃牌、移动强盗。不能因事件文字和点数同为7而重复执行。 |
| Robber Flees | 强盗移到沙漠，不偷牌；地图没有沙漠时移到场外。多沙漠选择需接入回应。 |
| Tournament | 亮出最多骑士牌者各选1普通资源；城市骑士按激活总强度，不允许选商品。零骑士平局仍待进一步核对。 |
| Trade Advantage | 最长路线奖持有者随机偷1资源；2025文本未给出无人持奖时的最长路后备规则，不能从第三方旧程序照搬。 |
| New Year | 重新建牌堆并立即再抽普通牌。 |

## 旧版真实牌表的交叉核对

`catan-event-cards-legacy-reference.csv`保存36张旧版牌的生产点数、旧版红骰和事件名。三份公开完整表的 `(生产点数, 事件)` 多重集合相同；只有组件清单提供红骰值。第四份资料仅核对事件数量。来源URL、固定Git blob及内容SHA256见 `catan-event-card-sources.json`。没有复制第三方程序实现。

核对结果：点数2至12数量依次1/2/3/4/5/6/5/4/3/2/1；旧版红骰对应36种唯一骰子组合。无事件16张、强盗袭击6张；风平浪静、援助邻居、瘟疫、强盗逃跑各2张；其他6种事件各1张。

**该表仅为旧版参考，不是已验证的2025实体牌表。** 官方2025规则列全事件效果，但未列每张牌的点数和数量；还需核对当前实体牌面或官方完整牌表。牌表没有打包进运行时代码。第三方程序存在旧效果差异和洗牌/循环问题，不能用作规则执行依据。

## 本阶段内部组件

`internal/game/catan_event_deck.go`提供36个不绑定牌义的内部卡槽和新年哨兵，使用项目现有随机洗牌。保存完整抽牌堆、当轮公开弃牌及轮次；新年在同一步内重建并抽牌。尚未向`Catan`状态增加事件牌字段，现有正式比赛行为不变。

JSON恢复先检查数量、卡ID唯一性、轮次及新年位置，再替换状态；无效存档和无效抽取不产生部分修改。公共视图只提供当轮已揭示牌、当前牌及公开计数，复制返回的数据，不含隐藏顺序或底部5张。完整牌堆只能用于服务器持久化，后续接入不能直接序列化给客户端。

验证：5项顶层定向测试（含9种损坏状态子用例）通过，覆盖4轮抽牌/跨年、32个抽牌位置的保存恢复、边界立即再抽、隐藏顺序不影响公共视图、引用隔离、无效存档原子拒绝及轮次溢出；`go test ./internal/game -run '^TestCatanEventDeck' -count=1` 为0.579秒。`go vet ./internal/game`通过。验证范围仅此组件，不是完整对局、真实服务重启或浏览器验收。
