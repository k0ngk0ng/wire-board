# 疯狂坦克后端第一阶段验收

本阶段只改服务端动作时间轴、伤害归属、出界处理、移动及落地，不以此宣称原版玩法已经还原。固定行动顺序、旧武器参数、特殊弹限制和地图碰撞来源仍待原版证据及后续重构。

## 已落实

- 开火请求只产生炮弹及飞行时间轴，不即时扣血、挖坑、落地或结算。公开投影在命中前保留旧 HP 和位置。
- 命中时发布弹坑、逐目标伤害及音效事件；落地按每辆坦克的独立绝对截止时间更新位置、坠落伤害及死亡。
- 飞行和落地期间没有行动席位；真人和电脑均不能插入动作。下一回合从实际解锁时刻获得完整行动时间。
- 主动走下台阶与炮击失去支撑使用同一落地过程。主动移动落地后继续剩余操作时间；若当前玩家坠亡但仍有队友，转入下一席位。
- Restore／Reclaim 保留在途阶段；旧存档的已完成炮弹不被补播，也不延长旧行动期限。
- 范围伤害保留所有目标，受害者和自伤不获得造成伤害积分；记录实际扣除 HP，避免过量伤害计分。
- 出界炮弹不在地图边缘产生替代爆炸。移动不超过剩余 fuel，检测高墙身体碰撞。

接口见 [implementation-contract.md](implementation-contract.md)。

## 测试先于实现

首先增加公共模块 E2E 及已列失败场景的针对性物理测试，再运行旧实现。2／4／6／8 人立即结算、致命炮弹提前结束、Reclaim 延长期限、受害者记分、移动超过 fuel、出界炮弹变边缘爆炸均出现预期失败。高墙测试使用独立实体掩码，以免把原图中的浮空平台误当成垂直实心墙。

后续增加公共模块 E2E 验证「主动移动落地死亡且队友存活」，先观察到 `eliminated player cannot act`，再修复转回合处理。此补充采用完整公开模块操作及计时器路径，没有在实现后补写单元测试。

原规则测试中涉及射击结果的场景改为通过真实 `OnTimer` 完成阶段后断言，不再要求开火请求同步换人。HTTP／SQLite 验收保存飞行中的对局并重启，确认阶段不被重置；团队战绩测试等待实际结果后查询历史记录。

## 重跑命令

在仓库根目录运行：

```sh
source scripts/env.sh
go test -json -count=1 ./games/fortressblue/...
go test -race -json -count=1 -timeout=10m ./games/fortressblue/...
go vet ./games/fortressblue/...
```

普通测试通过 64 个测试及子场景，覆盖所有开放人数、17 张地图的全电脑对局、HTTP 会话、SQLite 重启及新增时间轴场景。竞态结果和完整机器可读输出保存在 `.local/fortressblue-refactor/backend-stage1/`。不启动其他游戏验收。

本阶段仅证明服务端状态及公开接口；真实浏览器逐帧绘制、公共玩家栏、音效以及原版手感，须由对应前端和原版对照验收单独证明。
