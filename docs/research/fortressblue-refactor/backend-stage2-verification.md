# 疯狂坦克后端第二阶段验收

本阶段在第一阶段时间轴上修正已确认的规则偏差。证据包括官方客户端 `character.txt`、官方门户 `configs__items.json` 及本次 native 分析记录。只将明确证据对应的字段和行为称为原版来源；运行频率、物理常数、地面效果具体数值仍单独标为项目参数。

## 完成范围

- 已发布旧版 13 号坦克使用 990 最大生命的 fallback，而原表校正为 1000。恢复旧有限弹药存档时保留 990 与当前 HP，不拒绝存档、不补满生命、不重置回合或期限；新局使用原表 1000。
- 人类射击和电脑搜索都遵守每款车的最小／最大炮角。`A1Round/A2Round` 没有被猜作 delay，也没有引入未经确认的 delay 算法。
- 新局普通弹／特殊弹可以持续切换，删除每局两发特殊弹的人工配额。旧存档的有限库存标记保留兼容。归一化蓄力范围为 0～100；速度映射仍保留既有常数，等待原版精确弹道校准。
- 发射请求先进入准备动作，334 ms 后才出膛及产生 `shot` 音效事件。该时长采用项目 30 Hz／每两 tick 一帧校准与源第 5 帧出膛锚点，未把原版帧率当成已确认事实。
- 炮弹和坦克使用同一份可见前景实体 mask，删除服务端忽略浮空平台的人工补丁。没有改写原地图 JSON 或已发布 v2 媒体。stage-4 的明确平台坐标仅证明本项目图像／碰撞一致，不代表原版逐格行为已经实跑确认。
- 底盘使用约 20 世界像素的支撑范围，跨窄缝不再只看中心列；移动检查整个简化车身范围，防止中心尚未撞墙时车头已穿进去。该轮廓是项目物理模型，不冒充原版逐像素车身碰撞。
- 电脑会通过合法移动退离近处高台、寻找可用射角，并离开正在造成伤害的地火；不直接修改结果或跳过服务端行动规则。下一发已装填回血弹时，优先考虑己方回复收益。

## 八种道具

`games/fortressblue/data/items.json` 同时保存了 `sourceId/sourceDescription`，避免服务端改变而 UI 仍描述旧规则。

| 道具 | 当前行为 |
| --- | --- |
| 小补丸 | 自身回复 20% 最大生命 |
| 大补丸 | 自身回复 40% 最大生命 |
| 能量补充弹 | 装填下一发回血弹；真实命中时，附近双方存活坦克回复 30% 最大生命，不伤害、不挖坑 |
| 团补弹 | 全体存活队友回复各自 20% 最大生命 |
| 防护罩 | 完全抵挡一次敌方伤害，触发后消耗，不按回合自然倒数 |
| 威力增强弹 | 下一发攻击炮弹威力增加 50% |
| 风向转换器 | 反转当前普通风方向 |
| 穿风弹 | 下一发攻击威力增加 50%，保留穿龙卷风属性；不再消除普通风 |

当前场景没有另行加入龙卷风实体。强化与穿风同时装填时取 1.5 倍一次增益，不叠乘；这是尚待原版组合证据确认的项目处理。回血范围沿用本项目爆炸范围模型，不能把具体半径解释为原版已证数值。

## 火与毒改为地面实体

火、毒在实际落点地面生成 `hazards`，不再给新命中目标添加随身三回合状态。每秒检查范围内所有存活坦克；移出区域或位于另一层平台时不再受伤。支撑面被后续弹坑移除时效果消失，避免悬空命中下层。旧存档中已经存在的携带状态只作兼容，并按所属席位的行动机会推进。

实体的创建、下一次 tick、过期时间均保存为服务器绝对毫秒。其他炮弹飞行中仍照常 tick；伤害增量写入当前 HP，不会被待结算炮弹覆盖。落地过程中按公开轨迹的 X 线性、Y 进度平方定位；途中死亡发布实际位置。同一时间的落地与地面伤害全部处理后才判断结果，双方同时全灭使用平台显式和局。

项目参数为：火半径 40、寿命 8 秒、每秒 18；毒半径 50、寿命 12 秒、每秒 25；地面接触带向上 24、向下 12 世界像素。这些参数与原版已确认的「地面持续伤害」机制分开记录，后续可按运行证据调整。

## 红回归与验证

实现前先记录失败场景并增加测试。已在旧实现上观察到：低于源最小角仍可射击、平台站立与炮弹碰撞分裂、窄缝穿落、电脑无法退让、状态随人数加速、零蓄力被拒绝、固定回血值、能量弹误补移动力、防护罩只减半、原地效果丢失、飞行中伤害暂停、出膛动作缺失。后续新增公开模块 E2E，先验证失败再修复「电脑站火中射击」和「同时间双方死亡提前判赢家」。

专属检查包含规则、所有开放人数、17 张地图全电脑对局、HTTP／SQLite、恢复、计时器重复／提前／迟到、多目标伤害与回复、地面效果及死亡时序。没有运行其他游戏规则矩阵。

```sh
source scripts/env.sh
go test -json -count=1 -timeout=10m ./games/fortressblue/...
go test -race -json -count=1 -timeout=10m ./games/fortressblue/...
go vet ./games/fortressblue/...
```

机器可读记录保存在 `.local/fortressblue-refactor/backend-stage2/`，以 `summary.json` 的最终数量及结果为准。服务端验收不替代真实浏览器逐帧、PC／触屏操作或原版视频对照。
