# 疯狂坦克出生点与准备取消复核

独立复核发现，旧地图目录按最低层平台生成出生点，仅检查中心列的约 20 像素净空。stage-1 的四人第 4 席、八人第 6 席可落入低层洞穴，两侧无法移动；旧位置的连续炮击会立即在自身附近爆炸。stage-17 的边缘席位虽可移动，仍被限制在低层洞内，不能据此判定出生点可玩。

## 出生点修复

开局完成选车后，运行时将目录坐标保留为水平位置偏好，在同队一侧寻找最接近的外部顶面。候选点必须同时满足：

- 与实际移动一致的 20×28 世界像素碰撞体和炮口不嵌地形。
- 履带得到实体支撑，至少一个方向可以移动。
- 普通炮有不自伤、不被队友截住且落点距自身至少 110 世界像素的非出界路线。
- 席位之间保留距离；全队就位后再次检查射界，防止后来放置的队友封住先放置者的唯一线路。检查包括无风及每席首次实际行动的风。

未改写地图 JSON 或已发布媒体。该选择只在新局由 `select` 进入 `playing` 时执行，不移动已进行对局中的存档角色。无法提供安全布局时返回开始失败，不把玩家放进不可玩位置。

最初的额外验收曾把整张 idle 图片的对称外接矩形当成实心车身，导致 stage-6 大车测试被透明边角和坡度姿态误拒绝。最终验收采用实际移动碰撞体，不把素材矩形等同于实体轮廓，也不声称该简化轮廓就是原版逐像素碰撞。

## 准备死亡取消

炮击准备阶段，若射手在 `launchAt` 前死亡，`LastShot.cancelledAt` 记录死亡节点，产生 `shot_cancelled` 事件并清除待发射状态。之后不会出现这发的炮弹、发射音、命中、弹坑或伤害；存活的下一席位得到完整操作期限。

已经出膛的炮弹独立继续。公开模块 E2E 分别验证死亡发生在准备后 100 ms、出膛时 334 ms 和出膛后 400 ms：100 ms 取消，334／400 ms 继续。相同时间先处理出膛，再处理地面伤害，避免客户端各自决定结果。客户端须根据 `cancelledAt` 抑制历史待发射画面。

## 验证范围与复跑

出生验收通过公开 `Start` 和逐席 `select` 建立真实对局，覆盖 17 张地图 × 4 种人数 × 14 款车型，共 952 场、4,760 个实际席位。每个席位检查净空、支撑、公开移动请求与公开射击请求；按公开回合计时器切换席位，没有为通过测试改写出生位置或当前席位。独立复核另保留了前后位置与射界诊断。

```sh
. scripts/env.sh
go test -json -count=1 -timeout=10m ./games/fortressblue/tests -run 'TestAllNativeStartsHaveClearSupportedPlayableSpawns|TestDeathCancelsOnlyUnlaunchedShot'
go test -json -count=1 -timeout=10m ./games/fortressblue/...
go test -race -json -count=1 -timeout=10m ./games/fortressblue/...
go vet ./games/fortressblue/...
```

最终机器可读产物保存在 `.local/fortressblue-refactor/backend-stage3/`，具体测试数量、普通／竞态检查结果及源码 SHA-256 以 `summary.json` 为准。公共模块时钟的 50 ms 精确到期检查由根任务单独验收；本报告不替代该公共检查或浏览器视觉验证。
