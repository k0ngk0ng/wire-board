## 画面构成

S2、S4、S5 是最清晰的完整对局参照。画面主体是横向卷动的近景战场，坦克、炮弹与地形都具有可辨认尺寸；底部为紧凑、连续的操作仪表盘，而不是战场旁边的大表单。

- 左下角为炮口角度盘，带射界线、当前方向线和数字。盘下有风向／风力样式的水平标尺；仅凭截图不能确定该标尺的数值算法。
- 中下部有绿色「能量」、红色「力度」、金色「移动力」三条横向仪表。坦克旁另有生命条和名字。不能把绿色「能量」误当成射击力度。
- 力度条可见红色填充与三角记号。S2 和 S4 均在炮弹已经飞出时仍保留力度读数；观察到的表现支持保留本次／上次发射力度作为参照，不能仅凭静态图断定两枚记号的全部语义。
- 四个方形道具槽、当前坦克标识、等待数字和右侧大倒计时位于同一底栏。S3 显示「等待 680」，S4 显示「等待 750」。这证明存在独立等待读数，不能据此反推出 Delay 公式或回合排序算法。
- 右上角有全图小地图和视野框。V1 的镜头横移时小地图保持在角落，战场主体跟随运动。
- 活动坦克头顶可见红色向下箭头；地图中的其他名字和生命条仍保留。地图边缘、断桥、悬空地块与深坑本身构成主要玩法空间。

## 动作与时间轴

完整视频为发行方剪辑，未展示键盘或鼠标输入，且多数战斗画面处于观战状态。以下秒数是媒体时间，并非从原版模拟器记录的物理时钟。

| 片段 | 可复查观察 | 不能据此确定 |
| --- | --- | --- |
| V1 23–26.4 s | 镜头从左侧坦克向右追踪飞行物；底栏位置固定，前景和背景横向移动；25.9 s 仍可见弹体，约 26.0 s 出现爆炸，随后镜头移回 | 输入释放时刻、完整飞行时长、固定重力、转场是否全部由游戏自动触发 |
| V1 29.00–30.25 s | 镜头继续追踪炮弹；29.50 s 弹体接近目标，29.75 s 爆炸展开；30.25 s 爆炸收尾，桥面出现明显缺口 | 精确伤害判定帧、爆炸伤害半径、是否每种弹都使用相同演出时长 |
| V1 30.50–32.00 s | 镜头回到左侧坦克，出现竖向旋风效果；近景地形缺口仍存在 | 旋风随机概率、持续回合数及对弹道的准确数学作用 |
| S3 `steam-shot-2.jpg` | 大型爆炸与「-150」伤害数字同时显示，地形有既存弹坑 | 爆炸前后生命值的精确变化帧；静态截图不能验证血条先后顺序 |

逐帧抽样图：`gameplay-20-27.jpg`（0.2 秒间隔）、`impact-25-27.jpg`（0.1 秒间隔）、`impact-terrain-29-33.jpg`（0.25 秒间隔）。每格左上角标注源视频采样时间。`shot-camera-impact-23-34.mp4` 保留连续 11 秒片段，不使用剪贴帧替代完整时序。

可以据此要求重构版保留清楚的「飞行→命中爆炸→地形变化／下落→下一次行动」反馈，并让镜头帮助观察炮弹落点。原版影片中存在剪辑，不应拿某一片段的秒数硬编码为所有武器的时长。重构的伤害、地形与人物状态必须受服务端事件时间轴驱动，并由自身 E2E 验证。

## 复查命令

在仓库根目录执行以下命令，可核验保留材料并重新抽取关键帧：

```sh
python3 -B docs/research/fortressblue-refactor/verify-reference.py
ffprobe -v error -show_entries format=duration:stream=width,height,r_frame_rate -of json .local/fr/evidence/steam-gameplay.mp4
ffmpeg -hide_banner -loglevel error -ss 29.75 -i .local/fr/evidence/steam-gameplay.mp4 -frames:v 1 -y .local/fr/evidence/recheck-impact.png
```

`evidence.json` 保留两支视频的 HLS URL 及选取的变体。下载使用 HTTPS curl，按播放清单顺序拼接初始化段和 fMP4 段；`ffprobe` 已核对完整文件可解码。V1 保留视频流，未获取音轨，因此本证据不能用来评价原版音效时机或音色。

清理范围限于此次新建的 `.local/fr/profile/`、`.local/fr/tmp/`、`.local/fr/ab/` 和已合并的视频分片；原始 API 响应、完整参考视频、可复查片段、截图和清单保留。未修改游戏实现或封面。
