# 强手棋（Monopoly）加入可行性调研

调研日期：2026-10-04。范围：经典强手棋的规则、素材和现有平台接入；未实现游戏、未上传素材、未部署。

**结论：适合加入，规则和技术都可行；素材已验证有棋盘及基础图标可下载，但还没有取得同一版本的完整高清中文卡面和原版金属棋子图。** 推荐经典 2–6 人版，完整保留拍卖、交易、建房、抵押与破产，不先做大量主题版或家规。

本次把“强手棋”理解为 Hasbro 的 Monopoly，而非电子游戏《大富翁》系列。地名先采用经典美版大西洋城棋盘的统一中文译名；中国城市版、香港版等应作为独立版本选择，不能只换底图却沿用另一版卡牌指令。

## 规则依据与版本

主要依据为孩之宝官方 **C1009 英文规则书，©2016、2017 排版文件**，不是声称当前所有发行版都相同。

- [官方 C1009 PDF](https://www.hasbro.com/common/documents/dad288661c4311ddbd0b0800200c9a66/97DF546B6BF64A70A2A759D3FA5BD804.pdf)：实际下载完整文件，2 页，15,457,359 字节；阅读文字并渲染核对关键页面。
- [官方 C1009 产品说明页](https://instructions.hasbro.com/en-us/instruction/monopoly-board-game-for-ages-8-for-2-6-players-includes-8-tokens-tokens-may-vary)：确认产品名称为 2–6 人；页面另有其他发行文件链接，未把它们混入本报告规则依据。
- [官方旧版 00009 PDF](https://www.hasbro.com/common/instruct/00009.pdf)：实际下载、阅读，©2004/2007，有可选加速骰及旧税制，仅作版本对照。

旧版有“所得税付 200 或总资产的 10%”的选择，C1009 棋格则标明所得税 200、奢侈税 100。C1009 对公用事业写明再次掷骰计算租金；租金追讨截止为下一名玩家掷骰前。这些细节必须随选定版本固定，不能凭熟悉的家规拼接。

规则书不会逐张列出所有事件卡。**16 张机会卡、16 张公益金卡的同版完整内容仍需在实施前核对实物图或可靠卡表。**

## 核心规则范围

| 项目 | 建议采用的经典规则 |
|---|---|
| 人数与组件 | 2–6 人；40 格；28 张地产证（22 条街道、4 个铁路、2 个公用事业）；机会与公益金各 16 张；32 栋房屋、12 栋酒店；两枚骰子 |
| 开局 | 每人 1,500；所有人掷两骰，最高者先行，再按座次轮转；同点重掷细节在实现规格中补明，不能总让房主先手 |
| 行走 | 掷骰、移动、处理落点；经过或到达 GO 收 200；前往监狱不收经过起点的工资 |
| 连掷 | 双骰相同可再次行动；连续第三次双骰相同立即入狱，不先走第三次点数 |
| 买地与拍卖 | 踩到无人地产可以按标价购买；不买必须公开拍卖，原先拒买者也能参加；该版起拍 10，至少加价 1；无人出价则仍归银行 |
| 租金 | 按地产证计算；整组街道无建筑时租金翻倍；铁路按拥有数量收 25/50/100/200；公用事业依骰子点数与拥有数量计算，卡牌特殊指令优先 |
| 建筑 | 集齐同色组且组内没有抵押，才能均匀建房；整个组都到 4 栋房屋后才可逐块升酒店；每块最多一个酒店，升级归还该块的 4 栋房屋 |
| 建筑库存 | 全局只有 32 栋房屋、12 栋酒店；缺货不能凭空建造，多人争最后库存需要拍卖；库存影响策略，不能省略 |
| 交易 | 可交换现金、地产和免狱卡；整组建筑必须先卖回银行，才能交易其中街道；不允许玩家间贷款、免租承诺或直接转让建筑 |
| 抵押 | 抵押某街道前，先卖掉整个同色组的建筑；抵押地不收租；解押付本金加 10%；抵押地转手还有立即付息／立即解押的选择 |
| 监狱 | 支付 50、用免狱卡或尝试掷双骰；最多尝试三回合；第三次失败需支付 50 后按该次点数移动；掷双骰出狱不额外连掷；狱中仍可收租、交易、抵押与建房 |
| 事件卡 | 从牌堆顶抽取，执行后放回底部；免狱卡暂留玩家；移动、最近铁路双倍租金、公用事业特殊租金、后退触发新格子都需要连锁结算 |
| 债务与破产 | 现金不足先进入筹款：卖房、抵押及合法交易；无法偿债才破产。欠玩家与欠银行的资产去向不同；欠银行时地产回收、解除抵押并拍卖 |
| 胜负 | 最后一个未破产的玩家获胜；玩家破产后可观战。免费停车不给奖金，税金不进公共奖池 |

游戏的乐趣来自凑色组、交换关键地块、拍卖抬价、留现金和建筑库存控制。只实现掷骰买地会损失主要互动。

建议朋友局优先 3–5 人；2 人可玩，但交易关系少。经典模式存在运气、滚雪球与提前淘汰，对局也可能较长。网页自动算账可以减少操作时间，但本次没有真人计时，不能承诺稳定半小时结束。限时按净资产结算可以以后作为明确标识的变体，不混进经典模式。

## 素材实测

以下“确认”指实际下载并检查，不只是搜索结果。第三方仓库中的文件不自动等于官方原始素材；仓库代码许可证也不证明所有图片的来源。当前仅记录来源与质量，没有将它们纳入游戏或发布。

|---|---|---|
| 棋盘 | `itaylayzer/Monopoly` 的 `public/board2.png`，2000×2000，约 2.14 MiB；已目视核对经典环形 40 格棋盘、八组颜色及中央标识 | 可以作为版式／素材处理来源；英文小字存在锯齿、边缘有辅助虚线，不能直接当最终中文界面 |
| 机会／公益金 | 同仓库 `chance.png` 为 172×362 的问号图；`chest.png` 为 1500×1000 透明底蓝色宝箱，均已目视核对 | 是类别图标，不是全套事件卡插画；完整同版事件卡正面尚未找到并核验 |
| 地产证 | 同仓库有地产数值 JSON 和 `streetCard.tsx`；另一仓库有完整棋格及租金表代码 | 这些卡面实际由文字、色条与图标排版，并非 28 张扫描卡图；需核数值，再按经典卡面结构排中文 |
| 骰子与房屋／酒店 | 同仓库 `c1.png` 为 250×250 骰子点数图，`h.png`／`ho.png` 为 234×216 绿房／红房；另有小尺寸房屋、酒店、骰子图 | 基础棋盘展示够用；两套图风格不同，应选一套统一，不混搭 |
| 棋子 | `all.png` 为 1920×1920 图集，含礼帽、汽车、靴子、战舰等平面图案，已目视核对 | 是扁平化图标，**不是原版金属棋子的精细照片／渲染**；若要求金属质感，要继续补源；`p0.png` 是红底白叉，不能当棋子 |

**实际发现的数据问题：** 第一套 JSON 的 `chance` 数组只有 15 张；第二套虽然有 16 张，但含不同事件组合。不能因为开源项目能运行，就认定其卡组与 C1009 一致。第一次实现必须按选定版本逐张建立卡表，保留同名重复卡的独立数量。

本次未确认可用的 BGA Monopoly 素材入口。尝试的游戏页返回服务器错误，这不能证明 BGA 没有该游戏，也不能据此声称能从 BGA 提取全套素材。

## 推荐呈现方式

保留经典浅绿色棋盘、八组地产颜色、绿房红酒店、机会与公益金视觉元素。采用已有图案加独立中文文字层，价格、租金和状态仍由规则数据渲染；不要把所有字压进一张图片，也不要用整层滤镜改变地产颜色。

- PC：棋盘为主体，侧边放玩家资产、交易与操作；选中地产时在棋盘中央或侧栏显示大地产证，拍卖面板尽量不遮住报价所需的资产信息。
- 手机：保留整盘概览，可点地块、缩放和拖动；当前位置和本次决策用清晰的大卡展示。40 格棋盘在约 390 像素宽屏幕上，每条边的普通格仅约 30 多像素，不能承诺一屏内所有地名和租金同时易读。
- 明确显示每位玩家的现金、同色组、建筑、抵押状态和托管标识；自己的资产可分组展开；详细日志需记录买地、报价、交易、租金与破产去向。
- 棋子移动、骰子、买地归属、收付金钱、房屋升级都可做短动画；动画是服务器事件的表现，不决定结果，断线恢复不应重播全局历史。

确认素材后，可沿用现有 OSS/CDN 流程，放独立的 `bga/monopoly/<版本>/` 目录。先检查每张的真实文件格式、尺寸和解码结果，再压缩、上传并验证 CDN 返回；本次没有上传操作。源文件、规则数据与本地化文案分别管理，未来增加语言不用重新做棋盘。

## Go 服务接入评估

现有 `internal/game/game.go` 已有 New / Apply / View 的游戏分发；卡坦岛有交易与待响应阶段，三国杀有打断结算，服务器已有计时、托管和状态恢复。可以沿用 Go 权威判定、持久化状态、WebSocket 同步，无需增加重型服务或 3D 引擎。

主要新增工作：

1. **阶段状态机：** 行动准备 → 掷骰移动 → 落点／事件链 → 买地或拍卖 → 债务／清算 → 连掷或结束。另有交易回应、抵押转手付息、建筑库存争购等待决操作。
2. **并发与原子性：** 拍卖报价、交易接受、房屋库存变更必须由服务器顺序校验；交易双方看到的报价版本必须一致。多人同时买最后一栋房屋应进入规则规定的争购流程，不能单纯由网络先到者取得。
3. **非当前玩家行动：** 纸面规则允许在自己回合外交易与建房。线上应定义明确可操作窗口，禁止在骰子结果已经揭晓后补建房追收当前租金。窗口与暂停方式属于需要定稿的线上交互规格。
4. **超时：** 常规回合可以沿用 120 秒；拍卖、交易回应、筹款各自有时限并暂停普通计时，具体时长待试玩。超时可托管、放弃报价或拒绝交易；不能把一时现金不足直接判破产。
5. **线上适配：** 自动收租，取代纸面版的口头追讨时限；这是有意的线上适配，应在游戏说明中写明。退出／踢出也不能凭空删除地产，优先托管或按明确弃权清算规则处理。
6. **电脑：** 买地、报价上限、集色、建房、现金缓冲、抵押及解押都可用规则与估值实现；交易谈判要另写估值，识别拆散自己的色组、帮助对方垄断等风险。可接复用的托管框架，但策略不能直接套其他游戏。电脑不得读取尚未揭示的骰子结果或卡序。
7. **全平台入口：** 游戏列表与人数、机器人调度、观战视图、战绩计分、管理员游戏开关、帮助文案、桌面与手机 UI 都要一并接入。

实现验证应重点覆盖：第三次双骰入狱、入狱结束连掷、事件后退再触发事件、最近铁路特殊租金、均匀建房卖房、建筑耗尽与酒店拆售、抵押地转手付息、债权人付不起接收利息、多人收付款中途破产、银行回收拍卖、同时报价／交易与重连恢复。无需在研究阶段编写游戏实现测试。

## 建议的首版边界

**经典 C1009 风格、2–6 人、中文、完整交易与拍卖、电脑与托管。** 不预设免费停车奖池、加速骰、电子银行、特殊角色能力或主题地图。

技术可行性高；规则实现复杂度中等偏高，重点在经济结算和并发响应。素材可做出辨识度明确的经典风格，但“全套原版高清卡牌已齐备”目前不成立。进入编码前，优先冻结版本并完成 28 张地产证和 32 张事件卡的数据核对、确定棋子的最终风格，再制作一张桌面和手机素材样张供确认。

来源尺寸、散列及核验状态见 [sources.json](sources.json)。研究用 PDF、截图、下载样本与临时浏览器目录在核对后清理；不把大文件加入仓库。
