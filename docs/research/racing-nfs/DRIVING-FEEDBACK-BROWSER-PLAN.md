# 离道计圈与驾驶反馈：浏览器先行失败清单

以当前 v1.54.1 构建为红测基线。使用正式认证房间、真实原起点、普通 HTTP `action/drive` 闭环与原生键鼠／触控；不直接修改位置、检查点、圈数、复位锚点、快照或时钟。普通 HTTP 控制意图不等同车辆状态注入。等待 root 唯一构建冻结后再跑长绿测。

1. 只让托管沿中心线完赛，遗漏真人离开路面后无法继续计圈的故障。
2. France、Coastal、UK、Park 任一赛道出路缘 3 m、10 m 或更远后回道，检查点永远追不上；同一次真实跨线仍停留 1/3。
3. 离道采样只报告相对中心线距离，没有扣除对应分段的左／右路宽；实际没有达到约定出路缘距离。
4. 用任意横向距离上限拒绝正常绕行；原地、来回过线或 R 瞬移刷圈。横向完全放开，只由实际地形／碰撞自然约束，远离路面不是非法计圈理由。
5. 复位把车送回旧起点／旧锚点，清空实际进度；刷新、重连和恢复改变 epoch、比赛期限或已完成圈数。
6. 后端圈数增加而真实 HUD 不动；只读后端数字，未保存实际 1/3→2/3→3/3 画面。
7. PC／320 px 速度、转速圆表或指针被遮挡；真实加速、升挡和刹车期间指针不变或与显示数值相反。
8. 平稳直行、普通对齐转弯也持续留胎印；真实急刹／滑移却没有写入几何或可见路面轮迹。
9. 胎印无限增长、消失时卡顿，或为满足性能而省略有效碰撞、输入或画面。
10. 发动机只在片段边界周期触发、换挡时断声或怠速误静音；仅 currentTime 增长而实际数字输出为静音。
11. 将离线合成的试听文件冒充网页输出；录音没有标记来源、真实操作、时间和用户输入。
12. 多指释放、菜单中断、拖出、键盘／Gamepad 混用和禁选等既有 safety 回归失败。
13. 平台 continuous 路径仍退回逐片原生 loop，或同时启用两个播放出口；把旧 per-voice 录音再次拼接当作最终混合流。
14. continuous sink 的音轨已含各声部 gain/pitch，试听文件又重复乘声部包络、二次变速或漏乘原生 master；缺少逐行 muted/paused/context/owner 状态。
15. 只观察 BufferSource 计数或 currentTime，未录到实际混合流；缓冲接缝仍出现旧版约 126 ms 的周期近静音。
16. 任一五车的原驾驶舱 steering／RPM／MPH 部件不活动，或新增假针掩盖原件静止；MCF1 无原 MPH 针时错误要求假针。
17. 默认 R 键仍在高速拒绝，或保留额外 5 秒冷却；2 秒复位动画内再次按 R 没有「正在复位」反馈，动画结束后仍不能再次复位。
18. 将并发负载下带「赛况同步中断」的 320 px 布局图冒称健康操作或性能证据；只裁去告警，却没有隔离环境的真实触屏操作、车况、帧率和完整截图。
19. 只检查单条动态 view 不超过 8 KiB，遗漏实际双向 WebSocket 的消息数量、应用 payload 字节数、每秒字节数和状态到达间隔；把输入到像素、RTT 或 ACK 中的任意一项冒称完整联网流畅度。
20. 把 CDP 解码后的应用 payload 大小冒称包含帧头、TCP 或压缩后的线上传输量；把慢连接故障注入混入普通两人／六车负载统计，或记录不必要的消息正文和认证数据。
22. 因果像素测量只确认车速静止，却在上一轮车轮回正／权威校正仍活动时发下一次输入。`final-latency-02` 的慢连接第 6 次输入前已有 179 个变化像素，校准门槛抬高后得到 142.16 ms；该原红保留。后续在发任何新输入前，等待实际渲染车轮 `displayedSteering` 回零并稳定至少 250 ms、至少 6 次真实绘制，有界 5 秒并记录全部等待样本。仍完整发送八次输入，保留所有试次，原像素噪声公式、80 ms 预算、RTT／ACK 和慢连接门槛不变；不得删去已发送的失败试次。更早普通连接 83.64 ms 且 baseline 无噪声的原红不归因于此问题，也不覆盖删除。
21. PC 仪表整体仍悬在左下地图上方，底边没有对齐；手机右侧仪表与左上地图顶边不齐；F7 开镜后只移动一侧，或新位置越出画布／遮住触控。844×390 px coarse 横屏也必须覆盖 F7 关／开，检查同顶、地图与仪表不互压、不压 HUD 文字与全部场内按键，开镜后不与真实镜面重叠。布局按真实 DOM outer rect 测量，允许 2 px 排版误差，保存 PC、320 px 与横屏完整截图。

布局收尾的已观测红点：621c1977 构建 PC 虽底边对齐，但聊天按钮与仪表外框重叠 1165.17 px²；横屏名次存在断行。后续 CSS 修正只移动游戏仪表为聊天留角落、保持手机右边距，并使横屏 F7 名次单行。新验收明确断言 PC 聊天外框与仪表不重叠，保留旧图，不改公共聊天位置。

最新用户否决 87b510de 的布局：PC 为避聊天而留出 right96 空白不符合「贴右边」；手机双表和地图遮挡前方视线；D1 挡位块过大。后续 UI 验收必须覆盖 PC 右边距不超过 16 px 且底边齐地图、320 px 可见纯数字 fallback、390／430 px 紧凑圆表（按最终设计）、小号 `1`／`2`／`R` 且不压实际圆盘。记录真实可见地图与仪表的面积／中央视区占用，不把 CSS 隐藏的 SVG 当成仍可见圆表，不移动公共聊天来掩盖布局。

compact 模式还必须在隔离健康触屏油门场景读取实际可见 speed／rpm／gear，不能仅挂出永远为零的数字。若权威车辆正在运动，speed 数字也必须非零；rpm 必须是有效怠速或负载读数。该检查和已有原生触屏操作复用同一场景，不扩大性能或延迟预算。

f31d50c0 已观测的横屏红点：844×390 两圆盘没有压按钮，但 gear 文字底部与油门按钮重叠 0.8125 px；原完整 9 图和报告保留。后续补 320×480 矮竖屏，防止短横屏宽度规则误盖 compact108；补 844×520 中等横屏 F7 关／开，防止镜开 top206 再压踏板。仅短横屏 analog 缩为 160 px；数字、地图尺寸、锚点、HUD／按钮／真实镜面净空继续按实际 rect 核验。

小号 gear 与数字 readout 需要在亮路背景上仍可读。深色半透明底按最不利白色底合成，记录实测 computed 前景／背景色及对比度，要求至少 4.5∶1。gear 有背景时按整个实际 16×16 底板判 paint 净空，透明 footer 才按文字 Range；不把透明 wrapper 空角当作圆盘，也不忽略真实底板。

连续音频工程门槛先行冻结：稳定怠速 0.5～7.5 s、驻车负载 8.5～15.5 s，按 2 ms RMS 窗口统计，小于该稳定段 RMS 中位数 5% 的最长连续近静音不得超过 20 ms。开始／控制过渡排除段在报告中逐项保留；加速、升挡、刹车和完整录音同时保留统计与真实车况，不把有意控制变化冒称容器断声。该指标用于发现已实证的约 126 ms 周期洞，不是主观听感分数。非唯一原生 sink、fallback、context 未 running 时不能通过连续路径验收。

计圈记录保留完整输入、权威车况、真实路缘外距离、圈数变化、复位前后和刷新身份。每轨离道距离按原地形开放区域实际可达范围记录，不为任意 20 m 验收数字穿过固定墙、屋顶或缺地面；例如 UK 路径若达到 10 m，就精确报告 10 m。无人工横向上限同时由完整代码审阅与拓扑 0／10／20／100 m 及更大距离测试覆盖。普通控制回道、R、完整三圈及真实地形断言不因此放宽。

反馈记录保留指针计算样式、截图、实际胎印几何计数与原生数字音频工件。所有结论绑定赛车源码、前端构建和资源摘要。PC ≥50 FPS／P95 ≤35 ms；320 px 仿真 ≥30 FPS／P95 ≤50 ms，六车动态 JSON ≤8192 bytes；不在测后调宽预算。实体 iOS、扬声器和 Windows 原版运行未实测时必须明确标注。
