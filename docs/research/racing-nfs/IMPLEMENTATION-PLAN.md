# 极品飞车参考复刻：实现前契约与失败清单

本文件在产品实现修改前建立。目标是完成平台内可玩的老极品飞车参考复刻，包含可辨认的主流车型、真实三维原版近似赛道和接近参考的街机驾驶手感。赛道数量根据真实转换效果和最终资源体积增加，不将同一路线的昼夜版本计作两条赛道。保留平台房间、2～6 人竞速、电脑、托管、重连与结算；不部署原版模拟器作为最终游戏。

## 版本与数据边界

- 新比赛使用版本 3 的驾驶模型和经典车型 ID；旧快照没有该标记时继续使用其已有规则，不改变道路、车位、期限、进度或结果。
- 车型 ID 使用稳定的小写标识，例如 `p911`、`fm50`。原有 `skin` 操作保留为旧版外观兼容，新版在统一等待房间通过 Preparation 选择车型，不在比赛中瞬间切换物理性能。
- 新赛道保存真实的二维路线、每点高程/路宽/法线和边界规则数据；客户端几何与服务端采用同一来源和变换。规则数据可由服务器维护，客户端 GLB、纹理与音频使用独立发布资产。
- 服务器与存档沿用现有分米单位；独立运动核心与转换资产使用米/秒/弧度，转换仅发生在明确的边界。
- 常规新版本 View 仅包含静态几何版本引用和动态车况；客户端在就绪前获取并校验所选道路。旧版快照继续支持其完整 Track。
- 车辆 GLB 使用 +Z 车头、Y 向上和独立车轮节点；赛道 GLB 与道路 JSON 共享 origin，不能靠渲染偏移掩盖规则碰撞不一致。

## 失败清单

1. 格式转换漏读成员、坐标轴交换、比例错误、车头反向、轮胎埋地、纹理/透明排序错误，或用程序盒子替代可读取的原车和建筑。
2. 平滑/重采样改变原版弯道；道路、碰撞与地图中心线不重合；起伏被压平；桥梁/隧道按二维最近点误命中；原版墙体可穿越，或路面中出现不可见障碍。
3. 起跑格落在路外或墙内；检查点顺序反向；进入路肩后瞬间限速；倒车跨终点刷圈；切弯或离开当前道路仍增加进度。
4. 油门、刹车或转向瞬时跳变；高速可原地旋转；零速轮胎方程不稳定；车辆没有差异；手刹永远失控；松手不回正；制动过零意外反向，或断线保护自动倒车。
5. Go 与 TypeScript 的固定步长、车型参数、刹车力度和待执行输入不同；轻刹被远端预测成满刹；普通 ACK 重建时钟，出现拉回或无输入的位移。
6. 电脑绕过规则写位置、靠复位或绝对超时完赛；六人首车后 30 秒不足时其他电脑永远不能自然完成；卡墙、错过检查点、倒车恢复或并排碰撞时卡死。
7. 更换车型或恢复旧存档重置 epoch/序号/进度/期限；等待房间越权替他人选车；人数改变导致车型数组失效；旧客户端合法输入失效。
8. 浏览器提前确认就绪；冷加载没有真实字节进度；拉取未选择的赛道；更换/离开房间后仍保留 RAF、几何、贴图或音频；一次失败导致永久缓存错误。
9. 车身遮挡前路、镜头穿墙/穿地、转弯道路绕车旋转；视角和 HUD 的挡位/RPM不一致；320px 画面或控制器被公共区域挤出视区。
10. 实时消息携带完整静态道路/模型；慢端拖住快端；失焦/重连补发旧按键；只报告 ACK 或帧率而未验证首次可见响应。
11. 新素材进入正式服务器资产正文；资源清单的大小/摘要不是实际产物；原始音频被有损转码；公开参考源码的许可被误当作原版素材再分发许可。

## 先行验证

- `games/racing/tests/classic_e2e_test.go`：生产 Module 的新车型、等待准备、几何引用、原始路线/高程、输入安全、持久化恢复、独立车型自然完整比赛。先运行形成预期失败，再实现。
- 独立运动核心的 Go/TypeScript 轨迹对照：仅用于验证必须隔离的跨语言确定性边界，使用原始参数与长输入时间线，覆盖上述操控失败场景；不以逐句镜像单测替代完整比赛。
- 转换工具验收：对实际原始载荷执行完整转换，再独立读取 GLB/道路 JSON 的索引、范围、纹理和摘要，保存输出与体积；失败清单先于转换实现。
- 浏览器 E2E：复用生产 HTTP/认证/计时器与正式页面，覆盖地图/车型选择、加载、操控、完整比赛、窄屏、恢复与网络条件，保留截图和事件到像素证据。

## 性能预算（实现前固定）

桌面正式页面目标可见更新至少 50 FPS、帧间隔 P95 不超过 35ms；320px 触屏仿真目标至少 30 FPS、P95 不超过 50ms，仿真不能冒充实体手机 GPU 测量。正常及单端 150ms RTT 下，原生输入到首次可见驾驶响应 P95 不超过 80ms；单端慢连接不得降低另一端的规则和显示推进。六车常规动态状态 JSON 不超过 8 KiB/消息，不含静态道路、纹理和模型；总载荷、ACK、权威到达和显示排队分别报告。不能在测后调宽预算。

首次转换保留原始纹理分辨率和可识别细节；先去重、按需加载和采用无损压缩，再按实际 GPU/传输证据决定必要的呈现优化。扩展赛道数量依据最终大小和转换质量，不先把安装包大小当作网页预算。
