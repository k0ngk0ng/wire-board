# 可破坏物件浏览器验收：实现前失败清单

物件目标驾驶使用正式房间、原始起跑格和经过正常校验的 HTTP `action/drive` 模拟量闭环；不写入位置、速度、破坏位、比赛快照或时间。原生 CDP 触控输入由独立 safety 阶段覆盖，不把 HTTP 驾驶宣称为原生键盘回放。原目录为 France 29、UK 108 个物件；客户端目录与权威 catalog、旧 geometry 必须一致。先打通 France index 1 与 UK index 0 的普通驾驶接触，再覆盖昼夜、恢复与性能。

1. 原起点无法通过普通 HTTP `drive` 输入接触目标；脚本依赖近目标初始化或直接修改 snapshot。正常 `drive` 动作只改变控制意图，不等同直接写入车辆或物件状态。
2. 目标不属于已确认白名单，catalog／geometry 不一致，或事件把 index 0 当作缺省值漏掉。
3. 真实接触没有破坏位和唯一权威 prop 事件；同一物件被重复计为破坏。
4. 权威确认前提前隐藏物件；确认后只改数据，没有实际原 CAN 动画或可见姿态变化。
5. 低／高速选择与权威 high 字段不一致；0.46875／1.5 秒原动作循环重放，或迟到事件从头播放。
6. 独立观众没有同步到相同 catalog 和破坏位；另一个房间受到错误的全局破坏影响。
7. 后续车辆穿过已破坏位置时仍被旧碰撞边阻挡；固定墙或非白名单物件被错误移除。
8. 刷新／晚加入让目标复活或重播过期动画；epoch、期限、圈数或排名被测试重置。
9. 昼夜使用不同物件身份或节点，UK index 0、France index 1 没有实际绑定对应原 mesh。
10. 320 px 触控不可操作，或新破坏状态使 PC／320 px 实际六车移动帧率低于原预算。
11. 新状态重复传输静态目录，六车动态消息超过 8192 bytes；实际网络和原生事件没有保存。

保留普通输入、可信事件、位图／事件、renderer 的 propsCatalog／propsCount／propsBroken／propAnimations、截图及来源摘要。动画数据来自原 CAN；8 m/s 高速分界是本项目重建约定，不称为原版实测。PC ≥50 FPS／P95 ≤35 ms；320 px 仿真 ≥30 FPS／P95 ≤50 ms。实体 iOS 与原版 Windows 运行不在本轮实测范围内。
