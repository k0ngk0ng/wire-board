# 长圈浏览器驱动中断：先行失败清单

以下清单先于有界 HTTP 与增量日志实现。运行时、前端构建和 94 项源摘要保持冻结。

- 单次 `GET /api/state` 永不结束，驱动与进度文件永久停止，而产品仍响应其他连接。
- 只读 GET 暂时失败后不重新读取；或无限重试掩盖已中断的验收。
- drive POST 超时后不知道是否已生效，却重发旧版本／序号；或吞掉非预期 4xx。
- 对原生 R 自动重试，意外执行两次不幂等复位。
- 完成第一圈后停在采样、R、动画结束或真实刷新阶段，日志只有最后一次驾驶进度，无法定位具体步骤。
- 驱动被中断时，完整输入和权威车况只在未返回的 JavaScript 内存中，未留下增量证据。
- 诊断时用不完整环境连接既有 agent-browser session，触发浏览器重启，旧 CDP 长调用失去目标。
- 单个 CDP `returnByValue` 返回约 5 MB 深对象，连纯 `about:blank` 都会卡住整个 target；旧页面随后的短请求也无法作为独立对照。每圈结束由 binding 回调同时请求截图，进一步混淆返回阶段。
- 后端正常省略 `false` 的 `seat.autoPlay` 字段，Python 校验器直接下标访问触发 `KeyError`；此时完整真人输入、真实三圈、原生 R 和截图已成功落盘，却被校验器读字段错误标红。修正后必须对原始文件 SHA 绑定独立重验，保留原红报告，不重写原报告成功标志。

红证据位于 `.local/racing-nfs-browser/final-circuit-{france,coastal,park}-01` 与 `final-circuit-diagnostic-01`。Coastal／Park 的诊断前后 target ID、CDP 端口确有更换；France 第一圈后中断的具体请求原因尚未证实。三条已主动终止并保留失败记录，不计为通过。

修正只允许：有界只读 GET 重试并记录错误；drive POST 不重发，409 等待下一轮新状态；非预期状态保留并失败；R 保持原生单次按下／释放。每秒原子进度、阶段标记和增量原始行日志写入各自验收目录。不得修改比赛位置、圈数、规则、时钟或冻结运行时。

独立复现见 `.local/racing-followup/cdp-transport-probe/`：全新页面的小摘要约 68 B、带截图的小摘要均在约 110 ms 返回；约 5 MB 对象在 12 秒超时。长圈改为每圈只回传小摘要，原始行全部经分段 binding 写入 journal，由 Node 复原；每圈截图由主驱动在小摘要返回后逐次等待。因调试已消耗旧对局 20 分钟期限，旧对局不延长、不暂停；新 03 对局使用显式 22 m/s 铺装巡航控制计划，弯道制动、离道 4 m/s 和全部验收门槛保持不变。
