# 热血篮球声音素材与接入

当前已导出 **31 个实现中会请求的原版效果音、8 个场地的独立背景音乐、有限结局曲 75，以及结局曲 76 的原时间轴预览**。每项都运行未改动的原声音驱动和数据，由 FCEUX 的 APU 渲染器输出 PCM；没有根据听感合成替代声音。已接入游戏侧的平台音频适配器，素材仍是本地研究候选，`accepted_for_release: false`，未上传 OSS。各场地来源、持续播放派生和结局范围见 `games/basketball/assets/COURT_AUDIO.md`。

运行时的 9 首音乐另有已验证的 MP3 分发文件，母版保持本地留存。分发总量从约 1.344 GB 降至 243.8 MB；原周期和解码样本数保持一致。压缩来源、真实浏览器循环及回退结果见 `games/basketball/assets/MUSIC_DISTRIBUTION.md`。以下原录和接缝段落保留研究过程，不能将其中历史 WAV 文件名作为当前网络分发清单。

## 原版驱动和 REA 证据

源 ROM SHA-256：`0fa28f60abb8d2ccbbeee90e79e3fa160a5cf32feb90f47ebf1a89168cff569b`。提取使用 `.local/nes-basket/basketball.nes`，原文件不变。

固定 `$C000` 跳转到 `$FBCC`，保存当前 bank，切 bank 0，将 A 中的 ID 交给 `$8000`，再恢复原 bank。更新入口 `$FBE3` 映射 bank 0 并调用 `$8003`；实际驱动位于 `$8183`。正数 ID 使用 `$8BE0 + 2 × (ID − 1)` 的小端指针；`$80B0` 加载声道和优先级，`$8166` 重置状态。

REA 输入 `.local/basketball/audio/bank0-visible.bin` 将原 bank 0 映射到 `$8000–$BFFF`，固定 bank 7 映射到 `$C000–$FFFF`。保留的批次为：

- 请求入口：`ev_47846c00a63fba1c06339b9ef74ac40f0d659bd4b8ab5537fa514ab02924fd1a`，目录 `audio/rea/`。
- 声道驱动：`ev_9925b47bdf83028e38be3e23572c67d65c54c6cacd64b34f9b239f465eadaa73`，目录 `audio/driver-rea/`。
- 序列跳转和 DPCM：`ev_40254883b39687c64df49af92ebca814b0b4f7545314f190e451b532b75705ca`，目录 `audio/music-rea/`。

上述目录均位于 `.local/basketball/` 下，包含完整证据、函数报告、种子和快照。静态分析与指令核对确认序列命令 `$D0` 进入 `$8521`，使用数据中的小端地址跳转；`$8679` 按原驱动值设置 DPCM 地址、长度和播放控制。

## 背景音乐与循环边界

原 `hoop-control-cpu-long` 的全部 6,000 帧 `$0700` 都是 66，证实它是当前纽约比赛记录正在使用的曲目。本次导出 8,000 个仿真帧，约 133.097 秒，文件为 `music-066.wav`。

原主声道在采样步 **3280、6556** 执行同一个 `$D0`，从 `$AC1D` 跳回 `$ABB0`；声道 1 和 2 在这两帧也回到各自循环起点。对应录音帧末 PCM 游标为 **2,406,078 和 4,809,979**，相隔约 **54.510 秒**。这些是直接记录的序列循环候选边界，不是按听感裁剪。

完整驱动状态尚未在这两个位置完全相等，节拍累加器的相位不同；APU 振荡器相位也不能从序列跳转直接推定。清单因此标记 `sequence-loop-candidate`、`pcm_seam_accepted: false`，保留完整录音、逐帧驱动 RAM、原跳转记录和精确 PCM 游标。当前不能把候选片段宣称为已验收的无缝循环。

曲目 66 使用原 DPCM 鼓点：地址 `$FE80`，长度 257 字节，范围到 `$FF80`。该范围全部来自未改动的原固定 bank，未覆盖 `$FFF0` 的开发包装。验证器检查每次 DPCM 启动对应的地址与长度；没有以禁用 DPCM 的方式简化音乐。

满渲染音量 255 曾出现 52 个负峰削波样本。音乐改用明确记录的 FCEUX 渲染音量 192 后通过无削波检查；效果音保留 255。没有对导出的 PCM 做后期归一化、滤波、变速或重合成。

## 提取和验收

先更新失败场景和验证器，再扩展导出实现。复现命令：

```sh
source scripts/env.sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/basketball/extract_audio.py
PYTHONDONTWRITEBYTECODE=1 python3 scripts/basketball/verify_audio.py
```

输出目录 `.local/basketball/audio/export/` 中：

- `manifest.json` 保存源 ROM、目录清单、提取脚本、FCEUX 二进制、NSF、原录音、裁剪结果和执行记录的 SHA-256，以及效果／音乐分类、音量和 DPCM 区间。
- `verification.json` 保存 28 项素材的通过结果。
- 每项两次运行都保留 `full.wav`、请求与更新调用、APU 写入、逐帧驱动 RAM、序列跳转和 PCM 样本游标。

**首批 28 项素材的两次完整 PCM、APU 写入、调用记录、驱动 RAM、序列跳转、样本游标全部逐字节一致。** 新增场地曲、结局曲和效果也有独立批次与双录摘要，不覆盖首批证据。验证同时核验 ROM 和驱动字节、素材清单完整性、控制 ID 不被导出、WAV 参数、非静音、无削波、效果尾部完整性以及 DPCM 源范围。原生输出为 44,100 Hz、单声道、16 位 PCM；效果 WAV 只截取原 PCM 的连续区间，保留前沿和尾部余量，音乐保留完整录音。

开发用 NSF 只在固定 bank 最后的向量区放置 11 字节包装：先请求 0 复位，再请求目标 ID。bank 0 全部保持原样；固定 bank 除该包装外也保持原样。NSF 和 FCEUX 只参与离线提取，不能成为最终网页游戏的运行时。

macOS Qt 构建的 `--soundrecord` 在本次环境中只保存配置而未启动录音，因此 `audio_wave_bridge.c` 从 Lua 仿真线程调用 FCEUX 已有的录音函数，并记录实际文件样本游标。它不修改 CPU、APU、原驱动或游戏规则。进程使用离屏 Qt、软件绘制、SDL dummy 声音设备、专用仓库内配置和写入 sandbox，不显示原版窗口或向扬声器播放。

## 平台接入和剩余工作

Go 引擎继续输出原 ID 和有序事件。前端维护事件序号以避免恢复快照、重连和观战时重播，通过 `BoardProps.audio.playWithFallback([OSS 地址, 本地地址])` 播放效果；两个地址是同一素材的候选源，不能作为播放列表传给 `play()`。音乐在循环验收后使用平台 `audio.music`。

统一静音、设备媒体音量、页面隐藏和离桌清理由平台负责。篮球目录不创建播放器或 `AudioContext`。游戏侧 `web/audio.ts` 已使用平台新增的 owner 范围 `pause()`／`resume()` 接口；恢复不重装源、不重播曲头。客户端只消费 Go 新发的 ID，原 `StartOriginalCourt` 已发出纽约音乐 66，不按画面阶段另补一份。适配器的水位、错误处理和验收见 `games/basketball/web/AUDIO_VERIFICATION.md`。

追加 20,000 帧接缝审计确认，完整声音驱动状态在 16,384 帧（5 次曲目循环）后才重合，但原 PCM 相位仍不同。单循环边界跳变为 805，五循环边界为 430；原证据保存在 `.local/basketball/audio/seam-verification.json`，不把未加工片段冒称为无缝循环。

持续播放使用另外制作的 `music-066-loop.wav`：保留 272.617732 秒原 5 循环周期，只对末尾 1,411 样本（31.995 毫秒）做披露的余弦衔接；源片段、公式及 SHA 在 `music-066-loop-source.json`。99.9883% 样本未变，接缝相对原相邻样本误差为 0；8 毫秒窗口／2 毫秒步长的局部 RMS 最大偏差约 −0.308 dB，无削波。两次独立原录音和派生结果一致。

`audio-playback.json` 保留该 WAV 母版摘要，实际 `file` 指定其 MP3 分发文件，平台 `audio.music(..., {loop:true})` 播放。真实浏览器分别保留了 WAV 早期验证和 MP3 当前分发验证：两次跨尾持续播放、位置不重置的暂停／继续及离桌清理。数值验证、浏览器结果及人工听感的边界见网页音频验收文档；人工听感尚未核验，不能称为音频整体验收完成，素材仍未发布。

原驱动按声道和优先级覆盖同时发生的声音。WAV 混播或串行播放不自动等价于该行为，仍需实际对局时间线、密集攻击、音乐与效果并发、手机及 PC 试听验收。8 场持续音乐与 75 有限曲已具备验证记录；76 的「前奏一次＋循环段」、其余菜单音乐和未实现玩法对应的声音仍待恢复。当前素材的对外分发许可没有因提取而得到证明，所有文件保留本地，未上传 OSS。
