# 原版 HUD 资源失败场景

先固定样本、列出失败和测试，再实现解析器。入口为 `python3 -B scripts/cs16/test_hud_assets.py`，原始来源与全部输出限定在 `.local/cs16/`。

- SPR 魔数、版本、尺寸、调色板、帧数或帧类型错误；帧越界、数据截断、索引超出调色板、尾部未消费。
- 把 ADDITIVE 的黑色背景输出为不透明矩形，或丢掉灰度强度；INDEXALPHA 和 ALPHATEST 被混作同一种透明方式。
- `hud.txt` 计数被当作实际行数，误拒绝原文件声明 215、有效 190 行的情况；重复名称／分辨率、错误字段数和越界裁剪未拒绝。
- 忽略 cstrike→valve 搜索优先级，低分辨率共用精灵或 crosshairs 无法恢复。
- 原包遗留 320 武器选择定义越过 Valve 共用精灵时，补绘或错误裁剪冒充有效素材；应明确记录未输出的源行，640 核心定义仍须完整。
- 图标自行绘制或改名导致来源不可追溯；C4、购买区、计时、生命、护甲、爆头或任一枪械／弹药缺失。
- atlas 合并时改变原裁剪宽高、像素、透明度，裁剪间串色，重复执行导致排序或摘要变化。
- 原购买确认 WAV 未恢复、使用替代声音、有损转码或还原 PCM 不符。
- 新 HUD 处理重建六图、模型、音频或 Go 规则，造成未变资源 URL 或身份变化。
- 源下载不固定 commit、重复下载已验证文件、隐式回源、目录逃逸或符号链接。

菜单顺序另以选定 `cs.so` 的静态控制流、重定位和字段证据核对；网上泛化快捷键不作为原版行为依据。HUD 与原版菜单均不能仅凭文件名或字符串声称已完整复现运行行为。
