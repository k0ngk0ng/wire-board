# 刀伤、命中部位与护甲

对照样本为既有第三方归档中的 `cstrike/dlls/cs.so`，SHA-256 为 `608904a0357af349466c7b34e69f224268090e3b553b5d46bf13b180001c9d8c`。这是静态指令与原始常量取证，不是原版运行实测，也不声称已取得 Valve 官方分发签名。ReGameDLL 仅用作可读的辅助对照。

原生证据保存在 `.local/cs16/verification/knife-reference/sources/`：`CKnife::Stab` 位于 `0x14fbb0`，普通重刺写入 65；水平朝向点积大于样本中的 0.8 常量时改为 195。`CBasePlayer::TraceAttack` 的命中组分派表位于 `0x1e0f48`，头、腹和腿分别应用 4、1.25、0.75 倍。刀的武器编号 29 在 `0x1e13fc` 表中跳到 `0x110ecd`，把基础护甲比例 0.5 乘以 1.7；护甲消耗使用损伤差的 0.5 倍，包括通用命中组。

## 失败场景

- 水平近距离直刺实际命中原模型头部，不能因为发生一击致死就把伤害强制改成胸部伤害。
- 正面胸部、腹部、腿部和头部须区分；背刺须另乘 3。护甲只保护原版覆盖的部位。
- 腹部刺击不能先把 81.25 截成 81 再计算护甲，否则健康伤害会从 69 错成 68。
- 通用碰撞命中不能套用爆炸的护甲消耗；薄甲、零甲和扣尽护甲的边界均须验证。
- 连续轻刀不能每次丢失护甲残值；刀击后接枪击、再接刀击须保留残值，不能改变既有枪械伤害和散布。
- 目标实体前向水平时，背刺原阈值映射为一圈 65536 单位下的绝对角差不超过 6711；6710、6711、6712 及环绕后的对应负角必须左右对称，不能由近似三角函数把一侧边界扩成 6712。
- 背刺点积使用攻击者水平攻击朝向与目标实体朝向，不是双方位置连线。侧向通用碰撞须保留这一区别，不能被名为 `vec2LOS` 的临时变量误导。
- 存活者跨回合保留护甲及残值；死亡后重生、购买整件护甲时清零残值。旧存档缺少残值字段时按 0 读取。
- 完整护甲点为 0、残值仍为正时继续保留头盔；完整值与残值都耗尽时按原版清除头盔，重新购买整套防具不能沿用仅补防弹衣的折扣。
- 旧存档可能由旧代码留下零护甲但头盔标志仍真的状态。购买折扣和生还回合继承均按实际完整值与残值判断所有权；失败购买不得为规范旧状态而提前修改玩家。
- 残值只进入内部规则与存档，不进入公开玩家投影或每帧网络消息。
- 人质也须能被刀的原模型射线与扩展碰撞命中，不能仅识别玩家。人质调用独立的怪物／人质两层部位倍率和扣款，不能套用仅玩家适用的背刺加成。
- 原版刀追踪以 `fraction < 1` 判断命中；扩展碰撞距离恰好位于端点及其相邻定点单位必须验证，不能把 `fraction == 1` 当命中。
- 玩家、人质和墙体同时位于刀的追踪范围时只命中最近目标；死亡、已营救及被墙体遮挡的人质不受伤。
- 轻刀不能凭「首刀 20、距上刀超过 40 帧恢复 20」的猜测实现。所选原生样本须核对普通无盾路径中冷却写入与伤害分支的真实先后，再验证首次、连续、空挥、击墙、重刀切轻刀及长时间等待。

## 固定数规则

刀伤中间计算与内部护甲余数统一采用每点 800000 单位的整数。命中部位、误伤折扣与护甲比例先按整数精确运算，最终健康伤害向零截断。公开护甲显示为剩余完整护甲点的向下取整，残值继续保存。刀与枪共用同一最终伤害路径，护甲不足时使用完整值与残值共同吸收伤害；原始枪械伤害、散布及弹道距离结算独立对照。这里重现的是上述原始规则的定点形式，不模拟原浮点寄存器对任意人为微小数值的位级舍入。

## 所选样本的轻刀伤害与间隔

上述 Linux 样本的普通无盾轻刀基础伤害为 15，包括首次命中、连续命中、空挥后命中、击墙后命中、重刀转轻刀及长时间等待后的命中。部位倍率和护甲继续在基础伤害之上结算，不能把基础伤害等同于所有部位的最终扣血。Windows 样本 `cstrike/dlls/mp.dll` 的 SHA-256 为 `132b956c745c9637eaaab9c618b056741341ef2b90c7d4d25764e9a280a372ba`，独立指令复核得到相同结果。

Linux `CKnife::Swing` 在 `0x14f2e5–0x14f2ff` 先调用 `GetNextAttackDelay(0.4)`，把结果写入武器的 `m_flNextPrimaryAttack`；`0x14f385–0x14f39f` 才读取刚写入的冷却值，再加 0.4 与零比较。`GetNextAttackDelay` 的 `0x135f70–0x135fe0` 各返回路径均为传入间隔加不可变零常量，不从结果中减去等待时间。因此普通命中路径实际比较的是 0.8 与 0，选择 15 的分支；不能由较早一次攻击的时间推断恢复到 20。

Windows 对应路径在 `0x10008f7b–0x10008fd3` 写入新冷却，`0x10009054–0x10009072` 再执行相同方向的比较；辅助函数 `0x100cf930–0x100cf990` 直接返回传入间隔，也没有等待时间修正。两个样本的调用顺序、字段位置、常量字节及静态证据摘要见 `sources/slash-cadence.json`。

轻刀空挥间隔为 350 ms，命中人物或墙体为 400 ms；独立实现对应 35 帧与 40 帧，每帧 10 ms。测试覆盖间隔前一帧、边界帧、后一帧，以及 750 ms、800 ms 附近和 50 秒等待。重刀命中与空挥仍分别使用 1100 ms、1000 ms。

此结论限定于这两个固定样本的普通无盾路径，不覆盖持盾路径，也不推断所有历史版本。ReGameDLL 的 `REGAMEDLL_BUILD_6153` 等条件分支包含不同的等待时间修正，不能直接代替所选二进制的行为。

以下为原模型命中盒经 `StepCombat` 实际产生的健康伤害，防具栏以 100 点护甲为起点；头部有防具时包含头盔。

| 命中方式 | 无防具 | 有防具 |

| 正面胸部 | 65 | 55 |
| 正面腹部 | 81 | 69 |

胸部一刀不会杀死满血玩家；头部和背刺超过 100 的伤害保留原版的一击致死结果。模型朝向与手臂姿势会影响射线实际先命中的部位，测试不能把瞄准方向的名称当成实际命中组。

## 背刺向量来源复核

原始 ELF 重定位确认 `0x14fbd5` 和 `0x15012f` 都调用 `_Z16UTIL_MakeVectorsRK6Vector`，`0x150111`、`0x150177` 读取的是 `gpGlobals`。同一原二进制的 DWARF 明确标注 `entvars_s.origin=0x8`、`angles=0x50`、`v_angle=0x74`，以及 `globalvars_t.v_forward=0x28`。

`Stab` 首先在 `0x14fbc5–0x14fbd4` 使用攻击者 `pev+0x74` 生成攻击方向。命中玩家后，`0x150115/0x150118` 把 `gpGlobals.v_forward.x/y` 保存到栈，`0x15011d–0x15012e` 再用目标 `pev+0x50` 重建全局前向向量。`0x150133–0x150172` 只归一化此前保存的攻击方向；`0x150180/0x150185` 将它与目标的新前向向量相乘相加，再与 0.8 比较。这个区间没有从双方 `origin` 取差。

侧向回归使用 `X=33、Y=±31` 的不重叠玩家位置。双方同朝向时原判定仍是 195；目标朝向偏转至 `±45°` 时是 65。若错误换成位置连线点积，这两组结果会反转。这里只验证独立实现对上述静态规则的遵循，不将其称为原版运行结果。

原指令只归一化攻击者水平前向向量，目标水平前向向量没有再次归一化。因此上述整数角差映射以目标实体俯仰为 0 为前提，符合当前独立人物实体仅使用水平朝向的表示。参考 ReHLDS 的 `SV_RunCmd` 会用视角俯仰的负三分之一更新实体俯仰；选定原生样本中尚无原引擎二进制来直接核验这层更新，不能把该参考实现当作本次原版运行证据。

## 人质扩展碰撞

原 `CHostage::Spawn` 的 `0x191d15–0x191d48` 直接写入最小角 `(-10,-10,0)`、最大角 `(10,10,62)` 并传给尺寸设置函数，证据见 `sources/native-hostage-spawn.txt`。叠加既有头部追踪模板后，人质的刀扩展碰撞为水平半径 26、高度 `[-18,80]`，不能套用站立玩家的水平半径 32 与高度 `[-54,54]`。

沿重刺攻击轴，扩展碰撞的人质中心边界为 58 HL 单位，玩家为 64 HL 单位；中心恰好位于边界时追踪分数为 1，不算命中。测试另外覆盖两侧相邻的 `1/256` HL 定点单位。

验收命令为 `go test -json -count=1 -run '^(TestKnifeReference|TestKnifeHostage)' ./games/cs16/engine`；重放结果保存在 `.local/cs16/verification/knife-reference/`。
