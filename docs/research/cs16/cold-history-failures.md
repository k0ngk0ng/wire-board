# 冷历史检查点与 CI 根因

相同十连接 100 Hz 压测的 Linux 剖析记录为 `.local/cs16/release/capacity/phase-linux.pprof`。四核 Xeon 8370C、Go 1.26.0，没有 cgroup CPU 节流；整段 JSON 校验约占 CPU 43%，字段边界扫描约占 13%，串行输入提交路径约占 55%。压测期间分配约 380 MB，触发九次 GC。控制本地 Go 版本后仍通过，排除编译器补丁版本作为主因。

当前私有状态约 52927 字节，其中历史约 36514 字节。历史不由普通输入修改，却被每次操作和投影反复扫描与复制。私有存档格式 2 将完整历史作为 gzip 冷检查点保存，仅规则推进时解压；公开投影格式与客户端运动核心保持原样。旧私有格式 1 仍可读取，规则推进后迁移为格式 2。新格式属于尚未发布的 CS16，平台存档兼容代次已升至 7。

实现前的失败场景：

- 压缩前后历史、历史命中补偿、当前门状态或完整规则结果改变。
- 格式 1 不能恢复、迁移丢失历史，或格式 2 与原始历史同时存在产生歧义。
- gzip 截断、CRC 损坏、尾随数据、错误声明长度或解压超限没有被拒绝。
- 普通输入重复压缩、丢弃尚未应用输入或错误更新历史。
- 复用压缩器导致并发污染、非确定输出、错误后泄漏状态或持续保留大缓存。
- 压缩数据进入公开投影、恢复网络包、地图清单或客户端核心。
- Linux 容量仍不符合原门槛，或依靠删历史、降规则频率、放宽预算取得通过。
