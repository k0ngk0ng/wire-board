# 数值比较 lint 的范围与开发前失败场景

通用规范允许不参与业务判断的浮点存储和计算。登记的公共 Go／TypeScript 业务源码检查浮点值是否流入大小、相等、阈值、容差、极值和排序比较；不是见到浮点类型或常量就失败。参与判断前须按明确单位、倍率与舍入规则量化为整数。

CS16 规则、协议、测试夹具与共享预测继续采用自身的跨端确定性约束：登记的游戏 Go 源码及私有输入／预测 TypeScript 保留整数全链要求。公共文件不继承这项游戏约束。渲染、素材转换和音频表现不因纯浮点运算而失败。其他游戏既有更严格的 lint 属于各自的确定性约束，本轮不修改其实现或扩大其验收范围。

实现前失败清单：

- 纯浮点变量、字段、函数返回或算术尚未参与比较就被误报。
- 直接浮点比较，或者经变量、别名、重新赋值、对象字段、数组元素、函数返回进入比较后被漏掉。
- `Abs`／`EPSILON`／微小常量等容差绕过整数边界，或 `min`／`max`／排序 API 隐式比较浮点值。
- 已按倍率和舍入量化为整数的结果仍被误报；Go 的 `math.Round` 仍返回浮点类型，必须再明确转换为整数。
- TypeScript 的 `Number.isInteger`／`Number.isSafeInteger` 校验未传递到后续判断，或者仅 `isFinite` 就被当作整数证明。
- 字符串、布尔、对象身份、`null`／`undefined` 哨兵判断被误判为业务数值比较。
- 仅检查新增行时漏掉来自既有浮点变量的新增比较，或错误追溯并拒绝既有未改的比较。
- 为允许公共纯浮点计算而放松 CS16 确定性核心，或不同入口采用相互矛盾的规则。

检查器基于登记文件的语法、可解析类型和文件内数值流；不以未解析的动态 JavaScript 调用证明值为整数。公共协议声称整数时须有相应输入校验，不能用容差、字段名称豁免或任意类型断言替代量化。

定向复跑入口为 `web/tests/numeric-comparisons.test.mjs`、`games/cs16/tests/numeric-comparisons.test.mjs` 及既有 lint 正负例。产物统一位于 `.local/cs16/verification/lint/numeric-comparisons/`。本轮不运行游戏规则、重放或性能测试。
