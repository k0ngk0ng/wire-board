# 普通排队输入延后投影失败场景

先编写真实 WS 验收，再加入可选 RealtimeDeferredInput。仅已成功 Apply、公共元数据未变化、没有关键事务／结果／检查点变化的普通排队输入可以省略本次房间广播；ACK、内存提交、回执与下一规则帧广播保持原行为。默认未声明模块不变。

| 场景 | 预期 |
| --- | --- |
| 十条真实连接，100 次普通排队输入 | ACK 全部 200；下一规则帧前不执行重复投影；下一帧发布完整结果 |
| 混合普通排队与 buy／cancel | 批次即时广播；取消立即清除保持输入 |
| 检查点、结果、暂停、公开 actor／attention／deadline 变化 | 即使模块谓词返回 true 也强制即时广播 |
| 未声明谓词、无有效系统时钟或谓词失败 | 保留原即时广播；异常不能丢失已接受操作 |
| 重复 nonce、拒绝的 Apply | 不重复执行；谓词不在拒绝输入上执行 |
| 提交后旧电脑搜索失效 | 即使省略广播也照常取消 |
| 托管、权限与重连 | 普通 state 通知、权限校验和完整初始化保留 |
| capability 注册 | 仅 Realtime＋OnTimer＋StreamView 模块可声明，函数不进入公开 JSON |

所有数据库、临时目录与证据仅位于 .local/cs16/。本测试为宿主契约，不替代 CS16 十真人 100 Hz 与四房间容量验收。
