# 竞态与性能验收边界

Linux 普通构建的十真人吞吐与四房慢端性能检查已通过；同一四房用例在 `-race` 下因规则时钟 P95 412 ms 失败。竞态插桩改变执行成本，不能把插桩构建的时间当作普通构建性能证据。

拆分后，保留电脑寻路负载的插桩用例又触发了正确的 200 ms 排队过期拒绝。竞态隔离夹具改用四房各十个真实登录账号，以验证连接、游标、并发规则推进及慢观战；普通构建继续使用四房各一真人加九电脑，并保留原性能预算。两种参与组成分别记录，不把竞态用例称为电脑负载性能验收。

修改前列出的失败场景：

- 普通构建不再执行原四房性能用例，或放宽 ACK 100 ms／时钟落后 100 ms 的预算。
- 竞态选择删除四房检查，却没有同样连接和规则操作的真实并发／慢端隔离替代。
- 将只验证并发正确性的结果误标成性能通过。
- 竞态用例不再检查输入确认、四房时钟推进、慢观战及真人不自动托管。
- 修改竞态选择时让其他游戏失去原有检查，或重新运行已通过且输入未变的游戏。
