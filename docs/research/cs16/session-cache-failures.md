# 实时连接会话查询缓存失败场景

先登记失败场景并编写真实 HTTP／WebSocket 测试，再实现缓存。性能前证据见 `.local/cs16/verification/server/high-rate-pressure-profile.txt`：服务器 user 查询及 SQLite WAL 文件锁约占累计采样 28%，十连接高频流量反复执行相同会话查询。

| 场景 | 预期 |
| --- | --- |
| 同一有效 session 的重复帧及输入 | 复用已由数据库验证的 ID、昵称、实际到期时间，避免反复查询 |
| 注销、管理员撤销、改密码或封禁 | 已缓存 HTTP 与 WS 身份立即失效 |
| 角色、昵称、会话目标或期限变化 | 不返回旧身份；席位和房间权限继续动态检查 |
| 自然过期或直接同库 SQL 撤销 | 不能依靠缓存继续认证 |
| 鉴权读取跨失效写入 | 失效 generation 改变时不得写回旧快照 |
| 身份写事务尚未提交／最后回滚 | dirty 期间不从缓存放行；提交及回滚均再次失效，回滚后可重新验证旧合法会话 |
| 数据库连接重开或关闭 | 新连接安装失效钩子，旧钩子卸载并清缓存 |
| 多账号或令牌切换 | 按 token 摘要隔离，不缓存房间、席位或管理员权限 |
| 大量会话 | 条目与 LRU 有明确上限，不保存原始令牌、密码或无界失效历史 |

缓存由服务器管理的单 SQLite 连接提供同步 pre-update／commit／rollback 失效通知，不能依靠固定 TTL 代替失效。缓存期限不得超过实际 session.expires。测试数据库、临时文件、profile 与证据仅放 `.local/cs16/`。
