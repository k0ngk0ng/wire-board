# 原版操作与战斗表现修复

本轮修复对应玩家反馈，不另设计 CS 的购买菜单与状态图标。原始样本身份、原模型／精灵静态解析、参考重实现和本项目的实际测试分别记录。亮度按玩家后续反馈保留现状。

## 对照与改动

| 问题 | 修复与原版依据 |
| --- | --- |
| 电脑过快、过准 | 普通电脑增加 300 ms 反应、限速转向及连续变化的确定性瞄准偏差；从原 MDL 胸部命中盒取瞄准中心。难度参数属于本项目的独立电脑策略，不冒充原版运行轨迹。原枪伤、头／腹／腿倍率与 AK 原始整数散布计算保留。 |
| 命中部位不清楚 | 伤害事件保留伤害值，另携带实际命中组；本人的受击反馈区分头、身体与腿，击杀栏用原 `d_headshot` 图标标示爆头。 |
| 开枪与开镜没有正确表现 | 使用原武器动画名称，补齐 Glock 与双持的射击变体及即时枪身后坐。原版 4:3 水平 FOV 换算为 Three.js 垂直 FOV，两档狙击倍率与 AUG／SG552 的单档倍率分别处理。 |
| 购买菜单与快捷键 | 原二进制的菜单分派、武器 ID、实际购买调用和参考表一致；保留队伍编号，例如 CT 的 B31 是 TMP、B43 是 M4A1。使用原编号文本菜单，购买成功播放对应确认音，关闭菜单即申请恢复原先的鼠标锁。 |
| 刀动画与声音 | 原 `slash1/2` 只有两帧，改用真正的 `midslash1/2`；右键区分 `stab_miss` 与命中。空挥、击墙、入肉各有事件与原声音，不以右键本身判断命中。 |
| 脚步、落地与手电 | 实际移动生成脚步，静步保持安静；落地生成单次冲击，继续使用原高坠伤害阈值与跳跃恢复规则。F 切换手电，电量与规则由服务器处理，局部照明不改变整图曝光。 |
| 地上装备无法拾取 | 普通掉落也接入接触拾取；空闲槽、同枪弹药池、手雷数量、C4 队伍限制与 CT 拆弹器分别处理。活人丢枪前抛，死亡掉落继承速度；原 `w_thighpack` 作为拆弹器模型复用。 |
| C4 状态与安装反馈 | 左侧状态区使用原 `c4`／`buyzone` 精灵，购买区与购买时限分别判断；进入爆破区闪烁。安装／拆弹进度来自权威帧，安装按键声按原 MDL 事件帧播放，埋设后滴声在本地按权威倒计时去重。 |
| 电脑不拆弹 | 增加 1000 原始单位内听声发现、持续记忆与到点后继续搜索；途中交火继续赴点。保留靠近后按使用操作完成有包 5 秒、无包 10 秒拆除。 |
| 阵亡后消失 | 尸体按自身视线独立投影，不复用活人可见性过滤。按原命中部位与蹲姿播放死亡动画，保留原类型的死亡抛速、地图碰撞和短暂死亡视角，下回合清理。胸腹中弹不强制飞出；爆头、蹲姿与爆炸使用各自分支。 |
| 房间与触屏界面 | 公共准备卡片压缩为固定 64 px，CS 队伍区为每队五人保留紧凑空间。添加电脑按钮满员后保留位置并禁用。普通页面聊天同样避让触控，手机手电与丢弃收进更多菜单。 |

购买编号的地址、调用与枚举证据见[原始购买菜单核对](original-buy-menu.md)。HUD 使用固定归档的 `hud.txt`、`weapon_*.txt` 和原 SPR；默认 640 档完整包含全部枪械，原包中 18 个越界的 320 档选择图定义明确记录，不补绘替代图。

## 确定性与传输边界

规则仍使用 256 倍位置定点与 65536 角度单位。新增的手电按键只在按下时出现于操作 JSON；死亡、命中组、电量和跳跃恢复只投影所需状态。机器人目标、听声记忆、掉落物内部速度及拾取冷却不进入公开投影。没有目标的空间事件不能把默认的目标值 0 当作第一个席位，从而泄露远处敌人的位置。

C4 连续滴声与安装按键声由权威帧推导，不为每一声增加网络事件；刷新、重复投影与恢复不补播历史声音。尸体的重力、碰撞插值与枪身后坐属于呈现，不回传或改变伤害。

完整对局曾发现电脑旋转移动向量超限：合法的 `(1000, -1000)` 旋转后出现分量 1414。修复在电脑策略内以整数等比归一化，保留输入校验上限；失败输入与真实原图重跑记录保存在验收产物中。

## 复跑入口

先创建 `.local/cs16/tmp`、`go-cache`、`go-mod` 和 `verification`，使用 Go 1.26.0。原始素材转换为显式本地研究步骤，普通 CI 从已核验缓存恢复公开产物，不自动下载原样本。

- 规则、服务器与真实传输：`go test -json -count=1 -timeout=20m ./games/cs16/engine ./games/cs16/server ./games/cs16/tests`。
- 客户端与协议：`node --test games/cs16/tests/*.test.mjs`。运行时构建和使用同一缓存的运动一致性检查顺序执行。
- 六图正式页面：`python3 -B games/cs16/tests/accept_browser.py`；额外设置 `CS16_BROWSER_WAITING_AUDIT=1`、`CS16_BROWSER_CLASSIC_AUDIT=1` 可验证连续加电脑和原生键鼠购买操作。
- 原资源 WebGL 定向：`games/cs16/tests/classic-render-browser.mjs`；场景与边界见同目录 `classic-render-failures.md`。
- 公共控制器与实际尺寸聊天按钮：`node web/tests/controller-overlay-browser.mjs`，覆盖四个实际消费者的普通页面和公共全屏，仅验证界面与原生触点，不重复无关游戏规则。

规则与原生静态证据位于 `.local/cs16/verification/classic-engine/`，实际 GPU 图像位于 `classic-render/`，整合检查位于 `classic-ui/`，正式六图报告位于 `.local/cs16/browser/reports/`。桌面／Duo／Pad 验证使用 macOS Chromium 仿真；实体 iPhone、iPad 与 Safari 不在已实测范围内。Linux 的规则与构建以同一提交的 CI 产物为准。
