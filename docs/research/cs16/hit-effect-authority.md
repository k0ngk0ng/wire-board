# 命中特效的权威判定

本次对照固定归档中的 Linux `cs.so` 与 Windows `mp.dll`，不是原版进程运行观测，也不代表所有历史构建。Linux 样本 SHA-256 为 `608904a0357af349466c7b34e69f224268090e3b553b5d46bf13b180001c9d8c`，Windows 样本为 `132b956c745c9637eaaab9c618b056741341ef2b90c7d4d25764e9a280a372ba`。

Linux `TraceAttack` 位于 `0x100500`，Windows 对应函数为 `0x1009be00`，后者另由玩家工厂、虚表和等价分支确认。两者按命中前护甲类型决定血效，不读取剩余护甲值：

| 命中部位 | 命中前护甲类型 | 效果 |
| --- | --- | --- |
| generic 0 | 任意 | 血 |
| 头部 | 带头盔 | 头盔火花 |
| 头部 | 无头盔 | 血 |
| 胸、腹、双臂 | 有护甲 | 无血效 |
| 胸、腹、双臂 | 无护甲 | 血 |
| 双腿 | 任意 | 血 |

`TraceAttack` 先进入伤害聚合，随后 `TakeDamage` 扣甲并在耗尽时清除护甲类型。因此，耗尽护甲的当前一枪仍按原有类型显示，下一枪才出血。枪与刀均经过该路径；标准 HE 的 100 基础伤害直接进入 `TakeDamage`，不能套用枪弹头盔火花。

实现复用权威 `hit` 事件，增加可省略的整数 `fx`：1 表示血，2 表示头盔火花，0 不序列化。非零值仅增加 7 字节，不发送敌人的护甲、头盔或库存。事件投影不再把隐藏受击者的精确位置交给攻击者；伤害与部位反馈仍保留，隐藏目标的坐标和 `fx` 省略。

当前角色以护甲值、护甲余数和头盔标志表达正常护甲生命周期。单独构造的「护甲值为零但仍持有背心类型」异常状态没有独立类型字段，不能据此声称覆盖原引擎所有异常状态。友伤关闭时平台不发送伤害命中事件，因此也不补发原样本可能产生的无伤害友方头盔火花。

原样本逐字节检查、函数范围、重定位与 20 组校验保存在 `.local/cs16/verification/classic-engine/sources/impact-fx/`。规则与投影的 RED／GREEN、竞态记录保存在 `.local/cs16/verification/hit-effects-*.jsonl`。血点位置、聚合霰弹和呈现时序的剩余近似见 [客户端反馈对照](combat-feedback.md)。
