# 高频输入存档路径失败场景

Linux CI 已复现十连接 100 Hz 压测失败：1000 条输入耗时 1730 ms，578 条／秒，ACK P95 为 149563 µs。原验收门槛保持每秒至少 800 条、ACK P95 不高于 100000 µs。

优化前列出的失败场景：

- 普通排队输入错误改写其他玩家、历史、门、目标、经济、事件或随机状态。
- 修改原 Match 的字节或共享切片，影响独立投影、恢复或并行候选。
- 旧 JSON 的空白、字段顺序、未知扩展、转义字段名或字符串内括号破坏字段定位。
- 重复键、错误类型、畸形 JSON 或缺失必需字段绕过原有规则校验。
- 队列超过上限，错误生命、序号、地图摘要、瞄准帧或过期操作被接受。
- 非法武器或死亡后的攻击绕过同源 QueueInput。
- 取消输入与购买错误进入普通排队优化，改变释放、蓄力或经济结算。
- 接收／应用序号、真实接收时间、截止时间、控制权限或电脑标记改变。
- 普通输入之后的完整规则推进与原存档路径出现差异。
- 只在开发机通过，Linux CI 原容量门槛仍失败。

新增隔离检查先于优化实现；既有真实 HTTP／WebSocket／SQLite 容量失败作为端到端红证据。优化仅涉及 CS16 服务端，不改规则、预测或传输预算。
