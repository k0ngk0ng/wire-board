# 连续射击与装备快捷入口

## 故障与修复

| 现象 | 原因 | 修复 |
| --- | --- | --- |
| 按住自动武器只偶尔有枪身动作 | 本地呈现受 `nextAttack > frame` 持续阻挡，而渲染器又直接忽略本人权威 `shot` | 扣下扳机先本地呈现首发；随后每个真实权威射击逐发呈现。半自动、三连发、开镜后的射速、刀击间隔和装填／消音器切换均沿用实际规则事件，不在显示层复制另一套武器规则。 |
| 连发枪声不像连续射击 | 本人枪声用 180 ms 时间窗去重，70～100 ms 间隔的独立射击被丢弃 | 用有界预测队列逐发匹配。每条确认只消费一条同种动作、武器和生命代次的预测；没有对应预测的权威射击正常发声与呈现。 |
| 首发确认产生双响或双后坐 | 预测与确认没有逐发身份 | 预测使用独立本地序号，音频标识包含对局和生命代次。匹配确认不再次呈现；500 ms 仅是待确认记录的保留上限，不是抑制相邻射击的时间窗。 |
| 刀空挥重复发声 | 原规则同时发送攻击开始与空挥／命中结果 | 本地只预测刀的动作，空挥、击墙和入肉声音采用实际结果事件，避免预测空挥再重复播放权威空挥。 |
| O 无效 | 控制器定义与 Board 只有 B 入口 | 新增可改键的 O 装备入口，直接进入与 B8 相同的数据源；菜单关闭保持原鼠标锁，触屏不请求鼠标锁。 |
| 歼灭目标一直占据画面中央 | 无交战倒计时的地图用目标文案替代时钟 | live 阶段隐藏整个时钟区；冻结、回合结束、爆破、人质与 C4 继续显示权威倒计时。 |

预测记录在本地关联具体输入序号和生命代次。操作被服务器拒绝时只移除对应记录，迟到的旧生命拒绝或射击不会消耗新生命的预测，也不会让后续真实射击静音；这些标识复用已有输入信息，不增加射击网络字段。

枪身使用现有原模型射击动画及每发瞬时位移；视角使用权威 `recoilPitch/recoilYaw`，不把显示层后坐写回瞄准或伤害规则。平台原生空间音频仍使用武器通道；新的射击替换同一武器通道尾音，但每发均有独立播放身份，不增加游戏专有播放器。

## 装备编号与夜视仪

O 与 B8 共用 `classicBuyEntries`。前五项是防弹衣、防弹衣与头盔、闪光弹、高爆手雷和烟雾弹。已核对的原样本采用 6 夜视仪、7 反恐精英拆弹器；7 仅在 CT 爆破地图出现，不将另一份记忆表当作当前样本证据。原始购买与切换的字节依据由本次 NVG 引擎审计记录；此前菜单原样本身份见 [原版购买菜单对照](original-buy-menu.md)。

夜视仪使用自席位私有所有权与开关状态，N 只提交开关操作；手机开关位于已有「更多」内，不增加右侧常驻按钮。购买与开关复用已存在、已发布的 `items/equip_nvg.wav`、`items/nvg_on.wav` 和 `items/nvg_off.wav`，未新增或重新编码音频。

绿色整帧滤色与相机附近照明属于浏览器中的独立呈现：使用局部 750 HL 单位的照明包络，并保留原贴图细节。现有服务端二进制证据不能证明原 `client.dll` 的像素着色参数或动态光半径，因此不宣称这一渲染算法与原客户端逐像素一致。关闭夜视仪后完全恢复此前画面，不改全局亮度、原光照贴图、人物可见性或伤害判断。

## 验收

- 失败清单位于 `games/cs16/tests/classic-ui-scenarios.md`。
- 逐发匹配、边界、菜单、音效资源、时钟及输入检查：`.local/cs16/verification/continuous-fire/`，保留 RED／GREEN 与 TypeScript、lint 结果。
- 实际 WebGL：`.local/cs16/verification/classic-render/continuous-fire-nvg.json`。覆盖夜视开／关、未持有、恢复原像素、本人未预测权威射击，以及既有开镜、刀和尸体场景；截图位于同名目录。
- 原生持射和购买场景接入 `games/cs16/tests/classic-ui-audit.mjs`，通过 `CS16_BROWSER_CLASSIC_AUDIT=1` 在血战回廊的手动样本验证 O1～O6、N 与触屏「更多」、持续自动射击、每发音频启动、枪身脉冲和实际视角后坐。半自动手枪按住仅一发。
- 测试钱包仅由浏览器测试模块首次开局设置：两张小图、30 回合、前两个非托管存活真人为 16000。正式模块和自然比赛保持正常经济，后续帧与后续回合不补钱；边界与原状态不被修改的证明见 `browser_wallet_test.go`。

浏览器验证为 macOS Chromium 与触屏仿真，不能代替实体 iPhone／iPad 测试。完整六图和正式延迟验收由主代理在统一构建后执行。
