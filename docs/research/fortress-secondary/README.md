# 疯狂坦克二号弹审计与修复

此前不是完全没有二号弹：已有单独伤害数值和少量通用火、毒、雷效果。但全部车型只发一枚，主副弹共用 `bulletXX.i16` 第 0 帧，未实现原生多弹、锁定、地雷和同队治疗，部分 `portal.skills` 还被错误地当成了完整武器定义。

## 可核验来源

原始官方网页客户端 WASM：`.local/fortressblue-original/game/tankclient_emsc.eeb2b.wasm`，SHA-256 `35974c0d7a06cf86f1f028b0ee1fc46c324921f6d829ce4db684f776199e489d`。REA / WABT 1.0.42 的 55 函数静态切片 Evidence ID：`ev_aa61593bdab830e5487eb117817a4526e22dd84743146acd31ae1df7406931c0`。它保留原始函数体、类型、导入和数据，其余代码用不可执行桩替代；没有执行原客户端或恢复原服务器。

`games/fortressblue/assets/evidence/secondary-native-evidence.json` 保存原始文件偏移、函数 SHA-256、车型分派和虚表。完整 REA 记录及可重复切片脚本位于 `.local/fortress-secondary/research/`；聚焦状态、追踪和地雷原文位于 `.local/fortress-secondary/details/`。

- `f3303` 按车型、主副武器分别创建原生弹体类，循环直接证明多弹数量；不能把 A1Round／A2Round 猜成弹数。
- `f421` 把 A1Round／A2Round 写入弹体 `+108`，由命中及地形函数作为半径输入使用。这是 v5 新确认的含义；v3 记录中的 `roundMeaning: unverified` 保留当时的证据状态，不改写已发布来源。
- `f1890` 使用独立武器图组、方向和动画相位。原图全部主副对照见 `.local/fortress-secondary/research/primary-secondary-contact.png`。
- `f1774` 配合 `f2992`／`f3154` 在下降时锁定一次最近现存角色点，不排除友军、射手或死亡状态，也不是持续追踪。
- `f983`／`f1721`／`f2973`／`f2983` 证明地雷落地存在、同队可见、敌我均可触发、原生车型 8／11 不触发，以及没有已观察到的固定寿命。
- `f3382` 的状态 12 经 `f1548` 证实持续生命损失；`f2927` 的状态 1 经横移消费者与初始化代码证实抑制移动力补充，服务端清除周期未知。
- `f2795` 的 HP 存储为负数表示，减去正值是同队回血；此前当成普通伤害是错误的。

地雷免疫编号已单独核对：`f1580` 将参数 p1 原样写入角色 `+512`；`f3303` 读取后减 1 再进入 14 分支，运行时 8／11 分别对应 ELser／EPose，和平台 `TankID`、`char08/11`、`bullet08/11` 一致。`f1721` 的 `load +512; const 8; sub; br_table` 跳过索引 0 和 3，确实排除原值 8 和 11。TSV 第一列 0 起始的资料序号不能再套到运行时 ID 上。

每枚弹道单独保存出膛、命中及已结算标记，爆炸保存独立时间戳。第一枚命中不能扣除后续弹体的伤害；刷新、恢复和计时重入不能重复结算。全部弹体完成后才进入最终落地结算并交出回合。旧单弹存档保留原伤害、半径、出膛、命中和操作期限。

地雷在服务端保存，View 只向同队提供未揭示雷；观众及对方不收到该列表或 `mine_plant` 坐标事件，结束后可复盘。公开可见的发射和落点仍保留。电脑不读取敌方隐藏雷进行规避。接触路径覆盖穿越与落地；移动接触在 180 ms 后结算以对齐画面，驶离不取消已确认接触。地形损毁触发相邻地雷的同时间轴连锁。友军被状态或地雷伤害时不奖励敌对伤害／击杀分。

## 平台参数与仍未恢复的部分

原服务器、完整物理和状态同步协议不在本次原文件中。本批没有宣称逐项复现所有公式：

- 重力、风和防御伤害模型沿用平台；多弹计数来自原代码，散布速度幅度和波动的 30 ms 步长属于平台参数。
- 锁定窗口采用 150 像素，按已确认的一次锁定改向方式处理；保留平台角色中心坐标及现存角色记录。原始配置半径数值和死亡对象退出注册表的时点仍未知。
- 地雷采用 28 像素触发范围、现有伤害模型，最多 32 枚；原版全部保护、联网同步、可见天气及百分比伤害细节尚未完整复原。
- 中毒使用平台每次 25、3 个自身状态周期；移动力限制阻止 3 次补充。这不是把原始参数 1／3 直接解释为原版秒数或回合数。
- 离子炮采用定位命中后等待 350 ms、光束飞行 200 ms；同队治疗限制不超过平台最大生命值。原版离子炮完整扫描公式和外部回血上限尚未证实。
- 当前平台按发射时的局面规划整组弹道；逐弹命中即时改变生命、地形，重力落地在整组结束后统一结算。没有声称已经恢复原版全部连续碰撞重算与落地物理。
- 图像帧和锚点精确；90／100／70／60 ms 等前端呈现间隔为平台值，详见 v5 资源说明。

## 验收

失败场景先写入 `server/secondary_test.go` 和 `tests/projectiles.test.mjs`。验证覆盖 14 车型、九发上限、逐弹命中／恢复去重、同队治疗、一次锁定、地雷隐私与快穿、落地与连锁、移动限制、治疗电脑以及友军伤害统计。旧毒雾夹具改为原生毒雾车型 5，车型 2 改验中毒状态，没有把旧错误映射继续当规则。

```sh
. scripts/env.sh
go test -race -count=1 ./games/fortressblue/server ./games/fortressblue/tests
node --experimental-strip-types --test games/fortressblue/tests/*.test.mjs
python3 -B scripts/fortressblue/verify-assets.py --dist
python3 -B scripts/fortressblue/check-refactor.py --only projectiles --out .local/fortress-secondary/browser-repeat
```

`.local/fortress-secondary/rule-results.json` 记录规则、34 组完整比赛和三档 12 种人数组合，原始 `-race` 为 `race-final.jsonl`；后续友军计分保护的最新规则 `-race` 记录为 `server-final-race.txt`，完整模块记录为 `modules-final-current.jsonl`。精确 RGBA 核验为 `source-pixels.json`。真实 UI／HTTP 的 28 组合浏览器报告为 `browser-projectiles/report.json`，另有 6／9／10 号追踪、地雷、延迟光束聚焦验收，由总验收文档汇总最终路径。
