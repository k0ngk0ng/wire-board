# 游戏按需加载与开局就绪

所有游戏使用统一加载页。点击开始后，客户端下载当前游戏代码、样式和必要素材，初始化画面，再确认加载完成。加载页使用淡化封面背景，显示实际下载进度、初始化阶段和各席位状态。全部真人确认后，服务端才推进游戏；电脑自动就绪，观战者不阻塞。

首页只导入游戏目录元数据和封面。`catalog.tsx` 是名称、分类、人数及能力字段的唯一来源，`module.tsx` 在选择或进入对应游戏时按需导入。加载页依据构建清单分阶段计算进度：程序下载占 35%，素材下载占 55%，初始化占 10%；每阶段以实际字节或运行时完成事件推进，不按计时器增加进度。100% 表示本机完成，其他真人未完成时继续显示等待。

## 服务端边界

开始命令先生成初始局面，以确定随机地图等素材范围，同时建立持久化加载阶段。游戏行动、电脑行动、系统计时和超时托管在此阶段停止。模块游戏使用扣除加载等待时间的游戏时钟，普通回合期限恢复剩余时间；不逐项修改游戏私有时间戳。生产入口启用 `Config.ClientLoading`，已有嵌入式服务可保留旧协议。

加载确认绑定对局、前端构建摘要和当前客户端会话。刷新及重试先撤销本人旧确认；错版本、旧会话和观战者不能确认。最后一人的确认与放行在同一 SQLite 事务中提交，保存失败不放行。重复完成确认不重置期限。服务重启保留等待，新部署重新绑定构建与确认；已进行的旧局和重连不会重新暂停全员。

实时快照同步加载状态与时钟偏移，避免高频帧先到达时保留过期等待状态。加载期间出错可重试；玩家长期离线时仍须由房主结束牌桌，不用自动托管绕过全员确认。

## 资源与缓存

- 泡泡堂按实际地图加载经典地形，同时准备可选人物与坐骑；疯狂坦克只加载当前地图及可选坦克，不下载全部旧地图。
- 扑克牌只加载当前牌面皮肤。赛车须完成实际首帧；热血篮球沿用 OSS 运行时及当前球场的真实进度，媒体不进入应用构建。
- 构建清单绑定最终 `index.html` 的 SHA-256，客户端同时校验当前入口脚本。版本不一致时提示刷新。
- 带内容摘要的 JS/CSS 提供 gzip、独立 ETag、`Vary: Accept-Encoding` 和一年 immutable 缓存。首页与加载清单使用 `no-cache`。

## 复跑验收

前置条件：Go、Node.js、Python 3、已安装的前端依赖，以及可用的 agent-browser。全部缓存、临时服务数据和浏览器 profile 保持在仓库内。

```sh
. scripts/env.sh
go test ./internal/server -run '^(TestClientLoading|TestStaticDeliveryHTTP)' -race -count=1
sh scripts/game-loading/run.sh
```

浏览器验收覆盖全部游戏的开始加载，以及双真人泡泡堂的资源失败、等待、重试、320px 布局和已开局重连。HTTP 验收覆盖模块与旧版回合时钟、实际观战者、旧页面确认、数据库失败、部署恢复和重复确认。`check-build.mjs` 检查目录完整性、构建摘要、资源字节数及首页无棋盘模块；所有游戏前端／素材检查和共享平台竞态验收另由 CI 执行，不运行未变更游戏的服务端规则矩阵。

本地结果与截图保存在 `.local/game-loading/`，包括每次独立的 `load*`、`peer*` 目录及 `home/browser.json`。脚本退出后清理本次浏览器 profile 和 socket；总入口另清理测试服务数据与二进制。
