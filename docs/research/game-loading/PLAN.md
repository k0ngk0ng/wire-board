# 游戏按需加载与开局就绪：实现前边界

目标：大厅不加载全部棋盘实现和地图／动画大表；进入对局后使用淡化封面背景的统一加载页，显示实际下载／初始化进度；所有真人加载就绪后才推进游戏和操作时限，电脑默认就绪、观众不阻塞。

## 失败场景（先于实现）

- 首页静态依赖仍含任意 Board、地图掩码或大型动画表；CSS/JS没有压缩，带hash的静态资源反复完整下载。
- 分类、名称、人数、封面或创建选项因懒加载丢失；选择未加载游戏报undefined；同一游戏草稿因加载完成重置。
- 动态代码／样式／图片失败后一直假进度或误报100%；取消、换房、旧承诺回调误确认另一局；更新部署后混用旧代码与新清单。
- 只加载JS就发ready，Canvas／WebGL／原生运行时或必要图片尚不可用；背景封面先于大量游戏资源可见；320px和桌面进度、重试和玩家状态可读。
- 第一个真人就绪就放行；机器人或观众阻塞；外人、错席位、旧token、错误build、重复/并发确认绕过校验。
- 加载期间物理、电脑、回合／选角期限继续推进；加载慢变成超时托管；恢复存档按真实经过时间误跑加载阶段。
- 使用统一游戏时钟抵消加载等待时间，不改写游戏内的私有状态时间戳；旧局不补加载关卡，进入已经进行的局只加载本机，不暂停其他玩家。
- 刷新/重试使先前确认失效而旧确认又抢先生效；已完成的确认重试重置时钟；退出、结束和最后一个真人离开后遗留永不完成的门槛。
- 热血篮球现有原生资源/玩家就绪与战役轮次加载仍然有效；游戏规则、隐私、托管、地图准备不因平台加载改变。

验收采用共享HTTP/SQLite并发、时钟和恢复场景；25款游戏前端／开局加载E2E（覆盖电脑+真人、真人等待、直接对局链接与窄屏），不运行未改变规则的其他游戏完整规则矩阵。保留冷启动网络、下载字节、首屏时刻、每步状态和截图。加载进度按资源字节或实际阶段完成计算，不使用定时器假进度。
