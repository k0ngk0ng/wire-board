# 独立 PCM 播放器的先行失败场景

本清单先于本组原生私有输入采样器、时序模型、Go 播放器与测试。已有 `audio/pcm`、`audio/dsp`、世界调度和原始四流证据保持只读。

- 固定采样周期代替原缓冲状态分支，遗漏单槽 128 字节预装、每字节的两字节预取或双槽交替的四字节预取。
- 仅按有效 payload 长度发出 bank 读，遗漏原头部读、尾部超前读或不进入解码器的读，导致并行 68k 时钟改变。
- 把缓冲游标、源读游标、剩余源字节、解码累加器、当前高／低输出、待启动描述和槽生命周期误合并；或把同一字段保存为原 RAM 与 typed 两份 owner。
- 双槽无活动槽的中性值不为 128、非线性限幅时点错误、最后一个高／低输出与停止／禁用 DAC 顺序错误。
- 单模式音速、零音速、长度不足一轮、末尾不足四字节、8-bit 游标回绕、16-bit 剩余数下溢分支处理错误。
- 替换音效、另一槽启动、忙标记和 descriptor 事务可见性错误；把音乐 6 字节描述协议与普通音效的第 7 字节模式混用。
- 原 native 时间表或 PC 被作为生产输入，或将原固件、Z80 指令解释器、任意寄存器／RAM VM 带入 Go。
- 给定原 DAC 时刻的数值通过被误称自主节拍通过；无外部 stall 的私有原生验证被误称全世界／68k／DMA／IRQ 调度通过。
- 隐藏给定的原始初态、外部命令时刻或外部总线暂停输入；凭波形拟合循环常数。
- 参考核经验 bank 等待被宣称真实硬件时序；观察器改变 original handler 参数、返回值、RAM、播放器状态或 PCM 而未检出。
- 分批推进、半阶段 snapshot 恢复、非法资源、非法时刻、溢出或有界事件队列在失败时部分提交。

首先保留「缺少独立播放器」的真实失败，再以声明的合法私有播放器初态、无 68k／VDP stall 的原固件连续执行建立原生 oracle。状态机使用语义阶段和静态求和的执行成本，不执行指令。所有未覆盖的环境依赖和协议保留为明确缺口。

单槽候选 API 复核：当前私有单槽 profile 的 dummy 读取从 bank 窗口起点开始。不能把超过已验证原生单槽完整 payload（7,788 字节）的输入静默纳入同一有限合同，因为更长的 dummy 游标可能跨出 bank 窗口，原程序会触及另一地址域。先增加负向测试取得实际 red，再将本初始化 profile 的单槽长度明确限制为 129～7,788 字节。双槽合同为 69～32,768 字节；69 是原预取超过 64 字节后启用解码的首个有限长度。

链路验收还须显式启用私有初态的 DAC 并设置声像。跳到已初始化播放器入口只恢复了固件状态，静音检查点中的芯片仍可能 disabled；这种输入下播放器事件可以正确，但 PCM 全静音不能证明播放器与 DSP 链路正确。新增独立 audible 原生组，不覆盖此前记录；以同一真实 chip／resampler 初态和原生非零 PCM 检查自主事件到独立 DAC DSP 的连续输出。
