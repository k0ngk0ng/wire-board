# 动作主分派、共享尾段与构造器边界

日期：2026-10-26。目标 ROM 与首轮静态记录相同，SHA-256 为 `c39d52b2e2298b3784ada3de70d64b26b67e172114c7d18494faad70fc4d7c06`。本轮继续使用直接 Ghidra 有限范围分析，没有把全 ROM 自动反汇编，也没有宣称已完成连续角色更新。

## 顺序与边界

`0x15a18` 在动作分派前先执行角色专属准备 `0x15c10`、共用输入准备 `0x15c36`。当 `+0x69.b` 命中停顿计数非零时，使用 `0x15b84` 分支并跳到 `0x15b40`，绕过普通动作和输入尾段。正常路径更新相关计时后，先执行衰减位移 `0x19cc4`，再执行动画时钟 `0x19c96`，然后按 `+0x5d.b` 分派。

[动作表](action-dispatch-table.txt) 位于 `0x15a68..0x15afa`，共有 74 个相对 word 槽。表槽数量不等于已还原动作数量，也不证明运行时全部索引都可达。已经确认的前四槽为地面等待 `0x19cee`、行走 `0x19da2`、空中积分 `0x19dc6` 和攻击完成等待 `0x19f90`。

这些路径跳到共享尾段 `0x15afc`。尾段不是无副作用的 return，其调用顺序严格为：

1. `0x15bb2` 检查全局战斗状态、地面和生命，可能尾跳 `0x1877e`。
2. 依当时 `+0x6c.b` 的 bit0／3／4／1／2，分别调用 `0x15cb0`、`0x15efe`、`0x15f24`、`0x15de6`、`0x15e28`。前面的调用可能改变后面所检查的标志。
3. 清 `+0x89.b`，根据动画编号设置 `+0x63.b`。
4. `0x1eb40` 提交当前动画记录、精灵参数和判定数据。
5. `0x15bfe` 消耗原 RNG，用参数 `+0xc4.w` 更新 `+0x65.b`，随后在 `0x15b82` 返回。

完整静态指令见 [actions-shared-tail.txt](actions-shared-tail.txt) 与 [actions-tail-dependencies.txt](actions-tail-dependencies.txt)。因此以 `0x15afc` 为退出边界的行走／空中夹具只覆盖进入共享尾段之前的阶段，不能命名为完整人物更新。

## 小而完整的函数

| 入口 → 最后 RTS 地址 | 写入与输入 | 限制 |
| --- | --- | --- |
| `0x19c1c → 0x19c44` | `59=0, 5a=8, 5b=ff, 60=0, 64=0, 6d=0, 77=0, 6e=6f`，均 byte | 通用动作重置；不清理速度、请求和所有历史 |
| `0x19c96 → 0x19cc2` | `5b++` byte 回绕；若 `5a <= 5b`（unsigned），清 5b 并递增 59；当 5c.bit7 为 1 时再清 59、令 60=1 | 未推进时保留旧 60；需要先消费旧记录时长，再由 `1eb40` 装入新记录 |
| `0x19cc4 → 0x19cec` | 若 `98.l > 0`，先 `98 -= 0x4800`，再按 `61.b == 1` 加到 `40.l`，否则从位置减去 | 最后一次衰减允许过零且仍应用负余量；不能 clamp |

时钟和衰减段的完整指令在 [actions-ground-constructors.txt](actions-ground-constructors.txt)。适合先用真实调用夹具恢复为独立语义，再由连续更新按原顺序组合。

## 地面、起跳与落地构造器

下表列出的构造器多数尾跳 `0x19c1c`，其效果必须包含上面的通用重置，返回点不是构造器地址范围的末尾。

| 入口 | 重置前的主要写入 | 依赖及特殊点 |
| --- | --- | --- |
| `0x18440` | `5d=0, 5f=0, 6c=0b` | 站立 |
| `0x18454` | `5d=0, 5f=1, 6c=0b` | 蹲起过渡；后续状态解释仍需画面对照 |
| `0x1846a` | `5d=0, 5f=2, 6c=0b` | 蹲下 |
| `0x18480` | `5d=0, 6c=0b`；按输入 bit1 选择 `5f=9/0a` | 站立／蹲下防御 |
| `0x184ac / 0x184f0` | `61 = 1 - old61` 的 byte 运算，`5f=3/4`，`5d=0, 6c=0b`；清 `a8..b7` 和 `6b` | 转身清理了命令历史，不能仅翻转渲染方向 |
| `0x18534` | `5d=1, 5f=5, 6c=0b` | 行走；运动阶段从 `obj90` 指向的参数表取速度 |
| `0x1854a` | `5d=0, 5f=0d, 6c=0b`；把入口 D0.b 暂存到 `obj14.b` | 起跳预备；该字节随后被起跳构造器消费，不可提前按速度解释 |
| `0x18564` | 先 `1fce8`，再 `5d=0, 5f=0e, 6c=0b` | 落地会分配特效对象，不能省略全局对象池副作用 |
| `0x18580` | 先 `1fce8`、通用重置；读 `obj14.b` 暂存方向，再装入表中初速／重力；`5d=2, 5f=6, 6c=14` | 根据保存的方向 9／5／1 设置横速、朝向相关动画或垂直起跳；方向不匹配时不擅自清旧横速 |

落地特效函数 `0x1fce8` 两次调用分配器 `0x1fa96`，尝试建立 `0x149ac` 更新的两个 0x80-byte 对象，复制位置／层级，横向偏移分别为 -4／+4，速度分别为 -1／+1。分配器每次推进 `0xffa036`，扫描池 `0xff9400..0xff9bff`，最多尝试 15 个槽，满池时返回 A0=0；两次分配独立，可能只有一侧成功。完整副作用在 [actions-tail-dependencies.txt](actions-tail-dependencies.txt) 和 [actions-ground-constructors.txt](actions-ground-constructors.txt)。

酎的样本参数指针 `obj90 = ROM 0x1262c`。已确认消费项为：`+0` 行走速度 `0x18000`（1.5），`+4` 起跳纵速 `-0x58000`（-5.5），`+8` 加速度 `0x3600`，`+c` 起跳横速 `0x1c000`（1.75），`+18` 为另一构造器使用的 `0xc000`。见 [action-chu-parameters.txt](action-chu-parameters.txt)；没有把整段相邻字节假设成同一种参数结构。
