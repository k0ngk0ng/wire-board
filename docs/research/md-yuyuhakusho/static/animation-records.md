# 动画记录、形状缓冲及声音提交边界

日期：2026-10-28。目标仍为固定日版 ROM `c39d52b2e2298b3784ada3de70d64b26b67e172114c7d18494faad70fc4d7c06`。主体指令见既有 [fighter-motion-ai.txt](fighter-motion-ai.txt)，声音尾跳见 [animation-records-tail.txt](animation-records-tail.txt)。本轮使用直接 Ghidra 有限范围分析；REA 6.5.0 未提供 68000 裸二进制入口，不能称为 REA 已恢复完整游戏。

## 数据选择与对象写入

原函数 `0x1eb40` 使用对象 `+0x50.l` 的动画集合、`+0x5f.b` 姿态和 `+0x59.b` 帧索引选择记录：先读取集合起点加 `pose*2` 的 signed word 偏移，将偏移加到**集合起点**，再加 `index*8`。它不是相对表项地址。所选记录为 8 bytes：时长、形状目录索引、标志、动作阶段标志、声音索引、当前未使用的 byte、X 偏置编码、Y 偏置编码。

形状集合来自 `+0x8c.l`，目录项为 4 bytes：组标志、图形参数、相对集合起点的 signed word 数据偏移。图形参数乘 2 写入对象 `+0x3c.w`。本轮自然记录只得到 1 组动画／形状集合的 101 个不可变帧，不能据此称为全部角色或全部动画。

| 对象字段 | 更新语义 |
| --- | --- |
| `+5a`、`+5c` | 当前动画记录的时长和原标志；不推进时钟 |
| `+6c` | 动画记录阶段标志 OR 当前 `+6d` |
| `+94.l` | 仅 `+5b==0` 且记录标志 bit4 置位时设为 `0xffffffff`；具体用途未扩展命名 |
| `+28.w`、`+2a.w` | X 编码减 128，Y 编码减 160；面对方向 byte 非零时先对 X 偏置取负 |
| `+24` 高 byte | 清 bit3/4，再用 `(recordFlags XOR facing) & 3` 更新翻转位；低 byte 保留 |
| `+65` | 每次先清零；只有第一类形状存在时由该类元数据覆盖 |
| `+64/66/67/68` | 第一类形状存在时读取前缀数据；最后一个前缀 byte 拆成高／低 nibble，其他情况下保留 |

Go 中以 `AnimationFrameKey{AnimationSet, ShapeSet, Pose, Index}` 选择只读 `AnimationLibrary`，然后提交解析后的语义数据。集合 ID 仅用于数据身份，不作为可执行地址。缺帧明确返回错误，不从每帧期望值或原 ROM 临时提供结果。

## 四类 16-byte 记录

组标志 bit6/5/4/3 分别控制 `FFA200/300/400/500` 的四个 256-byte 缓冲，写入偏移计数为 `FFA004/006/008/00A`。前三类由宽度的 bit7 结束列表，并在目标记录中清除该位；第四类固定写一条，**不清该位**。类别的业务语义尚未经消费者恢复，不提前命名为攻击框或受击框。

每个记录仅写 X word（偏移 0）、Y word（偏移 4）、宽 byte（8）、高 byte（9）及所属对象 word（12）。另四个 word 原样保留。坐标使用世界位置高 word 加图形偏置，再加按翻转位处理的形状偏置，所有中间加法保留 word 回绕。

写入前若偏移 `>=255` 则改成 `240`，因此超出容量的后续条目反复覆盖最后一个槽，而最终计数为 `256`；不能改成扩容、丢弃或追加第 17 槽。Go 拒绝小于 255 的非 16-byte 对齐偏移，防止无法用语义槽表达的损坏状态；较大的原计数仍按原规则夹到最后槽。

## 声音生产者与外部消费者

当动画计时 `+5b==0`，记录声音索引经 ROM `0x218d8` 映射，非零映射写入 `FFA030`；零映射不清旧请求。函数末尾消费非零 A030，先清零再尾跳 `0x21960`。该生产者依次检查 `FFF80A..D`：首个 signed 非负槽或与请求相同的槽可写；四槽均负且不同则拒绝。真实出口为 `21970/21982/21994/219a6/219aa`，不能只观察无声音出口 `1edaa`。

自然全状态比较发现 8 次额外队列消费。只读 M68K 写入观察定位到独立的 `0x37c44` 声音优先级消费者，其中 `0x37c56` 清理槽位。其优先级表由 PC 相对指令指向 ROM `0x3a50e`；它还会写 `FFF809/FFF800`，完整消费者及其触发时基不在本组件中恢复。指令见 [animation-records-consumer.txt](animation-records-consumer.txt)。

这 8 次期间均没有 `21960` 的新提交。观察到队列按 D→A 清零，写宽度为 1、值为 0；CPU SR 从 `0x200x` 切换到 `0x270x`，栈变深，说明是在同一视频帧内进入更高优先级／临界处理，而不是跨视频帧。完整事件和原始前后快照保留在测试夹具及 `animation-records-external-consumption.json`。

验收分别声明：4,134 个自然对象／缓冲／计数／A030 一致；4,126 个自然完整队列状态一致；8 个外部消费者造成的原始队列差异被完整记录并严格核对来源，**没有将期望变化注入 Go，也没有宣称 Go 动画函数预测了外部消费**。另有 69 个隔离原 CPU 用例完整状态一致。实际声音播放和世界调度仍需后续接入平台音频通道。
