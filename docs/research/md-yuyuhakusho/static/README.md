# 原版控制流与角色字段首轮定位

日期：2026-10-26。ROM SHA-256 为 `c39d52b2e2298b3784ada3de70d64b26b67e172114c7d18494faad70fc4d7c06`。本轮由 Ghidra 12.1.4 直接按 `68000:BE:32:default` 导入，在明确入口和有限地址范围内反汇编。REA 6.5.0 当前仍不支持该 ROM 的 68000 裸二进制导入；本目录不能称为 REA 已恢复的游戏逻辑。

下文 RAM 地址使用 MD 的 24 位 CPU 地址；Ghidra 对绝对短地址显示的 `0xfffff780` 等符号扩展形式，对应 MD 的 `0xfff780`。没有把未知数据解释为业务字段。指令证据不等于动态覆盖；人物入口额外使用了父任务捕获的第 2,400 帧 CPU 顺序 RAM，以确认当时调用指针和对象位置。

## 控制器到逻辑输入

`0x2514` 先清零 `0xfff700..0xfff74f` 共 80 bytes，再分别采集两个物理端口：第一个原始区从 `0xfff700` 开始，第二个从 `0xfff728` 开始。每个原始设备槽为 8 bytes，槽首 word 表示设备分派类型。ROM `0x257e` 是硬件识别后的 16 项跳转表。普通手柄路径 `0x25d4` 将三键标记为 `4`、六键标记为 `8`，并记录三个原始低有效 nibble。

`0x2c9e` 把原始区转换为逻辑通道数组，最大通道数来自 `0xfff552.w`，过程索引为 `0xfff554.w`。每一项数组预留 8 个通道，以通道索引 `i` 加到下表地址：

| 地址 | 基础 8 键状态 | 六键扩展对应地址 |
| --- | --- | --- |
| `0xfff780+i` | 当前按住 | `0xfff7a8+i` |
| `0xfff788+i` | 上次按住 | `0xfff7b0+i` |
| `0xfff790+i` | 当前与上次的异或变化 | `0xfff7b8+i` |
| `0xfff798+i` | 新按下：当前 AND 变化 | `0xfff7c0+i` |
| `0xfff7a0+i` | 松开：上次 AND 变化 | `0xfff7c8+i` |

`0xfff7d0+i` 的 bit7 标记接入，bit6 区分六键；从六键切到三键时会清理扩展状态。基础 8 位在硬件标准映射下依次为上、下、左、右、B、C、A、Start；扩展低四位为 Z、Y、X、Mode。游戏选项 `0xffff50+i` 非零时，`0x2dac` 交换基础位 5 和 6；保留这个语义，不应把所有样本都强行按固定 A／C 映射解释。输入归一化的确切指令见 [logical-input.txt](logical-input.txt)，设备采集见 [device-decode.txt](device-decode.txt)。

这里只定位了正常三／六键路径及多设备分派结构，没有运行四人设备完整局。设备分派中未使用的类型、断开后的全部时序和异常硬件输入仍未验证。

独立实现必须保留入口寄存器的 byte／word 语义。`0x2dce` 对 D0／D1／D2 先执行 `move.b`，随后使用 `eori.w` 和 word 移位；旧寄存器高字节可能进入扩展状态的高四位。父任务捕获的第 382 帧出现原始 nibble 均为 15、扩展状态却为 `0xf0` 的真实样本，因此不能为满足「只有四个扩展键」的直觉而屏蔽高四位。当前已确认 `0x15c36` 消费扩展新按下的位 0／2，有限字节模式扫描还定位到 `0x15cb8` 使用位 1；这不足以证明所有消费者都忽略高四位。

## 人物对象与战斗阶段

动态 RAM 样本显示，当时 `0xff8400` 和 `0xff9000` 的 `+0.l` 均为 `0x12668`，`+4.w` 均为 `0x100`。这与原 AI 目标表 `ROM 0x1cd58` 中的四个人物槽 `0x8400 / 0x8800 / 0x8c00 / 0x9000` 一致。不能据此推断每个槽在所有阶段都会启用。

人物入口 `0x12668` 按 `+6.w` 分派：`0` 初始化，`2` 活跃，`4` 销毁。活跃路径 `0x12682` 顺序为：注册本帧对象列表 `0x14922`，在未暂停且 `0xfff55a == 0` 时执行 `0x15540`、`0x15a18`、`0x156f0`，再进入边界／显示列表、资源条和精灵绘制。入口证据见 [fighter-entry.txt](fighter-entry.txt)、[fighter-active.txt](fighter-active.txt)、[fighter-stages.txt](fighter-stages.txt)。

| 对象偏移 | 已确认用途／当前解释 | 证据边界 |
| --- | --- | --- |
| `+0.l`、`+4.w`、`+6.w` | 更新入口、步长、生命周期状态 | 调度和入口指令 |
| `+8.w`、`+0xc.w` | 屏幕投影坐标 | `0x156f0`；不能当世界坐标 |
| `+0x40.l`、`+0x44.l` | 世界位置，运动按 32 位相加，投影读取高 word | `0x19dc6`、`0x156f0`；与 16.16 定点形式相符 |
| `+0x10.l`、`+0x14.l`、`+0x4c.l` | 空中阶段的横向速度、纵向速度、纵向加速度 | `0x19dc6` 的运算顺序已确认 |
| `+0x9c.l` | 当前轨道地面基线 | 地面状态回写到 `+0x44`，空中落地比较使用高 word |
| `+0x54.w`、`+0x56.w` | 本次屏幕位移偏置，投影后清零 | `0x156f0`；包含受击抖动路径，不是持久速度 |
| `+0x58.b` | 角色类型索引 | 初始化、角色阶段和 AI 分派使用 |
| `+0x5d.b` | 动作大状态 | `0x15a18` 的相对跳转表 |
| `+0x5f.b`、`+0x59.b` | 动画动作表编号、表内 8-byte 记录索引 | `0x1eb40`；动画定时尚未完整恢复 |
| `+0x61.b` | 朝向／翻转相关标志；bit0 影响移动和映射 | 运动、投影前的数据提交及输入请求路径 |
| `+0x6b.b` | 待处理动作请求 | `0x15c36` 可写 `7` 或 `8`；全枚举未知 |
| `+0x6e.b` | 当前队伍标识 | AI 排除同队；初始化从 `+0x6f` 复制 |
| `+0x71/72/73.b` | 人物基础按住／新按下／变化 | `0x15540`；第三个字段是 XOR，不能当松开 |
| `+0xc0/c1/c2.b` | 人物扩展按住／新按下／变化 | 同上 |
| `+0x74.b`、`+0x75.b`、`+0x76.b` | 原始基础按住、输入保留计数、控制通道；通道 `0xff` 走 AI | `0x15540`；保留期间的攻击键处理需单独取证 |
| `+0x78.w`、`+0x7a.w` | 生命值及显示追赶值 | 初值 `0xdf`，资源条函数逐次让 `+0x7a` 靠近 `+0x78`；AI 排除生命为负的目标 |
| `+0xb8.w`、`+0xbc.w` | 第二资源及显示追赶值，结合原版灵力 UI 推断为灵力 | 初值 `0xdf`，攻击按住和资源条路径使用；仍需消耗／恢复动态边界确认 |
| `+0xc9.b`、`+0xca.l` | 人物输入录制／回放控制与数据指针 | `0x15540`；尚未恢复其菜单入口 |
| `+0x90.l` | 移动参数表指针 | `0x19da2` 读取其第一项长字；不是函数回调 |

投影 `0x156f0` 的已见行为：先以 word 运算得到 `worldX.high - cameraX + 128 + offsetX`，夹到 `64..511` 后写屏幕 X；Y 为 `worldY.high - cameraY + shake + 32 + offsetY`，夹到 `64..448` 后减 8。相机为 `0xffa014.w / 0xffa016.w`，shake 为 `0xfff566.w`。移植时需保留 16 位回绕和有符号比较，不能只按无限精度整数公式计算。

空中动作 `0x19dc6` 的顺序是 `x += vx`，`vy += gravity`，`y += vy`；当纵向速度非负且世界 Y 的高 word 达到地面高 word 时落地，完整位置恢复为地面基线，调用 `0x18564` 并清 `+0x87`。这不是完整跳跃状态机，起跳、空中攻击、切线与落地后的动作仍待恢复。

## 原版 AI、随机数及判定数据的入口

AI 入口为 `0x1cc8a`，由控制通道 `0xff` 进入。它维护 `+0xd2.w / +0xd4.w` 等计时，使用难度 `0xffff12.w`、随机数和角色类型，遍历固定人物槽并排除自己、无效槽、生命为负及同队目标，然后进入 `0x1cd70` 与角色专属分派。此处只定位路径，未恢复完整电脑策略。

随机数函数 `0x3982` 使用 `0xffff18.l` 作为状态。设旧状态为 `s`，零值先替换为 `0x2a6d365a`，则 `t = 41 × s mod 2^32`，`r = (low16(t) + high16(t)) mod 2^16`，新状态为 `(r << 16) | low16(t)`。D0 的低 word 返回 `r`，高 word 保留经过零值替换后的 `s` 高 word。指令见 [fighter-active-actions.txt](fighter-active-actions.txt)。仍需原函数调用输入／输出夹具确认后再写实现。

`0x1eb40` 消费角色动画表与每帧形状表，把四类 16-byte 记录写入 `0xffa200 / 0xffa300 / 0xffa400 / 0xffa500`，计数分别在 `0xffa004/006/008/00a`。记录包含世界空间位置、对象地址及大小相关数据，并处理朝向翻转。这是碰撞／受击区域的候选提交路径；四种类型的确切语义和消费顺序尚未恢复，不能先命名为攻击框、受击框或投技框。证据见 [fighter-motion-ai.txt](fighter-motion-ai.txt)。

## 复跑与保留范围

探针为 `scripts/yuyuhakusho/static/MdControlProbe.java`，包装命令为 `run_probe.sh`。参数格式是 `入口[,入口]:允许起点:允许终点`，全部按十六进制，必须从已确认的向量、直接调用、动态对象指针或已确认跳转表取得入口。例如：

```sh
sh scripts/yuyuhakusho/static/run_probe.sh logical-input.txt \
  2d20:2d20:2e5d 2d4c:2d4c:2e5d
sh scripts/yuyuhakusho/static/run_probe.sh fighter-stages.txt \
  14922:14922:149ab 15540:15540:156ef 15a18:15a18:15e00 \
  156f0:156f0:15771 15772:15772:15840 208d8:208d8:20b00
```

有限范围之外的目标不自动扩展。输出中某条分支指向范围外属于明确未覆盖区域，不能据输出没有该代码认定原版没有功能。语言定义支持的指令集比 MC68000 宽，仍须动态可达性校验。

本轮没有添加游戏实现、修改上游模拟器或编写单元测试。已删除仅用于探索的错误入口输出、Ghidra 临时项目／配置／编译缓存和控制台日志；保留确认过的指令输出、脚本、文档和摘要。原始动态 RAM 由父任务管理，本目录只保存其 SHA-256 和已确认字段位置，不复制完整存档。
