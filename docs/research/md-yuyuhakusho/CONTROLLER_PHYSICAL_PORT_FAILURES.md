# 公共实体手柄最小接入：先行失败场景

本清单和新测试先于 port 实现。来源为 main 已提交的 `caedfc4c`；main 当前未提交的星垒文件只读，不移植。保留当前 FC／MD SVG、键位与单一设置入口，不恢复 SFC 配置，不批量改其他游戏的输入。

- 物理采样缺失，MD 六个普通面键、Mode／Start／十字和左摇杆映射不全；按厂牌猜编号而未要求浏览器 `standard`。
- MD U／I 被当作 FC 连发；FC B／A／Turbo B／Turbo A 的默认与 phase 改变。
- 相反方向同时输入不归零；一个来源松开、断开或连发间隙取消另一来源正常按住的按钮。
- 新连接、重连、换配置、失焦、页面隐藏、设置弹窗、禁用和卸载后旧按住状态复活；未回中即重新输出。
- 稀疏连接编号或后来插入的设备抢走当前选择；非标准设备无配置仍输出；无 Gamepad API 或权限异常阻断键盘／触屏。
- 录入开始前已按住的按钮被立即绑定；同物理按钮／轴方向重复，非法 index／direction、死区、device key 或过大配置被保存。
- 用户、游戏、实体型号共用可变配置；键盘和 physical 配置相互覆盖；旧 keyboard-only 客户端保存抹掉 physical 设置。
- 重复入口或只为未接入游戏显示可保存的空操作方案；当前游戏未优先，FC／MD 旧方案在设置中消失。
- 旧 `md-6` 迁移后仍共享同一保存 key，或游戏默认值被用户修改污染；stale revision 覆盖新值。
- 只验证虚拟 sampler 或设置页 ACK，未在 MD 实际 Canvas／服务器输入路径看到响应与释放；虚拟 Gamepad 被误称实体品牌兼容。

验证分层：现有纯 sampler 用例复用原提交；新增真实 HTTP／SQLite 验证用户／游戏／型号与旧客户端；浏览器以明确标注的虚拟 Gamepad API 配合可信鼠标／键盘／触屏，检查设置与 MD 实际对局。实体硬件品牌没有在本环境验证时保持未实测。
