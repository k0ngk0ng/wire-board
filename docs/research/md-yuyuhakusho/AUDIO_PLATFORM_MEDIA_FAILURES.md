# 平台原生音频接口的验收失败场景

本清单先于本分工的浏览器验收工具。当前只评估既有 `GameAudio`；不修改播放器、游戏规则、素材清单或其他游戏。

## 需要确认的接口缺口

- 将房间 owner 当作独立有限声道：两个有限请求实际复用同一媒体，后一个截断前一个。
- 把 `play()` 的 URL 数组当作 fallback；实际它是最多四段的顺序列表。`playWithFallback()` 才表示同一声音的来源替代。
- 把 `loop(key)` 当作有限声道：该入口强制媒体循环，无有限实例 ID、恢复位置和按实例停止语义。
- 把相同音效的新请求误去重，或重复快照、回滚重放、旧停止事件重新启动或截断当前实例。
- 为双 PCM／FM／PSG 的策略决策加入平台优先级；原驱动的通道和抢占决策应由独立规则产生，平台仅执行媒体生命周期。

## 既有生命周期和浏览器观察

- 未经真实用户手势就把 `play()` Promise 成功或失败写成全设备支持结论。
- 有限音乐 `8f` 被强制循环；恢复超过其真实时长后从开头重播。
- 暂停改变媒体位置，恢复重新装载来源；新效果误停 BGM，或 `stopMusic()` 误停效果。
- 相同 `playbackID` 的 BGM 状态刷新重播前奏，新实例不能重新起播。
- 取消、静音、隐藏、离桌和 dispose 后，旧 `ended`／metadata／play Promise 重新启动媒体；未恢复偏移就补播过期声音。
- CDN 失败后的 fallback 丢失 offset；迟到的旧 metadata 定位新来源。
- 非零 `loopStartSeconds` 重复前奏，或循环边界的异步 `ended → seek → play` 被误称原生整段循环或样本级无间隙。
- 将真实浏览器的媒体事件、`currentTime` 或可选 `captureStream` 记录等同于扬声器输出、物理手机听感或原版任意混音。
- 以合成诊断 WAV 的循环成功替代 `82/87` 或其他原曲的完整合成相位证明。

## 验收边界

验收使用生产 `GameAudio`、真实 `HTMLAudioElement` 和原生浏览器手势。有限音效并发的期待会明确保留真实 red；该结果是待扩展能力，不应更改既有单任务接口的兼容语义。原始有限 WAV 先核对文件与 PCM 摘要，再测试播放生命周期。循环诊断可以使用独立生成、明确标记的静态 WAV；不裁短原曲或变更播放速率。至少观察两个实际经过的循环边界，保留事件时间与可选原生捕获，明确不能证明的样本级结论。

所有文件、浏览器 profile、socket 与临时构建位于当前 worktree。不得创建游戏私有播放器、`AudioContext` 或静音开关。
