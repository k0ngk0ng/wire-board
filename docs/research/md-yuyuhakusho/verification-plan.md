# 首轮研究验证范围

本清单在本次运行探针编写之前记录。目标是验证研究工具能否运行、逐帧输入、读取内存及恢复回放，不代表游戏复刻验收。

## 可能失败的场景

- 下载包损坏、平台架构不匹配、动态库依赖缺失或 API 版本不符。
- ROM 名称与实际头部不一致、ZIP 中混有其他平台游戏、区域或修订版不同、校验和不匹配。
- 模拟器回调配置不全、没有输出视频、视频像素格式或行跨度解释错误。
- 输入位映射错误、方向或按键没有实际进入模拟器、三键与六键／四人适配模式不一致。
- 逐帧推进不稳定，存档恢复后相同输入的内存或图像摘要发生变化。
- 把合成诊断 ROM、模拟器 API 测试或静态反汇编当作本游戏玩法验证。
- REA 接口没有 68000／大端支持，却强行以 6502 或 ARM 解析，生成无效伪代码。
- 分析工具、缓存、存档或浏览器 profile 写到仓库之外。

## 通过条件与产物

1. 保存下载 URL、时间、包与内核 SHA-256；REA 包清单与实物摘要一致。
2. 本地内核成功初始化，记录 API／版本、帧率、分辨率、运行帧数、RAM 和存档大小。
3. 实际运行 ROM，明确标记其身份；如果只用诊断夹具，不能标记游戏通过。
4. 从同一存档重放同一输入序列，逐帧比较视频及 RAM 摘要，并产出机器可读报告。
5. 保留复跑命令、输入序列和截图；原 ROM、完整内存／存档和下载程序仅放在 `.local/md-yuyuhakusho/`。
6. 正式复刻另外先建立原版行为对照夹具，再写规则；未取得原版帧数据的招式、AI 和判定均标记待验证。
