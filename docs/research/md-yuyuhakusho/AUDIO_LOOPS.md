# 音乐 `82/87` 循环边界研究

本轮只读既有音频交付，研究原驱动的序列回跳、各通道周期与离线媒体循环的可行性。新采集、脚本和验证报告单独保存，不修改已经验收的媒体、目录、引擎或运行时桥。

## 实现前失败场景

可能失败的场景包括：把单通道回跳当成全曲回跳；漏掉 DAC／PCM 或 PSG 噪声通道；忽略音序中的有限计数循环、子程序栈、转调、音量、调制、节拍累加器和未归零计时器；用包含单调计数的整段 RAM 未重复，错误判定音乐无循环；反过来删掉有声音语义的寄存器，制造假周期；观察器或采样隔离改变原驱动；把视频帧边界等同音序 tick 或 PCM 样本边界；整数采样量、FM 相位、包络、LFO、PSG 噪声、重采样滤波状态在逻辑回跳时不相同；把相邻样本较接近或听感相似当作精确循环；跨淡出／暂停或效果声抢占切片；自动寻找零交叉后改变原节拍；把当前有界片段的起止点当成循环；将固定音频循环误称原版任意混音等价；覆盖既有验收产物或向工作树外写入缓存。

先确认 `82/87` 音乐头、通道序列入口和原回跳命令的实际语义，再记录受控原版执行时的序列指针、循环计数、驱动状态和波形。只有证据支持时才交付 intro／loop 文件；无法确认的层次保留为明确边界。

## 已定位的采样上限

对原 `F6` 回跳、`F7` 有限计数、`F8/F9` 子程序及逐帧完整驱动状态的首轮观察表明：`82` 的共同序列周期为 3,840 帧；`87` 的主旋律周期为 3,834 帧，PSG 噪声轨周期为 162 帧，共同周期为 `LCM(3834,162)=11502` 帧。后续采样按这些结构设定上限：`82` 最多 8,000 帧，`87` 最多 24,576 帧，用于覆盖两个候选共同周期及初始化，不继续盲目延长既有片段。是否可导出循环媒体，仍取决于完整状态和 PCM 接缝验证。

## 结论与证据层次

两首音乐的驱动序列循环均已确认；精确 PCM 循环未通过。新报告的 `logical_loops_verified` 为 `true`，`exact_pcm_loops_verified`、`release_ready` 为 `false`。没有导出或发布名为 intro／loop 的验收媒体，也没有修改既有 `82/87` 片段的状态。

本轮通过原内核与带观察器内核执行相同隔离输入，覆盖 `82` 的 8,000 帧及 `87` 的 24,576 帧。两组执行的完整 RAM、画面、驱动字节和逐帧 PCM 相同；各自前 7,200 步的 PCM 还与既有已验收 WAV 逐字节相同。采样继续使用原版合成，没有静音声道、修改寄存器或替换音频程序。

逐帧保留完整 928 字节驱动 RAM、8,192 字节 Z80 RAM、原内核导出的 YM2612／PSG 上下文、PCM 摘要及样本数量。YM2612／PSG 上下文分别为 3,624／124 字节，用于同进程状态比较；这些内核结构包含主机指针，不是可移植的播放状态或浏览器接口，也不要求跨进程导出的上下文文件 SHA 恒定。

## 原驱动回跳与共同周期

静态清单为 [`audio-loop-sequencer.txt`](static/audio-loop-sequencer.txt)。它通过既有 Ghidra 12.1.4 PUBLIC 备用路径和 `MdControlProbe.java` 从固定 ROM 解码，不是 REA 原生 raw-68000 分析结果。新增种子包括原入口 `0x375ae` 与 `0xe0..0xff` 的命令分派表，保留逐条指令。

| 命令 | 原处理入口 | 已核对语义 |
| --- | --- | --- |
| `0xf6` | `0x391b8` | 读取有符号 16 位大端相对位移，目标为命令地址 `+2+displacement` |
| `0xf7` | `0x391c4` | 使用 `row+0x28+index` 的字节计数器；归零时重新装载参数，再递减，未归零时走相对回跳 |
| `0xf8` | `0x391de` | `row+0x0d` 指向的栈先减 4，保存返回参数指针，再走相对跳转 |
| `0xf9` | `0x391f0` | 从当前栈位置取返回指针并加 2，栈位置再加 4 |

两首曲子的音乐头均为 6 个 DAC／FM 行和 3 个 PSG 行；6 行包含 DAC，不能解释为 6 个同时独立发声的 FM 声部。采集时非音乐效果声行始终为零，世界对象池为空，保留音乐自身的 DAC 鼓声。

| 音乐 | 音乐头 | 主轨 `F6` 示例 | 主轨周期 | PSG 噪声 `F6` | 噪声轨周期 | 全部轨共同周期 |
| --- | --- | --- | ---: | --- | ---: | ---: |
| `82` | `0x3a7e6` | DAC `0x3adb1→0x3acf1`；FM1 `0x3a909→0x3a816` | 3,840 帧 | `0x3aced→0x3acd2` | 96 帧 | 3,840 帧，约 64.082513 秒 |
| `87` | `0x3d36c` | DAC `0x3dbb0→0x3dab9`；FM1 `0x3d533→0x3d39c` | 3,834 帧 | `0x3dab5→0x3da8e` | 162 帧 | 11,502 帧，约 191.947153 秒 |

`87` 若只按一轮主旋律截取，会改变 PSG 噪声轨在下轮主旋律中的相位。共同序列周期是三轮主旋律、71 轮噪声序列。`82/87` 的噪声回跳目标都位于首次 `F3` 设置之后，因此轨道回跳不等于重新初始化硬件噪声状态。

`82` 在采样步骤 13 之后，完整驱动 RAM 与相隔 3,840 帧的状态具有 4,147 对连续逐字节相等记录；`87` 在步骤 1,472 之后，相隔 11,502 帧有 11,602 对连续相等记录。两者都完整覆盖一个共同周期，未删除驱动字段来制造原样相等。

两个连续共同周期的已选原生序列命令、YM 写入请求和 DAC 请求也逐条相同：`82` 每周期 30,163 条，`87` 每周期 73,069 条。比较保留步骤内顺序及相对步骤，排除 CPU 计数时间戳与重复内存快照。这不是全部 PSG／DAC 硬件写入的逐时钟轨迹，也不证明帧内写入时刻完全相同。

## 候选边界与 PCM 验证

采样步骤从 0 开始；状态在每个视频步骤完成后记录。因此「步骤 13 后」对应已经完成 14 个视频步骤。原始 PCM 不裁切，样本位置均按每声道 44,100 Hz 的立体声采样帧计算。

| 音乐 | 保守原样 RAM 边界：已完成步骤数 | 三个连续边界的立体声样本位置 | 两个周期的样本数量 |
| --- | --- | --- | --- |
| `82` | `14 / 3854 / 7694` | `10304 / 2836343 / 5662381` | `2826039 / 2826038` |
| `87` | `1473 / 12975 / 24477` | `1084051 / 9548921 / 18013790` | `8464870 / 8464869` |

`87` 的保守边界约为 24.58 秒。较早阶段的原样字节差异来自 FM3／FM4 已退出调用所留下的 `row+0x2c..0x2f` 返回地址。原 `F8/F9` 指令表明，栈位置为 `0x30` 时这些字节没有活跃调用；本轮全部 `F7` 使用索引 0，也未将这些字节作为循环计数器。只在这两个行且栈位置为 `0x30` 时排除这 4 个未使用字节后，步骤 14 后的完整有效状态与下一共同周期相等，已选事件轨迹也覆盖整个共同周期并完全一致。该项是额外的语义证明，不替代完整原样 RAM 证明。

据此，`87` 更早的候选边界是完成 15 个步骤、样本位置 `11040`，约 `0.250340136` 秒；后两次对应样本 `8475909 / 16940779`。它们的周期样本数量为 `8464869 / 8464870`。`82` 的候选边界为样本 `10304`，约 `0.233650794` 秒。这里没有宣称找到作者指定或唯一最短的音乐前奏，也没有把视频边界等同精确的音符起点。

完整 PCM 的对照未通过：保守边界下，`82` 两周期共有 5,643,011 个样本值不同，最大差值 17,132；`87` 有 16,854,977 个样本值不同，最大差值 12,917。长度相差一个立体声采样帧，比较采用共同长度；差值是整数 PCM 样本值，不是听感评分。

在保守边界直接回跳，`82` 回放首样本相对原生继续播放的左右声道误差为 `710 / 749`，`87` 为 `1801 / 1807`。完整差值、前 100 ms 对照、回放跳变和原生跳变均保存在报告中；没有用零交叉、容差或耳听判定为无缝。

原 PSG 噪声移位状态在三个保守边界分别为：`82` 的 `36130 / 24279 / 30728`，`87` 的 `35315 / 64186 / 1147`。FM 上下文和 PSG 频率计数器也未重复。驱动序列回跳保留这些合成状态，完整录音的一轮波形因此不能等同后续每轮原生波形。

内核使用 NTSC 主时钟 `53693175`、每行 `3420` 时钟、每帧 `262` 行，报告帧率为 `59.92274340431231`。在 44,100 Hz 下，3,840／11,502 帧的理论样本数量分别为 `2023186636800/715909`、`6060076223040/715909`，均非整数。这与实测相邻周期样本数量变化一致；扩大到样本时钟公倍数也不自动证明 FM／PSG 合成状态重置，本轮未作这种外推。

## 平台媒体方案及未通过的条件

现有 `BoardProps.audio.music` 已有 `loop`、`startOffset`、`playbackID` 与 `loopStartSeconds` 参数。后续若得到通过验收的媒体，可使用一个「前奏加循环段」文件，以样本位置换算 `loopStartSeconds`，由平台处理静音、暂停、离桌和恢复；有限结算音乐 `8f` 使用 `loop: false`。游戏不增加播放器、`AudioContext`、静音开关或运行时模拟器。

当前不能直接把候选样本位置写入正式资源清单。固定 WAV 后缀重复会重复同一噪声和合成相位，不能保证与原版连续合成逐样本等价。裁切、交叉淡化、时间伸缩或重新渲染并重置硬件相位都属于额外媒体处理，需要明确其保真边界并单独验证，不能作为本轮「已确认无缝循环」交付。

平台当前非零 `loopStartSeconds` 使用原生媒体的 `ended`／`currentTime`／`play` 路径。该接口能表达前奏后循环，但代码存在这些参数不等于浏览器已经通过样本级无间隙验收。正式接入仍需保留浏览器 E2E 的循环切换、暂停恢复、静音、隐藏和离桌证据。本轮只运行原内核采集与文件验证，没有修改平台，也没有声明 Go／Wasm 或浏览器播放验收通过。

## 产物与复现

固定 ROM、原内核与观察内核的来源和 SHA-256 沿用既有音频验证。完整本地捕获保留在 `.local/md-yuyuhakusho/audio-loop-verified/`；新脚本和 [`audio-loop-validation.json`](../../../games/yuyuhakusho/data/audio-loop-validation.json) 绑定来源、原回跳位置、所有逐帧状态文件、波形文件、事件日志及校验和。文件中的 `pass: true` 表示本轮研究断言通过，不表示 PCM 循环通过。

本轮清理首轮探索采集、临时 Ghidra 缓存／项目目录和重复日志，共 27 个文件、22,708,849 字节；清单位于 [`audio-loop-cleanup.json`](../../../games/yuyuhakusho/data/audio-loop-cleanup.json)。最终捕获、验证日志、脚本、静态清单和说明保留；既有音频验收文件保持不变。

在工作树根目录执行，使用新输出目录，保留现有交付：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 scripts/yuyuhakusho/research_audio_loops.py \
  --out .local/md-yuyuhakusho/audio-loop-review \
  > .local/md-yuyuhakusho/audio-loop-review-console.jsonl 2>&1

PYTHONDONTWRITEBYTECODE=1 python3 scripts/yuyuhakusho/analyze_audio_loops.py \
  --capture .local/md-yuyuhakusho/audio-loop-review \
  --report .local/md-yuyuhakusho/audio-loop-review/validation.json \
  > .local/md-yuyuhakusho/audio-loop-review-analysis.jsonl 2>&1
```

采集脚本默认固定 `82/87` 为 8,000／24,576 帧。`--steps` 只用于更短的定向捕获，不得超过各自结构确定的上限；完整分析需要足够覆盖共同周期，较短捕获会明确失败。分析脚本验证新 WAV 的全部逐帧摘要、原始状态数量、回跳来源与位移、共同周期、完整驱动状态、已选事件轨迹、上下文和 PCM 差异。元数据文件的 gzip 时间戳可变化，复现时比较内容与验证结果，不能仅要求容器文件 SHA 恒定。

仍未解决的范围是：精确帧内采样切点及任意时长原版合成等价的有限媒体方案、其他曲目、暂停／淡出／声道抢占，以及平台实际媒体切换的时序验收。现有证据已经排除了把初始 120 秒片段首尾直接相接视为无缝循环的做法。
