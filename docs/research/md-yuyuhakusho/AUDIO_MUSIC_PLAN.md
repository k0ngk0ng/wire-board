# 新增八首音乐的有界研究方案

新增范围是 `83/84/85/86/88/8a/8d/95`。8 个场地按原表选择 `82/86/83/95/85/8a/88/8d`；对手覆盖另有 `84/87`。`82/87` 已有逻辑共同周期但 PCM 精确循环未通过，`8f` 已有有限结束；本轮不重复这些采集。

## 第一轮：定位回跳和分类

从原音乐表读取 header 和每个 DAC／FM、PSG 入口，并用保存的 `384d8/385xx` 指令核对相对寻址。每首至多运行 4,096 个视频步骤，足以给出已观察到的回跳、晚启动和有限结束；该上限不是完整曲长声明。静音隔离和同进程检查点沿用已有经过验证的路径，所有恢复显式使用 `restore_refresh_cycles=True`。

分别运行未修改原内核和既有被动观察内核。逐步骤比较完整 RAM／视频摘要、PCM 摘要、立体声样本数量和 928 字节驱动状态；要求世界池和非音乐效果行保持为空。观察器只记录 `F6/F7/F8/F9` 等序列命令、音序 tick、选定 YM／DAC 请求，不修改驱动寄存器。

## 第二轮：按结构设定上限

只有在回跳结构明确后，才按各轨周期的最小公倍数设定完整捕获范围，目标为两个候选共同周期加有界初始化。若 4,096 步内缺少第二次回跳，则保留待定，通过更窄的静态序列路径或首次回跳长度确定下一上限，不能直接盲增几小时。

完整验证分别核对原样驱动状态、已选有序序列事件、YM／PSG 上下文和完整 PCM。与 `82/87` 一样，样本时钟的非整数周期和不回归的合成状态必须保持为反证；不自动生成名为 intro／loop 的正式媒体。

## 研究数据契约

`MusicSequenceStudy` 为 research-only JSON schema 1，包含 `code`、`header`、`sampling`、`track_f6_observations`、`track_periods`、`common_period_frames`、`raw_driver_recurrence`、`selected_event_recurrence`、`pcm_recurrence`、`classification`、`limits`。来源包含 ROM、两个内核、观察桥、采集器、原步骤和每个文件的 SHA-256。源地址只留在研究证据，不进入播放清单。

既有正式 `audio-assets.json` 不变。第一轮可返回 `bounded-loop-evidence` 或 `bounded-unresolved`；只有观察到完整原生停止和精确静音尾部，才返回 `finite-native-music`。共同序列周期证明与 PCM 精确循环证明是不同字段。

## 连续播放的验收边界

任意时长严格还原原版合成需要保留音序和合成状态的连续推进。固定 WAV 后缀重复会重置同一段波形；当前 `82/87` 证据已排除直接等同原生继续合成。独立 Go 音序／DSP 是可研究路线，不是携带原 ROM、CPU 或模拟内核；其输出仍须通过平台原生媒体通道承载，不能在游戏中新建 `AudioContext`。

本轮先给原音乐数据和实际回跳证据，为独立音序／DSP及原生媒体分段承载提供可测输入。若选择媒体处理方案，必须显式标明它与逐样本原版等价之间的差别，并先验证节拍、噪声相位、边界样本和至少两个真实浏览器循环，不能以一次播放替代完整 BGM 目标。

第一轮已显示 `84` 的噪声回跳间隔交替为 101／102 帧，不能将相邻两次回跳差值直接当作轨道周期。第二步先解析音序的控制流和时值，以原 4,096 步全部序列命令逐项核对。解析器只处理域内音符、时值、有限计数和调用，不执行 M68K／Z80，也不进入生产运行时。`F7` 的八个计数字节与两格返回地址共享同一对 word，不能分别保存两份状态；超出已恢复范围的栈深、计数器和扩展命令必须明确拒绝。
