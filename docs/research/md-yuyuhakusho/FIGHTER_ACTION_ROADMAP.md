# 全角色动作执行路线图

本页保留进入来源 10 阶段前的静态研究快照。当前可玩范围与完整验收以[复刻进度](../../../games/yuyuhakusho/PROGRESS.md)为准。

建议下一步恢复来源 ID 10。它还缺 `11/2d/47/48/49` 五个持续动作槽，但这些路径没有建立新的角色子对象；残影使用已经恢复的 `20202`。来源 2 和 8 的缺槽各为四个，还分别需要两种和一种新的子对象生命周期。这个顺序按整个人物接入的依赖选择，不按动画数量判断。

本轮没有修改 engine、测试、runtimebridge 或 PROGRESS，也没有新增原 CPU 调用。结论来自当前实现、已有原 CPU 验证记录，以及直接 Ghidra 的有限静态指令／分派表。REA 当前不支持 raw 68000；下面的静态资料不能称为 REA 已执行或已反编译该 ROM。

## 证据边界

固定 ROM SHA-256 为 `c39d52b2e2298b3784ada3de70d64b26b67e172114c7d18494faad70fc4d7c06`。本轮取得 5,454 条有限可达指令、24,744 bytes 的字节绑定，覆盖 44 个攻击选择器、74 个动作槽的 73 个独立入口和 29 张间接表。与既有清单重叠的 1,372 条指令全部一致。

- **已有原 CPU 观察**：酎完整 `15a18` 调用、23 个酎动作槽、相关子对象和独立公共阶段已有各自夹具；命令准备、AI、动画记录的全角色隔离验证另有记录。来源绑定见[覆盖 manifest](static/fighter-action-coverage.json)的 `sources`。
- **本轮静态观察**：原 ROM 表字、指令字节、直接流边、对人物 `+5d` 的动作写入、对子槽 `+0` 的回调标识写入。
- **静态推导**：角色的「可能使用槽」是四选择器与持续阶段写入的闭包，加上公共 `00..0d`。图遍历同时跟踪条件两侧及直接调用的后继，不分析寄存器约束；它可能多列路径，不等同于自然执行覆盖。
- **未知**：其余角色完整动作函数的 CPU 返回、自然招式与完整对局，新增子对象的完整函数范围／资源／生命周期，以及未列入闭包的其他外部状态写入路径。

动画目录的 4,732 条记录和全角色 AI／命令准备均不能代替动作执行验证。目录中的姿态、代码中的动作槽、来源角色 ID 和平台席位是不同标识。

## 准备与四个攻击选择器

完整动作入口为 `15a18`。它先调用命令准备分派 `15c10`，再执行公共输入准备 `15c36`；命中停顿路径不会执行普通动作分派。普通路径在推进一次动画时钟后，从 `15a68` 的动作表跳转，最终进入 `15afc`，在 `15b82` 返回。

共享尾段依次重新读取 `+6c` 的 bit0、bit3、bit4、bit1、bit2，执行地面控制、地面特殊、空中特殊、地面普通、空中普通。前一次构造可能改变后续阶段掩码，不能预先缓存原掩码。

## 下一角色：来源 10 的最小范围

必须新增／组合验证的原范围为：四选择器 `18164..1843f`，七个特殊构造入口 `19ac0/19aea/19b14/19b46/19b78/19ba0/19bd8`，后退 `1cb08..1cb67`、共享持续 `1b67a..1b6c3`，以及 `1c85e/1c8e0/1c9aa` 三个专属持续入口到 `1ca46` 之前的可达路径。已确认的下一动作是 `14`，直接复用已恢复滑行；没有新的角色子对象回调写入。

以下差异必须纳入测试前的失败清单：

- `19bd8` 的构造只清人物 `+48` 的一个 byte，`49` 会按 byte 增加并用低两位决定残影。当前 `ChuActionState`／`FighterBodyState` 没有这个字段的语义所有者，必须先定义边界并测试相邻字节保留。
- `47` 的接触提前跳帧检查是 `ContactFlags.bit0`，不是酎 `41` 的 bit2／bit3。它从第 0 帧起就可能移动并建立残影。
- `48` 落地先走站立构造，随后改为槽 `14`、姿态 `ae` 并减半横速；没有酎 `45` 的接触反跳分支。
- `49` 在帧 4..27 累加 `+48` 并以 `0x40000` 移动，帧 28／29／30／31 起依次使用 `0x30000/0x20000/0x10000/0`。方向判断使用朝向 byte 是否为零；`47/48` 的移动使用 bit0。
- 普通前向 A 的投技在 `18214..18286` 提交：命中区 X 偏置为朝向决定的 ±8，`TargetPose=41`、`TargetAction=9`、`OffsetX=20`、`OffsetY=-30`。这里的数值为十六进制；酎分别为 X 偏置 0、`40`、3、`18`、0。不能只替换动画姿态。
- 空中普通入口先调用 `1831c..183ae`：方向低 nibble 既非 0 也非 1，且 A 新按下时提交空中投技，再继续普通 B／A 选择。该记录使用 X 偏置 ±`18`、Y 偏置 `-30`、宽 `18`／高 8、`SourcePose=b9`／`SourceAction=9`、`TargetPose=41`／`TargetAction=9`、`TargetFacing=1`、`OffsetX=18`／`OffsetY=0`，数值为十六进制。A／B 同时新按下时也要保留先提交记录、后按普通优先级选择的顺序。
- 地面请求 1 直接尝试成本 24 的构造，不额外要求按键变化；请求 2 需要任一基础攻击变化，成本 16，进入 `2d`。请求 3 的 B／A 都消耗 16，姿态为 `a2/a3`，进入 `47`。请求 6 要生命不大于 111、A 变化和能量 200，进入 `49`。这些成本为十进制。
- 空中特殊只有请求 2；B／A 成本分别为 16／20，进入 `48`，速度为 `0x38000/0x38000` 或 `0x60000/0x28000`。方向与请求门槛不能照搬酎。

现有全角色动画目录已包含来源 10 的对应记录，初始化的集合与移动参数也有原 CPU 证据。仍需把这些已验证语义数据按来源接入完整动作库；现有酎世界组合继续是单角色范围。目录可读不代表新动作已经可运行。

## 复核与复跑

`fighter-action-coverage.json` 逐项保存 74 槽、44 选择器、角色闭包、动作写入位置、子回调写入、直接构造根入口、范围外调用和来源摘要。`structural_region_end_exclusive` 只是下一个已确认动作入口的物理边界，不能用来声称函数只包含该连续区间。

从 worktree 根目录运行以下只读检查，需要固定研究 ROM。检查会核对字节、旧清单、图结构、派生清单及 manifest，不写游戏实现：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 \
  docs/research/md-yuyuhakusho/static/derive-fighter-action-roadmap.py
```

重新导出静态图使用 [FighterActionRoadmapProbe.java](static/FighterActionRoadmapProbe.java)；其参数依次为 worktree 根目录、输出 JSON 绝对路径和 manifest 的 `ghidra_seed_arguments`。按[静态工具说明](static/README.md)使用已安装的 Ghidra／JDK，创建新的 worktree 内项目与独立 `user.home`、配置、缓存及临时目录；范围固定为 `15f4a..1cc81`，只递归直接流边。完成后将 JSON 以 `mtime=0` 压缩为 `static/fighter-action-flow.json.gz`，再以 `--write` 重新派生清单和 manifest。该流程不运行目标 CPU，也不修复 REA 配置。
