# 声音分派与 PCM 仲裁的先行失败场景

本清单先于本分工新增采样器、验证器和任何独立规则实现。复用既有固定 ROM、两个内核、静音检查点方法与已验有限媒体，不覆盖原资产和生产世界。

- 将 `06..7f` 全部当作两条同质 PCM 声道，漏掉 descriptor flags bit 0 控制的单 DAC／双槽分支。
- 将 routing 高两位当作立体声 pan；原路径实际据此定向 A、定向 B 或自动选槽，Z80 的 DAC 输出还受全局模式支配。
- 只按当前总优先级决定抢占，漏掉每槽 flags 高两位；相等优先级、空槽、待装入 `80`、活动 `40`、自动选择偏好或 byte 高位保留错误。
- 用视频帧末忙标记代替 `37da4/37e9e` 真正读取时的寄存器值，或将寄存器未定义的高位误当语义状态。
- 把请求到达或队列选中当成 PCM 接收；忽略分派器拒绝、别名、单模式转双模式和零长度／静音描述符。
- 将 `02/03` 的主／副 FM、PSG 效果行停止误映射到 PCM A／B，或者假定 `04` 一定立即停止 Z80 PCM。
- 漏掉 `F0` 在普通 `06..7f` 表之后使用的独立 descriptor；把它直接映射为编号 `7a` 的有限 WAV。
- 丢弃 descriptor bit 5、旧 mode bit 5 与 `F82B` 共同决定的 duck 请求；将 duck 请求等同已经完成的淡出／恢复。
- 只比较 RAM／视频而没有 PCM；观察器改变原执行；恢复遗漏 `refresh_cycles`；将私有输入假称正常玩法可达。
- 将不同原请求时基的单音 WAV 直接逐样本相加；忽略硬件 DAC 混合、相位、重采样、截断、启动延迟或状态相关增益。
- 两个媒体元素同时播放被误称原混音等价；未验证同槽停止与抢占、PCM 自然结束、原声部覆盖和平台实例取消。
- 验收通过仅靠排除所有发生改变的区域；未说明 Z80 自主执行与硬件寄存器不属于当前纯仲裁 helper 的状态边界。

计划先保留原版成对输入及被动分派边界，另做独立 verifier。未来 Go helper 只按 typed command 与临时语义 view 返回决策，不携 CPU、固件、ROM 地址或通用 RAM VM，不在本阶段接入世界帧尾消费。
