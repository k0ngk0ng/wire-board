# 音频资源接线的先行失败场景

本项连接现有 score、parser metadata、唯一 PCM 资源目录、命令设备与合成层，不新增世界／IRQ 排程，也不为未恢复的成本赋零值。实现前覆盖以下场景：

- 三份资源不匹配、损坏或缺少依赖，却返回可用目录；不同资源产生相同 checkpoint 身份。
- 描述枚举泄露可变内部数据，或配置保存第二份可变 payload；普通第七字节与音乐轨道声像混用。
- 129 个描述的 ID、编码内容、采样率、flags 或路由与原版来源不一致，F0 误映射或漏掉 7F 的内部采样生命周期。
- 将 7F 作为比赛普通请求，或对非 idle duck／choice 状态猜测处理；拒绝请求仍生成 publication 或更新 choice。
- 忽略真实优先级、pending／active busy、原 slot choice 或已采样的 StartDual；在发布时重新仲裁已接受的命令。
- 音乐 DAC 意图重新采样优先级，丢失独立 track pan；dac-pan 被误解释为重新启动样本。未知描述、普通描述冒充音乐、缺少 pan 或带多余效果字段应拒绝。
- Blocked、Priority 和 PanRedirect 混为同一条件，或将前一次反馈缓存在桥接层。
- 实际资源经配置适配后，23 条原版命令流程的物理端口、完整 YM／PSG／FIR 或立体声采样发生变化。

验收使用未修改的原版描述／命令／完整合成夹具。42 条音序轨迹的 9,230 个 DAC 与 2 个 dac-pan 意图仅作字面量提取，保留源 SHA 和可重复导出器，不由新实现生成期望。新资源接口只使用调用方提供的解压后字节；OSS／加载层仍须先按可信清单验证压缩产物与还原内容。
