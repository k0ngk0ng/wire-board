# 其他场地恢复起点

本页仅整理现有静态和资源来源，未新增 CPU／Ghidra 执行，也不把初始化请求或地址绑定称为场地完成。目前可玩与像素验收只覆盖默认场地 0；其他场地名称尚无核实映射。

原场地 ID 是 `A060.word` 的偶数偏移，以下表项均为十六进制：

依据为 [ARENA_ASSETS.md](ARENA_ASSETS.md)、保存的八组资源绑定、[场景静态](static/arena-assets-scenes.txt)和规则包 `match_start`。八 ID 的初始化请求已由 `StepMatchStart` 原 CPU 矩阵覆盖；这不证明菜单可达、持续规则、素材或完整画面。

## 必须补齐的证据

- 七个主 callback 的滚动与色盘规则、真实相机输入及连续状态。它们均调用已恢复的公共相机 `21556` 和反馈 `21690`，公共逻辑可复用，但不能直接套默认场地公式。
- ID4 的 `20dca` 色盘循环受 `F501/F572` 控制，经 `20e00` 表复制三个 word 到 `E092`，不同于默认 Sun 逻辑；须补 typed 表和连续对照。
- IDa 在 `21144` 创建 `FF9E00` 的 `21258` 子对象，大小40并有父引用。当前静态只有创建，callback 本文和资源行为未知，不能从邻近地址猜用途。
- 各场地 indexed A／B 背景、初始色盘、动态 tile 覆盖与原视频像素证据。当前默认包只含默认场地406 tile和两张64×32图。
- ID2 额外有 `28bde8→a000`，地图目标为 `c000/e000`；其余场地图从 `c100/e100` 开始，IDa 另有 `297056→ba00`。必须验证未写前缀及额外块，不机械补零。
- 八资源清单前两项 `27db80→0000`、`27dcb4→1800` 相同，公共 HUD／预载槽有复用候选；仍须核对各场加载后的实际内容。

## 接入边界

`ChuSessionOptions`、资源完成和 `runtimebridge.Ready()` 当前固定默认场地。背景／HUD decoder 也严格绑定默认清单21720；需要改为校验已恢复的所选场地及其真实就绪资源，而不是取消身份检查。保存恢复必须保留同一选择，平台房间准备阶段接入场地选项，不返回原菜单重复选择。

`ArenaRuntimeLibrary` 当前是默认场地相机、尾行、色盘和天空数据，尚非八场 profile。world 调度只有默认20918；其他七主入口及已见21258都必须原 CPU 先测后接。光栅核心可复用，但默认可见行14..207、窗口y<48与320×224滚动 profile能否共用，要由各场实际显示输入证明。

下一闭环是合法固定输入与完整基线、各场规则／必要表、紧凑背景包与公共槽、prepare／resource-ready、全新独立对局和原画面／恢复验收。默认场地或角色素材的通过结果不代替其他场地验收。
