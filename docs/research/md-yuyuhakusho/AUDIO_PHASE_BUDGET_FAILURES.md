# 声音 phase 预算原型的失败场景

本清单先于新的只读观察器和研究模型；不修改已冻结的 scheduler、采样器、测试或生产代码。

- 将有声音选择副作用的 request、consumer、driver 内部队列写入、优先级释放或分派清空遗漏、合并或裁去。
- 将只有函数入口／返回快照的既有 marker 当作完整逐写轨迹，漏掉 `38f28` 的内部后续曲请求等路径。
- 将请求在线性化到入口，忽略 IRQ 恰好插在比较与实际队列写入之间；尤其第 3612 步的 `7d` 事件。
- 只检验 83 次非空消费，不检验空队列 tick；把先于请求的空 tick 移到请求后会早播一 tick。
- 把 arena 内部无声音副作用的计算与有声音写入的 actor 混为一类，或把「可在 callback 内交换」误称「可移到世界帧尾」。
- 通过重放原 PC 时间表或给生产代码装入 CPU／RAM VM 来取得表面匹配。
- 将 68k 基础执行成本与 MD bus refresh、IRQ entry／RTE、VDP DMA／FIFO、Z80 总线与握手等待混成同一常数。
- 直接取原观测的 block 时长作为预测，或在预测中输入原未来队列／分派结果。
- 没有完整 RAM／视频／PCM 被动观察等值，或未知声音字段写入未归属。
- 语义成本模型的边界过宽仍强行指定 IRQ 所在 callback／producer，或以 host CPU 快慢决定虚拟时序。
- 以队列选择相同证明 PCM 样本、抢占和混音精确相同；DSP／采样的验证层次必须另列。
- 为了通过原型修改既有冻结测试／producer，或写入工作区外。
