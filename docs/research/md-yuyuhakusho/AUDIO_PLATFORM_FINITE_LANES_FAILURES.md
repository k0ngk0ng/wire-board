# 有限声道扩展的先行验收契约

此清单和对应 E2E 先于任何共享实现修改。旧 `play` 的单任务语义继续保留；新增能力不能通过改变旧接口来满足。

拟定扩展：`effect(lane, sources, { playbackID, startOffset? })` 与 `stopEffect(lane, expectedPlaybackID?)`。来源数组是同一有限媒体的 fallback，媒体不循环；通道、抢占与实例由游戏规则决定，平台仅执行媒体生命周期。

失败场景：

- 缺少新方法；两个有限声道和 BGM 不能同时维持独立的真实媒体。
- 同 lane 的相同实例刷新重新装载来源或倒退播放位置；同实例变更来源没有拒绝；新实例播放相同来源却被错误去重。
- 已经 ended 的实例因重复状态重新播放；迟到的旧 `stopEffect` 或旧播放 Promise 停止新实例。
- 停止指定 lane／实例误停其他有限声道或 BGM。
- 有限媒体强制循环；起始 offset 丢失或小于当前有效偏移；超过时长的过期恢复从开头补播。
- 非法 offset 改变现有有效媒体；真实 fallback 或迟到 metadata 改变其他 lane。
- owner 暂停改变位置，恢复重新加载；静音、停止、隐藏和 dispose 后旧回调复活。
- lane 直接使用不断增长的事件 ID 导致媒体元素无界增长；事件实例 ID 与少量稳定 lane 不分离。

原版两个 PCM 通路与 FM／PSG 部分抢占语义由独立驱动／素材研究另行证明。此扩展通过也不代表独立 WAV 叠放与原混音等价，更不代表浏览器可保证样本级起播和循环接缝。
