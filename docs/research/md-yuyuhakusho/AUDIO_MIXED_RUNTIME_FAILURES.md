# 音频组合运行层的先行失败场景

本层将独立 PCM Device 的真实物理端口输出交给 FM／PSG 合成器，并提供可恢复的组合状态。使用已有原版夹具，不重新采集或改写期望。世界声音触发、音序完整周期成本和平台播放仍由后续集成完成。

在实现前覆盖以下场景：

- 23 条原版 PCM 流程中，地址写、数据写、同周期顺序、复位及跨帧尾部发生变化，造成完整 YM／PSG／FIR 状态或立体声采样不一致。
- 将数据时刻推造的地址写送入芯片，或按 cycle 排序，改变真实共享地址锁存。正式层必须要求物理端口配置，并按 Device 输出顺序消费。
- 复位请求早于已完成 DAC 写时丢失因果关系，或将此例外推广到普通芯片访问。只保留一个“最后一次芯片操作来自 PCM DAC”的语义标志；cycle 继续由芯片 Cursor 唯一持有。
- PCM 已推进、芯片在中途拒绝输入时，留下半提交的 Device／chip 状态或返回部分 PCM。组合操作失败须丢弃整个工作分支。
- 保存、JSON 往返或恢复后丢失真实 bus hold、未完成声部、FIR 尾部或 DAC 复位因果标志。快照不得共享可变 slice／指针。
- 恢复到不同的芯片配置、PCM 资源身份、参考帧或未消费 ledger。组合层不接收来源不明的未消费输出。
- 实际 ServeYM 的 bus、mailbox、Busy 重试与端口访问脱节。使用四条既有原版总线场景逐项核对 Main 访问、结束时钟和 PCM 状态。
- 为事务分支重新认证全部音频资源，或把分支的 pending ledger／held／single 指针与原实例共享。分支必须借用不可变资源，只复制 canonical 动态状态。

不增加 CPU、ROM、RAM 镜像、全局时钟副本、声音事件历史或固定帧内触发表。成功返回的音频块和诊断 ledger 不存回 Runtime。
