# 乐器选择身份的先行失败场景

同一 bank 中已有两组不同乐器条目产生相同音色：曲目 8D 的条目 8／13、95 的条目 8／14。只保存去重音色 ID 无法恢复真实查找工作。本项以不可变逻辑乐器引用替换 bound catalog 的 Tone 值，仍由唯一 VoiceState.Tone 持有当前选择，音色内容通过引用派生。

实现前覆盖：

- 以音色 ID 猜查找次数；不同条目在 Snapshot／Restore、claim／restore 或 level 更新后合并，造成错误成本。
- 为当前选择新增一份源 instrument index、RAM、第二个 Tone／patch 字段或历史事件表；不得增加可互推的动态镜像。
- bound catalog 修改共享旧目录，泄露可变元数据，改变原音色、音符、意图或原 native view。
- 音色引用、工作定义、逻辑 selector、fallback、目录 SHA、缺失／重复条目不匹配；部分绑定失败却返回半成品。
- 旧格式 Tone 在 bound 目录中有歧义，却在恢复时静默选择一个条目；恢复到其它选择集合没有拒绝。
- 68 个初始选择与 892 个控制选择未完整覆盖，prefix／cycle 的逻辑索引错位，F5 的 FM 选择被当成 PSG envelope。
- 相同音色／不同选择不能在保持原 native view 与输出一致的同时保留不同工作引用；实际 8D／95 完整原轨迹、保存恢复或其它代表性原流程失败。

新资源只含逻辑 owner／事件键、音色内容引用及有界语义工作量，不包含源 bank／index／PC／地址或可执行代码。原来源保留在独立研究证据中。此项补选择身份，不宣称已完成所有乐器传送、参数或整场音频时序。
