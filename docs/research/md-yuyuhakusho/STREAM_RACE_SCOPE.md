# 原生性能与竞态正确性的验收范围

本说明先于新增的独立功能 race 用例及其共享驱动。Root 明确决定保留原性能用例和全部 race 失败，不提高预算，不为插桩性能扩大公共优化范围。

## 保留的性能要求

`TestCursorHTTPWSReplaySizesAndReconnect` 在未插桩 native 下保留 300 帧完整重演、60 次动作与确认、2048 字节常规视图和 500 ms 输入确认硬预算。Root 的真实浏览器预算另行验收。原性能用例在 `-race` 下观察到约 5 秒确认延迟，相关失败原样保留，不能标记为绿色。

## 独立功能 race 的先行失败范围

- 只运行 dummy 模块 race，遗漏本作实际房间、HTTP 鉴权、WS、完整客户端规则／呈现和恢复。
- 将插桩耗时当作网络 SLA，或通过修改原 500 ms 阈值把失败改为通过。
- 规则重演只检查位置或部分对象；输入丢边沿、重复应用、双摘要不一致或少于 300 帧／60 次确认仍算通过。
- 接收和重演使用无限队列；不同连接共用游标；未读慢端阻塞快端或重连继承旧 cursor。
- `/sync` 的 confirmed 已前移，却错误地用 confirmed 代替本连接上一 WS 帧，导致合法的新增帧被误判为超出 6 帧冗余。
- 新功能用例悄悄替代原性能用例；最终 manifest 隐藏原 race 红灯或混用 native 与 race 统计。

新增功能用例保留原始 HTTP／WS、生产时钟、300 帧完整重演、60 次动作／确认、每个边界的规则与呈现摘要、2048 字节视图、独立快慢连接和重连恢复。接收队列保持有界。插桩 wall time 只用于防止测试无限等待，不作为性能通过标准；确认耗时仍记录为观测值，不声明满足 500 ms。
