# 原生战场浏览器验收场景（脚本实现前）

1. 使用已构建页面和真实 HTTP、登录、SQLite、平台时钟，合法创建两张不同的经典地图房间，完成选人与倒数。检查原生资源确实加载／绘制、地图中文名、地图画面和桌面／320px 截图。
2. 在测试专用的开局快照准备短走廊、可推灰箱和不可通过的树；开局后只使用原生键盘。采集实际 Canvas 推箱坐标的连续样本，确认 300ms 中间位置、目标不重复画、源／目标对象 ID 变化；连续推到树前不能穿墙。
3. 手机 320px 使用原生触摸拖动摇杆，确认四向移动及松手结束，没有选择按钮文案。
4. 分别在开局快照准备乌龟／飞碟地面道具，真实操作拾取。核验地面图片与骑乘实际绘制、公共玩家栏状态、服务端 speedMs 和真实位移斜率；飞碟穿过箱子但不能穿树。
5. 刷新后保持动态箱子位置和骑乘状态，所有资源通过已发布路径或同源回退读取，不重播旧推箱。

隔离边界：前两张地图完全使用原始生产 Start；后面三个场景仅在测试夹具包装 Start 初始返回值，清理局部走廊并设置测试实体。没有运行中状态注入，没有替代生产 Apply/OnTimer/View，没有在浏览器篡改胜负、物理或素材加载。它证明这些固定条件下的交互，不证明随机掉落概率或全部地图对局。

保留可重复脚本、完整场景说明、关键状态／逐帧诊断、原生输入记录、截图和校验摘要；结束后清理本次浏览器 profile、SQLite 测试库、临时 Go overlay 和 socket 目录。
