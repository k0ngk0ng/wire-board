# 推箱实现前失败场景

隔离范围为服务端单次推箱 helper；移动入口、全量地图及浏览器操控由父任务集成验收。

- 四向接触正确，但人物整数格坐标和小数偏移错误地被当作箱子位置。
- 尚未接触、斜向输入、沿箱角挤压、垂直格线未对齐时提前推箱。
- 固定砖、树、墙、地图边界被误当成可推动箱；旧规则版本被改变。
- 目的格已有普通箱、可推箱、水泡（包括实体与 cell 标记不同步）、道具或任何存活人物碰撞体；人物在相邻格但身体伸入目标也须阻挡，困泡人物同样阻挡。
- 已淘汰人物错误地阻挡目的格；飞碟穿箱能力错误地发起推箱。
- 连锁推箱、两箱同时争抢目的格、重复输入同一接触点导致多推一格。
- 推动后灰箱变成砖、源格未清空、原始 object ID 丢失、事件缺少源格／方向／服务端时间。
- 存档恢复后动态原始对象坐标回退；推动后的箱子不能被水流破坏或错误允许水流穿透。

实现选择：沿格线接触容差与现有服务端碰撞计算一致，为 1e-6；该数值是重构边界容差，不声称原版参数。现有原版证据确认每步 4 像素的推箱绘制和未落位不能再推，本 helper 只决定服务端目标格，不使用前端动画决定碰撞或规则。

追加（实现前）：推箱运动持续 300 ms，服务端保留源格／目标格／起止时间／原始对象 ID。未结束的同箱不可再次推动；另一箱不可进入运动中的源格或目标格；到期后允许下一次接触推动。最多保留 32 个活跃运动，成功推动时清除已过期记录，拒绝请求不修改状态。`canPushBox` 按 `ServerAt` 判断，`tryPushBox` 以本次子步 `at` 判断，避免时钟在子步结束后才更新造成过期误判。
