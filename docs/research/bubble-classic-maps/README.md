# 2002 经典地图来源与格式

本次从保留的原版客户端提取全部 112 个 `Map/` 成员，保留原始格子、出生点、扩展段、对象表与贴图帧。这个范围是该份客户端资源的全量，不代表泡泡堂历年所有版本的地图。未运行 Windows 客户端；以下代码结论来自 REA / Ghidra 12.1.4 静态分析。

## 产物与复现

- 提取器：`scripts/bubbleparty/extract-classic-maps.py`。
- 机器目录：`games/bubbleparty/data/classic-2002.json`。
- 原始贴图解码：`games/bubbleparty/assets/public/bubbleparty/v4/classic/sprites/`，366 张 PNG，全部动画帧保留在图集及 `framesRaw` 中。
- 静态地图预览：`games/bubbleparty/assets/public/bubbleparty/v4/classic/previews/`，112 张 PNG。由原始默认帧合成，属于资源重建图，不是原作实机截图。帧字段 `[4]/[5]` 按绘制锚点解释，原始矩形左上角放在 `(x × 40 − frame[4], y × 40 + 39 − frame[5])`；该解释经主题合成图目视核查，未单独反编译原版绘图函数。
- 供版本审阅的已引用原始 REA 记录：本目录 `native-evidence.json`（15 条，保持原记录内容）。
- 完整 REA 证据：`.local/bubble-classic-maps/source-evidence/rea-native-map-tile-evidence.json`。
- 可重复提取核验：本目录 `verification.json`。

```sh
python3 -B scripts/bubbleparty/extract-classic-maps.py
```

默认从 `.local/bubbleparty-original/` 读取保留文件，输出到仓库指定目录。源文件不随脚本下载，也不执行。所有数据、PNG 及源资源范围均带 SHA-256。精灵资源名 `Tile04/chest01` 唯一大小写匹配 `Tile04/Chest01`；记录分别保留引用名和实际索引名，不改写原始对象表。

## 二进制格式

所有整数均为小端有符号 32 位。地图顺序为：

1. `width, height, spawnCount, rawOffset12, rawOffset16`。
2. `spawnCount` 对 `(x, y)`，从偏移 20 开始。
3. 配对计数，然后每组 `(x1, y1, x2, y2)`。
4. 按行顺序 `width × height` 对 `(groundObjectID, overlayObjectID)`；`-1` 表示没有对象。
5. 道具记录数，然后每条 `nameByteLength, ASCII name, rawWeight`。

尾部道具名使部分成员长度不是 4 的倍数，不能直接将整个成员解释为整数矩阵。提取器完整消费每个成员，无忽略尾部。地图原始偏移 12、16 的含义仍未验证，保留在 `metadata.headerFieldsRaw`。

`Village00` 在格子数据前有两组双向配对：`(1,9) ↔ (1,1)` 和 `(11,1) ↔ (11,9)`。原版加载器确实把两端互相写入地面对象的目标坐标，支持传送点解释；触发时机、冷却和目标被占据时的处理未通过该加载函数证明。

## 地形字段与规则边界

对象表共 490 条，本批地图引用 367 种；`TileInfo/TileInfo` 共 388 条。每条是名字加 11 个整数。部分未使用字段包含编辑器内存残留（例如 `0xCCCCCCCC`），不得把所有非零值都当成玩法开关。

| 适用类型 | 原始字段 | 结论与证据范围 |
| --- | --- | --- |
| 全部 | `[0]` | 0 地面，1 固定障碍，2 箱子，3 可穿过对象；原版加载器分别实例化对象类型。 |
| 地面／固定障碍 | `[1], [2]` | 占格宽高；大物体不能仅阻挡锚点一格。`footprintRaw` 保留值；加载器中部分跳转表反编译不完整，展开方向仍应结合原始图像及汇编验证。 |
| 箱子 | `[2]` | 0 固定箱，非零可移动箱。BoxGray 为 1；BoxOrange、BoxRed 为 0。字段不是可爆破性开关，二者都是箱子。 |
| 可穿过对象 | `[1..4]` | 四向离开许可；顺序左、上、右、下。进入检查使用对向许可。 |
| 可穿过对象 | `[5]` | 水流传播分支参与的开关；非零时使用方向许可阻挡水流。为 0 的对象可被水流清除。 |
| 地面 | `[3..5]` | 复制到地面运行时 `+0x30/+0x34/+0x38`；`[3]==0` 时后两者被规范为 0 / -1。TileConv 的 `[3]=2`，`[4]` 与来源方向一致，`[5]` 与出口方向一致。传送带逐帧位移及转向时机尚未完整追踪。 |
| 地面 | `[6]` | Island / Cliff 为 1，加载器加入地形阻挡；正常地面为 0。 |
| 地面 | `[7]` | 复制到 `+0x6c`；Factory 的 `Tile03_Ground/Tile07` 为 1。确切危险／交互语义仍未知。 |
| 地面 | `[8]` | 复制到 `+0x70`；Rail 系列为 1，乘坐时使用坐骑特定地面速度覆盖普通速度。 |
| 地面 | `[9]` | 复制到 `+0x74`；Ocean 的 Tile00/01 为 1，角色更新用它决定水域脚印效果。不得仅凭它将地面标为必死。 |

推箱输入检查可证实：角色须处于可行动状态；目标在地图内；目标无地形／对象阻挡；当前及目标的方向门允许通行；可移动箱须完全落在格点且目标没有未引爆水泡。调用 `FUN_00434d00` 的额外占用条件在本次未继续拆解，因此不能宣称全部原作推箱条件已穷尽。网络广播后才更新箱子的目标格；绘制每逻辑帧朝目标移动 4 像素，并禁止尚未落位的箱子再次被推。

## 速度核验

`Attr/BomberAttr` 无条目总数；直到 EOF 重复长度前缀名字及 10 个整数。字段 `[1]/[2]` 为初始／上限移动像素数，`[3]/[4]` 为初始／上限水泡数，`[5]/[6]` 为初始／上限威力。字段原始顺序随来源保留，不能按数字角色名重排后误用原始索引。

逻辑步长为 30 ms：`0x43cbd0` 按已过时间除以 `0x1e` 计算更新次数，`0x43d1d0` 执行这些步，`0x43c1c0` 更新人物。`0x442bb0` 将人物 `+0x3c` 的数值直接交给像素移动函数；格宽由 `0x28` 确定为 40 像素。速度道具每次加 1，并按该角色上限钳制。

| 角色来源 | 初始像素／步 | 上限像素／步 | 初始等效毫秒／格 |
| --- | ---: | ---: | ---: |
| C00 | 5 | 6 | 240 |
| C01 | 4 | 7 | 300 |
| C02 | 4 | 7 | 300 |
| C03 | 5 | 7 | 240 |
| C04 | 4 | 8 | 300 |
| C05 | 5 | 7 | 240 |
| C06 | 5 | 9 | 240 |
| C07 | 4 | 7 | 300 |
| C08 | 6 | 9 | 200 |
| C09 | 5 | 9 | 240 |

以上毫秒／格是直线无碰撞、稳定逻辑步长的静态换算，未以 Windows 实机计时测量。现平台初始 150 ms／格比 C00 的 240 ms／格快 60%，比 C01 的 300 ms／格快 100%。
