# 浏览器投影与复制验收

200 敌人的实际页面曾测得约 54.3 次运动像素更新／秒、33.4 ms 的 RAF p95，以及 139.1 ms 的原生点击到截图变化上界。预算保持不变：RAF p95 ≤25 ms、运动像素更新 ≥55 次／秒、点击像素上界 ≤100 ms。

当前正式验收 `ec10a1c2` 已通过全部网络与密集场景。普通、快端、慢端、短暂断网和 200 敌人场景均约为 60.0 次运动像素更新／秒，RAF p95 约为 16.7～16.8 ms，原生点击到操作结果的截图帧上界分别约为 21.0、17.7、11.1、17.3 和 28.1 ms。慢端协议 RTT 为 241 ms，输入 ACK 约为 246.1 ms，本地像素先响应。断线重连、六次连续输入及席位未自动托管检查均通过。规则版本为 `9876336948efbb240c8ebcac6876cf49e72772ceeb38357614b217b77b003210`，Wasm 构建为 `29b905005e0d35a6d53c00c1da207b78e13b073cddf45637d409a5560351f93f`；上一构建的正式通过记录 `97d365e3` 单独保留，不能替代本构建的验收。正式页面实际加载的五份 JS／CSS 资源还与当前构建逐字节摘要核对。

前一构建调整多塔排序和发射／命中交错，并将 63 处产品距离计算改用固定中间舍入的公共函数。10 组原版对照与 70 项多塔 Go／Wasm 完整状态／投影比较通过；之前因斜线距离末位不同而失败的记录保留。本构建进一步按每塔顺序推进世界级特性，保存盘旋塔的真实精灵位置，并保留原版电荷连接的普通射击、双阶段计时和绘制。扩展后的 24 组原版对照、402 项严格重演和九组连接绘制均通过。当前普通保留句柄复制 p95 约为 0.36 ms，合成密集复制约为 3.63 ms；旧 JSON 接口的合成密集复制约为 17.03 ms。13 项原生预测检查串行执行后通过，正式页面另按原预算验证实际像素。

本轮先保留两次失败。`b3cbf3bd` 的快端点击像素上界为 104.8 ms；实际本地输入约 2 ms 内已发布，后续诊断中按钮属性约 4.9～6.2 ms 更新，但平台通用悬停背景和 160 ms 背景过渡覆盖了原版反馈。按原版控制按钮改用专用主题颜色、1.15 倍悬停亮度、50 ms 位移过渡和按下内容偏移后，真实开启／关闭检查通过，详见[控制按钮验收](../../../games/pokepath/tests/classic-controls-scenarios.md)。

`91cce70a` 的慢端只有约 44.6 次运动像素更新／秒，RAF 仍约 60 Hz。轨迹显示本地时钟反复达到 200 ms 领先上限，保留的溢出时间使每批权威消息到达后突进、随后停帧。预测时钟现丢弃被上限截断的时间并保留有界显示相位，领先仍最多 200 ms、待确认输入仍最多 8 条；57、60、144 Hz 的固定延迟场景及恢复检查均通过。最终正式页面重新验证了实际运动像素，未放宽预算。并行构建和原生测试时另有旧 JSON 复制场景的 29.0 ms 成本失败，记录单独保留；停止构建并串行测量后为 17.7 ms，完整 13 项原生检查通过。正式页面使用的保留句柄复制同样通过，其合成密集场景 p95 约为 4.2 ms。

浏览器适配器的紧凑投影为一批敌人提供共享零值元数据，接收端还原完整公开字段。每只敌人的可变列表仍独立；浮点负零单独保留。200 条混合敌人记录的投影从 285704 B 降到 87254 B，还原后与完整 Go 投影逐字段一致。

地图版本与操作版本分别维护。暂停和恢复复用地图；路线编号、镜像方向或自定义路线变化时重新读取。规则状态复制先完整值复制结构体，再按类型计划递归复制可变字段。计划只保存类型及字段编号，不保存对局数据。

实际 Wasm 验证完整字段、可变集合隔离、负零、暂停与恢复，以及同编号自定义路线的缓存失效。Go 回归另覆盖真实持久场来源、敌人被动集合、存档恢复和分支遍历修改后的原快照。

历史记录中，中间构建的 200 敌人场景约为 60.0 次更新／秒、16.7 ms 的 RAF p95、92.1 ms 的点击截图请求返回上界。最终保留负零的构建曾测得 105.1 ms 的请求返回上界，截图请求在输入后约 3.4 ms 开始。这段记录不足以证明实际像素变化超过或满足 100 ms，现保留为旧测量方式的未通过样本。

原生截图帧测量现已通过 9 个校准场景，覆盖颜色变亮、所有颜色通道下降、图标变化、故意延迟 250 ms、不变化，以及观察回调额外晚到 250 ms。焦点框和临时等比例变暗不作为操作结果。完整 PNG、内容裁剪及其 SHA256、原生帧交换时间和消息接收时间分别保留。具体证据规则见[原生截图帧校准](../../../games/pokepath/tests/pixel-response-scenarios.md)。

测量使用独立的运动窗口和输入窗口。运动采样停止后才启动原生截图捕获；原生帧 ACK 在接收通道立即发出，不能等待解码或延迟的观察回调。PNG 解码、裁剪和编码在独立的 Node 进程执行，不再向游戏页面传回图像。离线裁剪与 Chrome 对基线及最终帧的解码结果一致，另有 156 张旧正式截图的完整裁剪 RGBA 与响应上界保持一致。此前按焦点变化判定的旧记录不计为最终通过；重新审核这些原生 PNG 的记录保留原始报告路径和摘要。

同一最终构建的旧原生帧复核中，普通、快端、慢端、快端断网及密集场景的输入结果上界分别约为 50.2、65.2、24.8、57.5 和 16.6 ms。该复核只分析已有图片。旧正式运行 `688c2885` 的短暂断网场景约为 53.3 次运动更新／秒，且出现 100 ms 长帧，保留为未通过记录。后续诊断跟踪发现，验收工具向渲染主线程传入约 12.6 MB 图像表达式，一次 DevTools 消息处理约为 326.6 ms，另有约 103.2 ms 的微任务；诊断资料保存在 `long-frame-profile.json` 和 `long-frame-profile-summary.json`。这证明旧工具存在主线程干扰，不能单凭新一轮通过追认旧样本通过。

断网场景通过真实操作收回塔，以避免正常击杀提前清空运动对象；记录操作前后金币和伙伴等级。此前 `4abcec6d` 在该场景没有可见敌人，保留为无效运动样本。普通及快慢双人场景保留实际战斗塔；当前密集验收结束仍有 200 名敌人，使用金币 50、伙伴 1 级的合法编辑器实践。

通过、失败和无效样本均保留，不能以中间构建或单项通过代替完整验收。汇总见 `.local/pokepath/verification/current-status.json` 的 `compactClient` 和 `nativePixelMeasurement`；完整字段与载荷记录见 `prediction-session-result.json`。当前未部署。
