# 后四关固定精灵知识审计

BotFutureSpriteVisionRecipes 只读取固定 LevelBundle，生成 73 条有来源的视觉配方；不接收 World、当前关卡、槽位、HP 或计时，也不在 Label 中填写当前 Stage／Scene 筛选条件。独立函数由主视觉构造器统一接入，本项不修改策略。

## 为什么部分弹体不能强分敌我

迫击炮的 code 32 是 compact 描述，原描述属性为 2。敌弹输入属性 6 合成后只比友方属性 0 多一个不参与渲染的 OAM bit 2；使用同一 CHR／调色板时像素与锚点完全相同。

炮兵子弹 code 31／attr 0 与玩家 M／S，雪地炸弹 code 34／attr 0 与玩家 F，更是相同绘制输入。本项逐像素验证这三类别名，并要求分类结果不产生 enemy。以后若根据可见运动或本人射击历史推断归属，必须在视觉时序层单独验证，不能读取真实 owner／kind。

移动矿车 20 与最初静止矿车 21 也共享 42／43 和属性 0，不能从单帧区分规则种类。因此采用统一的可见车体编号 253。

## 已报告的旧组合问题

- 狙击兵真实表为 41、44、45、65..70，属性只有 0／8／64／72。旧组合误含 decimal 42／43、64、71，并漏掉 45。42／43 是矿车；不能把十六进制表值 0x42／0x43 与十进制 sprite 42／43 混为一谈。
- Snow 炸弹由 Carrier 子表赋 sprite 34。Sprite 196 属于冰接缝；其 StateWidth=0x81、HP=0xF0，玩家与弹丸接触都被规则门禁跳过。
- 胎儿、异形弹体、蜘蛛、UFO 和手雷不能统一乘以四种 flip。
- EnemySystem.StepBullet 的合法活体图案为 30／33／7／121 的特定属性，不能扩成 30..37 × 属性列表。那样会将玩家激光的 35／36／37 伪标成敌弹。已将此项交给主构造器 owner 收紧。

主构造器的对应旧组合由 contra_static 修改；本项只新增独立配方函数，避免并行改同一处。

## 原版证据

固定 ROM SHA-256 为 6ba53139fa88b8de1ae527c438bda6f1541d1ee7df26d63dec5164a32d166bfe。新增像素基准只静态解码已固定的 ROM 图形数据，不运行模拟器，不给 Session 注入录制后态。

原版执行记录分别证明初始化／状态转移：$F02F/$F041/$F052 的炮兵 189↔190，$F085 的子弹 31，$F13C 的 32／attr 6，$AE6D/$AEAF 的 187↔188，以及 $B1AB/$B20A/$B212 的 42↔43。原始 REA Evidence ID 和来源摘要保存在 [图形基准](evidence/bot-future-sprites-original-art.json.gz) 中。

受控状态夹具有时故意将非初始阶段的 Sprite／属性设成 1，以验证保存语义。这些值没有被当作自然可达的外观组合。合法配方依据初始化、真实状态写入、资源切换与生成链共同确定。

73 个配方的 RGBA、尺寸和逻辑锚点都与独立平面图形解码一致。检查同时覆盖精确组合上限、资源不变性、敌我同图歧义及三种巨兵颜色。结果见 [验证记录](evidence/bot-future-sprites-verification.json)。
