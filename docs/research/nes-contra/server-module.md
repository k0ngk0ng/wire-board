# 魂斗罗正式服务端模块

`games/contra/server` 已实现正式平台模块，并完成模块、真实 HTTP／WebSocket／SQLite 边界验收。没有注册生产大厅，没有发布。完整八关自然通关、电脑策略达标及浏览器原生交互由对应引擎和前端验收继续完成。

## 权威边界

新局只允许原版标准一人或双人合作：每个有效角色两条备用生命、三个续关机会、第一关开局。种子和 epoch 由服务端生成，客户端不能选择初态、生命、关卡或结果。`ModuleWithConfig` 必须注入共享引擎构建清单的真实 SHA-256，测试从 `runtime.ReadRulesBuild` 读取；模块回调不读取源码或网络。

平台席位固定映射到原版角色 0／1。客户端只提交本席位按键，使用 epoch、严格递增序号和 8 位 held mask。完全相同的重试不重新执行，也不延长按键租约；倒序、冲突、越界、未知字段和客户端席位字段被拒绝。短按按顺序进入有界队列，显式释放可以清空已满队列。750 ms 未收到新输入只释放按键，不切换电脑。

宿主周期为 50 ms，规则和音频仍按 60 Hz 逐帧推进，每个正常批次三帧。长时间中断最多追赶 250 ms，即十五帧。每帧保存独立 pads、frame、revision 和状态摘要，摘要同时绑定规则构建与资源包。普通 View 保留最近 120 个紧凑事件，显式 `SyncSnapshot` 提供完整检查点。恢复拒绝错误资源／规则身份、不连续帧和修订号、错误末帧摘要；恢复保留战役与序号，释放物理按键。

暂停由原版 P1 Start 边沿触发。暂停期间宿主只调用 `PresentPaused`，不推进规则、随机数、按键采样、生命、得分或电脑策略。只有经 `Apply` 授权的 P1 恢复请求才能恢复规则；持续按住 Start 的心跳不会误恢复。恢复、暂停呈现和终局提交分别有独立重放事件。

电脑仅由宿主 `Context.Automated` 启用，通过最终 RGBA／实际公开 HUD 的 `BotVisualFrame` 观察与 `Bot.Decide` 产生合法按键，服务端已删除 `ObserveBot(World)` 路径。取消托管清理该席位输入，不重置战役或其他人的输入。初始加载由平台统一屏障处理；真实换关时创建当前关卡屏障，绑定 epoch、规则构建、资源包、关号和资源 SHA。电脑自动就绪，观战者不阻塞，重连不重新建立已结束的屏障。

## 合作结算

原版战役产生结局后，先提交对应 pads 帧，再调用 `FlushTerminal` 提交最终画面和音频，只有 `Session.Finalized` 后才生成平台 Result。成功时所有席位都获胜，失败时没有赢家，所有人的 rank 为 1，使用 `Cooperative=true` 与 `coop_campaign_v1`。

实际平台账本已验证：一人、双人共同成功各加 20 分，共同失败各扣 10 分；SQLite 重启后仍只有每人一条账本记录。这里采用服务端测试专用的原版终局边界初态，后续执行真实规则、呈现提交、平台归档和账本事务；它不证明从第一关自然打通八关。

显式电脑席位和占玩家角色的电脑不计分。敌兵、Boss 不属于电脑玩家；真人主动托管保留开局计分资格。模块不接受客户端积分数值，资格和分值由平台决定。

- 标准新局、客户端权限、序号与短按、60 Hz 时钟、输入过期、恢复。
- 原版暂停、纯呈现计时、显式恢复、混合席位、取消托管。
- 120 条重放窗口、逐事件重新执行与摘要一致、观战检查点恢复。
- 跨关就绪、错误资源身份、加载中切换托管、重连不重复屏障。
- 真实初始加载屏障、HTTP／WS 鉴权、nonce 重试、旧进程标识拒绝。

## 换关期间迟到输入

根审查提出的迟到窗口已经复现：旧实现会把加载期间的两个按键保存到队列，新关首帧实际重播 `[130,0]`、`[80,0]`、`[80,0]`；托管取消提交前，`release` 也会因宿主仍标记托管而失败。

现在屏障内的合法 `input` 只确认递增序号并保留去重键，同时清除 held、队列和租约。本人已经确认、另一人仍加载时同样适用。全部就绪后再次清除输运输入，不修改 `Session`、电脑记忆或输入序号；屏障内已确认请求在解除后的同序号重试保持惰性。新的按键或心跳正常建立新意图。`release` 在托管时也可用，但不取消自动归属。

新增模块 E2E 覆盖双真人及加载中取消托管，检查迟到输入、本人先确认、全员就绪、旧请求重试、新关首三个零输入帧及后续新按键。完整包 race 共 24 项通过；测试期间源码前后摘要相同，实际规则构建 ID 为 `87059b62ccfa918bba4eef95824c9e50534eaaa022cc4569585b10b07db55abd`。之后电脑策略再次修改，报告单独列出其时间，不把这轮结论推广到后续策略。

客户端已确认：进入屏障时取消本地输入，输入／释放／`stage-ready` 共用递增序号与发送链，解除后发送零值或新的物理按键。门槛内 ACK 不表示规则已执行。red、完整 race、HTTP 轨迹和源码摘要见 `evidence/server-stage-input-verification.json`。

## 托管释放与公平观察更新

托管期间的释放现已贯穿真实 HTTP／WS。平台仅对显式声明 `IsInputRelease` 的实时模块开放合法释放，普通按键、恢复、伪造席位、错 epoch 和观战请求仍被拒绝；模块 predicate 的参数独立复制，panic 按拒绝处理。API、真实传输及公共既有回归共 11 项 race 通过，见 `evidence/server-host-release-verification.json`。

服务端电脑观察改为注入已验证、冻结的视觉资源和纯 observer。每个规则帧只生成一次最终像素，再为两席位提供独立 actor；只填 UI 实际外显的席位、备用生命和暂停，零生命保持 Known，其他 HUD 字段未知。没有原始 World 回退。资源在模块构造外完成读取和全页验证，回调只访问内存，存档绑定 `visualsID`。

这次完整服务端包 race 共 50 项通过（19 个顶层、31 个子场景），显式浏览器服务入口按预期跳过。测试包含合成 atlas／纯 observer spy 的信息边界验证与正式 fixture 的资源加载检查；源码在编译前和完成后的摘要一致。真实视觉分类器与标准完整电脑战役仍待对应任务完成，不能用这些边界测试宣称策略已经验收。接口和失败清单见 `games/contra/server/BOT_VISIBILITY.md`，证据见 `evidence/server-bot-visual-verification.json`。
