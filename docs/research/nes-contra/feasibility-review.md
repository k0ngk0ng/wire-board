## 「全部通过都得积分，否则一起扣分」的口径

「全部通过」定义为整队完成第一轮八关。所有初始参战真人共享结果；一名玩家生命耗尽、由队友继续完成挑战时，仍一起得分。只有最终失败才扣分，单次死亡、关卡失败后合法续关和短时掉线均不立即结算。过关分、杀敌分和原版个人得分只记录成绩，不能分段领取平台积分。

| 事件 | 平台结算 |
| --- | --- |
| 完成第一轮八关 | 全队成功，所有计分参与者同加分 |
| 全灭且仍可继续挑战 | 保持同一局，暂不结算 |
| 续关耗尽或退出继续菜单 | 全队失败，所有计分参与者同扣分 |
| 已开始后主动结束房间或达到公开到期期限 | 按放弃／到期失败结算，不能关闭房间逃避扣分 |
| 刷新、重连、服务端恢复 | 延续原挑战和参战名单，不重复结算，不自动托管 |
| 首次加载尚未完成便取消，或管理员中止 | 不加减分，保留中止原因 |
| 显式电脑玩家参与或练习模式 | 按平台规则整局不计分；关卡敌兵和 Boss 不属于电脑玩家 |

当前工作区的 `coop_campaign_v1` 采用通关每人 `+20`、失败每人 `−10`；具体数值来自现有平台规则，用户要求本身只确定同加同扣。真人主动托管沿用开局计分资格。这有自动通关刷分的产品影响：如果后续要改变托管计分，须统一调整平台政策并在开局前公开，不能结算时临时取消奖励。

合作失败使用 `Result.Cooperative=true` 且赢家为空；合作成功使用全员赢家。失败不记作和局，不给队友虚构竞争排名。策略与计分资格在开局冻结，归档和积分流水在同一事务提交，每个 `(match_id,user_id)` 只结算一次。旧局不追溯启用。详细规则见 [平台积分](../../ratings.md)。

这套结果与账本机制也适用于其他有明确共同终点的 PvE 合作游戏。各游戏自行定义通关／失败并显式声明策略，平台负责资格、分值、放弃、到期和幂等结算；不能仅因游戏标记为合作就自动启用积分。

1. 补齐公平电脑和八关连续流程；先保留失败场景、原版轨迹与 E2E 入口，再改规则或策略。辅助补命诊断与标准命数验收分开记录。

4. 达到游戏交付条件后再接入正式目录与资源发布，沿用已验证构建和版本 tag 流程。
