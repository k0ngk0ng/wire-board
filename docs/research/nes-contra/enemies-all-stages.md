# 日版八关敌人接入与共享阶段

八关敌人已经接入独立 Go 规则的 `EnemySystem.Tick`，统一使用原版倒序槽位、碰撞门槛、图形队列和声音事件。初始化、出生脚本和分发已有完整阶段的原版对照。各关的自然观测与受控场景覆盖不同，不能据此声明八关自然通关或平台对局验收完成。

本项沿用 [第一关恢复记录](enemies.md) 的日版 ROM：`Contra (J).nes`，SHA-256 为 `6ba53139fa88b8de1ae527c438bda6f1541d1ee7df26d63dec5164a32d166bfe`。REA 使用工作区内的独立 Ghidra 会话；原版模拟器仅生成开发对照。生产规则不解释 6502 指令，也不依赖通用 RAM 读写。

## 初始化与出生脚本

`Initialize` 对应日版固定区 `$EDAD`，按关卡选择属性。相同数字类型在不同关卡中不代表同一种敌人。全八关共 199 个合法「关卡／类型」属性组合，以槽 0、7、15 和污染的邻槽做了 597 次原版初始化对照；全部 16 槽一致。

`SpawnScreen` 对应 `$A97B/$AA11`，包含 99 个日版脚本。室外每次只消费一个触发组，保留垂直卷轴坐标、重复出生、无空槽跳过和强制替换敌弹。基地房间使用独立的三字节条目，保留横纵半格偏移位和完整属性字节。

基地脚本仅在游标为零时载入。载入时清空各槽的 Sprite／Routine，并重置护板、轮次及生成标记；未激活槽的其他字段保留。空的 `$FF` 脚本保留核心数，只有显式零核心脚本才设置 `ScreenCleared=1`。不能在每帧或普通载入时清除／重建平台正在使用的过关状态。

3,230 次原版出生对照覆盖全部脚本、触发前后、部分空槽、全满槽、敌弹替换、室内游标重复调用和旧过关状态。数据导出及原版记录入口分别为 `enemies_all_data.py`、`enemies_capture_initialization.py` 和 `enemies_capture_all_spawn.py`。

## 唯一状态所有者

`EnemySystem` 维护实体池、基地计数、Boss 已毁部件数、异形瞄准游标和冰接缝标记。关卡推进、滚屏、调色板和平台结果仍由 World 持有，敌人上下文借用其指针或调用即时回调，不建立第二套场景状态。

- `ScreenCleared` 指向现有战斗帧的过关状态；`TankScroll` 指向现有滚屏状态。
- `Scene` 借用 Boss 滚屏完成值、`PaletteOutput` 和同一份 `PaletteState`。`RefreshBackgroundPalette` 执行真实颜色载入，并立即返回本次兼容工作结果。
- `AlienBoss` 借用自动滚屏计时、呈现节奏及地形／图形定位工作结果。最后一个字段可能来自地形查询，不能一概当成最后一次图形地址。
- `PlayerWeapons` 由 Tick 从即时玩家状态更新；蜘蛛生成器按原版读取两位角色武器的低三位决定间隔。

`BossControl` 分开表达音频重置、开始击败流程和出口就绪。音频重置发生在真实调用位置；开始击败不代表平台合作对局已经通关。出口延时保留首关 `$30`、中间 Boss `$60` 和最终心脏 `$A0` 等原值。旧 `BossDoorSignal` 入口通过显式转换保留兼容。

## 跨槽声音与地形查询

巨兵落地后的运算会使用原版声音请求的进位结果。`SoundRequestCarry(code, prefix)` 只做音频状态投影：World 从敌人阶段入口的安全副本开始，应用最近重置之后的有效声音前缀，再计算当前请求返回值。它不实际排队；正式声音仍通过 `PendingSounds` 和阶段结果提交一次。Tick 合并此前槽位与当前槽位的前缀，原版边界和「前槽爆炸 → 后槽落地」场景都已通过。

最终关守卫有一条特殊路径：图形队列拒绝时仍使用此前地形工作结果清除碰撞。普通查询留下 Column／SourceIndex；高 Y 查询也留下这个结果。`Y+dy` 溢出时只更新横向探测结果，保留先前低字节。`enemyTerrainSample` 和 `terrainAt` 从实际规则操作发布这些具名结果，不回放原版写入轨迹。

74 个混合原版阶段、154 次实体调用和 1,332 次定位值写入验证了此顺序，涵盖正常查询、高 Y、垂直溢出、有效图形定位被后续查询覆盖，以及守卫的两种清墙阶段。图形、碰撞、实体、玩家、弹丸、声音和最终工作结果一致。World 仍须把上游玩家／滚屏／武器过程的真实结果交给敌人阶段，不能用常量或原版帧末快照补值。

## 验证与范围

八关分发使用 372 个完整原版 `$E54F` 阶段、2,232 次实体调用，覆盖各个实际接入类型的初始化、滚动与满池迭代。测试比较全实体池、玩家、玩家弹、分数、图形请求及字节、地形、当前调色板、共享计数、声音和 `$06` 工作结果。原有第一关 5,396 个完整阶段回归继续通过。

实际包路径用于最终编译和限定 race 检查，避免文件名构建约束被人工文件名单掩盖。龙臂源码原名的 `_arm.go` 后缀会被 Go 当成 ARM 专属文件，现已改为 `enemies_waterfall_arms.go`。验证入口为：

```sh
python3 -B scripts/contra/enemies_verify.py
```

[子系统结果](evidence/enemies-subsystem-verification.json)记录实际包输入、运行命令、70 项通过的限定 race 检查、SHA-256 和验证期间的文件变动；本次运行中没有检测到源码变化。[本项摘要](evidence/enemies-all-verification.json)绑定新增规则、夹具和结果的摘要。[独立重录结果](evidence/enemies-all-replay.json)包含本项 13 对原版运行的输入、完整 RAM 和调用记录逐字节比较。各关另有自己的重复录制与限定验收记录。

后续连续 World 验收触发了真实首关大门击杀，补齐炮台与狙击兵对 bit 7 销毁标记的合法处理。新增 42 个实际击杀附近阶段、3 个 F 道具阶段及 12 项正常包 race 检查见 [销毁标记补充记录](enemies-falcon-followup.md)。第一关完整阶段总数因此增至 5,441；70 项基线报告保留原时间点的源码摘要。

[清理记录](evidence/enemies-all-cleanup.json)列出本项删除的 186,925,300 字节：自有 Swift／模拟器缓存、已验证的重复录制、被完整视觉快照替代的早期记录和未采用的指令入口分析。主录制、有效 REA、规范夹具及必要 red／green 证据保留；未删除用户 ROM、其他游戏或其他任务目录。

这些检查属于敌人子系统及完整敌人阶段。整个 World 的连续推进、自然 Boss 战、跨关加载、八关终局、真人／电脑合作以及网络恢复仍须由主任务分别验收。没有在本项中注册游戏、发布版本或上传 ROM。
