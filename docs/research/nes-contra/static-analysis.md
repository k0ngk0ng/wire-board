# 日版《魂斗罗》输入与角色物理恢复

本记录绑定日版 ROM SHA-256 `6ba53139fa88b8de1ae527c438bda6f1541d1ee7df26d63dec5164a32d166bfe`。使用 REA 6.5.0／Ghidra 12.1.4 的独立 stdio 会话，未操作共享 MCP target。当前恢复的是输入、主流程分派与角色物理的静态代码，不代表独立游戏已经完成。

完整 REA 记录保存为 [固定区证据](evidence/static-fixed-rea.json.gz) 和 [物理证据](evidence/static-physics-rea.json.gz)；[地址与汇编索引](evidence/static-index.json) 保留每个 Evidence ID、完整函数范围、汇编、工具限制及 ROM bank 摘要。

## 地址与 bank 身份

PRG 分成 16 个 8 KiB bank。银行编号、原文件偏移和 SHA-256 均在索引的 `bank_manifest` 中。固定分析片段覆盖 `$C001..$FFFF`，对应 ROM 偏移 `0x1C011`，长度 16,383 字节。选择 `$C001` 是因为 NMI 明确 `JSR $C001`；未把 `$C000` 的 bank 标识字节误当入口。

动态录制 `boot-solo-r2` 的 10 份完整 CPU PRG 窗口已逐段匹配原 ROM：`$C000` 始终为 bank 14，`$E000` 始终为 bank 15；启动初态的 `$8000/$A000` 都为 bank 0，其余留存帧为 bank 4/5。这个运行证据支持本轮固定区映射，不覆盖未记录的 mapper 状态。

`$F989` 读取 `$8000` 的 ROM bank 标识到 `$07EC`，随后落入 `$F98F`：将 Y 写 `$8000`，Y 加 1 后写 `$A000`。每个偶数 bank 的首字节为 `$10 + bank_index`；这些 bank 标识在本 ROM 的有效 bank 范围中产生别名。例如 `$14/$15` 对应 bank 4/5。不能把 `$8000` 读取值误解成读取 mapper 寄存器。

## 控制器与帧入口

| 地址 | 已确认行为 |
| --- | --- |
| `$F889` | NMI 保存寄存器，执行图形／声音处理，调用 `$C1BD` 后调用 `$C001` |
| `$C1F9` | 写 `$4016` strobe，依次读取 `$4016/$4017` 的 bit 0 与 bit 1，形成两个输入字节 |
| `$C1BD` | 两次硬件读输入；不一致时保留上一有效输入；生成当前按键和新按边沿 |
| `$C001` | 增加 `$1A` 帧计数，以 `$18` 经 `$C6F2` 的内联表分派主流程 |
| `$CC42` | 以 `$2C` 经同一表分派器选择关卡流程；是主流程 `$18=5` 的入口 |
| `$D3CA` | 以 `$90+x` 分派玩家状态，x 为 0／1 |

当前按键在 `$F1/$F2`，上一有效按键在 `$F9/$FA`，新按边沿在 `$F5/$F6`。边沿计算为 `(current XOR previous) AND current`，松开不产生新按边沿。位序为 A `$80`、B `$40`、Select `$20`、Start `$10`、上 `$08`、下 `$04`、左 `$02`、右 `$01`。`$1D & $04` 为零时，两个硬件端口 OR 合并到第一名角色输入；平台需要按明确单人／双人角色映射接入，不能依赖这个硬件兼容行为来混用席位。

相关 Evidence：`ev_a192bc938be1c175b33f6bab96de574afb18f35301def9e670692bc0b19e7831`（`$C1BD`）。原版自然录制中，Start 连续按住时 `$F1` 持续为 `$10`，而 `$F5` 仅首次按下帧为 `$10`；完整录制与后续动态差分由游戏实施记录维护。

## 角色状态与字段

`$90+x` 的内联分派表为：0 → `$D3ED`（入场初始化），1 → `$D45E`（正常行动），2 → `$D4BD`（死亡动画），3 → `$D30B`（无常规行动及借命检查）。当前可操作状态应同时结合主流程、关卡流程和角色状态判断，不能仅以人物已绘制判断。

| 字段 | 静态代码中的含义 |
| --- | --- |
| `$031A+x`／`$0334+x` | 屏幕 Y／X 坐标 |
| `$94+x` | Y 位移小数累计，起跳不会清零 |
| `$C4+x`／`$C6+x` | Y 速度低／高字节，组成有符号 16 位定点值 |
| `$BA+x` | Y 坐标的高字节／屏外状态，跟随 Y 位移进位更新 |
| `$98+x` | X 整数速度；`$96+x` 为室内推进小数速度 |
| `$92+x` | X 小数累计 |
| `$A0+x` | 跳跃标志及方向，起跳设置 `$11` 或 `$91` |
| `$A4+x` | 踏空／向下穿平台状态 |
| `$B2+x` | 水中及出水状态 |
| `$C2+x`／`$BC+x` | 瞄准方向／动画序列 |
| `$9E+x`／`$A6+x` | 动画计时／动画帧索引 |
| `$D0+x`／`$CA+x` | 室内推进／强制跳跃状态 |
| `$32+x`／`$38+x` | 余命／Game Over 状态 |
| `$40` | 场景类型；bit 0 决定室内起跳速度，bit 7 改变出生位置索引 |
| `$41` | 滚动方向；零走横向分支，非零走纵向分支 |
| `$30` | 关卡索引，进入出生位置表等关卡数据索引 |

场景类型在所有关卡的实际取值仍需运行覆盖，不把第一关观察扩大到整个游戏。

## 可直接进行差分验证的定点操作

| 入口 | 恢复出的精确操作 | Evidence ID |

| `$D601` | 按朝向设置 `$A0`；清 `$9E/$A6`；室外速度 `$FBF0`，室内 `$FC90`；不清 `$94` | `ev_1c1060982ecaff8c0da66d68603c8efb8edf43c6fed5056cc3d668cad1f0d4e0` |
| `$D922` | 16 位速度加 `$0023`，按字节进位并回绕，无终端速度钳制 | `ev_ad19c82c4c04bbc59f2f19062c86067b7723a619551790af71b25ac37fd35f4e` |
| `$D901` | 24 位位置 `$BA:$031A:$94` 加上符号扩展后的 16 位速度 `$C6:$C4` | `ev_a0873916fe6f341835314f297839a1833dd04f8cbe52a71f956e8618f91e1f88` |

`$FBF0` 作为有符号 16 位整数为 −1040，除以 256 后是 −4.0625；`$FC90` 为 −880／256，即 −3.4375。不要把高字节和低字节分别当成十进制负整数与小数。公开美版反汇编中的部分文字注释有这种数值解释错误，本轮以日版字节和 6502 进位语义为准。

先验失败场景包括：负速度符号扩展错误、小数累积被起跳重置、字节进位遗漏、24 位溢出被饱和截断、按住跳跃重复初始化、室内外跳速混用。Go 实现应先读取原版调用进入／返回轨迹建立差分测试，避免先实现再根据结果编写测试。

## 完整动作逻辑仍有依赖

`$D495` 正常动作流程依次调用瞄准 `$D848`、边缘检测 `$D8B0`、射击换页入口 `$FA12`、状态和 X 更新 `$D518`，随后继续自动滚屏逻辑。`$D518` 在非室内推进时先清 X 速度，再调用 `$D595`，之后还要经过实体地形、场景边缘和滚屏约束。

`$D595` 依次区分室内强制跳跃、触电、踏空、已在空中、室内推进、水中、A 新按边沿及 Down+A。`$D6DD` 的跳跃处理包含下降落地、头顶碰撞、重力、纵向镜头约束与朝向更新；不能只以抛物线替代整个动作。

`$D941` 的横向滚屏分支会检查另一名玩家是否落在 X `< $21`，必要时冻结推进角色的 X 速度，避免镜头甩掉队友；纵向滚屏从 Y `< $50` 且向上移动等条件开始。具体场景界限表与碰撞数据还需恢复。

REA 的函数边界是分析器和显式 seed 的结果；内联跳表、跨片段 fallthrough 和尾跳不一定对应原源码函数。本轮保留完整汇编及局限，不能只按伪 C 中的一个函数名称推断完整流程。

## 日版借命约束

在 `$D2D9` 后半段、入口 `$D30B` 的代码中，借命要求：关卡流程 `$2C=4`、双人模式 `$22!=0`、Game Over 玩家产生 A 新按边沿、队友余命大于零；队友只剩一条余命时，其角色状态必须为 1；队友还必须不处于 `$D0!=0` 的室内推进阶段。然后队友余命减一，调用 `$DA07` 初始化复活角色，并清该角色的状态及 Game Over 标记。

最后一个室内推进限制在本轮参考的美版注释中没有出现，不能把美版文本直接当日版规则。Evidence 为 `ev_76a270dce5c6594f7bfd2b33dc402a6ea5150f169a962aeff81798f604d35ef1`，实际成功／拒绝借命轨迹仍需采样。

## 重复执行

```sh
python3 -B scripts/contra/static_prepare.py
node scripts/contra/static_rea.mjs .local/contra-static/fixed-spec.json
node scripts/contra/static_rea.mjs .local/contra-static/physics-spec.json
python3 -B scripts/contra/static_export.py --runtime-run .local/contra/runs/boot-solo-r2
```

分析缓存限 `.local/contra-static/` 与 `dist/contra-static-tmp/`。工具复用仓库已有 Ghidra、JDK 和 MCP 客户端包，不安装或改写工作区外文件。导出的 gzip 是完整 REA bundle，可解压复查；索引是派生阅读视图，不代替完整证据。

用于寻找候选字段的外部参考为 [nes-contra-us](https://github.com/vermiceli/nes-contra-us) 的 tree 对象 `687d651c021fd7020f10d05b970ccb62663c94bd`，读取 `src/ram.asm`、`src/constants.asm` 和 `src/bank7.asm`。其角色只是候选地址和术语参考；日版代码地址、运算和借命条件均另由本地原版字节及 REA 恢复。
