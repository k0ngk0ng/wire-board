# 基地滚轮属性字节兼容例外

当前实现已经撤除 `BASE-ROLLER-STALE-ATTRIBUTE` 归一化，改为继承真实碰撞高度，见 [后续恢复记录](enemies-base-throw-height.md)。下文保留先前的单字段无玩法影响证明及原始证据，不能作为当前输出比较的豁免。

先前方案在基地士兵通过 `$92E4 → $971B → $971E` 新建类型 `$11` 滚轮时，将没有玩法作用的 `Attributes` 归一化为 0，其他字段严格比较。无玩法影响的结论结合固定日版代码审查和 32 条原版配对执行，不根据变量名称或四条初始差异直接推断。

## 原版数据流审查

两个基地的敌人表均指向 `$E5FF`，类型 `$11` 的阶段表为 `$8F8F`。五个实际入口依次为 `$8F9B`、`$8FA3`、`$E67C`、`$E6D5`、`$E737`。原版属性行是 `$05A8..$05B7`；测试使用槽 15，因此只允许 `$05B7` 保留差异，邻近 `Data[0]` 行从 `$05B8` 开始。

| 路径 | 代码审查结果 | 证据入口 |
| --- | --- | --- |
| 新建 | `$971E` 在初始化后将 `$0A` 存入属性，随后只按已有方向索引设置速度；`$ECB2/$ECB4` 计算方向，不设置 `$0A` | `$971E`、`$97EF`、`$ECB4` |

## 配对原版运行

8 个场景各运行 `Attributes=0/12/19/255` 四个版本，每个版本连续执行 400 个视频帧，共 32 条运行、12,800 帧和 24 组相对 0 的配对比较。每组从同一个已绑定来源的日版基地二初态开始，变体间唯一不同输入是滚轮属性。四种原始出生数据被放入同一测试槽；不声称这些设置后的场景是自然通关。

| 场景 | 原版实际覆盖 |
| --- | --- |
| 四条原始出生数据，各自延续 | 初始化、尺寸变化、碰撞代码 2→14、移动及移除；保留各自 X 和速度 |
| 玩家接触 | 原版玩家受击、死亡与后续状态；接触前后其余 RAM 一致 |
| 投射物命中 | 明确放入 5 枚合法原版玩家弹，由原版碰撞令 HP 5→0、发放街机击杀分并完成阶段 3～5 爆炸与移除 |
| F 道具 | 明确放置 F 拾取物后，由原版拾取逻辑调用 `$E949`，OR `$80` 并完成完整爆炸 |
| 原版槽复用 | 滚轮自行移除后，明确放置一个请求生成弹体的 Eye；原版 `$EAB8 → $EDAD` 复用槽 15，变为类型 `$1B`，随后 57 帧完整 RAM 一致 |

各场景的共同设置和定时触发都记录在 `interventions.jsonl`。投射物和拾取物由原版处理命中、得分和销毁；没有直接设置滚轮的伤害结果或最终状态。

比较结果为：

- 每帧完整 2 KiB CPU RAM 只有允许的滚轮属性字节可能不同；槽变为其他活动类型后不再掩码，完整 RAM 必须相同。
- 400 次实际 OAM DMA 内容及其帧号一致；记录器检查每帧确有 DMA，避免比较未更新的占位数据。
- 全部 PPU／APU 寄存器写入顺序和所属帧、分派及碰撞调用、声音请求、控制器输入与帧记录一致。
- 五个选定视频帧的 PNG、完整 PPU 和当前 PRG 窗口逐字节一致。
- 属性访问钩子没有观察到玩法或绘制读取。F 场景只见 `$E96E` 的读取及索引存储预读；复用时只见 `$ED70` 清零写入的预读。FCEUX 回调报告的是该三字节指令之后的 PC，因此日志对应 `$E971/$E976/$ED73`，不能把报告 PC 误认为另一条属性消费指令。

原版运行逐帧保留自己的状态，没有在每帧前从期望结果重置滚轮。[配对材料包](evidence/enemies-base-roller-paired.json.gz)保留所有用于比较的原始字节及逐项 SHA-256；[验证结果](evidence/enemies-base-roller-verification.json)列出每场景覆盖、属性访问和对比结论。

## 复查

只需 Python 标准库，即可从保留材料重新执行全部比较，不依赖临时录制目录：

```sh
python3 -B scripts/contra/enemies_base_roller_verify.py
```

重新录制时使用尚未存在的新标签。每个场景需要分别运行四个属性值；参数 `--record` 可选 `140/8586/8715/9174`，`--mode` 可选 `natural/contact/shot/falcon/reuse`，其中 `natural` 仅是「保留原出生数据的受控延续」这一内部场景名。

```sh
.local/board-art-env/bin/python -B scripts/contra/enemies_base_roller_capture.py --record 140 --mode falcon --attr 19 --label recheck
```

本次仅新增分析、原版录制及比较材料，未修改生产规则。兼容白名单收紧由父级基地验收维护；显式受控样本也必须绑定来源，不得因本证明而绕过记录准入。

已将全部成功配对的比较字节归档后，清理本组私有原始录制、旧探针、REA 缓存和模拟器临时 profile；离线比较在清理后再次通过。[清理清单](evidence/enemies-base-roller-cleanup.json)限定本组路径，其他基地或游戏产物未改动。另保留[六张可直接查看的原版截图](evidence/enemies-base-roller-screens/manifest.json)，完整 160 张配对 PNG 均在材料包内。
