# 原声音逐 slot 生命周期采集约定

范围：固定日版 ROM 的有效声音 ID 1–129。仅记录原声音控制程序，不导出 PCM，不修改游戏规则实现。原 ROM SHA-256 为 `6ba53139fa88b8de1ae527c438bda6f1541d1ee7df26d63dec5164a32d166bfe`。

## 实现前列出的失败场景

1. 用复合声音整体存活时间代替每个 slot 的寿命；其他 slot 发出更高优先请求提前覆盖被测 slot。
2. 每 tick 清理其他 slot，误删被测音序正常发出的打击乐。
3. 只比较声音 ID、指针或少量 RAM，遗漏循环计数、栈、寄存器及共享状态，误判无限循环。
4. 只出现一次相等状态就宣布周期，未核对之后完整周期的逐 tick 状态及请求序列。
5. 采样达到上限后仍未证明循环，却输出无限寿命；未知必须保持 `unknown`。
6. 音序内请求、其他 slot 请求、slot 清除后的结束回调相混；按共用 sequence 指针错误套用 ID 专属回调。
7. `$6A` 结束触发 `$6E`、`$77` 的 slot 5 在 `$0194>0` 时触发 `$62` 被遗漏。
8. `$7B` 等以复合 entry 开始的音序被错误缩成首 entry；同 slot 重复 entry 的最终指针未验证。
9. 初始请求未被接受、返回 carry 被猜测、预热少一 tick、释放与循环坐标错一 tick。
10. 回调产生的新声音污染被测 ID 的请求时间表；无 source slot、source ID 或 caller 记录无法追溯。
11. 开发计数器持续增长导致完整 RAM 无法重现；删去不同字段后宣称完整状态相等。
12. 重用旧目录伪装独立复录、共享 emulator 配置引入竞态、进程失败留下半成品、压缩后丢失来源摘要。

## 验证要求

- 每个 `(ID, targetSlot, context0194)` 独立启动 FCEUX。原版静默更新 120 tick，调用原请求入口，再只清一次其他 slot 的活动 ID；披露写入地址与前后值。`$0194=0` 是默认输入，`$77/slot5` 另采 `1`。
- 保留原表 ordered entries、实际接受后的六个 slot、目标指针及 A/X/Y/P/S/C。直接 DPCM 请求不伪造普通 slot。
- 每次原 `$80D5` 返回后保存完整 2 KiB RAM 和 A/X/Y/P/S。开发计数器进入录制后冻结。原版代码和数据保持逐字节一致，仅经验证的 FF padding 放入调用包装。
- 状态在 tick `p` 与 `q` 后相等时，候选周期从 `p+1` 开始、长 `q-p`；继续执行一个完整周期，逐 tick 比较全部状态与请求事件。未验证前不输出 `loop`。
- 目标 ID 首次退出时输出有限 `releaseTick`。只有已证明循环才允许 `releaseTick=-1`；未知为 `null`。
- prefix/loop 仅纳入来自目标 slot 且 source ID 仍为被测 ID 的请求。清除后请求单列 `endCallbacks`，所有原请求仍在原始证据中。
- 选取复合声音、有限声音、循环和两种 `$77` context 独立复录；比较原始状态及请求的 SHA-256。验证器须拒绝单字节状态或请求扰动，以及将未知伪装成循环的结果。
- 发布研究 JSON 使用原子替换并带 `partial/complete` coverage；保留可复验的压缩原始记录、wrapper/Lua 和工具摘要。只清理本任务私有 profile、缓存及已核对相同的重复中间产物。

该隔离实验回答「目标 slot 在指定共享初态下的独立生命周期」。不证明任意声音组合、暂停、PCM、浏览器混音或自然对局均已验收。
