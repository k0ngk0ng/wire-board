# 第六、七关机械与共用炮弹恢复

本记录覆盖日版原版的第六、七关机械、Boss，以及共用迫击炮弹、炮兵和炮兵子弹。生产代码采用独立状态机、定点速度和图形请求，不执行 6502 指令，也不读取模拟器 RAM。REA 用于恢复原始条件与数据；FCEUX 仅生成开发对照。

本组 17 个类型的状态机与图形队列已通过 11,381 条原版记录对照，完整包编译下的本组测试全部通过。巨兵已接入公共音效返回值接口，所需调色板也已补齐。结果见 [验证记录](evidence/enemies-machines-verification.json)；连续独立世界及平台验收不在本组结论内。

## 原版中必须保留的行为

`RequestTileAnimation` 恢复 `$F9F7 → $C593`，与 32 × 32 的 `RequestSupertile` 分开。它检查当前队列游标是否小于 `$50`，允许一次接受后超过该门槛。每行写两个 tile，行数由源表决定；机械爪的三行数据会继续读取相邻条目的字节，不能截成四个 tile。

`$C593` 在发出调色板包之前，把定位器的属性地址低字节 `$14` 覆盖为行数。原版带调色板的请求因此写入 `$2302`／`$2702` 等地址。实现保留这个实际行为。接受后调用者 `$0F` 对应 `code & $80`；拒绝不覆盖旧值。该路径不修改 `$06`、`$23`、超图块映射或碰撞窗。

火焰只有图形请求被接受后才更新可伤害长度；裁切到屏外时的成功返回保留原始顺序。三个方向分别使用邻近玩家、全局帧匹配和倒计时触发。日版点火音为 `$19`，缩回路径的 `SBC #7` 在进位清零时实际减去 8。

士兵生成器的双超图块更新 `$EB34` 会复用碰撞例程写出的 `$07`。首次碰撞写入后的游标影响第二次碰撞更新是否执行，不能直接按理想的两段地形重新生成结果。满槽时，原版士兵生成器仍向父槽写属性；实现和用例均保留该分支。

巨兵的落地音 `$2B` 返回进位会参与之后的 `ADC Frame`。普通路径返回清零，但活动声音槽 1 为 `$62` 时，早退路径返回置位。实现通过 `SoundRequestCarry` 对当前有序请求做语义投影，然后只追加一次声音请求。死亡路径先执行 `$F9D4` 清空声音槽，再请求 `$75`，该链条可确定返回置位。

巨兵受伤时的调色板组 `$51`／`$52` 已从原版 `$D1D6`／`$D1D9` 补入全局和第六关资源，分别为 `[32,19,39]`、`[32,22,39]`。对照覆盖全 32 色加载、颜色请求计数、淡入淡出状态和对应的随机工作值。

## 复验

在仓库根目录执行：

```sh
python3 -B scripts/contra/enemies_machines_verify.py
```

该命令运行本组 Go 检查，保存完整日志、夹具摘要和 REA 归档。其他任务处于未完成的共享编译状态时，结果会明确失败。

```sh
.local/board-art-env/bin/python -B scripts/contra/enemies_machines_replay.py --label review2
```
