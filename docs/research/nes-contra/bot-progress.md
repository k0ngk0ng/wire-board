电脑／主动托管仍在开发中，**标准单人、双人完整八关验收未通过**。不得据此注册或发布游戏，也不能把原先直接读取规则对象的首关／基地通过记录作为最终电脑能力证明。

当前生产观察入口为 `ObserveBotFrame(BotVisualFrame, *BotVision)`。`BotVisualFrame` 只保留玩家实际已显示的 RGBA、公开 HUD、席位和输入时刻；旧 `ObserveBot(World, …)` 已删除。源图形目录经 SHA-256 校验后，由 `NewBuiltinBotVision` 编译固定视觉知识。策略输出仍是普通 held pad，世界、生命、伤害、续关次数和胜负均由正常 `Session.StepPads` 推进。

已验证的基础：

- 只从实际像素识别角色、公共精灵、背景核心／炮台／门、关卡文字及续关光标；未知 HUD 值不补读规则。
- 空白、未提交、隐藏画面不产生规则对象；图案别名按实际图像归一。相同闭合核心／炮台图像使用公共类别 254。
- 遮挡角色依据剩余可见颜色和空间结构定位。水中头部即使在单人房间也只保留候选：占位不能排除敌兵头部复用相同像素。局部身体匹配同样不直接确认身份；完整匹配优先，已有公开轨迹在等距候选中优先 `Exact` 图案，无历史不强选席位。
- 敌人跟踪不信任每帧序号，按公开位置和外观关联；已见过的独有核心／炮台类别可以跨闭合外观保留。
- 人物脚部遮住支撑格时，仅在剩余半图案跨固定目录唯一且无矛盾时补充地形识别；相同剩余像素对应不同材质仍保留未知。
- 单人／双人恢复检查同时保存 `Session` 和 `Bot`，恢复后重新决定按键并比较策略记忆和下一帧世界。取消托管只停止电脑输入，不重置 Session。

证据分别位于 `evidence/bot-visual-tracking-first.jsonl`、`bot-visual-markers-first.jsonl`、`bot-visual-terrain-occlusion-first.jsonl`，以及 root 维护的水中图案、像素提供者和匹配差分记录。以上是基础模块验证，不等于完整通关。

标准对局入口：

```sh
python3 -B scripts/contra/bot_run.py --name unique-run-name --players 1 --frames 120000 --target 8
python3 -B scripts/contra/bot_run.py --name unique-coop-name --players 2 --frames 120000 --target 8
```

每次运行在 `.local/contra-bot/runs/<name>/` 保存完整 held pad、公开观察检查点、最终 Session／Bot、结果与源文件摘要。完整通过要求 `CampaignCleared`、终局呈现 `Finalized`、输入／恢复一致、源码运行期间不变，且没有开发用前缀。失败对局即使已完成终局呈现，也不算通过。

`--prefix` 仅用于从标准新局重放此前合法按键后继续定位问题，不注入内存、位置、生命或结果；其记录始终标记为 focused continuation，`complete_campaign=false`。独立回放使用 `go run scripts/contra/bot_replay.go <playersN目录>`，不会调用策略。
