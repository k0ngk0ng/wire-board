# 游戏基础配置验收

实现前确定的失败场景：

- 未登录或普通玩家写入配置；未知游戏、缺少字段、null 和非布尔值未被拒绝。
- 修改基础配置意外改变游戏顺序、上下架状态或关闭等待牌桌；一个游戏的配置影响另一个游戏。
- 配置或审计写入失败后，数据库与内存不一致；失败请求留下成功操作记录。
- 老数据库升级失败，重启丢失配置，新游戏继承其他游戏的配置。
- 后台请求期间重复提交、刷新显示旧值、保存失败仍显示已开启。
- 桌面或 320 px 手机无法操作开关，长名称和大量游戏导致横向溢出；搜索、分类和空结果受影响。
- 开启后必须额外点击才能全屏；原生请求被拒绝时没有网页全屏回退；关闭后仍自动进入。
- 等待房间或观战自动进入；加载完成、普通刷新或配置切换把主动退出的玩家重新全屏。
- 新对局未重新进入；进入、退出或卸载后棋盘重挂载、焦点、滚动或 inert 未恢复。
- lint 未登记改动文件，或未拒绝错误目录、命名、注释和动态执行；已有文件中的历史写法不能借本次变更扩散。

新配置默认关闭，按游戏独立保存。开启后参与玩家从开局加载阶段自动进入游戏区全屏，适用于桌面和触屏。关闭后通过全屏按钮或 F11 手动进入；观战保持手动。

重放：`go test ./internal/server -run '^TestAdminGameConfig' -count=1`。浏览器验收另设 `WIRE_BOARD_GAME_CONFIG_BROWSER=1`，运行 `go test ./internal/server -run '^TestAdminGameConfigBrowserE2E$' -count=1 -timeout=5m`。运行前创建工作区内的 Go 缓存和临时目录，并将 `GOCACHE`、`GOMODCACHE`、`GOTMPDIR`、`TMPDIR` 指向这些目录。结果与截图保存在 `.local/admin-game-config/`；浏览器使用实际平台页面、真实 HTTP 和 SQLite，不覆盖其他游戏的完整对局。
