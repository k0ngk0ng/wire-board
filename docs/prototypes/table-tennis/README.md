# 乒乓球第一人称纯球拍双打原型

状态：美术与局部交互提案，尚未接入正式游戏。分类确定为「体育」，首版范围调整为单打和双打，不再推迟双打。

打开 `index.html` 可切换三种场馆风格。当前版本改为站在球台前的第一人称：自己的球拍在前景，对手的两支球拍位于球网后，搭档的球拍在侧边。画面不出现人物、手、手臂或人物头像，镜头保持稳定。手机不需要控制身体、走位或摇杆。

直接在球场画面划动挥拍，底部不设按钮、力度条或独立手势区。手机手指和 PC 鼠标按住划动，前划抽球、后划削球、斜划变线、短点挡球；球拍跟随拖动。画面获得焦点后，上下方向键仍可抽球／削球。移出画面松手正常结束，取消手势、失焦与切换风格不会补发击球。

文件已内嵌渲染代码，可直接在支持 WebGL 的浏览器中打开，不需要联网下载图片、字体或脚本。当前球路是表现演示，不是比赛物理或旋转规则；没有真实计分或对手回球。

## 三种方向

- A「现代球馆」：奶油白、鼠尾草绿、赤陶色对手球拍与柔和日光。建议优先讨论这一方向。
- B「街机赛场」：深蓝空间、珊瑚色球台、青绿色边光与聚光，强调速度和动作剪影。
- C「复古体育馆」：高窗、木地板、长凳和传统胶皮球拍，温暖的社区体育馆氛围。

场地、球台与球拍均为本项目编写的程序化 3D 几何，纹理由 Canvas 生成；没有使用 AI 生图、外部人物模型、商业游戏截图或未授权贴图。原型内嵌仓库现有 Three.js 运行库；其许可见 `THREE-LICENSE.txt`。人物造型方向已取消。单打计划显示两支球拍，双打显示四支球拍，己方与对方采用不同色系，身份通过姓名和接球提示区分，不添加席位数字。当前原型展示双打。

## 双打首版范围

正式游戏计划开放 2 席单打和 4 席双打，使用统一房间和准备流程。双打支持四名真人、真人与电脑混合、两名真人搭档对两名电脑，以及统一托管和手动接管。双方均可使用 PC 或手机，不要求同类设备。正式接入复用平台 `GameFullscreen`，只让游戏区全屏，并在全屏内保留比分、接球次序、画面内挥拍与结算；本轮视觉原型尚未接入此组件。

- 双方各两人，同队必须交替击球。连续击球次序由服务端维护，不允许同队一人连续包办。
- 双打发球从己方右半台到对方右半台，正确处理发接球次序、换发球、局间与决胜局换边。完整裁判细节在规则实现前列出失败场景并逐条核对。
- 每名真人只控制自己的球拍。手机使用单指在画面内划动，PC 使用鼠标拖划；不提供人物移动、走位摇杆或身体控制。击球覆盖范围、挥拍时机与旋转由正式规则统一约束，不能替队友击球。
- 当前接球者通过公共玩家信息和简洁的接球提示辨认。球拍不叠加席位编号，不使用人物模型或头像。
- 非接球搭档保留球拍准备反馈；其输入不能消耗当前接球者的挥拍，也不能跨轮次留下陈旧击球。
- 每个席位使用自己的第一人称稳定视角，只转换显示坐标，不改变服务端席位、旋转和落点规则。
- 手机竖屏优先保留球网、来球、对手球拍与自己的球拍，允许裁切近侧球台边角和侧边搭档球拍。PC 提供更宽的周边视野。两端均直接在球场画面划动，不另占一条操作区。桌面与触屏映射同样的力度和旋转范围。

当前界面中的比分、席位姓名、接球者和站位是固定展示数据；尚未实现交替击球、计分、联网、电脑或托管。球拍演示不代表手感和完整比赛已经验收。平台外框在此为视觉参照，正式接入时复用公共组件。

## 原型验证

```sh
node docs/prototypes/table-tennis/build.mjs
python3 -B docs/prototypes/table-tennis/verify.py
```

`verify.py` 启动临时本地 HTTP 服务，以独立的 agent-browser 会话渲染三套方向，保留 1440px 桌面、390px 手机、320px 窄屏截图；检查第一人称场景、四支球拍、无人物与身体移动操作、无底部操作控件、页面溢出、画面内鼠标挥拍、键盘削球、CDP 原生触摸削球及风格切换。验证对象仅为视觉原型。手机采用 Chromium 视口模拟，不作为 iPhone／Android 真机或 Safari 验证。

新版截图在 `screenshots/rackets-*.png`，此前提案截图保留供对照。可重复执行报告与源码摘要在 `.local/table-tennis-design/rackets-verification.json`。`compare.html?style=club`、`arena` 或 `heritage` 展示对应的桌面／手机对比。临时浏览器 profile、socket、构建中间文件和失败日志在交付前清理，保留最终报告与截图。
